# 意图（intent）：SDO 无插件版流程 skill

状态：**已签 S1**（2026-11-18T17:30+08:00，选项：签：复述准确）
版本：intent-001

## 1. 一句话

把在 `docs/`+`design/`+`plan/` 里跑通的那套项目管理流程（意图→计划评审→卡→两轮评审→签字→读数门→台账），做成**不装插件、没有 SDO 工具、没有数据库**也能用的 skill 与流程 preset。

## 2. 为什么

- 现在这套流程只在装了插件的环境里成立：真源是事件表、门禁由 `judgeStage` 判、签字由 signerd 产签名。
- 但在客户机器、临时会话、别人的仓库里，往往装不了插件（宿主权限、无 Node 环境、纯 Web 会话）。
- 结果是：**流程只存在于这个仓库的操作习惯里，不能被带走**。skill 化之后，换个环境也能按同一套规矩干活。

## 3. 三条保证怎么降级

| 保证 | 插件版载体 | 无插件版载体（本 skill） | 降级后的诚实说法 |
|---|---|---|---|
| 对齐 | 签字 `intent`/`plan` 事件 + hash | 意图/复述文件 + **人签用问答选项** | 人点过“对，这是我要的”，但**没有密码学签名** |
| 可审计 | 事件链 + `verify` 重算 | 追加式 Markdown 账本 + 每条带日期与出处 | 账本是文本，**同 uid 可改**，不防篡改 |
| 防漂移 | 判据/门禁/baseline 冻结 | 判据清单 + 自检脚本/命令 + 计划评审 | 只有**人工判读 + 可复跑命令**，没有机器强制 |

## 4. 做什么（范围）

1. `.dsh/skills/sdo-flow/`：`SKILL.md` + `references/`（八篇）。
2. 一套 `templates/`（意图/计划/卡/台账/签字/读数/看板）。
3. 三份**流程 preset**（生命周期：`waterfall` / `prototype` / `incremental`，与设计 `docs/08` §1 一致），各含阶段序列、出口判据表与等价 policy YAML。
4. 人签模板：一律 `ask_user_question` 三选项（但本行按裁定：注册=问答询签）。

## 5. 不做什么（非目标）

- 不实现事件表、`append` 网关、`verify` 重算、门禁自动判定、签名密钥。
- 不复制 `docs/` 全文；SKILL.md ≤ 120 行，每篇 reference ≤ 80 行。
- 不假装等价：降级点必须写进「已知边界」。

## 6. 验收判据

| # | 判据 | 怎么验 |
|---|---|---|
| A1 | 只含 skill 与流程产物，**零插件代码** | `git ls-tree -r --name-only HEAD \| grep -E '^(src/\|index\.(js\|cjs)$\|cordis\.patch\.yml$\|lib/\|test/)'` 输出为空 |
| A2 | skill 可被文件系统 skill 提供者发现 | 会话 skill 目录出现 `sdo-flow`（已实测出现） |
| A3 | 流程可执行 | 本仓库自身按七步循环走一遍（立项已签、计划待评审） |
| A4 | 人签只用问答选项 | SKILL.md 与 references 里“人签”一律指向 `ask_user_question` 三选项 |
| A5 | 降级诚实且可演示 | SKILL.md §1 与 `references/07` 逐条“挡不住什么”；R4 为每条配可复现反例命令 |
| A6 | 流程 preset 不是宿主 bundle | `presets/` 下只有 Markdown（阶段/判据/等价 policy），无 `package.json`、无 `cordis.patch.yml` |

## 7. 假设

- A1：目标环境至少能读文件、能跑 `git`；不能跑 Node 时用人工对账。
- A2：人签由会话里的真人点选项完成；没有真人时流程阻塞（不许模型自签）。
- A3：skill 只依赖“读文件 / 写文件 / 跑命令 / 问人”四类能力。
