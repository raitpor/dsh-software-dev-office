# 横切：语言无关与安全脱敏

> 本篇合并自「语言无关与可移植」+「安全与脱敏」（合并目的：一个事实只有一处，防漂移）。

> 规则只有一条：**引擎不认识任何编程语言，也不认识任何文件格式**。项目的一切"语言特性"都由**适配器**声明，输出归一到少数几种"事实类型"。

---

## 1. 为什么必须这样

v1 的需求里"判据语言无关"提过，但实现里到处是"读某个文件、按某个键名取值、按某种目录布局判断"。后果：

- 判据要为一个具体项目写特例 ⇒ 判据越加越多，可移植性越差；
- 换语言/换目录布局就误判；
- 路径与大小写假设在 Windows 上整片失效（v1 的真实事故：路径前缀硬编码 `/`，Windows 上工作区写入被全量误拒）。

v2 把这条变成结构约束：**判据只能吃"事实"，不能吃"文本"**。

---

## 2. 事实类型（全部判据的唯一输入）

| 类型 | 形状 | 谁产出 |
|---|---|---|
| `verdict` | `{ status: pass\|fail\|na, code, detail? }` | 测试/构建/静态检查适配器 |
| `metric` | `{ name, value: number, unit?, scope? }` | 覆盖率、复杂度、耗时、体量 |
| `artifact` | `{ uri, sha256, bytes, media_type }` | 产物、报告、日志 |
| `duration` | `{ name, ms }` | 执行时间 |
| `log_excerpt` | `{ uri, from_line, to_line, digest }` | 日志片段（**只存引用与摘要**，不存全文） |

判据的签名因此变成：

```ts
criterion(facts: FactSet, params: Params): Result
```

**没有 `cwd`、没有 `readFile`、没有 `exec`**——判据不能碰文件系统，只能读事实集。

---

## 3. 适配器（项目侧声明）

```yaml
adapters:
  test:
    command: "node --test --test-reporter=tap lib/test/*.test.js"
    produces: [verdict, duration, log_excerpt]
  coverage:
    command: "npx c8 --reporter=json-summary"
    produces: [metric]
    parse: json-summary        # 声明的解析器，不是代码
  build:
    command: "npx tsc -p tsconfig.json"
    produces: [verdict, artifact]
```

规则：

1. **适配器由项目声明，引擎只执行并归一**；新增语言 = 新增适配器，不改引擎；
2. 适配器输出必须能映射到 §2 的事实类型；映射不了 ⇒ 该事实缺失；
3. 事实缺失时判据的默认行为是 **`fail` + remedy"声明 XX 适配器"**（fail-closed），**除非** gate 把该判据标为 `optional`（那时为 `na` + 理由）；
4. 适配器本身要版本化（`adapter.version`），升级适配器 = 一次带签字的变更。

---

## 4. 平台支持：Linux × Windows

**一期必须两端都能跑；"只在 Linux 绿"视为缺陷**（v1 就踩过 `本地全绿 ≠ CI 绿`）。

### 4.1 路径（最容易错）

| 规则 | 说明 |
|---|---|
| 引擎内部**只有 POSIX 相对路径** | `/` 分隔、相对仓库根；绝对路径与外层前缀一律拒绝 |
| 只在**边界**转换 | 读 OS 参数、调 OS API、落盘时才转；转换点集中在一处 |
| 不拼字符串 | 用 `path.join` / `pathToFileURL`，禁止 `dir + '/' + name` |
| 盘符与 UNC 必须解析 | `C:\...`、`\\server\share\...` 可以出现在**输入**，但入库前必须转成仓库相对路径 |
| 长度 | 内部路径保持短：**> 240 字符即红**并给建议（Windows `MAX_PATH` 是 260，且不能要求用户改系统设置） |
| 临时目录 | 用 `os.tmpdir()`（`%TEMP%` 可能含空格），禁止硬编码 `/tmp` |

### 4.2 大小写

| 规则 | 说明 |
|---|---|
| **身份按字节** | `Foo.ts` ≠ `foo.ts`（判据、哈希、排序都按字节） |
| **只做碰撞检测，不做归一** | 大小写不敏感的文件系统上（Windows/macOS），`Foo.ts` 与 `foo.ts` 是**同一个文件** ⇒ 声明两个即红 |
| 启动自检 | 运行时探测文件系统是否大小写敏感，写进诊断；不敏感时**必须**启碰撞检测 |

### 4.3 行尾与编码

- 只认 **UTF-8**；写入一律 **LF**；
- **哈希前统一 CRLF→LF**（否则 `core.autocrlf` 一开，"产物变了"满天飞）；
- BOM 不参与比较：读到 BOM 先剥掉再算。

### 4.4 文件系统语义

| 坑 | 规则 |
|---|---|
| 原子替换 | Windows 上 `rename` 覆盖已存在文件会 `EPERM` ⇒ 用"写临时文件 → 删除目标 → rename"，带少量重试 |
| 占用 | Windows 上被占用的文件不能删/改名 ⇒ 所有删除操作**允许失败并重试**，不许一次性抛死 |
| 权限位 | POSIX `0600/0700` 在 Windows 无对应语义 ⇒ 尝试 `chmod`，失败则记录"平台无此能力"，**不许假装设上了** |
| mtime | NTFS/ext4 精度不同 ⇒ **不用 mtime 做身份**（身份用哈希） |
| 保留名/非法字符 | `CON PRN AUX NUL COM1-9 LPT1-9`、结尾点/空格、`<>:"\|?*` ⇒ 生成 slug/文件名时**拒绝**并给替代 |

### 4.5 进程与 shell

- 引擎**不假设 POSIX shell**：适配器的命令按声明执行，`shell` 由声明决定；
- 不用 `fork`、不用信号语义做控制流；子进程用 `spawn` + 显式参数数组；
- 子进程退出码与信号在两端语义不同 ⇒ **统一成一个结果对象**（`exitCode | signal | timedOut`），不直接暴露原始值。

### 4.6 SQLite 在两端

- WAL 在 Windows 可用，但**杀毒软件与文件锁**会造成 `SQLITE_BUSY` ⇒ 设 `busy_timeout`（≥ 5s）+ 有界重试；
- **不支持网络盘**（SMB/NFS）：锁语义不可靠 ⇒ 启动检测到网络路径即拒绝并说明原因；
- 数据库文件路径同样受 §4.1 长度约束。

### 4.7 双平台验收（必跑）

| 检查 | 判据 |
|---|---|
| CI 矩阵 | Linux 与 Windows **两套都跑全量**，任一红即红（不接受"只在 Linux 绿"） |
| 结果一致 | 同一仓库快照：两端 `fold` 结果、`verify` 结论、`claim` 的 `code+params` 与 hash **完全相同** |
| 坏数据抗性 | 正/反斜杠、CRLF、BOM、非 ASCII 排序、大小写碰撞 ⇒ 引擎不崩、结论不变或有明确红 |
| 深路径 | 构造超过 §4.1 长度上限的卡路径 ⇒ 红并给替代建议（不是崩溃） |
| 并发写 | 100 次并发写 SQLite ⇒ 无 `SQLITE_BUSY` 泄漏 |

## 5. 语言与文案：`code` + `params`，不拼句子

```ts
type Result = { status, code: 'plan.blocked_by_lock', params: { path, holder }, remedy_code: 'lock.release_or_wait' }
```

- 引擎**不产出人话**；人话由渲染层按 locale 拼（`zh-CN` / `en`）；
- 判据测试断言 **`code`**，不断言文案 —— 这是 v1 的另一个大坑：文案一改，几百个用例红；
- 文案键与 `code` 一一对应，缺键即红（防止"有 code 没文案"）。

---

## 6. 与 policy 的关系

[10](10-方法论与策略.md) 的 policy 只声明"开关与 gate 绑定"；**适配器声明是另一块**，两者都不含语言逻辑。一个项目换语言 = 换 `adapters` 段，`policy` 与判据不动。

## 7. 多语言：跟随宿主、缺省 `zh_CN`、一期两包

### 7.1 语言包与命名

| 项 | 规定 |
|---|---|
| 目录 | `lang/` |
| 一期范围 | **`zh_CN.lang`**、**`en_US.lang`**（文件名即 locale 标识，下划线 + 大写地区） |
| 格式 | UTF-8、LF、`key = value`，键为扁平点分（`gate.core.not_signed`），占位符 `{p1}` `{p2}` |
| 基准包 | **`zh_CN` 是键的权威集合**；其余语言跟随它（缺键即红） |

新增语言 = **加一个文件**，不改代码；`zh_CN` 永远存在（作为缺省与回退终点）。

### 7.2 locale 解析顺序（跟随宿主）

```text
① 会话显式覆盖（可选参数 locale，仅当调用方明确要另一种语言）
② 宿主 locale（宿主的 BCP-47 值，如 zh-CN / en-US / de-DE）
③ 缺省 zh_CN
```

**归一化规则**（宿主给的是 BCP-47，包里是下划线式）：

| 宿主值 | 归一化 | 命中 |
|---|---|---|
| `zh-CN` / `zh-Hans-CN` | `zh_CN` | `zh_CN.lang` |
| `en-US` / `en-GB` | `en_US` | `en_US.lang` |
| `zh-TW` / `zh-HK` | `zh_TW` | 无 ⇒ 回退 `zh` ⇒ 无 ⇒ **`zh_CN`** |
| `de-DE` | `de_DE` ⇒ 回退 `de` | 无 ⇒ **`zh_CN`** |

**回退链**：`xx_YY → xx → zh_CN`。回退发生时**记数**（`i18n.fallback`），不许静默。

### 7.3 三条硬规则

1. **locale 只影响渲染，绝不影响判定。** 判据、`claim`、哈希、签字载荷必须与语言无关——否则同一条事实在两种语言下会得出两个 hash，`verify` 立刻失效。
   > **`claim` 只存 `code + params`，不存渲染后的文字。** 文字是渲染层的产物，不是事实。
2. **两包键集必须完全相等**：多一个、少一个都红（键奇偶检查）。
3. **引擎源码里不许出现人类句子字面量**：静态扫描（CJK 与成句英文）命中即红——否则“文案”会绕过语言包直接写死在代码里，v1 就是这么长出 2783 个键的。

### 7.4 数字、日期、单位

- 句子里**不许拼数字**，一律走参数（`{p1}`）；
- 数字/日期格式化只在渲染层做（同一条 `code` 在不同 locale 下格式可以不同，**但参数值必须一致**）；
- 排序与比较仍按码点（见 §4），不随 locale 变。

### 7.5 验收（一期）

| 检查 | 判据 |
|---|---|
| 键奇偶 | `zh_CN` 与 `en_US` 的键集**恰好相等** |
| 占位符一致 | 同一 key 的 `{pN}` 集合在两包中相同 |
| 硬编码文案 | 引擎源码命中 **0** 处 |
| 缺键回退 | 删掉 `en_US` 一个键 ⇒ 渲染回退 `zh_CN`，且 `i18n.fallback` +1（不静默、不空白） |
| 判定无关性 | 同一输入在两种 locale 下：`claim` 的 `code+params` 与 hash **完全相同** |

## 8. 不变式

1. 判据不得 import 任何解析器/文件系统/子进程模块（静态检查：依赖白名单）；
2. 引擎代码里不得出现语言名（`typescript`/`python`/`java`…）作为分支条件；
3. 一切路径进入引擎前已归一为 POSIX 相对路径（入口校验，不合规即拒）；
4. 事实类型的 schema 变更 = 迁移（[03](03-真源-存储事件与折叠.md)）；
5. 引擎文案零硬编码（只允许 `code` + `params`）。

---

## 9. 验收读数（M1）

- 用一个**非 TS 的最小项目**（例如纯 Python + 一个测试脚本）跑通三个 gate：不改引擎、只写 `adapters`；
- 把仓库路径全部改成反斜杠输入：引擎正常归一，判据结论不变；
- 故意塞 CRLF 文件：产物哈希稳定（同内容不同行尾 ⇒ 结论一致，由行尾归一保证）；
- 引擎源码里 `typescript|python|java` 作为分支条件出现次数 = **0**。

> 两件事必须分开：**安全**是"不该做的事做不到"（鉴权、密钥、最小权限、供应链）；**脱敏**是"该出去的东西不带脏"（回执、日志、快照、备份）。
> 两者的共同点：**都必须在单一出口上做**，否则每一处都要记得——而"记得"正是 v1 反复失效的那类保证。

## 10. 威胁模型（先列清楚，再谈对策）

| 威胁 | 谁 | v2 的对策 | 章节 |
|---|---|---|---|
| **agent 越权** | 被派发的模型会话 | 工具白名单 + 无 `sign`/`decide` + DB 不可读 + 写范围锁 | [03](03-真源-存储事件与折叠.md) · [09](09-协作-权限-并行与子代理.md) |
| **代签** | agent 或恶意脚本 | signerd 独立进程 + 只能人解锁 + `no_proxy_sign` 判据 | [08](08-签字-身份与免密.md) |
| **密钥泄露** | 插件日志/回执/异常 | 密钥只在 signerd；回执经脱敏器；类型层禁字段 | 本文 §2 |
| **库被拖走** | 备份外泄/机器失窃 | 库文件 0600；备份加密；PII 脱敏策略 | 本文 §2、§4 |
| **提示注入** | 仓库里的文本/注释 | 仓库内容只当**数据**；决策只由 DB 行 + 人签驱动 | 本文 §5 |
| **供应链** | 依赖包/安装脚本 | 锁文件 + 完整性校验 + 默认禁安装脚本 + 依赖变更进 release | 本文 §6 |
| **多人越界（T2）** | 多租户/多团队 | 每行 `tenant_id` + 行级策略；视图层裁剪 | 本文 §7 |
| **审计被篡改** | 有库权限的人 | 事件 hash 链 + `verify` + 快照外存 | [03](03-真源-存储事件与折叠.md) |

## 11. 脱敏：一个出口，三种策略

**唯一出口**：所有对外文本（工具回执、每轮注入、日志片段、导出快照、发布说明）都必须经过同一个 `redact()`。

```ts
type RedactPolicy = {
  secrets: 'mask' | 'drop' | 'hash'      // 默认 mask
  pii:     'mask' | 'drop' | 'hash'      // 默认 mask（邮箱/手机/证件号/地址）
  paths:   'keep' | 'mask-home'          // 家目录一律 mask-home
  internal: 'keep' | 'mask'              // 内网主机名/IP/端口
}
```

**检测层（顺序固定）**：

1. **结构化规则**：私钥块（`-----BEGIN … PRIVATE KEY-----`）、常见 token 前缀（`sk-`、`ghp_`、`xoxb-`、`AKIA`）、Bearer/Basic、连接串（`scheme://user:pass@`）、Cookie/Set-Cookie；
2. **高熵串**：长度 ≥ 24 且熵 ≥ 阈值，且不在白名单（哈希、base64 内容哈希）里；
3. **PII 规则**：邮箱、手机号、证件号、IPv4/IPv6、家目录路径；
4. **项目自定义规则**：`redact.patterns`（项目声明，随 policy 走）。

**记录**：脱敏动作落 `redaction.applied {count_by_kind}`，**永不记录被脱敏的值**（连哈希也不记，防彩虹表）。

**覆盖点（必须全覆盖，缺一即红）**：

| 出口 | 是否脱敏 |
|---|---|
| `sdo_query` 返回 | 是 |
| `sdo_act` 回执 | 是 |
| 每轮注入 | 是 |
| `evidence.output_digest` 的原文 | 是（只存摘要 + 引用） |
| `ledger export`（进 git 的审计快照） | **是（默认强制）** |
| 备份文件 | 是（加密 + 可选脱敏） |
| `log_excerpt` | 是 |

**审计快照默认强制脱敏**，因为它是**唯一会进 git 的东西**——一旦泄露就是永久泄露。

**脱敏发生在写入前**：事件落库时敏感字段就已经被掩掉（或加密密钥不随行），库里没有明文可删。

> **推论：v2 不提供“删除”语义，也不需要 crypto-shredding。** “只能追加”与“必须能抹掉”的冲突因此不存在——**抹掉在写入那一刻完成，不是事后**。这条必须由写入路径保证，不能靠事后扫描补救。

## 12. 密钥与凭据

| 项 | 规则 |
|---|---|
| 签名私钥 | 只在 signerd；盘上加密（Argon2id）；文件 0600；socket 0600 |
| 登录口令 | Argon2id（独立盐/参数）；**与签章口令不同源** |
| 会话 token | 只在内存/短期存储；库里存哈希；TTL + 可撤销 |
| DB 连接串 | 环境变量或 OS keychain；**不许**写进仓库、日志、回执 |
| CI 只读凭据 | 最小权限、按需签发、可撤销、每次使用留痕 |
| 轮换 | 口令/密钥支持轮换；轮换时旧签名的**公钥保留**（否则历史签字不可验） |

**类型层禁止**：工具参数与返回值里出现 `password | secret | token | private_key` 字段名——静态检查（工具 schema 审计）即红。

---

## 13. 库与备份

| 层 | 措施 |
|---|---|
| 文件 | 0600；目录 0700；不在 agent 可读路径（[03](03-真源-存储事件与折叠.md)） |
| 备份 | 加密（age/GPG 或云 KMS）；备份清单含 sha256；恢复演练每月 |
| T2 | TLS；静态加密；最小权限 DB 账号（app 只拿 DML，不给 DDL） |
| 审计 | `backup.taken` / `restore.done` / `verify.passed` 事件（不含路径口令） |

---

## 14. 提示注入：把"数据"与"指令"分层

**原则**：仓库里的任何文本（注释、文档、issue）都是**数据**；它不能改变判据、不能产生 decision、不能触发签字。

落地：

1. 决策只能由**结构化输入**产生：`claim` + `evidence` + `frontier`；
2. 渲染层把仓库文本一律标记为 `untrusted`，并在注入上下文时包上"这是数据"的边界；
3. 判据 `injection_suspected`：当某个 claim/decision 的 payload 里出现"指令式文本来源=仓库文件"时告警；
4. **禁止**任何"自动决定"路径（例如"看到 TODO 就建卡"）绕过人签。

---

## 15. 供应链

- 锁文件必须进 git，安装用 `--frozen-lockfile`（或等价）；
- 默认**禁**安装脚本；启用需 `approved_builds` 白名单 + 人签；
- 依赖变更（新增/升级）是 release item（`kind=dep_policy`），要评审；
- 产物发布前校验 `SHA256SUMS`；发布快照里记录依赖树摘要。

---

## 16. 多租户（T2）

- 每张表带 `tenant_id`；行级策略（RLS）保证"跨租户读=失败"；
- 视图按租户裁剪，**缺租户的查询直接报错**（不是返回空）；
- 审计与备份按租户隔离；
- 跨租户的 actor 不存在（一个账号只属一个租户，多租户用多账号）。

## 17. 不变式与判据

| 不变式 | 判据 code |
|---|---|
| 所有对外文本都过脱敏器 | `security.redaction_bypass`（静态检查：绕过出口即红） |
| 备份加密 | `security.backup_encrypted` |
| 密钥不在库/日志/回执 | `security.no_secret_in_store`（定期扫描）+ 类型层审计 |
| 无人能代签 | `security.no_proxy_sign` |
| 库文件权限 0600 | `security.db_perms` |
| 依赖变更进 release | `security.dep_change_reviewed` |
| 跨租户读被拒 | `security.tenant_isolation`（用两个租户的夹具验证） |

## 18. 验收读数（M2–M3）

- 把一把假 token 写进测试日志 ⇒ 回执/注入/快照里**都**是 `sk-…***`，且 `redaction.applied` 计数为 1；
- 用 agent 会话尝试 `sign` ⇒ 拒绝 + `auth.failed(agent_attempt)` 告警；
- 用租户 A 的会话查租户 B 的对象 ⇒ **报错**（不是空结果）；
- 导出审计快照后对全仓 `grep -E "sk-|BEGIN .*PRIVATE KEY|@"` ⇒ 命中 0（脱敏覆盖）。
