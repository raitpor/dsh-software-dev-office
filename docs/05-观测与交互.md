# 观测与交互

> **框架坐标**（对齐 [01 理论与边界](01-理论与边界.md)）
>
> - 守的层：**L1**
> - 涉及真源：过程（投影）
> - 对应命题：注意力预算
> - 本文引入/定义的概念：视图、页面、待审队列、注意力实体

> 一个事实只有一处：**视图/工具/预算是“能查什么”**，**页面/队列/降级是“人看到什么”**——两者都是对外可见面，所以合并。
> **预算常量**（单次回执、每轮注入、查询行数）在本篇唯一定义，别处只许引用。

## 1. 三个工具（上限，不再增加）



| 工具 | 作用 | 写/读 |
|---|---|---|
| `sdo_query` | 读视图：`{ view, where, select, order, limit, cursor, as_of }` | 只读 |
| `sdo_act` | 写动作：`{ action, subject, expected_version, payload, request_id }`；**带影响面的动作走两段式**（preview → confirm/cancel，见 [11](11-变更与影响链.md)） | 写 |
| `sdo_check` | 现算判据：`{ gate }` 或 `{ criterion }` | 只读（失败时落 `gate.judged`） |

**`baseline_freeze` 也是一个 `sdo_act` 动作**（不在工具清单里另加工具）：`sdo_act(action='baseline_freeze', payload={policy, criteria, gates, thresholds, assurance, engine})`。**它改的是所有人的尺子，所以走两段式**（[11](11-变更与影响链.md)）：preview 阶段跑完 P15 的全部校验，返回 `will_change`（哪些 gate 增删、哪些判据转 `na`）、**`guarantee_delta`**（这一版把哪条保证降了级）与 `payload_hash`；校验不过 ⇒ 返回 `reason_code` 并落 `baseline.rejected`；confirm 绑 `payload_hash` 之后才转 `request_sign`（`decision(kind='baseline')`，payload 必带 `will_change_hash` 与 `guarantee_delta`），由 **decider/signer** 签，签完才落 `baseline.frozen`。模型只能**发起**，不能签。**人签的不能只是一个 hash**：签名对象里必须含"这一签降了哪条保证"，否则保证等级表只是文档里的一句提醒（[06](06-签字与安全.md) §5）。

**关于签字**：模型只有一个动作 `sdo_act(action=request_sign)` 与一个只读字段（`decision.status` / `reason_code`）。**没有“验签”工具**——校验由插件在写入与 `verify` 两处完成（[06](06-签字与安全.md)「模型不在信任链上」）。

**为什么不按业务拆 N 个工具**：每缺一个视图就长一个工具，会重演 v1 的 68 条判据——工具越多，越没人知道该用哪个，agent 又会回去读源码猜。**视图是数据，工具是解释器**。

## 2. 视图是数据（`view_catalog`）



```sql
CREATE TABLE view_catalog (
  name        TEXT PRIMARY KEY,
  sql         TEXT NOT NULL,          -- 只允许 SELECT；服务端静态校验
  columns     TEXT NOT NULL,          -- JSON：列名、人话名、单位、类型
  doc         TEXT NOT NULL,          -- 这个视图回答什么问题
  min_right   TEXT NOT NULL,          -- reader | reviewer | decider | signer
  row_budget  INTEGER NOT NULL        -- 默认返回行数上限
);
```

`sdo_query({view:'list'})` 返回目录本身：**视图自描述**。agent 先看目录再查，而不是猜名字。

**新增视图不改代码**：写一条 `INSERT INTO view_catalog`（经迁移脚本），下一次查询即可用。

## 3. 首批 13 个视图



| view | 回答什么 | 关键列 | 最低权限 |
|---|---|---|---|

| `review_queue` | **待我决策的项**（一项一行） | `item_id, proposition, evidence_refs, impact, options` | decider |
| `board` | 每张卡：阶段/谁/上一步/阻塞原因码/最新报告 | `task_id, title, status, owner, last_action, last_report, block_code` | reader |
| `plan` | 待办、计划、依赖链 | `task_id, status, blocked_by[], scope` | reader |
| `evidence` | 每条声明 → 证据 → 产物指纹 | `claim_id, criterion_id, artifact_sha256, at` | reader |
| `defects` | 分布、复发族、未修清单 | `defect_id, family, status, severity, criterion_id` | reader |
| `team` | 谁在做什么、谁能决策哪个域 | `actor_id, kind, scopes[], rights` | reader |
| `gaps` | `query_miss` 聚合 + 退休候选判据 + 生效豁免 + **红队 deferred（`block(kind='redteam_deferred')`）** | `kind, subject, count, last_seen` | reviewer |
| `pm_gaps` | **PM 的完成读数**：未决项与新增项的计数（不含 reviewer 才看的明细） | `kind, count, new_since, last_seen` | reader |
| `agents` | 代理池：状态/水位/绑定快照/复用次数/停泊原因 | `id, state, watermark, snapshot, reuse_count, parked_reason` | reader |
| `pm_queue` | **作为 PM，现在最该做的 ≤7 件事**（排序固定，见 §10.1） | `rank, kind, subject_id, title, action, reason_code, since, owner, block_code, blocked_by[]` | reader |
| `alignment` | **对齐进度**：每条 requirement 复述了没有、2 正 1 反齐不齐、还有几条 open 假设挡着 | `spec_id, title, restated, examples_pos, examples_neg, assumptions_open` | reader |
| `baseline` | **现在按哪把尺子判**：policy/preset、每个 stage 承担哪些 kind、gate 绑定、阈值/开关、assurance、哪些判据 `na` 及原因、谁在何时签的、hash | `policy_id, preset, stages[{id, kinds[], after[]}], gates[{id,stage,criteria[],policy_mode}], review{sample_every,sample_seed}, limits{max_members,max_pending_attention,max_payload_bytes,cleanup_timeout_s}, thresholds, switches, assurance{independence,db_confidentiality,na_stages,level}, engine{version,criteria_manifest_hash}, artifact_kinds, na_criteria[], frozen_by, frozen_at, hash` | reader |

**`review_queue` 是产品核心**（[05](05-观测与交互.md)）：一行三样——可反驳的命题、可点开的证据、不签的后果。

## 4. 输出契约（预算与游标）



```ts
type QueryResult = {
  rows: Row[]                 // 已按 select 裁剪
  bytes: number               // 本次返回的字节数（服务端计算）
  truncated: boolean          // 是否截断
  next_cursor?: string        // 截断时给游标，绝不静默丢
  as_of: Frontier             // 这批数据对应的事件 frontier
  view: string                // 视图名 + 版本
  miss?: { reason: string }   // 视图/列不存在时的结构化说明（同时落 query_miss）
}
```

硬规则：

1. **每次返回必带 `as_of`**——读数是"到哪一组事件为止"，不是"现在"；
2. **超预算必截断且给游标**，不许静默；
3. **列名是人话 + 单位**（`count_7d` 显示为"近 7 天数量"），编号只作次要标识（[05](05-观测与交互.md)）；
4. 同一 `(view, args, as_of)` 的结果**确定性**（用于对账与快照）。

## 5. `query_miss`：缺工具由使用记录决定



```json
{ "kind": "query_miss", "payload": { "view": "release_gaps_by_owner", "reason": "view_not_found",
  "hint": "想按负责人看顺延缺口", "task": "TASK-280", "actor": "a-dev-7f3a" } }
```

- **何时落**：视图不存在 / 列不存在 / 行被权限裁掉（后两者带 `reason`）；
- **怎么用**：`gaps` 按 `(kind, subject)` 聚合，显示"最常被问却答不上的前 N 项"；
- **怎么关**：补一个视图或列 ⇒ 该聚合行自然消失（不是手动标记"已处理"）。

这条闭环让工具面**按需求长**，且每个新增视图都有原始诉求可查。

---

## 6. 权限裁剪（读也要最小权限）



- `min_right` 由 `view_catalog` 声明；`sdo_act` 的每个 action 有自己的 `right`；
- **列级裁剪**：agent 视图不含 `human_only` 列（如"别人的签章状态"）；
- 裁剪**要留痕**：`query_miss(reason='filtered_by_permission')`，否则 agent 会以为"没有数据"。

## 7. 预算常量（**唯一定义处**，别处只许引用；属**契约判据**，不算“度量进门禁”）



| 面 | 预算 | 超限行为 |
|---|---|---|
| 单次工具返回 | **≤ 8 KB** | 结构化截断 + `next_cursor`（不静默） |
| 每轮注入 | **≤ 1500 字符** | 折叠成摘要 + 指针 |
| 单次查询行数 | **≤ 500**（可调） | 截断 + 游标 |
| `sdo_query` P95 | 见 [02](02-真源-存储事件与折叠.md)「存储侧三条预算线」 | 判据红 |

三条**反模式判据**（出现即红）：`perf.n_plus_one`（同请求内重复查同一表 ≥3 次）、`perf.unbounded_select`（无 `LIMIT`）、`perf.ui_compute`（界面层做聚合/排序）。

## 9. 八个页面



**首屏必须先回答三个问题（2 秒内）**，否则人会回去翻聊天记录：

1. **我现在到底要做什么？** → `intent` / `spec` / `criterion` 同一屏；
2. **我刚改这个会影响什么？** → 影响集 + 要重开的卡 + 返工面数字；
3. **这件事为什么是这样？** → 决策/变更链（不是聊天记录）。

审计页**不是首屏**：它是"要证明给别人看"时才打开的页面，不是每天开工的第一眼。

| 页面 | 回答的问题 | 关键交互 |
|---|---|---|
| **总览** | 三个问题（做什么 / 改了影响什么 / 为什么） | 点任意数字 → 钻到对应清单 |
| **待审** | **我要决定什么**（项级，一项一行） | 批准 / 驳回 / 要改；可批量但每行独立 |
| **计划** | 待办、计划、依赖链、容量；**按分解树折叠**，默认只展开"需要我决定的节点" | 拖动排序只改"建议顺序"，需落动作；一次决策只对一个节点 |
| **证据** | 每条声明的出处、指纹、有效 frontier | 点开看命令与读数；失效的高亮 |
| **缺陷** | 分布、复发族、未修清单 | 按 family 聚合；点开看"哪条判据该抓没抓" |
| **团队** | 谁在做什么、谁能决策哪个域 | 权限矩阵只读 + 申请入口 |
| **审计** | 签字记录、快照导出、豁免清单 | 导出一份 `export --at <frontier>` |
| **设置** | 免密窗口、通知、默认视图 | 免密窗口**默认关** |

**语言**：界面跟随**宿主 locale**，缺省 `zh_CN`，一期 `zh_CN` / `en_US` 两包；规则（归一化、回退链、键奇偶、硬编码 0）见 [10](10-语言与平台.md)「多语言」，此处只管显示。

> 页面数量刻意压在 8 个：**每加一个页面都要回答"现有页面哪个回答不了"**，否则会重演 v1 的"文档/页面只增不减"。

## 10. 待审队列：四项契约（核心）

**“在等谁”的唯一数据源是未回答的 `attention`**（[03](03-链条-意图到声明.md)）；`report` 只描述“做到哪了”，不含 `waiting`，不进这个队列。队列不是手写的列表，是 `attention` 未答行的视图；`block(kind='question')` 只是“卡住了”，不替代 attention。



每一行必须同时具备四项，缺一项**不允许出现**：

| 项 | 内容 | 反例（v1 出现过） |
|---|---|---|
| **命题** | 一句可反驳的话，含代价 | 「TASK-261 全绿，请审」 |
| **证据** | 可点开、可复算（命令 + 读数 + 指纹） | 「详见报告」 |
| **差异** | 相对上一版改了什么（`ledger diff`） | 「已按意见修改」 |
| **后果** | 不批会阻塞什么、会不会顺延 | 缺失 |

**批准 = 一次签发动作**（[06](06-签字与安全.md)）：绑 frontier、绑内容哈希、需要签章口令（或未过期的免密窗口）。

**分歧项（`disputed`）也是同一队列里的行**：标题前缀「待裁定」，展示双方主张 + 各自输入版本；动作是**选左 / 选右 / 撤回 / 延后**，选完必须填一句“被否掉的主张为什么错”。语义见 [07](07-协作-权限-并行与子代理.md)「分歧裁定」。

**委托项（`delegated`）是同一队列里的另一种行**：标题前缀「委托审计」，四项契约不变，但动作是三选一——**确认（转正）/ 推翻（触发级联复位）/ 延期（计一次超时）**。语义见 [07](07-协作-权限-并行与子代理.md)「预授权 grant」。

**假设项（`assumption`）是"没说清楚"的待确认行**：标题前缀「待确认假设」，正文必须给**假设内容 + 排除了哪些方案 + 假设错了会怎样**；动作是**确认 / 推翻 / 升级为条款**（三选一）。**批量提交 = 一次 `decision(kind='assumption_set')`，但 UI 上逐条确认**（不是"全部同意"）；**没处置完的假设挡开工**（判据 `assumption.disposed`），所以这一项不是"建议看看"，是**开工前置**。

---

### 10.1 `pm_queue`：agent 的「下一步」（≤7 行）

**`review_queue` 回答"人要决定什么"，`pm_queue` 回答"PM 现在该推进什么"**。两者不是一张表：前者是人签字的入口，后者是 agent 每天开工看的第一屏。排序**写死在视图里**，不让每个 PM 自己发明优先级——否则同一项目两个 PM 会给出两种顺序。

| 排序 | `reason_code` | 含义 | `action`（PM 能做的那一下） |
|---|---|---|---|
| 1 | `waiting_human` | 有 `attention` 未答，或**冻结被拒**（`baseline_rejected` 并进来：两者都只能等人/等权，PM 只升级） | **等**、**改派**（`assign`）或**升级**（`escalate`）；不能"降级"（没有这个动作） |
| 2 | `blocked` | 卡被挡住：`status='blocked'`（且没有对应 `attention`）**或** `blocked_by[]` 未满足（依赖还没到） | **按 `block_code` 现算**：`unblockable_by_pm=是` ⇒ `unblock`（要 `assign`）；否则 ⇒ `attention`（要 `escalate`）或 `rework`（要 `plan`）。`block_code` 与 `blocked_by[]` 必须出现在行里，别让 PM 点了才发现被 `verify` 拒；依赖等待只推依赖，别当成"解阻塞" |
| 3 | `gate_red` | 有 `stage_run` 判红（`changes_requested`） | **建返工卡**（`rework`，要 `plan`）；"重判"不是 PM 的动作 |
| 4 | `assumption_open` | 有 `open` 假设，会挡派发 | **准备处置 + 升级给人签**（`assumption_set` 只能人签，PM 不能"处置"） |
| 5 | `sampled_review` | 被抽样命中但缺 `review_round` | **建评审卡 + 派发**（PM 发起，但不评审——没有 `review` 权） |
| 6 | `rework_pending` | 变更带来 `rework_units > 0` 未处理 | **建返工卡**（`rework`，要 `plan`） |
| 7 | `unclaimed` | `ready` 卡无 `lease` | **预占/派发**（`assign`/`dispatch`） |

- `row_budget: 7`；超过带 `next_cursor`（[05](05-观测与交互.md) §16 不变式 3）；
- `min_right: reader`——看队列不敏感，**动作各自要权**（`dispatch` 要 `assign`、`request_sign` 要 decider…）；
- **只有 7 个 `reason_code`，正好等于 `row_budget`**：不再有"排到第 8 永远看不见"的项——`baseline_rejected` 并进 `waiting_human`（同为"等人/等权"）；
- **不含**"人才能做的事"的完整内容，只留一行指针（`waiting_human`）：PM 看到的是"有人在等"，不是替人做决定。

## 11. 人话命名（解决"REQ-123 是什么"）



| 规则 | 例 |
|---|---|
| 主标题永远是**人话**；编号只在次要位置（灰色小字、悬停、复制按钮） | **「发布范围必须能按版本声明」** · REQ-041 |
| 列表默认显示：标题 · 状态 · 负责人 · 影响面 | 不显示编号列 |
| 任何编号都可点开"对象页"，页内才有完整 id 与追溯图 | — |
| 后端不用改：视图里本来就带 `title`；编号只是 `id` 列 | `sdo_query` 返回 `title` 优先 |

## 12. 状态与配色



- **颜色不是唯一编码**：每个状态同时有文字或图标（色盲/打印可读）；
- 语义固定：绿=通过、红=失败、灰=不适用、**黄=未验证**（这一态必须有，不能只有两态）；
- **失效**（frontier 过期）用斜纹 + 文字"已失效"，不是只变灰。

## 13. 空态与错误态



| 情形 | 界面行为 |
|---|---|
| 没有待审项 | 「没有需要你决定的事」+ 最近一次决策时间 |
| 视图取不到（`query_miss`） | 显示"这个视图还不在" + 一键"报告缺失"（落 `query_miss`） |
| DB 连不上 | 显式红条 + 最近一次成功读数的时间与 frontier（**不许显示旧数据当新的**） |
| 无权限 | 显示"需要 X 权限" + 申请入口；不静默隐藏整行 |

## 14. 降级（重要）


**没有界面时不能签字**——这是设计，不是缺陷。卡进 `blocked(awaiting_signature)`，落 `review_queue` 的 P0；一次性凭据、以及“绝不发放长期凭据给 agent”的规则见 [06](06-签字与安全.md)「无 UI 时」（唯一定义处，此处不复述）。

## 15. 实现约束（承接 `dsh-context` 的经验）



1. **界面零本地计算**：所有数字来自 `sdo_query`，前端只做格式化；前端出现计算逻辑即视为缺陷。
2. **视图驱动**：新增页面 = 新增视图 + 一个渲染器，不改 host 业务代码。
3. **开发回环**：client 插件改动需 `pnpm run dev:web` 才能热更；M0 只做一个最小页面，避免长期等构建。
4. **i18n**：中英双语；视图的 `columns` 里带两套显示名，避免"界面文案与数据对不上"。

## 16. 不变式



1. 工具参数与返回值**永不含**口令、密钥、token（类型层面禁止该字段）；
2. 视图 SQL 只允许 `SELECT`（服务端静态校验 + 迁移期审核）；
3. 任何 `truncated=true` 必须带 `next_cursor`；
4. `sdo_act` 的任何写都必须给 `expected_version`（除 `create`）；
5. `query_miss` 是**唯一**允许 agent 写入的"观测类"事件。

## 17. 验收读数（M0–M2）



- `sdo_query({view:'list'})` 返回 11 个视图，每个含列的中文名与单位；
- 人为删掉 `review_queue` 视图 → agent 查询得 `miss.reason='view_not_found'`，`gaps` 出现该行；
- 视图返回 10 万行时：`truncated=true` 且 `next_cursor` 可用（两次请求拼出完整结果）；
- 同一 `as_of` 两次查询结果**逐字节相同**。



- 打开待审页，**3 秒内**能说出"我要决定什么、代价是什么"（可用真人计时）；
- 任一行点开证据，能在 **2 次点击**内看到命令与读数；
- 故意断开 DB：界面显示红条 + 最后成功时间，**不显示旧数字当新的**；
- 全站搜索 `REQ-` 编号作为主标题的情况：**0 处**。
