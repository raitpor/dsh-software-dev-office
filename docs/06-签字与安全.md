# 签字与安全

> 合并自「签字-身份与免密」+「横切」的安全面：**谁签、签什么、密钥放哪、数据怎么脱敏、供应链与注入怎么防**。
> 安全只留一个入口，避免“签字篇说一半、横切篇说一半”。

## 1. 三层凭据



| 层 | 目的 | 存什么 | 不存什么 |
|---|---|---|---|
| **登录**（who） | 身份与会话 | 用户名、口令哈希（Argon2id）、会话 token | 明口令 |
| **签章口令**（unlock） | 解锁该用户的签名私钥 | `signing_key`：加密后的私钥 + KDF 参数 | 明口令、派生密钥 |
| **免密窗口**（TTL） | 短时免口令签发 | `window_until` + `frontier_hash`（在 signerd 内） | 私钥明文 |

**三种口令/密钥相互独立**：登录口令泄露 ≠ 能签字；签章口令泄露 ≠ 能登录。

---

## 2. 模型不在信任链上



三方职责，边界清晰：

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **人** | 在 UI 里解签章口令 → 确认“签什么” → 完成一次签名 | 不直接写库 |
| **signerd** | 持私钥；`unlock / sign / lock` | 不判断业务、不落库 |
| **插件** | 校验（payload hash / frontier / 权限 / nonce）→ 落 `decision` → `verify` 时对账 | 不持私钥、不解密 |
| **模型** | **只做两件事**：`sdo_act(action=request_sign)`；读 `decision` 的状态 | **不签名、不验签、不接触密钥与公钥** |

**模型能拿到的字段只有三个**：

```json
{"decision_id":"d-8f21","status":"valid","reason_code":null}
```

`status ∈ {pending, awaiting_unlock, valid, invalid, revoked}`；`reason_code` 是稳定机读码（如 `payload_changed` / `frontier_stale` / `no_permission`）。**不下发签名原文、不下发公钥**——那既不需要，也扩大泄漏面。

### 2.1 验证在插件的两处

| 时机 | 验什么 | 失败后果 |
|---|---|---|
| **写入 `decision` 时**（前置） | payload hash 与 preview 一致、frontier 未变、签名可验、signer ≠ producer、nonce 未用过 | 拒绝落库，落 `decision.rejected(reason_code)` |
| **`verify` 全量对账时**（后置） | 历史 decision 的签名仍可验、公钥仍在、payload 未变 | 仲裁冻结（只读）+ 红 |

**不提供“模型验签”的工具**。给模型一个 `verify` 动作，只会让它误以为自己在参与判定；它要的只是“这张卡签没签、签得对不对”，那是一个**视图字段**，不是一次校验。

## 3. signerd：把密钥移出插件进程



```text
浏览器(UI) ──口令(一次性)──▶ host(插件，只转发) ──unix socket(0600)──▶ signerd
                                  │                                    ├─ 私钥（盘上加密）
agent ──sdo_act(请求签字)─────────┘                                    ├─ unlock(pw) / sign(payload) / lock()
       ◀── 结论（decision id / signer / frontier / hash）              └─ 免密窗口状态
```

**为什么独立进程**：插件有数万行代码，任何一次异常日志或调试回执都可能把密钥带进模型上下文。**同进程内的"不可见"只是约定，不是边界。** signerd 只做三件事，代码量控制在 300 行内。

### 3.1 socket 协议（JSON per line）

| 方法 | 入参 | 出参 |
|---|---|---|
| `unlock` | `{ actor, passphrase }` | `{ ok, window_until? }` 或 `{ error: 'bad_passphrase' \| 'locked' \| 'rate_limited' }` |
| `sign` | `{ actor, payload_hash, frontier_hash, nonce }` | `{ ok, signature, method: 'ed25519', key_id }` |
| `lock` | `{ actor }` | `{ ok }` |

**失败限速**：连续 5 次失败锁 5 分钟；失败事件落 `auth.failed`（不含口令、不含长度）。

## 4. 签字只签决策，不签状态



**状态由判据派生，不需要签字；需要签字的是决策。**

决策 = `(subject, proposition, choice, inputs.hash, frontier)` —— 有主张、有选项、有依据版本。

| 必须签 | 为什么 |
|---|---|
| **意图变更** | 它定义“想要什么”，是唯一只能由人表达的东西 |
| **release 冻结** | 一次发布就是一次不可撤回的事实声明 |
| **豁免** | 签的是“我接受这个风险” |
| **超出 grant 边界的行为** | 委托到期或越界，必须回到人 |
| **放松类 baseline 变更** | 降阈值 / 删判据 / 解绑 gate / 换引擎版本——**它放过的东西，等价于一次豁免**（见 [04](04-判据-门禁与负例.md)「baseline」） |

**不需要签**：卡的完成、评审通过、证据附加——这些由**判据与评审**产生。把签字扩散到每张卡，得到的不是更严格，而是一条等审队列（v1 的 12 张卡就在等评审）。

## 5. 签的是什么（命题由 renderer 生成，不由模型撰写）



```json
{
  "kind": "decision",           // 记录类型
  "decision_kind": "spec_set",  // ∈ {sign, spec_set, freeze, waiver}
  "spec_ids": ["S-1", "S-2"],   // 仅 decision_kind='spec_set' 时必填：签的是集合，不是一句话
  "subject": "TASK-261.idle-rule",
  "value": "finished-only",
  "as_of_frontier": "f:9c1e…",
  "content_hash": "sha256:…",
  "proposition": "空闲判定改为 finished 口径；代价：不再自动回收 30 分钟无动作的会话",
  "evidence": ["ev-3f21", "ev-3f22"],
  "signer": "u-liang",
  "ts": "2026-10-26T16:20:00Z",
  "nonce": "…"
}
```

- **`proposition` 由 renderer 从 `claim` 生成，模型不能自由撰写**——模型只能选 claim 集合；自由文本降级为 `note`（不参与 `content_hash`）。理由：允许自由命题，等于把“盲签”从后门放回来；
- **签字对象是结构化载荷**，不是一段文字；
- `content_hash` 覆盖"命题 + 证据引用 + 取值"，**任何一项变了签名即失效**；
- `as_of_frontier` 必须是签发时刻的**当前** frontier（防"签旧版本"）。

`decision` 表：`id, payload, payload_hash, signature, key_id, signer, frontier, at, revoked_at, revoke_reason`。**只增不改**；撤销是新增一行 `decision.revoked`。

## 6. 签字侧不变式（v2 的安全基线）



1. **不可代签**：`sdo_act(sign)` 只产生"申请"；签名只能由 signerd 在人类解锁后完成。agent 无任何路径触发签名。
2. **不可盲签**：签字页必须展示四元组（命题 / 证据 / 差异 / 后果），缺一项 ⇒ 拒绝签发（不是警告）。
3. **免密必绑 frontier**：窗口只对签发时刻的 `frontier_hash` 有效；内容一变（frontier 变）⇒ 窗口立即失效，重新要口令。

> 三条都写成**可判据**（族名 `security.`，与「不变式与判据」那张表一致）：`security.no_proxy_sign`（签名行的 signer 必须等于解锁的 actor，且 ≠ 生产者）、`security.no_blind_sign`（payload 必须含四元组且命题由 renderer 生成）、`security.window_bound`（decision.frontier = 解锁时记录的 frontier）。

## 7. 免密窗口（状态机）



```text
locked ──unlock(pw)──▶ unlocked(until=T) ──sign──▶ unlocked(消耗一次?) 
   ▲                        │                          │
   └──────lock 或 到期 ─────┘◀──────── frontier 变 ────┘
```

| 参数 | 缺省 | 说明 |
|---|---|---|
| TTL | **0（关）** | 可选 5 / 15 / 60 分钟 |
| 绑定 | 单次签发 | 一次签发后即回到 locked（"签完就锁"） |
| frontier | 必须 | 变了立即锁定 |
| 设备 | 不继承 | 换设备/换会话要重新解锁 |
| 可见 | 常驻图标 + 倒计时 | 随时可手动 `lock` |

**默认关闭**是刻意的：免密是便利，不是默认。

---

## 8. 撤销与重签



- `revoke(decision, reason)`：新增一行，原行保留（**审计要看到"曾经签过"**）；
- 重签：新 `decision` 指向被撤销的 id（`supersedes`），并保留旧 frontier 的证据；
- 撤销本身也需要签字（谁撤的、为什么）——否则撤销会成为新的后门。

## 9. 威胁模型：模型对密钥"不可见"的三层



| 层 | 保证 | 检查 |
|---|---|---|
| 接口 | 工具面无任何字段能返回密钥/口令/token | 类型定义 + 回执字段审计 |
| 内存 | 插件进程内无解密后的私钥 | signerd 独立进程；插件只持有 socket |
| 进程 | 私钥只在 signerd 内，文件 0600，socket 0600 | 运维检查 + `verify` 检查文件权限 |

**诚实说明**：T0（单机）下 signerd 与插件跑在同一台机器，root 可读内存——**这不是 v2 能防的**。`stored` 同理：它持 key 的前提是 OS 内存保护（Linux `ptrace_scope`/Yama、Windows 同一会话隔离），**root/管理员仍可读进程内存**。v2 防的是"模型/agent 通过工具调用拿到密钥"。更强的隔离（硬件密钥、T2 上的独立签名服务）作为可选项。

---

### 9.1 系统面的威胁（脱敏、注入、供应链）

| 威胁 | 谁 | v2 的对策 | 章节 |
|---|---|---|---|
| **agent 越权** | 被派发的模型会话 | **worktree + 准入**、无 `sign`/`decide`、DB 不可读、写范围锁（**工具面不治理**） | [02](02-真源-存储事件与折叠.md) · [07](07-协作-权限-并行与子代理.md) |
| **代签** | agent 或恶意脚本 | signerd 独立进程 + 只能人解锁 + `no_proxy_sign` 判据 | [06](06-签字与安全.md) |
| **密钥泄露** | 插件日志/回执/异常 | 密钥只在 signerd；回执经脱敏器；类型层禁字段 | 本文「signerd」「密钥与凭据」 |
| **库被拖走** | 备份外泄/机器失窃 | 库文件 0600；备份加密；PII 脱敏策略 | 本文「库与备份」「脱敏」 |
| **提示注入** | 仓库里的文本/注释 | 仓库内容只当**数据**；决策只由 DB 行 + 人签驱动 | 本文「提示注入」 |
| **供应链** | 依赖包/安装脚本 | 锁文件 + 完整性校验 + 默认禁安装脚本 + 依赖变更进 release | 本文「供应链」 |
| **多人越界（T2）** | 多租户/多团队 | 每行 `tenant_id` + 行级策略；视图层裁剪 | 本文「多租户」 |
| **审计被篡改** | 有库权限的人 | 事件 hash 链 + `verify` + 快照外存 | [02](02-真源-存储事件与折叠.md) |

## 10. 无 UI 时



- 卡进入 `blocked(awaiting_signature)`，进 `review_queue` 的 P0；
- 可选**一次性凭据**（UI 生成 5 分钟 token / TOTP）用于"人不在界面但必须签"的场景，默认关闭；
- 用一次性凭据签的 decision 打标 `channel: 'cli'`，审计时可见；
- **绝不**发放长期凭据给 agent。

## 11. 脱敏：一个出口，三种策略

> 两件事必须分开：**安全**是"不该做的事做不到"（鉴权、密钥、最小权限、供应链）；**脱敏**是"该出去的东西不带脏"（回执、日志、快照、备份）。
> 两者的共同点：**都必须在单一出口上做**，否则每一处都要记得——而"记得"正是 v1 反复失效的那类保证。

**唯一出口**：所有对外文本（工具回执、每轮注入、日志片段、导出快照、发布说明）都必须经过同一个 `redact()`。

```ts
type RedactPolicy = {
  secrets: 'mask' | 'drop' | 'hash'      // 默认 mask
  pii:     'mask' | 'drop' | 'hash'      // 默认 mask（邮箱/手机/证件号/地址）
  paths:   'keep' | 'mask-home'          // 家目录一律 mask-home
  internal: 'keep' | 'mask'              // 内网主机名/IP/端口
}
```

**检测层（顺序固定）**：

1. **结构化规则**：私钥块（`-----BEGIN … PRIVATE KEY-----`）、常见 token 前缀（`sk-`、`ghp_`、`xoxb-`、`AKIA`）、Bearer/Basic、连接串（`scheme://user:pass@`）、Cookie/Set-Cookie；
2. **高熵串**：长度 ≥ 24 且熵 ≥ 阈值，且不在白名单（哈希、base64 内容哈希）里；
3. **PII 规则**：邮箱、手机号、证件号、IPv4/IPv6、家目录路径；
4. **项目自定义规则**：`redact.patterns`（项目声明，随 policy 走）。

**记录**：脱敏动作落 `redaction.applied {count_by_kind}`，**永不记录被脱敏的值**（连哈希也不记，防彩虹表）。

**覆盖点（必须全覆盖，缺一即红）**：

| 出口 | 是否脱敏 |
|---|---|
| `sdo_query` 返回 | 是 |
| `sdo_act` 回执 | 是 |
| 每轮注入 | 是 |
| `evidence.output_digest` 的原文 | 是（只存摘要 + 引用） |
| `ledger export`（进 git 的审计快照） | **是（默认强制）** |
| 备份文件 | 是（加密 + 可选脱敏） |
| `log_excerpt` | 是 |

**审计快照默认强制脱敏**，因为它是**唯一会进 git 的东西**——一旦泄露就是永久泄露。

**脱敏发生在写入前**：事件落库时敏感字段就已经被掩掉（或加密密钥不随行），库里没有明文可删。

> **推论：v2 不提供“删除”语义，也不需要 crypto-shredding。** “只能追加”与“必须能抹掉”的冲突因此不存在——**抹掉在写入那一刻完成，不是事后**。这条必须由写入路径保证，不能靠事后扫描补救。

## 12. 存储边界的后果（机制见 02）

**机制（L0–L3、socket 认证、探针、降级）唯一家在 [02](02-真源-存储事件与折叠.md)「库的保密性」**，这里只写安全结论：

- 同一 OS 用户下，**只有加密能挡住 `cat`**；换独立 OS 用户（L2）是**更强的隔离**，不是"只有加密"；
- **socket 0600 不是防线**——它意味着同用户可连，所以 `stored` 必须做 `SO_PEERCRED`/capability/HMAC 认证；
- **探针不承诺归因**：它只提高被发现概率，不是读检测器；
- `stored` 缺失 ⇒ **fail-closed**（拒绝打开），除非安装时显式选明文并记 `assurance.db_confidentiality = false`。

## 13. 密钥与凭据



| 项 | 规则 |
|---|---|
| 签名私钥 | 只在 signerd；盘上加密（Argon2id）；文件 0600；socket 0600 |
| 登录口令 | Argon2id（独立盐/参数）；**与签章口令不同源** |
| 会话 token | 只在内存/短期存储；库里存哈希；TTL + 可撤销 |
| DB 连接串 | 环境变量或 OS keychain；**不许**写进仓库、日志、回执 |
| CI 只读凭据 | 最小权限、按需签发、可撤销、每次使用留痕 |
| 轮换 | 口令/密钥支持轮换；轮换时旧签名的**公钥保留**（否则历史签字不可验） |

**类型层禁止**：工具参数与返回值里出现 `password | secret | token | private_key` 字段名——静态检查（工具 schema 审计）即红。

## 14. 库与备份



| 层 | 措施 |
|---|---|
| 文件 | 0600；目录 0700；**工作区外**（策略层；同机同用户不可防读，见 [01](01-理论与边界.md)） |
| 备份 | 加密（age/GPG 或云 KMS）；备份清单含 sha256；恢复演练每月 |
| T2 | TLS；静态加密；最小权限 DB 账号（app 只拿 DML，不给 DDL） |
| 审计 | `backup.taken` / `restore.done` / `verify.passed` 事件（不含路径口令） |

## 15. 提示注入：把"数据"与"指令"分层



**原则**：仓库里的任何文本（注释、文档、issue）都是**数据**；它不能改变判据、不能产生 decision、不能触发签字。

落地：

1. 决策只能由**结构化输入**产生：`claim` + `evidence` + `frontier`；
2. 渲染层把仓库文本一律标记为 `untrusted`，并在注入上下文时包上"这是数据"的边界；
3. 判据 `injection_suspected`：当某个 claim/decision 的 payload 里出现"指令式文本来源=仓库文件"时告警；
4. **禁止**任何"自动决定"路径（例如"看到 TODO 就建卡"）绕过人签。

## 16. 供应链



- 锁文件必须进 git，安装用 `--frozen-lockfile`（或等价）；
- 默认**禁**安装脚本；启用需 `approved_builds` 白名单 + 人签；
- 依赖变更（新增/升级）是 release item（`kind=dep_policy`），要评审；
- 产物发布前校验 `SHA256SUMS`；发布快照里记录依赖树摘要。

---

## 17. 多租户（T2）



- 每张表带 `tenant_id`；行级策略（RLS）保证"跨租户读=失败"；
- 视图按租户裁剪，**缺租户的查询直接报错**（不是返回空）；
- 审计与备份按租户隔离；
- 跨租户的 actor 不存在（一个账号只属一个租户，多租户用多账号）。

## 18. 不变式与判据（安全面）



| 不变式 | 判据 code |
|---|---|
| 所有对外文本都过脱敏器 | `security.redaction_bypass`（静态检查：绕过出口即红） |
| 备份加密 | `security.backup_encrypted` |
| **store 客户端必须认证** | `security.store_client_auth`（夹具：不带 capability 的裸连 ⇒ 拒绝；HMAC 不符 ⇒ 拒绝） |
| **store 缺失必须 fail-closed** | `security.store_fail_closed`（夹具：删掉 socket ⇒ 启动失败，而不是回落明文） |
| 密钥不在库/日志/回执 | `security.no_secret_in_store`（定期扫描）+ 类型层审计 |
| 无人能代签 | `security.no_proxy_sign` |
| 不盲签 | `security.no_blind_sign`（`proposition` 由 renderer 从 claim 生成，payload 含四元组） |
| 免密必绑内容 | `security.window_bound`（`decision.frontier` 必须等于解锁时记录的 frontier） |
| 库文件权限 0600 | `security.db_perms` |
| 依赖变更进 release | `security.dep_change_reviewed` |
| 跨租户读被拒 | `security.tenant_isolation`（用两个租户的夹具验证） |

## 19. 验收读数（M2–M3）



- 未解锁时 `sdo_act(sign)` 返回 `awaiting_unlock`，且**不产生** decision 行；
- 免密窗口内签一条 → 内容（frontier）改变后再签 ⇒ 被要求重新解锁；
- 删除 decision 的 `proposition` 字段 ⇒ `no_blind_sign` 红，签发被拒；
- 用 agent 会话尝试签 → 拒绝，并落 `auth.failed(reason='agent_attempt')`（安全事件，需告警）。



- 把一把假 token 写进测试日志 ⇒ 回执/注入/快照里**都**是 `sk-…***`，且 `redaction.applied` 计数为 1；
- 用 agent 会话尝试 `sign` ⇒ 拒绝 + `auth.failed(agent_attempt)` 告警；
- 用租户 A 的会话查租户 B 的对象 ⇒ **报错**（不是空结果）；
- 导出审计快照后对全仓 `grep -E "sk-|BEGIN .*PRIVATE KEY|@"` ⇒ 命中 0（脱敏覆盖）。
