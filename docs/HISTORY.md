## 1. 怎么记一次变更

```bash
python3 docs/check.py                      # 有红先修
git add docs && git commit -m "docs: <一句话摘要>"
```

- 检查器覆盖：H2 编号连续 / H3 归属 / 相对链接 / 索引收录 / 占位符 / 度量计数与文案一致 / 语言包键集与占位符 / 关键常量只出现一次。
- **没有 check 过的改动算没完成**；有红先修，不许绕过。
- 取回某个旧版本：`git log -- docs/` 找提交 → `git checkout <sha> -- docs/` 或 `git show <sha>:docs/05-判据-门禁与负例.md`。

### v0010 · 2026-10-27T10:52+0800 · Linux × Windows 双平台支持

- **需求**：插件必须同时支持 Linux 与 Windows；**“只在 Linux 绿”视为缺陷**（v1 踩过“本地全绿 ≠ CI 绿”）。
- **改法**：把 12 §4 从“四类跨平台坑”扩写为「平台支持：Linux × Windows」，六小节 + 验收：
  1. **路径**：引擎内只有 POSIX 相对路径；只在边界转换；盘符/UNC 可输入但入库前必须相对化；**> 240 字符即红**（`MAX_PATH` 260 且不能要求用户改系统设置）；临时目录用 `os.tmpdir()`。
  2. **大小写**：身份按字节；**只做碰撞检测不做归一**；启动探测文件系统是否大小写敏感。
  3. **行尾/编码**：UTF-8 + LF；哈希前 CRLF→LF；BOM 先剥。
  4. **文件系统语义**：Windows `rename` 覆盖会 `EPERM` ⇒ 临时文件+删除+rename 带重试；被占用文件删除要允许重试；`0600` 在 Windows 无对应语义 ⇒ 记录“平台无此能力”，不许假装设上；mtime 不做身份；保留名/非法字符在生成 slug 时拒绝。
  5. **进程/shell**：不假设 POSIX shell；不用 `fork`；子进程结果统一成 `{exitCode, signal, timedOut}`。
  6. **SQLite**：`busy_timeout ≥ 5s` + 有界重试；**拒绝网络盘**（SMB/NFS 锁语义不可靠）。
- **验收**：CI 双矩阵；同一快照两端 `fold`/`verify`/`claim` hash 完全相同；坏数据（正反斜杠/CRLF/BOM/大小写碰撞/深路径）不崩或明确红；100 次并发写无 `SQLITE_BUSY` 泄漏。
- **度量**：02 增加第 13 条「双平台一致」，反指标为**平台分支处数**与“Windows 被跳过的用例数（应为 0）”；文案「十二个」同步改「十三个」。

## 5. 与 v2 设计的关系（自指）

这份历史文档本身就是 v2 的一个**最小原型**：

| 本文件的做法 | v2 里对应的机制 |
|---|---|
| 每次改动一条记录 + 快照 | 事件 + change set（[14](14-变更与影响链.md)） |
| 清单里带 sha256，恢复前校验 | 证据绑产物指纹（[04](04-链条-意图到声明.md)） |
| 恢复只覆盖正文，不动历史 | 追加式真源 + 派生物可重建（[03](03-真源-存储事件与折叠.md)） |
| 快照 id 单调递增 | frontier 取代“第几条” |
| “贴进本文件才算完成” | 声明只能由视图生成（[14](14-变更与影响链.md) §7） |

**这不是巧合**：文档的版本管理是 v2 的一次小型试跑——它暴露的坑（空匹配导致脚本静默失败、快照与清单两份真相）就是 v2 要防的坑。
