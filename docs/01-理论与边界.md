## 1. 一句话定位



**v2 要对人保证三件事**（这三件就是产品定义，其余都是手段）：

| # | 人的处境 | v2 必须做到 | 靠什么 | 度量 |
|---|---|---|---|---|
| **1** | **我说清楚了** | **（可机械保证）** 记录**忠实于我说的话**；**（条件保证）** 按判据做对——判据本身要经红队/抽样复核，记录再忠实也救不了判据写浅（§16 局限 1） | 复述 + 条款 fingerprint + 人签（意图=真源）；`work_unit` + 判据 + 证据（真源=被遵守） | 重复解释次数、首轮通过率 |
| **2** | **我没说清楚** | **（可保证）已声明的假设必须处置完**，没处置不许开工；**（不可保证）没声明的选择无法检测**——只能靠评审/红队抽样发现。所以这里不承诺"消灭静默选择"，只承诺"说出来的假设必须有账" | 阻塞性歧义 ⇒ `attention`；非阻塞 ⇒ `assumption` 条款（`blast_radius` + 状态 + 未处置挡开工） | 未处置假设数、假设被推翻率、红队/抽样发现率 |
| **3** | **我说完了** | **能证明按我们约定的标准做对了**（评审 + 测试 + 证据），而不是模型自己说做对了——判据本身对不对是另一层问题（§16 局限 1） | 非作者评审 + 判据负例 + 证据绑指纹 + `verify`（声明=真源） | 首轮通过率、返工小时（按原因分类） |

三件事分别对着三层漂移：**意图=真源**（人审/签字）、**真源=被遵守**（流程机制）、**声明=真源**（视图/投影）。少返工是这三件事的结果，不是第四个目标。

三层职责：

```text
┌────────────── 人 ──────────────┐   看视图、批事项、签字
│   UI（tab 页 / 页面 / 待审队列） │
├──────────── agent ─────────────┤   查视图、做动作、申请签字
│   sdo_query / sdo_act / check   │
├──────────── 真源 ──────────────┤   事件表 + fold + 物化视图（DB）
│   db（sqlite 缺省 / postgres）   │
└────────────────────────────────┘
```

## 2. 范围



**做（in）**

- 真源：事件表、fold、物化视图、并发写与冲突拒绝（[02](02-真源-存储事件与折叠.md)）；
- 链条：意图 → 条款 → 验收场景 → 判据 → 证据 → 声明（[03](03-链条-意图到声明.md)）；
- 判据与门禁：三态、负例夹具、预算、豁免、变异自证（[04](04-判据-门禁与负例.md)）；
- 工具面：一个只读 `query`、一个写 `act`、一个 `check`，视图由数据驱动（[05](05-观测与交互.md)）；
- 交互：类 `dsh-context` 的一级页面 + 会话 tab + 待审队列（[05](05-观测与交互.md)）；
- 签字：登录 + 签章口令 + 独立签名进程 + 免密窗口 + 撤销（[06](06-签字与安全.md)）；
- 协作与并行：权限绑 scope、工作副本/锁/复用、子代理约束（[07](07-协作-权限-并行与子代理.md)）；
- 方法论与交付：policy 数据 + 时序断言（[08](08-方法论与策略.md)）、release 与冻结（[09](09-交付与迁移.md)）；
- 横切：语言无关、安全与脱敏（[10](10-语言与平台.md)）；
- 迁移：v1 冻结只读、里程碑与判死读数（[09](09-交付与迁移.md)）。

**不做（out）—— 明确写下来，防止"只增不减"**

- 不做"通用项目管理"（甘特、工时、OKR）——它只服务"可验证的软件过程"；
- 不做"代码质量分析"（lint、覆盖率工具）——它消费这些结果，不生产；
- **不实现**会话创建与上下文压缩（那是宿主的执行能力，通过宿主 API 调用）；**但派发决定归 SDO**——唯一入口 + `lease`，复用由代码强制；只**声明**上下文所需预算，并回报实际用量；
- **不对宿主提要求**：宿主所有权不在使用者手里，v2 只依赖"能读写工作区 + 能起子会话 + 能注册工具 + 能访问自己的库文件"（[07](07-协作-权限-并行与子代理.md)）；**不依赖宿主 git**：版本与快照由**内嵌 git 对象库**（纯 JS 实现，MIT）承载，`snapshot` 表存引用与父链（[03](03-链条-意图到声明.md)）；**代码真源 = 内嵌库的快照**，主工作树是「当前基线快照的检出」，用户 `.git` 只是可选镜像；主树有未提交改动时**不覆盖**（`block(dirty_main_tree)`），交人先处置；
- 不做聊天框：交互是**视图与决策**，不是对话；**但"对齐"必须落成产物**（复述 + 例子 + 影响面/返工面），而不是靠聊天里说过就算——聊天记录既不可复算，也不能在换一个会话后复用；
- 不做"AI 自动签字"：任何形式的代签都在禁区（[06](06-签字与安全.md)）；
- **不内置方法论包**：生命周期、设计方法、测试方法只以 policy 数据 + 可机械检查的时序断言存在（[08](08-方法论与策略.md)）。

## 3. 与 v1 的关系

| 方面 | v1 | v2 |
|---|---|---|
| 真源 | `.sdo/` 文件（gitignore 忽略） | 数据库（sqlite 缺省） |
| 观测 | 文件 + `bash` 猜 | 视图（唯一观测面） |
| 声明 | 字符串拼装 | `claim` 表投影 |
| 判据 | 68 条，缺负例 | 判据即数据 + 强制负例 |
| 签字 | 工具参数里的字符串 | 密码学签名（独立进程） |
| 并行 | 轻量 git 字符串写范围 | 工作副本 + 锁表 + 准入 |
| 角色 | 四张角色卡 + 掩码 | 权限绑 scope（无角色卡） |
| 预算 | 设计写了，无判据 | 类型化预算，超限结构化截断 |

**搬运**：判据语义（三态、fail-closed）、证据绑定、顺延定价、变异自证、追溯边。
**重写**：外壳（真源、观测、回执、注入、派发编排）。
**冻结**：v1 台账转为只读档案，供查证（不进 v2 真源）。

## 4. 成功度量（可测，不许写成形容词）

### 4.1 主指标：注意力与返工

**人的注意力是唯一瓶颈**（§14）：agent 的时间可以并行、可以重跑，人的注意力不能。所以度量分两层——**先看注意力成本，再看返工结果**；前者是预算，后者是产出。

**A. 注意力指标**（判断"这套东西有没有把人当稀缺资源"）

| 指标 | 定义 | 目标 |
|---|---|---|
| **人时 / 决策** | 每次 `decision` 的人工秒数（含解锁与阅读） | 签字 **≤ 10s**；节点评审 **≤ 2min** |
| **非法打断数** | 不属于 §14 三类（必须人决定 / 机器判不了 / 失败不可恢复）的 `attention.raised` 数 | **0** |
| **等人时长** | `attention` 从 raised 到 answered 的中位时长（人不在时系统能推进多少） | 越短越好；变长说明卡在人身上而不是机器上 |
| **单次决策项数** | 一次决策需要人读的条款/节点数 | **≤ 7**（超过就该用分解树拆小） |
| **注意力浪费率** | 人看过但最终 `reject`/`defer` 的比例 | 下降；太高说明预览是噪音，不是对齐 |
| **单位注意力产出** | 每个决策覆盖的**可独立验收块**数（来自 `goal_node`） | 上升：一次决策认可更多小项，而不是更多大项 |

**B. 返工与对齐指标**（判断"注意力的投入有没有换来更少返工"）

它们全部可从事件表复算，且都回答"人和 agent 的沟通有没有变便宜"：

| 指标 | 定义 | 目标 |
|---|---|---|
| **返工轮次 / 意图** | 首个 `task.created` 之后发生的 `spec.revised` 次数（按 `intent` 聚合） | 比现状**下降**（首期先测基线，不设绝对值） |
| **重复解释次数** | 同一条纠正（同一 `spec`/`decision` 的同一处）被人重述 ≥2 次的次数 | **0** |
| **首轮通过率** | 第一次准入即通过的卡 / 总卡 | 上升（首期测基线） |
| **分歧前移率** | 在**第一次提交代码前**被发现的分歧 / 总分歧（来自 `restatement_diff` 与非空 `review` 的时间戳比较） | **≥ 80%** |
| **对齐耗时** | 从 `intent` 到首个 `task.created` 的人机往返次数与人工分钟数 | 下降；单次往返 > 3 轮视为对齐失败信号 |
| **返工面可见率** | 带 `rework_units` 数字的变更 / 总变更 | **100%** |
| **变更作废量** | 因变更被作废的已完成 `work_unit` 数 / 总 `work_unit` | 下降；**上升必须先看是不是变更太晚** |
| **变更处理时长** | 从 `change.proposed` 到 `change.applied` 的中位时长（含人操作） | 人工操作 **< 30s**、系统影响集 **< 2s**（超了就是在逼人绕过） |
| **stale 年龄** | 未处置 `stale` 对象的中位存在时长 | **< 1 天**；持续变长说明影响链只标记不处理 |
| **返工小时** | 每次 `change` 的人工耗时，按 `reason_kind` 分类（`misread`/`late_requirement`/`acceptance_missing`/`context_lost`） | 坏返工（后三类）下降；`late_requirement` 不设目标 |

**C. 效率指标**（回答"快不快"，与"对不对"分开看；不进门禁）

| 指标 | 定义 | 目标 |
|---|---|---|
| **卡/天** | `task.done` 数 / 活跃开发日 | 上升；**下降先看仪式成本，不要先怪模型** |
| **time-to-merge** | 卡 `done` 到并入主树的中位时长（并行度的真实读数） | 上升说明合并/准入成瓶颈（不是子代理不够） |
| **逃逸缺陷** | release 之后才发现的缺陷 / 该版本缺陷总数 | 下降；这是"产品正确"的最终读数，比判据通过率硬 |
| **每卡人工分钟** | 一张卡上人花的总分钟（确认、签字、评审、答疑） | 下降；超过阈值说明这张卡**不该这么重**，应拆或降仪式 |

> 这两组数字**不进门禁**（同 4.4 第 1 条）：它们用来判断"这套东西有没有让人的注意力更值钱、返工更少"，而不是给 agent 打分。

### 4.2 护栏指标（不是目标）

下面十四项是**约束**，不是价值主张——它们防的是"为了快而把可信拆掉"，但不构成"v2 有用"的证据：



| 指标 | 定义 | 目标 |
|---|---|---|
| **单一出口** | 一次 `status` 查询中，事件表被读的次数 | **= 1**（一次 fold 或一次视图查询） |
| **观测走工具** | 一个会话里 `query` 调用数 / `bash` 调用数 | **> 1**（v1 是 8 / 1813 ≈ 0.004） |
| **预算守约** | 每轮注入字节的 P95 | 达到 [05](05-观测与交互.md)「预算常量」 |
| **声明可追** | 回执里每一句结论都能在 `claim` 表找到行 | **100%** |
| **死字段** | 无消费者的字段数 | **0** |
| **判据冤枉** | 负例夹具红的判据数 | **0**（红了就修判据） |
| **签字不可代签** | `decision` 行全部有密码学签名且 signer ≠ 生产者 | **100%** |
| **读延迟** | `sdo_query` 的 P95（100 万事件库） | 达到 [02](02-真源-存储事件与折叠.md)「存储侧三条预算线」 |
| **脱敏覆盖** | 对外出口经脱敏器的比例 | **100%**（快照导出后 grep 命中 0） |
| **语言无关** | 引擎源码里语言名作为分支条件的次数 | **0** |
| **越界可发现** | 子代理越界被 `boundary.violation` 记录的比例 | **100%**（准入时必查 diff） |
| **本地化完整** | 两包键集相等 + 引擎硬编码文案数 | 相等 · **0** 处 |
| **双平台一致** | Linux 与 Windows 两套 CI 全绿；同一仓库快照下 `fold`/`verify`/`claim` hash 相同 | 全绿 · 逐字节相同 |
| **可复用而未复用** | 可复用而未被复用的次数 / 总派发（见 [12](12-代理池与生命周期.md)） | **0**（强制派发后不应出现）；退役数趋近 0 |

这十四个数字是 v2 的**护栏健康度**；它们全部可复算。审计、签字、事件链**不是卖点**：它们是让"少返工"不靠自觉的底座——底座坏了，上面的返工数就不可信。

### 4.3 反指标：每条度量都要有对手

度量一旦成为目标就会被优化，而且**优化的方式通常最省事**（v1 的 `C-66` 就被“清零”过）。所以每条度量配一条反向指标——两者同时偏离，说明在作弊。

| 度量 | 反指标 |
|---|---|
| 观测走工具 > 1 | **`query` 返回字节中位数不得上升**；`bash` 次数不得为 0（读代码仍须用 bash） |
| 预算守约 P95 < 1500 | **关键段必现率**（`frontier` / 结论 / 原因码必须出现）；“看不懂/缺信息”反馈数 |
| 声明可追 100% | 每份回执的**人类可读字段数 ≥ N**；抽样“可据以行动”判定 |
| 死字段 = 0 | **判据 `caught=0` 的比例**；判据总数增速 |
| 判据冤枉 = 0 | **退休判据数**；每条判据的 `caught` 值 |
| 签字不可代签 100% | **签字数 / 决策数**（防“签字通胀”）；单次签字耗时 |
| 读延迟（门槛见 [02](02-真源-存储事件与折叠.md)） | **确定性**（同 `frontier` 同结果）；陈旧读数投诉数 |
| 脱敏覆盖 100% | 脱敏后回执的**可复算率**（能否据它复现结论） |
| 语言无关 = 0 | **适配器覆盖率**（支持的语言数）；抽样人工审“是否换马甲绕过” |
| 越界可发现 100% | **越界数 / 写入数**（分母必须独立统计，不能自报） |
| 本地化完整 | **语言包使用率**（某语言长期 0 使用 ⇒ `retired_candidate`）；译文与基准包**语义偏离**抽样 |
| 双平台一致 | **平台分支处数**（`process.platform` 出现在业务逻辑里即需说明理由）；Windows 被跳过的用例数（应为 0） |
| 可复用而未复用 | **僵尸数**（`parked` > 7 天）、**强制复用导致的返工/污染率**、平均水位（长期 > 80% 说明压缩太晚） |

### 4.4 使用规则（四条硬约束）

1. **度量只进报告，永不进门禁。** 判据是“必须过”的线，度量是“观察趋势”的仪表——仪表一旦变成红线，人就只学会看表盘不看路。由判据 `metrics.not_gate` 干检。
   **白名单（唯一例外）**：**预算线**（P95 / 折叠 / 回执 / 注入 / 行数）是**契约判据**，超限判红不算“度量进门禁”——它们是承诺，不是趋势。[02](02-真源-存储事件与折叠.md)「存储侧三条预算线」与 [05](05-观测与交互.md)「预算常量」是这两个白名单项。
2. **反指标不得由被考核方自报。** 分母必须来自引擎自己的计数（例如“越界/写入”的分母是写入事件数，不是 agent 自述）。
3. **季度人工抽样**：抽 **5 份真实回执**，由人判“能否据以行动”；不通过则回查对应度量。
4. **度量会过期**：连续 **3 期完全不变**（说明没人真用它做决定）⇒ 标记 `retired_candidate`，进 `gaps`。防止仪表盘通胀——v1 的登记表就是这么长起来的。

## 5. 用户与部署形态



| 形态 | 存储 | 谁在用 | 说明 |
|---|---|---|---|
| **T0 单人** | sqlite 单文件 | 一个人 + 若干 agent 会话 | 装完即用；**没有网络服务端**（sqlite 单文件），但加密需要本机 `stored` 本地守护进程；关键决策用 `solo_cooldown(15m)`（见 [07](07-协作-权限-并行与子代理.md)「关键决策的独立性」） |
| **T1 小团队同机/同卷** | sqlite + WAL | 2–5 人；**一个常驻写服务进程**，多个 dsh 实例只连它 | 明确**不支持网络卷**；**多实例不直接写库**（与 [02](02-真源-存储事件与折叠.md)「只允许一个写者进程」一致） |
| **T2 多人多地** | postgres | 真团队 | 需要服务、备份、鉴权 |

配置一块，缺省 T0：

```yaml
store:
  driver: sqlite            # sqlite | postgres
  url: ~/.local/share/sdo/<project>.db
```

**"缺省即单人"是承诺**：不要求用户先起数据库。

## 7. 问题：当生成变便宜，什么变贵



经典软件工程建立在"写代码很贵"的前提上。Royce（1970）自己就反对按阶段硬推：运行时间、存储、I/O 这类约束往往到测试才第一次被"经历"，此前只是"被分析"；他的对策是 `do it twice`，用有限代价把最危险的不确定性提前兑现成事实。Boehm 的螺旋模型把它变成风险驱动的迭代。

生成模型把"写出一个能跑的实现"的成本压到极低。这没有取消 Royce 的洞见，只是把瓶颈挪了位置：

> **当"写"变便宜，"确认"必须变便宜；否则瓶颈会迁移到审计上，并以"看起来完成、实际未被确认"的形式堆积。**

本文把这一转移的对象称为 **Agent 软件工程（ASE）**，并给出工作定义：

> **ASE 研究：在生成者不可信（非确定性、无稳定身份、无长期记忆）、产出近零成本的前提下，如何构造可复算的判据与可审计的证据，使"完成/覆盖/通过"这类结论在被签署之前不可能为假。**

关键差别不在"用 AI 写代码"，而在**生产者的性质**：

| 维度 | 经典开发者 | 生成式生产者 |
|---|---|---|
| 身份 | 稳定、可追责 | 会话级、可替换；同名不同会话是两个人 |
| 记忆 | 长期、跨项目 | 会话内；压缩或重启即失忆 |
| 产出代价 | 高 ⇒ 天然谨慎 | 近零 ⇒ "看起来完成"的产量可无限放大 |
| 自述可靠性 | 有声誉成本 | 无成本 ⇒ 回执可以写得很漂亮 |

经典 SE 里"依赖开发者职业素养"的那部分机制（评审、签字、承诺）因此**整体失效**——不是人不守规矩，而是**规矩不再有物理约束**。

## 8. 六条失效与它们违反的原理



v2 的设计不是"更严格"，而是**把每条原理落到不可绕过的结构上**。

### 8.1 P1 单一真源 ⇒ 事实只能有一个计算出口

**原理**：同一个事实若有两个计算出口，两者迟早分叉；而分叉后的"哪一个对"没有判官。这是任何"文档 + 台账"双写系统的通病。

**v1 的病**：设计上写了"单一真源"，实现里真源只是**文件**；回执、判据、注入各自算一遍。实测一次状态查询曾解析台账 **1124 次**；57% 的缺陷属于"声明≠真源"。

**v2 的机制**：事件表 → `fold` → 物化视图；**只有 fold 能读事件**，所有消费者（回执、判据、UI、注入）读同一份投影（[02](02-真源-存储事件与折叠.md)）。

### 8.2 P2 可追溯 ⇒ 意图必须变成可判定的条款

**原理**：Gotel & Finkelstein 的可追溯性研究指出，"前置追溯"（需求从哪来）与"后置追溯"（需求落在哪）是两种不同义务，缺一就会产生"谁也不知道为什么这么写"的代码。

**v1 的病**：`intent → spec → scenario → criterion` 这条链没有数据结构承载，只存在于人的对话里；新 agent 接手时无从判断"这条判据在保护什么"。

**v2 的机制**：六张主表 + 十八张辅助表 + 强制外键（[03](03-链条-意图到声明.md)）；判据必须挂到 spec，spec 必须挂到 intent，intent 必须有人签字。

### 8.3 P3 被写 ≠ 被遵守 ⇒ 每个字段必须有消费者

**原理**：一条规则如果没有任何代码读取它，它在语义上等于注释。Meyer 的契约式设计要求前置/后置条件**可执行**；不可执行的承诺不构成契约。

**v1 的病**：一段"实现派子代理、流程官只记账"的分工写在文档里，而认领动作**不比对认领者的角色**。

**v2 的机制**：`field_consumer(field, criterion_id)`；没有消费者的字段判红（[04](04-判据-门禁与负例.md)）。

### 8.4 P4 证据绑定 ⇒ 结论的有效性是个区间，不是一个点

**原理**：证据只有绑在**产物指纹 + 事件 frontier** 上才有意义；否则"跑过了"与"现在还有效"混为一谈。

**v1 的病**：覆盖率判据曾只看"有没有通过结果"，不看"该结果是否被核实采纳"，导致"覆盖"虚高。

**v2 的机制**：`claim.as_of_frontier` + `evidence.artifact_sha256`；frontier 变了，claim 自动失效（[03](03-链条-意图到声明.md)）。

### 8.5 P5 人签不可代签 ⇒ 权威必须不可伪造

**原理**：数字签名提供的是**不可否认性**（non-repudiation）；而"谁有资格签"是授权问题，"他是否看懂"是产品问题——两者都不能由模型代劳。没有密码学签字的"确认"只是 UI 上的一个布尔值。

**v1 的病**：签字是工具参数里的一个字符串；模型可以替人签，人也可以盲签。

**v2 的机制**：登录 + 独立签章口令 + 独立签名进程（Ed25519）+ 三条不变式（[06](06-签字与安全.md)）。

### 8.6 P6 度量即目标 ⇒ 判据必须自证"不冤枉人"

**原理**：Goodhart / Campbell 定律：一旦度量成为目标，它就不再是好度量。工程上的形态是**判据被优化**（为了过检而灌水、为了让用例变绿而删断言）。

**v1 的病**：准入判据逼人给已否决的需求灌水才能通过；一条"永远红"的判据教会所有人忽略它。

**v2 的机制**：每条判据必须带**正例 + 负例**夹具，负例红了即判据本身判红；判据带预算与"抓到过几条真缺陷"的归因（[04](04-判据-门禁与负例.md)）。

## 9. 单写原理：为什么真源不能合并



这是 v2 最硬的一条，值得单独论证。

**代码可以合并，是因为合并后有判官**：编译器、类型检查、测试。三方合并把两边的改动揉在一起，然后**用一个外部标准判对错**。

**台账没有这样的判官**。两条分支各自把"任务 X 已完成"写进台账，合并后得到两条事实；"哪一个成立"没有任何外部标准可以裁决，因为台账**本身就是标准**。于是：

> **两个真相相加不会得到真相。真源只能单写，不能合并。**

这条原理推出 v2 的存储形态（[02](02-真源-存储事件与折叠.md)）：

- 真源是**服务**，不是文件；git 里没有台账；
- 并发由数据库的**事务与约束**串行化；
- 冲突**拒绝**而不是自动合并：写请求带 `expected_version`，版本不符即失败，由人基于最新版**重写**（这是一次新写，不是合并）。

同样的推理也解释了为什么"轻量 git 并行写"在 v1 里长期做不成：它试图用合并解决本质上是**串行化**的问题。

## 10. 可观测性即能力：工具是唯一的观测面



**原理**：一个 agent 能做什么，取决于它能看到什么。若状态以文件形式存在，agent 就会用 `bash` + `read` 去猜——不是因为不守规矩，而是因为**猜比查便宜**。

**证据**：v1 一个 560 轮的会话里，`sdo_status` 只调用了 **8 次**，`bash` 调用了 **1813 次**。

**v2 的机制**：状态在数据库里，观测只有 `sdo_query`（[05](05-观测与交互.md)）。至于“agent 能不能直接读库”，**必须诚实三分**：

| 层次 | 承诺 | 能做到什么 |
|---|---|---|
| ① 宿主沙箱 | 若宿主**已提供**只读隔离就用；**不新增对宿主的要求** | 挡住**意外**触达 |
| ② 文件权限 / 加密 | 权限位只防别的 OS 用户；**库默认 SQLCipher**（[02](02-真源-存储事件与折叠.md)「库的保密性」） | 权限位不防同用户；**加密后 `cat` 是密文** |
| ③ **tamper-evident** | 任何写入都进 hash 链、`verify` 可发现 | **不承诺 tamper-proof**（[06](06-签字与安全.md)） |

**准确的边界**：明文文件防不住同用户的读；SQLCipher 之后**文件层面**防住了 `cat`/`scp`，但 `stored` 的 socket 与内存仍是边界（需要认证，见 [02](02-真源-存储事件与折叠.md) 8.1）；要彻底不让 agent 碰，得上 L2（独立 OS 用户）。于是：

> **"取不到的状态"不再是 agent 的失败，而是产品的缺陷**——`query_miss` 事件聚合进 `gaps`，成为下一轮补视图的输入。

这把"补工具"从拍脑袋变成有据可依：缺什么由使用记录决定。

## 11. 预算是资源，不是文案



**原理**：上下文窗口是有限资源；任何"输出面"都在消耗它。若预算只写在设计文档里而不进入类型系统，它一定会被绕过。

**证据**：v1 设计写"每轮注入上界 1500 字符"，实测**每条 11.3 KB（7 倍）**，且没有任何判据在管；一个 132 MB 的会话因此撞上窗口，压缩请求同样越界，形成死锁。

**v2 的机制**：渲染签名 `render(kind, state, budget) → {text, bytes, truncated, pointers}`；预算是一等常量（唯一定义处在 [05](05-观测与交互.md)），超限必须**结构化截断 + 指针**，禁止静默。

**机制预算（同样受约束）**：文档篇数、判据条数、表数量、常驻进程数也是预算——v1 的教训是**机制膨胀**，不是文档不够多。规则：新增一类机制（判据/表/进程/页面）必须同时给**退休条件**（如判据 `caught=0` 连续 3 期 ⇒ `retired_candidate`），否则不许加；总量在每轮评审时报告一次，只增不减即视为漂移。

## 12. 三个真源（本文的底座）

| 真源 | 是什么 | 不是什么 | 落点 |
|---|---|---|---|
| **过程真源** | 只追加的事件序列，状态由它折出 | 不是"文档写的流程" | [02](02-真源-存储事件与折叠.md) |
| **内容真源** | 内容寻址的快照，工作目录只是检出 | 不是"当前目录里的文件" | [03](03-链条-意图到声明.md) · [07](07-协作-权限-并行与子代理.md) |
| **意图真源** | 人表达的目标，带强度与批准时依据的尺子 | 不是"条款集合"（条款是派生） | [03](03-链条-意图到声明.md) |

三者不可互相替代：过程真源不存代码，内容真源不存"为什么"，意图真源不存"做过什么"。任何让其中一个兼任另一个的设计，最终都会在审计时断裂。

## 13. 五个命题（本文的硬约束）

这五条不是观点，而是**设计要求**；每条都对应本目录里的一个可检查点。

| 命题 | 一句话 | 对应检查 |
|---|---|---|
| **P1 并发合并不可判定** | 多写者对同一真源的并发修改不可能自动合并成唯一正确结果 | 单写 + 拒绝并发（[02](02-真源-存储事件与折叠.md)「单写原理」） |
| **P2 判据空集陷阱** | 输入可为空的判据在空集上恒真 | 适用性 + 空集负例（[04](04-判据-门禁与负例.md)「适用性与 na」） |
| **P3 证据绑定** | 结论必须绑（产物指纹，世界状态）才能复核 | `evidence` 绑产物 + frontier（[03](03-链条-意图到声明.md)） |
| **P4 独立性不可委托** | 共享作者 ⇒ 评审退化为自评 | `reviewer ≠ producer(subject)`（[07](07-协作-权限-并行与子代理.md)） |
| **P5 门禁方向不对称** | 收紧可自动，放宽必须人签 | baseline 冻结 + 签名变更（[04](04-判据-门禁与负例.md)） |

## 14. 注意力预算（人是最稀缺的资源）

**定义**：一次人工交互的成本包括打断、上下文重建与决策承担。系统的目标不是"最小化人的参与"，而是**最大化单位注意力产生的价值**。

由此得到一条设计约束：**只有三种情况允许打扰人**——(a) 必须由人承担的决策（签字、授权、裁定）；(b) 机器无法判定的分歧；(c) 失败且无法自动恢复。其余一律静默。

工程后果：

- 系统中的"等人"必须是**结构化实体**（问题 + 选项 + 谁答 + 何时答），落在 `attention`（[03](03-链条-意图到声明.md)），而不是自由文本里的"可能需要确认"；
- 面板第一屏只回答一个问题：**有没有事需要我**（[05](05-观测与交互.md)）；
- 与[预算](05-观测与交互.md)的区别：**资源预算**约束输出长度与耗时，**注意力预算**约束"什么时候打断人"，两者不能互相顶替。

**因此度量必须落在注意力上，而不是"系统跑了多少"**：一次决策的人时、非法打断数、等人时长、单次决策要读几项（§4.1 的 A 组）。返工指标是结果，注意力指标是预算——预算破了，结果数再漂亮也是拿人堆出来的。

**一次决策的合理粒度 = 一个可独立验收的块**（§15 借 Blueprint 的分解树）：把大项拆成小项，人每次只看一小块、说"行/不行"，而不是对着一整份文档做整体判断。这不是 UI 细节，是注意力预算的直接推论——人一次能比较的项数是有限的（≤ 7，§4.1）。

## 16. 局限与未来工作

1. **判据的语义可靠性**：判据本身可能由模型生成，"通过"可能只是"模型认为通过"。变异自证能约束多少，仍是开放问题。
2. **构建可复现性**：本设计用"证据绑产物"回避重算，代价是无法从源码独立重建历史产物。
3. **独立性的社会维度**：评者 ≠ 作者是必要不充分条件；评者可能共享同一模型、同一提示、同一偏见。
4. **注意力成本的标定**：如何在不同团队、不同任务上估计"一次打断的成本"，尚缺经验数据。
5. **多模型协作**：当评者也是智能体时，"非作者"需要更细的身份模型。

## 18. 概念与规则（唯一清单）

**概念不是表**：这一节回答"有哪些概念、每个概念守什么规则、为什么存在"；物理落地（表/列/索引）见 [02](02-真源-存储事件与折叠.md)。**新增概念必须先在这里有一行**，否则不许建表。

| 概念 | 定义 | 它守的规则 | 为什么存在 |
|---|---|---|---|
| `intent` | 一句话说清"要什么" | 必须有人签（`approved_by`）；带**强度**（`explicit` / `inferred`）与**依据的 baseline**；`inferred` 不得进高风险条款 | 意图是所有下游的根，根歪全歪 |
| `spec` | 可判的条款（requirement / design / contract / impact / **assumption**；假设的规则见下一行） | 每条必须被 consumer 消费；`mech_checkable` 才允许无场景；`kind` 决定适用哪组判据 | 把"要什么"拆成可验证的最小单位 |
| `design_lock` | 设计指纹的只读副本 | 每次修订新增一行、旧行保留；判据读锁，不读可变字段 | 防止"实现的是另一版设计"事后改口 |
| `redteam` | 红队用例 | 按 `risk_flags` 强制产生；每条必须被处置（accepted/rejected），deferred 转 block | 字面满足、实质偏离的唯一探针 |
| `scope_decl` | 阶段范围声明 | 按路径前缀；**不是权限域**（权限在 07） | 让"本期动哪些路径"可查 |
| `receipt` | 一次决策/预览的回执 | 只引用 id（claim / decision / attention），不复制正文；字节数受预算约束 | 让回执可复算、不成为第二个真源 |
| `goal_node` | 分解节点（把目标逐层拆成可独立验收的块） | **只由需求/设计阶段显式声明**，不在运行时自行生长；叶节点必须绑验收判据；父节点验收 = 集成清单全接上 | 平行拆解否则无人负责，整体验收也无从谈起 |
| `integration` | 集成清单（父 × 子） | 每行 `connected/pending/dropped`；**父验收不看“子都绿”，只看接没接上 + 整体跑一次** | 各自完成不等于合起来能用 |
| `scenario` | 人审步骤 | 只管"人怎么验"，不含断言、无正负极性 | 有些东西机器判不了 |
| `criterion` | 一条判据 | 必须有 `remedy` + 至少一正一负夹具；注册后由 baseline 冻结 | 判据是唯一能拦人的东西 |
| `criterion_fixture` | 判据的夹具 | 正负例成对；负例缺失不许注册 | 没有负例的判据等于没有判据 |
| `evidence` | 一次执行的产物证据 | 必绑 `artifact_sha256` + `snapshot_id`；大对象只存 URI | "我跑过"必须可复算 |
| `claim` | 从真源派生的陈述 | **只能由视图生成**，不可手写 | 防止"模型说了算" |
| `policy` | 生命周期配置：stage DAG（**每段带 `kinds[]`**）+ gate 绑定 + 开关 + 回归；**存在 baseline 里** | 立项时选 preset（瀑布/原型/增量）或写自定义；随 baseline 冻结；运行期不换 | 同一引擎，模式只是数据；换模式不该改代码；`kind` 是 stage 名与判据词表之间唯一的接缝 |
| `alignment` | 对齐检查点：复述 + 例子（2 正 1 反）+ 回指 | **进下一阶段前必须全过**；缺例子或给不出反例 ⇒ 未对齐，不许开工 | 返工主要来自"理解不一致就动手"，不是执行不力 |
| `assumption` | 一条"我假设 X"的条款（`spec(kind='assumption')`） | 必须写清假设内容 + 排除的方案 + 错了的影响；`open` 未处置**不许开工**；只允许 `confirmed/rejected/converted` | "没说清楚"时最危险的不是错，是**模型静默替人选了一个方案** |
| `restatement` | 独立复述 | 必须先于第一条 `spec`；`inputs` 只含 `intent` | 读错意图是最常见的漂移 |
| `restatement_diff` | 复述差异 | 每条必须有 `disposition`；`defer` 必须转 block | 差异不处置等于没复述 |
| `task` | 一张工作卡 | 一卡一判据（`work_unit`）；生命周期状态独立于进展报告 | 工作必须可派、可停、可重开 |
| `work_unit` | 一卡一判据一证据 | `spec_id` 受复合外键约束；`evidence.criterion_id` 必须一致 | 把"做了"和"证明了"钉在一起 |
| `snapshot` | 内嵌库里的一个 commit | 内容寻址；主树是它的检出；dirty 主树不覆盖 | 代码真源必须在库里 |
| `workcopy` | 一张卡的检出目录 | 每卡独立 gitdir（不共用 index）；结束时删除 | 并行写不能互相踩 |
| `report` | 执行者的一次进度报告 | `state ∈ {progress, ready, blocked, failed, dropped}`（**没有 `waiting`**）；进度与 `task.status` 分开；消费者是 `board` 的 `last_report` 列 | 让"做到哪了"可查，且不冒充"在等谁" |
| `attention` | 等一个人回答的具体问题 | 结构化（问题 + 选项）；未答即面板第一屏 | 人的注意力是稀缺资源 |
| `review` / `review_round` | 逐条发现 / 整体结论 | 评者非作者；核实者是作者；`pass` 需当轮发现全核实 | 完成不能自说自话 |
| `decision` | 一次要签字的判定 | payload 绑 hash + frontier；`signer ≠ producer` | 决策必须可追责 |
| `baseline` | 冻结的尺子 | 冻结后只能签名变更；**收紧可自动、放宽必须人签** | 防"偷改阈值" |
| `gate` / `stage_run` | 门禁 / 一次阶段运行 | `verdict` 由 gate 读数算出，不能手填 | "什么时候算完"必须机器判 |
| `rework` | 返工面：变更前算出的作废工作量（`rework_units`） | 必须与 `will_change` **同时**出现在回执里，且必须是一个数字；不许只说"影响若干对象" | 看不见的返工才会变成"怎么又改了一遍" |
| `release` | 一个版本 | 缺口清单 = 集合差集；包产物绑 `snapshot_id` | 发布要能复算 |

### 18.1 被拒绝的概念（写清为什么不要，防止换个名字又回来）

| 被拒绝 | 理由 |
|---|---|
| 角色（developer / reviewer / office） | 角色对但域不对照样能操作；权力绑 `scope`，不绑身份 |
| 独立的状态机给"工单" | 与 `task` 的生命周期重叠，两个状态源必然打架 |
| "上下文"即授权 | 看得到 ≠ 可以改；上下文走 `task.inputs`，授权走 `scope_paths`，两者不互相推导 |
| 推导出来的"等人"（从自由文本猜） | 分类需要结构化事实，所以有 `attention` / `report` |
| 通用项目管理（排期、甘特、里程碑日期） | 成本估不准，且与"可验证产出"无关 |
| 自动签字 / 代签 | 一旦可代签，签字就不再是证据 |
| **节点级阶段选择** | 阶段由 policy 决定（[08](08-方法论与策略.md)）；让每个节点自选 stage，会让同一棵树里同时存在不同尺子，`stage_run` 与门禁不可比 |
| **投入档位（high/max/ultra）** | 无法从产物验证，且会诱导"按档位交差"（Goodhart）；质量由判据与门禁决定，不由投入档位决定 |
| 台账合并（多写者合并事件流） | 合并需要语义，真源不合并——串行化 + 拒绝并发 |
| 金丝雀"证明"库未被读 | 只能当 tripwire，不能归因；说了做不到就是撒谎 |

### 18.2 不该带走的实现选择（防止把权宜之计当理论）

| 实现选择 | 为什么不是理论 |
|---|---|
| 具体表名与字段名 | 换个存储就要改名；概念不变 |
| 关系库 + 递归查询 | 与"数据模型按图来"等价，选型可替换 |
| 内置某版本控制实现 | 内容真源的**能力**是理论，具体库不是 |
| 加密与进程隔离方案 | 属于威胁模型的实现层（[06](06-签字与安全.md)） |
| 文档编号与篇数 | 组织方式，不是概念 |
| 单人/多人模式的具体阈值 | 参数，应可配置 |
| 面板页签划分 | 交互实现（[05](05-观测与交互.md)） |

判据：换掉数据库、语言、插件形态后仍然成立的陈述，才配留在这里。

## 19. 三层漂移与 v2 的对应表



| 等式 | 断在哪 | 靠什么保证 | 对应 [§1](#1-一句话定位) 的哪件事 |
|---|---|---|---|
| **意图 = 真源** | 记录的不是我说的（读错、改写、代签） | **人审 + 签字**：复述差异逐条处置；`intent` 与 `spec_set` 人签；`content_hash` 变必须重签 | 第 1 件（我说清楚时记录要对） |
| **真源 = 被遵守** | 记录对了，但做的时候没照做（死字段、绕路、改完不验） | **流程机制**：`inputs` 派生边 + `field_consumer`；`work_unit` 复合外键把"做了"钉到判据与证据；独立评审 + `verify` | 第 1、3 件（做出对的 + 能证明做对了） |
| **声明 = 真源** | 回执/结论与库里的不一致 | **视图与投影**：`claim` 只能由 `derived_by` 渲染器生成；回执只引用 id | 第 3 件（不是模型自己说做对了） |

**意图 ≠ 真源这一层无法机械消除**（"意图"只有人能表达），所以 v2 不假装能消除它，而是把它**压缩到人签这一处**，并让签字必须看见（命题/证据/差异/后果）。**没说清楚**的情形单列：要么 `attention` 问，要么 `spec(kind='assumption')` 摆出来等人确认——不许静默选一个方案（第 2 件事）。

## 20. 一句话总结



v2 的每一条设计都能追溯到上面六条原理之一；反过来，**任何不能追溯到原理的机制，都是 v1 那种"只增不减"的负担**。这就是 v2 的取舍标准：不加不能说明"挡哪条漂移"的机制。
