# 理论与边界

> 这一篇回答两个问题：**v2 是什么、边界在哪**（前六节），**为什么必须这样**（后七节）。
> 合并自「总览与边界」+「理论支撑」：定位与原理本来就该一起读，拆开只会让“为什么”与“是什么”互相引用。

## 1. 一句话定位



**v2 是一个"过程真源 + 审计面"的服务**：它不替人做判断，它保证**每个判断都有出处、有证据、有签字**，并且**没签的东西不能当结论用**。

三层职责：

```text
┌────────────── 人 ──────────────┐   看视图、批事项、签字
│   UI（tab 页 / 页面 / 待审队列） │
├──────────── agent ─────────────┤   查视图、做动作、申请签字
│   sdo_query / sdo_act / check   │
├──────────── 真源 ──────────────┤   事件表 + fold + 物化视图（DB）
│   db（sqlite 缺省 / postgres）   │
└────────────────────────────────┘
```

## 2. 范围



**做（in）**

- 真源：事件表、fold、物化视图、并发写与冲突拒绝（[02](02-真源-存储事件与折叠.md)）；
- 链条：意图 → 条款 → 验收场景 → 判据 → 证据 → 声明（[03](03-链条-意图到声明.md)）；
- 判据与门禁：三态、负例夹具、预算、豁免、变异自证（[04](04-判据-门禁与负例.md)）；
- 工具面：一个只读 `query`、一个写 `act`、一个 `check`，视图由数据驱动（[05](05-观测与交互.md)）；
- 交互：类 `dsh-context` 的一级页面 + 会话 tab + 待审队列（[05](05-观测与交互.md)）；
- 签字：登录 + 签章口令 + 独立签名进程 + 免密窗口 + 撤销（[06](06-签字与安全.md)）；
- 协作与并行：权限绑 scope、worktree/锁/复用、子代理约束（[07](07-协作-权限-并行与子代理.md)）；
- 方法论与交付：policy 数据 + 时序断言（[08](08-方法论与策略.md)）、release 与冻结（[09](09-交付与迁移.md)）；
- 横切：语言无关、安全与脱敏（[10](10-语言与平台.md)）；
- 迁移：v1 冻结只读、里程碑与判死读数（[09](09-交付与迁移.md)）。

**不做（out）—— 明确写下来，防止"只增不减"**

- 不做"通用项目管理"（甘特、工时、OKR）——它只服务"可验证的软件过程"；
- 不做"代码质量分析"（lint、覆盖率工具）——它消费这些结果，不生产；
- **不实现**会话创建与上下文压缩（那是宿主的执行能力，通过宿主 API 调用）；**但派发决定归 SDO**——唯一入口 + `lease`，复用由代码强制；只**声明**上下文所需预算，并回报实际用量；
- **不对宿主提要求**：宿主所有权不在使用者手里，v2 只依赖"能读写工作区 + 能起子会话 + 能注册工具 + 能访问自己的库文件"（[07](07-协作-权限-并行与子代理.md)）；
- 不做聊天框：交互是**视图与决策**，不是对话；
- 不做"AI 自动签字"：任何形式的代签都在禁区（[06](06-签字与安全.md)）；
- **不内置方法论包**：生命周期、设计方法、测试方法只以 policy 数据 + 可机械检查的时序断言存在（[08](08-方法论与策略.md)）。

## 3. 与 v1 的关系

| 方面 | v1 | v2 |
|---|---|---|
| 真源 | `.sdo/` 文件（gitignore 忽略） | 数据库（sqlite 缺省） |
| 观测 | 文件 + `bash` 猜 | 视图（唯一观测面） |
| 声明 | 字符串拼装 | `claim` 表投影 |
| 判据 | 68 条，缺负例 | 判据即数据 + 强制负例 |
| 签字 | 工具参数里的字符串 | 密码学签名（独立进程） |
| 并行 | 轻量 git 字符串写范围 | worktree + 锁表 + 准入 |
| 角色 | 四张角色卡 + 掩码 | 权限绑 scope（无角色卡） |
| 预算 | 设计写了，无判据 | 类型化预算，超限结构化截断 |

**搬运**：判据语义（三态、fail-closed）、证据绑定、顺延定价、变异自证、追溯边。
**重写**：外壳（真源、观测、回执、注入、派发编排）。
**冻结**：v1 台账转为只读档案，供查证（不进 v2 真源）。

## 4. 成功度量（可测，不许写成形容词）



| 指标 | 定义 | 目标 |
|---|---|---|
| **单一出口** | 一次 `status` 查询中，事件表被读的次数 | **= 1**（一次 fold 或一次视图查询） |
| **观测走工具** | 一个会话里 `query` 调用数 / `bash` 调用数 | **> 1**（v1 是 8 / 1813 ≈ 0.004） |
| **预算守约** | 每轮注入字节的 P95 | 达到 [05](05-观测与交互.md)「预算常量」 |
| **声明可追** | 回执里每一句结论都能在 `claim` 表找到行 | **100%** |
| **死字段** | 无消费者的字段数 | **0** |
| **判据冤枉** | 负例夹具红的判据数 | **0**（红了就修判据） |
| **签字不可代签** | `decision` 行全部有密码学签名且 signer ≠ 生产者 | **100%** |
| **读延迟** | `sdo_query` 的 P95（100 万事件库） | 达到 [02](02-真源-存储事件与折叠.md)「三条预算线」 |
| **脱敏覆盖** | 对外出口经脱敏器的比例 | **100%**（快照导出后 grep 命中 0） |
| **语言无关** | 引擎源码里语言名作为分支条件的次数 | **0** |
| **越界可发现** | 子代理越界被 `boundary.violation` 记录的比例 | **100%**（准入时必查 diff） |
| **本地化完整** | 两包键集相等 + 引擎硬编码文案数 | 相等 · **0** 处 |
| **双平台一致** | Linux 与 Windows 两套 CI 全绿；同一仓库快照下 `fold`/`verify`/`claim` hash 相同 | 全绿 · 逐字节相同 |
| **代理复用率** | 复用次数 / 总派发（见 [12](12-代理池与生命周期.md)） | **≥ 60%**；退役数趋近 0 |

这十四个数字就是 v2 的"健康度"；它们全部可复算，且每个都有"现在是多少"的对照。

### 4.1 反指标：每条度量都要有对手

度量一旦成为目标就会被优化，而且**优化的方式通常最省事**（v1 的 `C-66` 就被“清零”过）。所以每条度量配一条反向指标——两者同时偏离，说明在作弊。

| 度量 | 反指标 |
|---|---|
| 观测走工具 > 1 | **`query` 返回字节中位数不得上升**；`bash` 次数不得为 0（读代码仍须用 bash） |
| 预算守约 P95 < 1500 | **关键段必现率**（`frontier` / 结论 / 原因码必须出现）；“看不懂/缺信息”反馈数 |
| 声明可追 100% | 每份回执的**人类可读字段数 ≥ N**；抽样“可据以行动”判定 |
| 死字段 = 0 | **判据 `caught=0` 的比例**；判据总数增速 |
| 判据冤枉 = 0 | **退休判据数**；每条判据的 `caught` 值 |
| 签字不可代签 100% | **签字数 / 决策数**（防“签字通胀”）；单次签字耗时 |
| 读延迟（门槛见 [02](02-真源-存储事件与折叠.md)） | **确定性**（同 `frontier` 同结果）；陈旧读数投诉数 |
| 脱敏覆盖 100% | 脱敏后回执的**可复算率**（能否据它复现结论） |
| 语言无关 = 0 | **适配器覆盖率**（支持的语言数）；抽样人工审“是否换马甲绕过” |
| 越界可发现 100% | **越界数 / 写入数**（分母必须独立统计，不能自报） |
| 本地化完整 | **语言包使用率**（某语言长期 0 使用 ⇒ `retired_candidate`）；译文与基准包**语义偏离**抽样 |
| 双平台一致 | **平台分支处数**（`process.platform` 出现在业务逻辑里即需说明理由）；Windows 被跳过的用例数（应为 0） |
| 代理复用率 | **僵尸数**（`parked` > 7 天）、**压缩后仍耗尽的比例**、平均水位（长期 > 80% 说明压缩太晚） |

### 4.2 使用规则（四条硬约束）

1. **度量只进报告，永不进门禁。** 判据是“必须过”的线，度量是“观察趋势”的仪表；仪表一旦变成红线，人就只学会看表盘不看路。由判据 `metrics.not_gate` 干检：**任何判据读度量值即红**。
2. **反指标不得由被考核方自报。** 分母必须来自引擎自己的计数（例如“越界/写入”的分母是写入事件数，不是 agent 自述）。
3. **季度人工抽样**：抽 **5 份真实回执**，由人判“能否据以行动”；不通过则回查对应度量。
4. **度量会过期**：连续 **3 期完全不变**（说明没人真用它做决定）⇒ 标记 `retired_candidate`，进 `v_gaps`。防止仪表盘通胀——v1 的登记表就是这么长起来的。

## 5. 用户与部署形态



| 形态 | 存储 | 谁在用 | 说明 |
|---|---|---|---|
| **T0 单人** | sqlite 单文件 | 一个人 + 若干 agent 会话 | 装完即用，零服务；关键决策用 `solo_cooldown(15m)`（见 [07](07-协作-权限-并行与子代理.md)「关键决策的独立性」） |
| **T1 小团队同机/同卷** | sqlite + WAL | 2–5 人、多个 dsh 实例 | 明确**不支持网络卷** |
| **T2 多人多地** | postgres | 真团队 | 需要服务、备份、鉴权 |

配置一块，缺省 T0：

```yaml
store:
  driver: sqlite            # sqlite | postgres
  url: ~/.local/share/sdo/<project>.db
```

**"缺省即单人"是承诺**：不要求用户先起数据库。

## 7. 问题：当生成变便宜，什么变贵



经典软件工程建立在"写代码很贵"的前提上。Royce（1970）自己就反对按阶段硬推：运行时间、存储、I/O 这类约束往往到测试才第一次被"经历"，此前只是"被分析"；他的对策是 `do it twice`，用有限代价把最危险的不确定性提前兑现成事实。Boehm 的螺旋模型把它变成风险驱动的迭代。

生成模型把"写出一个能跑的实现"的成本压到极低。这没有取消 Royce 的洞见，只是把瓶颈挪了位置：

> **当"写"变便宜，"确认"必须变便宜；否则瓶颈会迁移到审计上，并以"看起来完成、实际未被确认"的形式堆积。**

本文把这一转移的对象称为 **Agent 软件工程（ASE）**，并给出工作定义：

> **ASE 研究：在生成者不可信（非确定性、无稳定身份、无长期记忆）、产出近零成本的前提下，如何构造可复算的判据与可审计的证据，使"完成/覆盖/通过"这类结论在被签署之前不可能为假。**

关键差别不在"用 AI 写代码"，而在**生产者的性质**：

| 维度 | 经典开发者 | 生成式生产者 |
|---|---|---|
| 身份 | 稳定、可追责 | 会话级、可替换；同名不同会话是两个人 |
| 记忆 | 长期、跨项目 | 会话内；压缩或重启即失忆 |
| 产出代价 | 高 ⇒ 天然谨慎 | 近零 ⇒ "看起来完成"的产量可无限放大 |
| 自述可靠性 | 有声誉成本 | 无成本 ⇒ 回执可以写得很漂亮 |

经典 SE 里"依赖开发者职业素养"的那部分机制（评审、签字、承诺）因此**整体失效**——不是人不守规矩，而是**规矩不再有物理约束**。

## 8. 六条失效与它们违反的原理



v2 的设计不是"更严格"，而是**把每条原理落到不可绕过的结构上**。

### 8.1 P1 单一真源 ⇒ 事实只能有一个计算出口

**原理**：同一个事实若有两个计算出口，两者迟早分叉；而分叉后的"哪一个对"没有判官。这是任何"文档 + 台账"双写系统的通病。

**v1 的病**：设计上写了"单一真源"，实现里真源只是**文件**；回执、判据、注入各自算一遍。实测一次状态查询曾解析台账 **1124 次**；57% 的缺陷属于"声明≠真源"。

**v2 的机制**：事件表 → `fold` → 物化视图；**只有 fold 能读事件**，所有消费者（回执、判据、UI、注入）读同一份投影（[02](02-真源-存储事件与折叠.md)）。

### 8.2 P2 可追溯 ⇒ 意图必须变成可判定的条款

**原理**：Gotel & Finkelstein 的可追溯性研究指出，"前置追溯"（需求从哪来）与"后置追溯"（需求落在哪）是两种不同义务，缺一就会产生"谁也不知道为什么这么写"的代码。

**v1 的病**：`intent → spec → scenario → criterion` 这条链没有数据结构承载，只存在于人的对话里；新 agent 接手时无从判断"这条判据在保护什么"。

**v2 的机制**：六张表 + 强制外键（[03](03-链条-意图到声明.md)）；判据必须挂到 spec，spec 必须挂到 intent，intent 必须有人签字。

### 8.3 P3 被写 ≠ 被遵守 ⇒ 每个字段必须有消费者

**原理**：一条规则如果没有任何代码读取它，它在语义上等于注释。Meyer 的契约式设计要求前置/后置条件**可执行**；不可执行的承诺不构成契约。

**v1 的病**：一段"实现派子代理、流程官只记账"的分工写在文档里，而认领动作**不比对认领者的角色**。

**v2 的机制**：`field_consumer(field, criterion_id)`；没有消费者的字段判红（[04](04-判据-门禁与负例.md)）。

### 8.4 P4 证据绑定 ⇒ 结论的有效性是个区间，不是一个点

**原理**：证据只有绑在**产物指纹 + 事件 frontier** 上才有意义；否则"跑过了"与"现在还有效"混为一谈。

**v1 的病**：覆盖率判据曾只看"有没有通过结果"，不看"该结果是否被核实采纳"，导致"覆盖"虚高。

**v2 的机制**：`claim.as_of_frontier` + `evidence.artifact_sha256`；frontier 变了，claim 自动失效（[03](03-链条-意图到声明.md)）。

### 8.5 P5 人签不可代签 ⇒ 权威必须不可伪造

**原理**：数字签名提供的是**不可否认性**（non-repudiation）；而"谁有资格签"是授权问题，"他是否看懂"是产品问题——两者都不能由模型代劳。没有密码学签字的"确认"只是 UI 上的一个布尔值。

**v1 的病**：签字是工具参数里的一个字符串；模型可以替人签，人也可以盲签。

**v2 的机制**：登录 + 独立签章口令 + 独立签名进程（Ed25519）+ 三条不变式（[06](06-签字与安全.md)）。

### 8.6 P6 度量即目标 ⇒ 判据必须自证"不冤枉人"

**原理**：Goodhart / Campbell 定律：一旦度量成为目标，它就不再是好度量。工程上的形态是**判据被优化**（为了过检而灌水、为了让用例变绿而删断言）。

**v1 的病**：准入判据逼人给已否决的需求灌水才能通过；一条"永远红"的判据教会所有人忽略它。

**v2 的机制**：每条判据必须带**正例 + 负例**夹具，负例红了即判据本身判红；判据带预算与"抓到过几条真缺陷"的归因（[04](04-判据-门禁与负例.md)）。

## 9. 单写原理：为什么真源不能合并



这是 v2 最硬的一条，值得单独论证。

**代码可以合并，是因为合并后有判官**：编译器、类型检查、测试。三方合并把两边的改动揉在一起，然后**用一个外部标准判对错**。

**台账没有这样的判官**。两条分支各自把"任务 X 已完成"写进台账，合并后得到两条事实；"哪一个成立"没有任何外部标准可以裁决，因为台账**本身就是标准**。于是：

> **两个真相相加不会得到真相。真源只能单写，不能合并。**

这条原理推出 v2 的存储形态（[02](02-真源-存储事件与折叠.md)）：

- 真源是**服务**，不是文件；git 里没有台账；
- 并发由数据库的**事务与约束**串行化；
- 冲突**拒绝**而不是自动合并：写请求带 `expected_version`，版本不符即失败，由人基于最新版**重写**（这是一次新写，不是合并）。

同样的推理也解释了为什么"轻量 git 并行写"在 v1 里长期做不成：它试图用合并解决本质上是**串行化**的问题。

## 10. 可观测性即能力：工具是唯一的观测面



**原理**：一个 agent 能做什么，取决于它能看到什么。若状态以文件形式存在，agent 就会用 `bash` + `read` 去猜——不是因为不守规矩，而是因为**猜比查便宜**。

**证据**：v1 一个 560 轮的会话里，`sdo_status` 只调用了 **8 次**，`bash` 调用了 **1813 次**。

**v2 的机制**：状态在数据库里，数据库不在 agent 可读的路径上 ⇒ **绕路在物理上不存在**；观测只有 `sdo_query`（[05](05-观测与交互.md)）。于是：

> **"取不到的状态"不再是 agent 的失败，而是产品的缺陷**——`query_miss` 事件聚合进 `v_gaps`，成为下一轮补视图的输入。

这把"补工具"从拍脑袋变成有据可依：缺什么由使用记录决定。

## 11. 预算是资源，不是文案



**原理**：上下文窗口是有限资源；任何"输出面"都在消耗它。若预算只写在设计文档里而不进入类型系统，它一定会被绕过。

**证据**：v1 设计写"每轮注入上界 1500 字符"，实测**每条 11.3 KB（7 倍）**，且没有任何判据在管；一个 132 MB 的会话因此撞上窗口，压缩请求同样越界，形成死锁。

**v2 的机制**：渲染签名 `render(kind, state, budget) → {text, bytes, truncated, pointers}`；预算是一等常量（唯一定义处在 [05](05-观测与交互.md)），超限必须**结构化截断 + 指针**，禁止静默。

## 12. 三层漂移与 v2 的对应表



| 层 | 形式 | v2 的机制 | 可证伪检查 |
|---|---|---|---|
| L1 | 声明 ≠ 真源（两份实现） | 声明只能由视图生成；`claim.derived_by` 记账 | 任何回执字段无法在 `claim` 表里找到来源 ⇒ 红 |
| L2 | 真源 ≠ 被遵守（死字段） | `field_consumer`，无消费者即红 | 新增字段没有消费者 ⇒ 红 |
| L3 | 真源 ≠ 意图（判据自洽但违背意图） | 判据负例夹具 + 人签绑内容 + 免密绑 frontier | 判据负例被冤枉 ⇒ 判据红；签发页缺四项之一 ⇒ 拒绝签 |

L3 是唯一无法机械消除的一层（"意图"只有人能表达），所以 v2 不假装能消除它，而是**把它压缩到最小**：让它在"人签"这一处集中出现，并且**签字必须看见**（命题/证据/差异/后果）。

## 13. 一句话总结



v2 的每一条设计都能追溯到上面六条原理之一；反过来，**任何不能追溯到原理的机制，都是 v1 那种"只增不减"的负担**。这就是 v2 的取舍标准：不加不能说明"挡哪条漂移"的机制。
