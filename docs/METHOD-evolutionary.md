# 敏捷-演进式方法产物 · 人审文档

> 本文是 **`evolutionary` 方法包的人审文档**（G3 判据 C-2F）。文档头的 `basis` 是本包方法产物在台账里的**内容指纹**：
> 台账里任何产物变更都会让指纹改变，本文即失效，必须重新生成（用 `sdo_design action=method` 取当前指纹）。
> 真源是 `.sdo/design/method-debt.yml`、`method-reversibility.yml`、`method-increments.yml`，本文只是它们的**人读视图**。

## 2. 技术债台账（8 条）

| id | 债务 | 类型 | 影响面 | 偿还触发器 | 偿还计划 |
|---|---|---|---|---|---|
| DEBT-001 | `office.ts` 4141 行巨石聚合面 | code | 任何域改动都落在这一个文件上：定位成本高、评审难、合并冲突面大 | 任一新功能需要在 `office.ts` 里新增超过 200 行时 | 把该职责域拆到 `src/domain/<域>.ts`，保持对外接口与回执形态不变 |
| DEBT-002 | `index.ts` 2959 行工具面聚合 | code | 工具注册、参数解析、命令面、注入与钩子都挤在一个文件里 | 工具数超过 24 个或该文件超过 3200 行时 | 按分组拆为 tools / commands / inject / hooks 四个模块，注册入口保持一行不变 |
| DEBT-003 | infra 到 domain 的反向依赖（`isEffectivelyOpen` 等读端口径） | design | 分层规则被破坏：infra 无法独立于领域逻辑测试 | 下一次改动 infra 的读取路径时 | 抽成 infra 可用的纯形状判定，或由调用方注入判定结果（依赖倒置） |
| DEBT-004 | domain 到 integration 的反向依赖（`auditWriteScopes`、`independenceViolations`、`budgetShapeNotes`） | design | 领域层无法脱离宿主适配层单独测试，依赖方向与分层规则相反 | 下一次改动写范围对账或成本形状提示时 | 改为依赖倒置：domain 声明所需能力，由上层实现并注入 |
| DEBT-005 | 客户端半（`client.js`）无自动化测试 | test | 只能靠浏览器真机探针取证（本轮已发生三个症状各异的静默降级变体：OBS-003、OBS-006、OBS-009） | 下一次改动 `client.js` 之前 | 把三条探针读数脚本化，并纳入 0.1.6 的准出准则（无读数不得声称客户端半可用） |
| DEBT-006 | 子代理生命周期不可见（无超时回收机制） | design | 卡停在进行中时无法自动发现子代理已死，只能靠台账线索人工判断 | 宿主暴露子会话对象时 | 接入超时与自动回收；在此之前保持显式释放与改派留痕 |
| DEBT-007 | 语言包 en 逐键跟随基准 zh-CN | docs | 新增界面键时英文包缺键会静默回落到中文，覆盖率读数随之漂移 | 每次新增界面文案键时 | 保持守卫用例对配置键与语言包的比对；新增键必须同批补 en 与 zh-CN |
| DEBT-008 | 覆盖率依赖外部工具（自报测量） | design | 没有测量工具链的项目无法声明覆盖类准出准则 | 若出现必须内置插桩的宿主需求时 | 暂不偿还：内置多语言插桩与「语言无关」定位冲突（见 ADR-006），保持自报测量加机械核对 |

**读法提示**：DEBT-003 / DEBT-004 不是"以后再说"的模糊账，而是**本轮实测出来的具体反向依赖**（见 `docs/METHOD-oo.md` §4），它们的触发器就是"下一次碰这条路径"。

## 3. 可逆性分级（6 条）

| id | 决定 | 等级 | 为何现在定 |
|---|---|---|---|
| REV-001 | 台账目录布局与三类测试真源的分工（`tests/` 逐条用例与结果、`testing/` 测试过程与充分性、`construction/` 实现期方法产物） | `costly`（改起来贵） | 一旦使用者的项目写入台账，改布局就要迁移历史；语义三分必须在使用者规模出现之前定死 |
| REV-002 | 签字失效集合按门禁分别声明，且对未知事件类型取保守口径（不在中性表即视为真源变更） | `costly` | 它直接决定门禁语义与重签成本；本轮已被 `question/asked` 触发过一次真实失效，越早定越省重复成本 |
| REV-003 | journal 事件类型命名与形状（`requirement/updated`、`gate/result`、`signature/recorded`…） | `irreversible`（不可逆） | **追加式日志的历史不可重新解释**：改名等于让既有项目的旧事件失去语义，因此必须现在定 |
| REV-004 | 八维等权、每维 0/1/2、阈值 14/16，且评分卡随包固定（项目改不动门禁刻度） | `costly` | 门禁刻度一旦被项目调参，跨项目可比性与可复现性同时失效，必须在有外部使用者前固定 |
| REV-005 | 交付终点为「可部署产物 + 验收矩阵 + 回滚点」，发布与运维明确不做 | `reversible`（可逆） | 边界声明越早越省争议；但它本身可逆——未来要做发布助手，是**加能力**而不是改语义 |
| REV-006 | 客户端半的实现形态：waterfall 旁观者 + 宿主只读文件 Remote 取全文 + 侧边栏座位 + 探针五段读数 | `costly` | 建立在宿主服务的具体形态之上（`RemoteResult` 信封、`getSnapshot`、`openResourceIn`）；宿主 API 变化会迫使重写，因此把口径固定在契约里、把可替换点写清 |

**唯一不可逆的一条（REV-003）** 之所以单列，是因为它约束的是**已落盘的历史**：追加式日志不像代码，改不了过去。

## 4. 迭代设计增量（5 条）

| id | 迭代 | 涉及设计元素 | 说明 |
|---|---|---|---|
| INC-001 | 增量 1（0.1.x 早期） | DES-008, DES-011 | 设计阶段交互增强：设计提问 / 答复 / 确认 / 问题清单 / 渲染五条动作与界面视图支持，界面线框与 PlantUML 骨架源码随包交付 |
| INC-002 | 增量 2 | DES-011 | 设计方法论方法包：`structured` / `oo` / `evolutionary` / `porting` / `none` 可多选，逐包最小必产项与人审文档指纹绑定（G3 的 C-28 / C-29 / C-2F） |
| INC-003 | 增量 3 | DES-009 | 实现阶段方法包：`tdd`（红到绿，critical 档带变异自证）/ `contract-first`（契约冻结与契约测试）/ `small-batch` / `hardened-critical`，产物落 `.sdo/construction/**`，卡点挂在 `claim` 与 `done` |
| INC-004 | **增量 4（0.1.6，本轮）** | DES-022, DES-031, DES-010, DES-030, DES-006, DES-021 | ① **测试阶段强化**：验收大纲左移到需求基线、验证阶段方法包、测试设计规格（黑盒与白盒）、覆盖读数与未覆盖项处置、准出准则逐条现算、测试报告与用户签字、回归一等纪律、结果采纳与判定基准、变异复用与缺陷根因逃逸；真源落 `.sdo/testing/**`，承重三份文档由真源渲染。② **质量场景补白**（DEF-005 / DEF-006 → REQ-010 的 AC-226 / AC-227）：从 `.sdo/quality` 真源渲染 `docs/QUALITY.md`（带指纹），并给 G3 加一条质量场景判据（每个声明的质量属性至少一条场景，每条含刺激 / 响应 / 可测度量）。③ **审核单口径对齐**（DEF-004 → REQ-044 的 AC-228 / AC-229）：产物清单分「建议 / 必需」两栏、同一份文档只允许一个规范名、缺失项必须给可执行修法 |
| INC-005 | 增量 5（候选 0.1.7，**未承诺**） | DES-010, DES-012 | 候选增量（尚未进入变更控制）：类 / 方法 / 接口级结构覆盖读数、非功能测试的独立产物（性能 / 安全 / 可用性基线）、CI 集成，以及两处反向依赖的偿还（DEBT-003 / DEBT-004） |

**读法提示**：INC-005 明确标为**候选、未承诺**——它不在 0.1.6 的范围内，写在这里是为了让"下一轮可能做什么"有据可查，而不是承诺工期。
