## 2 0.1.7：主题 = **台账可信化底座**

> 一句话：**让"写下来的东西"开始被守，让"没守的东西"无处躲，让台账本身成为可入库、可回滚、可版本化的资产。**
> 选它的理由：U1/U2/U3/U4 四件事都在改**所有后续工作的成本结构**；不先做，后面每次发版都要像 0.1.6 那样**手写缺口清单**糊过去。

### 批 1（数据模型）—— 版本作用域 `U4`

- 字段：`defects/tasks/risks/changes/issues` 补 `targetVersion / deferredTo / deferReason / deferApprovedBy`；`requirements` 另加 `targetVersion`（**不复用**现有 `version`，那是架构轮次 `0.1/0.2/0.3`）。
- 判据：**`C-71` 版本作用域闭合** + **`C-72` 缺口清单与台账恰好相等**。
- 回填：155 缺陷 + 169 卡按 ★裁定① 处理。
- **交付物**：字段 + 两条判据 + 回填脚本 + `CHANGELOG` 缺口清单改为**从台账生成**（不再手写）。
- **DoD**：故意给一条缺陷写 `deferredTo: 0.1.9` 而 CHANGELOG 不点名 ⇒ `C-72` 必红；反过来只写 CHANGELOG 不写字段 ⇒ 也必红。

### 批 2（判据）—— 声明—判据覆盖 `U1`

- 元判据 **`C-70`**：声明必须"有机判器"或"显式豁免"，否则进「未设防清单」并计数点名。
- 用它**当场点名**已知的 14 条 A 族，并清掉其中 6 条最可能假绿的：`DEF-105`（`REQ-060` 零判据）、`DEF-115`（幽灵用例端点）、`DEF-126`（`C-50` 只 skip 不红）、`DEF-149`（登记≠验证）、`DEF-135`（AC 无实现）、`DEF-106`（契约无守）。
- **DoD**：`REQ-060` 这类"零判据 must 需求"被 `C-70` 当场点名；清掉的 6 条各有**反例**（改回去必红）。

### 批 3（并发）—— 子代理并行写的隔离与合并 `U2` ＋ **子代理标识改「角色+uuid」**（`DEF-133` 提前）

> **v2（2026-10-22 下午，用户更正；`ADR-024`）**：原口径是「`.sdo/` 自成 git 仓库」，已被否决 —— 写台账走工具不会并行、`journal` 已有历史、脱敏减重后台账随主仓库进 git ⇒ 台账自建仓库是重复投资。**对象改为工作区**。

- 派发时**拦截写范围相交**（`DEF-128` 从 0.1.8 提前）：目录边界判定（`src/a` 与 `src/ab` 不相交），`writeScopes` 空/缺按**整仓 fail-closed**；拒绝回执要点名两卡、相交路径、三条出路。
- 子代理在**主仓库的 git worktree** 里写 `src/`、`test/` 等产物，卡 done 时合并回主干；**冲突不自动解决**，落事件 + 列冲突文件 + **保留现场**交人工。
- `.sdo/` 侧只留一条约束：**不建第二层 git 仓库**；台账并发写不属本批（工具串行 + `journal` 可回溯）。
- **顺带解决**：`DEF-133`（两套子代理标识合一，`C-52` 名字回退按角色前缀）、`DEF-128`。
- **不再声称**解决 `DEF-131`/`DEF-127` 的台账层同类 —— 那需要台账层可回滚，已随本 ADR 一并作废；`DEF-131` 仍是 0.1.8 B 族的活。
- **DoD**：两个 worktree 改不同文件 ⇒ 零冲突合并且两边留痕；同文件冲突 ⇒ 被点名、合并阻断、现场保留；相交写范围 ⇒ 拒绝派发且回执可照着办。

### 批 4（资产化）—— 脱敏 ＋ **evidence 随版本归档删除** ＋ 入库 `U3` + `M2`

- 写入侧：落进台账的路径一律**相对路径**（`DEF-155` 规则的自然延伸）；会话 id 保留、主机名/用户目录不写。
- 一次性清洗：252 个真源文件 + 241 条 journal 事件 —— **需要一条 ADR**（"脱敏是唯一允许的历史改写，必须留前后哈希"），因为它与"历史不重写"冲突。
- **归档**（不是减重）：`evidence/` 随 task 所在版本周期结束而删除大体积部分（`scratch/` 等 748 MB → 目标 <50 MB），保留 `report.md` 与摘要；journal 记 `evidence/archived`（含删除字节数与保留清单）；`drafts/`、`handover/`、`project.json` 不入库。
- 入库边界：**真源层 8.2 MB 进主仓库**；`evidence/` **不入**（ADR-022 已定，随版本归档删除）。
- **DoD**：真源层里**本机家目录前缀的出现次数为 0**（用占位符表述，别在文档里写死那个前缀字符串）；`.sdo` 入库后仓库增量 <10 MB；`sdo_scrub` 留下前后哈希与批准人。

## 5 每个版本的**退出条件**（统一口径，取代"全绿"幻想）

一个版本可以发，当且仅当：

1. **作用域内**（`targetVersion <= 当前` 且未被 `deferredTo` 放行）的 blocker/major 缺陷、`must` 需求、契约**全部闭合**（`C-71`）；
2. 作用域外的遗留项**每一条**都有 `deferredTo` + 理由 + 批准人；
3. `CHANGELOG` 本版「已知缺口」与 `deferredTo === 当前版本` 的集合**恰好相等**（`C-72`）；
4. 声明—判据覆盖（`C-70`）的「未设防清单」**只减不增**；
5. CI 在 ubuntu + windows × node 20/22 四格**全绿**（0.1.6 的 `DEF-153` 教训：本地绿不算）；
6. 交付清单存在且绑定产物哈希（`C-60` / `C-delivery-bound`）；
7. 本版 task 的 `evidence/` **已归档**（`evidence/archived` 事件在案，体积回落），归档清单里不含下一版仍在飞的 task。

## 9 分工与独立性（2026-10-22 定，防后续遗忘）

分工原则：**不按"谁写代码快"，按"这批产物的风险落在哪"**。

| 批 | 谁做 | 为什么 | 复核方式 |
|---|---|---|---|
**批 1 版本作用域** | **驾驶舱** | 口径必须反复用 `sdo_gate`/`sdo_status` **现算校准**（创造模式没有这些工具，只能靠测试猜）；回填是**批量写台账**，而 `.sdo` 只由驾驶舱写；这类活最容易做成「测试绿但门禁不认」 | 评审会话采纳（`adoptedBy` 必须是另一个会话） |
**批 2 `C-70` 元判据** | **驾驶舱定规格 ＋ 创造模式实现检查器** | 判据语义就是「**什么算被守**」的标准本身，不能让实现者自己定义自己验收 | 驾驶舱复核 + 跑门禁现算 + 评审采纳 |
**批 3 并行写隔离 + 标识** | **创造模式** | 纯工具链，可**脱离台账语义**独立暴力验证（两个 worktree 并发写、故意制造冲突、故意让写范围相交）；失败模式是「worktree 现场乱了」（可清理），不是「台账里的判断错了」（不可逆） | 驾驶舱核台账完整性 + 跑全量 |
**批 4 脱敏 + 归档** | **驾驶舱，且必须用户批** | 触碰「历史不重写」底线，需要 ADR + 批准人；「哪些是真源、哪些是冗余」要靠台账知识判，误删不可逆 | 用户批准 + 演练报告（改了多少条、被拒哪些） |

**三条铁律**：

1. **执行者 ≠ 采纳者**：驾驶舱做的由评审会话采纳；创造模式做的由驾驶舱核。任何一方不得自证。
2. **创造模式没有 `sdo_*` 工具** ⇒ 台账（立卡/认领/记录/评审）**一律由驾驶舱代做**，并在 note 里写明「代记：执行者＝创造模式」。
3. **改历史的动作（脱敏、归档删除、回填）必须先出演练报告并取得用户批准**，且留前后哈希。

**交给创造模式的交付形态**：驾驶舱写**任务书**（`docs/plan/*任务书*.md`），由用户转交；它按任务书实现并把读数贴回，驾驶舱复核后记台账。
