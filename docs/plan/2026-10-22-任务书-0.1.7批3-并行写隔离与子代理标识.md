## 1 v1 → v2 改了什么，以及为什么

### 1.1 台账不再自建 git 仓库（`ADR-024`）

v1 要求「`.sdo/` 成为一个自己的 git 仓库，每次台账写入后提交」。**这条被用户否决**，理由是三条都成立：

| 用户的理由 | 结论 |
|---|---|
写台账一律走工具，理论上不会出现并行写 | 台账侧**没有**要解决的并发问题 |
台账本身已有 `journal.jsonl` 做历史 | 审计与回溯已被覆盖 |
脱敏与减重后台账也进 git（批 4） | 回滚已由**主仓库 git** 承担 ⇒ 第二层仓库是重复投资 |

所以：**并发隔离的对象是工作区（`src/`、`test/` 等产物），不是 `.sdo/`**。你要解决的是「两个 developer 同时改代码，一个静默覆盖另一个」这个问题。

### 1.2 顺带把 `DEF-128` 提前进来

`REQ-066` 的第①条 AC 要的是「派发时能**识别并告知**写范围相交」。对应的缺陷是 `DEF-128`（派发不检查写范围占用，**回执里看不出冲突**），原排在 0.1.8 —— 不提前，这条 AC 就没有落点。本批一并做。

**注意：相交不阻断派发。** 用户 2026-10-22 明确指出：git 对同一文件的不同区域本来就能干净合并 ⇒「范围相交」不等于「真冲突」，一律拦下只会让人白拆卡。所以相交只做**可见**，真正串行的只有两类（见 §2.1）。

### 1.3 为什么这三件事绑一批

它们都在动同一条链路：**谁在写、写到哪、写完怎么合**。标识（谁）、写范围（写到哪）、worktree 与合并（怎么合）是三段同一根链条，分开做会出现「标识改了但派发还按槽位判占用」这种半新半旧的中间态。

## 2 口径（驾驶舱已定，按此实现，不要自行改）

### 2.1 写范围相交 ⇒ 点名告知（不阻断）；只对两类情形串行

1. **判定时机**：`sdo_plan action=next` 挑卡派发时，以及派发入口（`dispatch`）本身。两处**同一份实现**，不许分叉。
2. **相交定义**：两张 `in progress`（或刚被选中的）卡的 `writeScopes` 存在**任一路径重叠**即算相交。重叠按**目录边界**判：`src/a` 与 `src/ab` **不相交**；`src/` 与 `src/a.ts` **相交**（目录包含文件）。
3. **默认行为 = 放行 + 点名**：相交**不阻断**派发；但派发回执必须点名相交的两张卡与**具体路径**（可见即约束），并提示「两边靠合并流程处理，冲突时留现场交人工」。
4. **只有两类串行**：
   - **独占窗口**：任一方声明要独占（如跑全量测试 —— 两边同时跑会互删夹具，这是 `DEF-127` 那类假红的来源）；
   - **无法判定**：`writeScopes` 为空数组或缺失 ⇒ 按「**整仓**」处理（fail-closed），与任何在飞卡都算相交。
   这两类情形下不派发，并给出**可执行**回执：点名两张卡、被挡的具体理由、三条出路（等前一张 done / 改 `writeScopes` / 拆卡）。
5. **回执不许只写「冲突」** —— 必须能被下一个人直接照着办。这是 `DEF-128` 的原病：旧回执里根本看不出有冲突。

### 2.2 工作副本 = 主仓库的 git worktree

1. **位置**：主仓库（本仓库根）的 worktree，路径在 `.sdo/drafts/worktrees/<task-id>/` 或仓库外的临时目录（**由你决定并写进设计说明**，但必须满足：不进入主仓库索引、不污染 `git status`、不落在 `src/` 与 `test/` 里）。
2. **创建时机**：派发子代理且它有 `task-id` 时。命令形如 `git worktree add <path> -b task/<task-id>`。
3. **写入路由**：子代理的代码写入落它自己的 worktree；驾驶舱的写入落主工作树（驾驶舱改的是台账，不经 worktree）。
4. **合并**：**由子代理自己**在完成时调用插件提供的轻量 git 能力，把 worktree 的分支合并回主分支（`git merge` 或 `cherry-pick`）—— 不是驾驶舱或人工代劳。合并后必须能回答「这次合并带来哪些文件变更」，并留一条事件（含卡 id、副本标识、变更文件清单）。
5. **清理**：合并成功或卡 `drop` 后 `git worktree remove`。**冲突时不许删**（留现场）。
6. **干净合并是常态，不是运气**：同一文件的不同区域必须能合过去 —— 把它误判成冲突（例如用「文件级」锁去替代真实的三路合并）算实现缺陷。

### 2.3 冲突不自动解决

1. 合并冲突时：**不自动解决、不 `-X ours/theirs`、不跳过**。
2. 必须落一条并发冲突事件（含卡 id、副本标识、冲突文件清单），并把 worktree 保留在原地。
3. 回执必须给出人工处置的三步（看现场 → 手工解决 → 重跑合并）。
4. `journal.jsonl` 的 append-only 是判据地基：**任何**重写/压缩都不许（归档是批 4 且有 ADR）。

### 2.4 台账侧唯一的一条约束

`.sdo/` **不建第二层 git 仓库**。如果你在实现中发现「不给台账建仓库就做不了某件事」，**停下来问**，不要自行补上。

### 2.5 子代理标识 = 角色 + uuid

1. **owner 形态**：`` `${role}-${sessionId.slice(0, 8)}` ``（如 `developer-20af1d60`）；`inline` 后端仍是 `cockpit`。
2. **写侧**：新派发一律用新形态。
3. **读侧兼容**：历史卡上的老形态（`subagent:developer:1`）**不迁移、不改写** —— 判据读的时候按「两者都可」处理。
4. **`C-52` 的连带**：材料不全时的名字回退分支现在是 `review.reviewer === task.owner`。改为**按角色前缀**比较（`developer-xxxx` 与 `developer-yyyy` 视为同一角色）。口径见 §6。
5. **回执与诊断**：派发回执里 owner 用新形态显示；`sdo_status` 的池面读数同源。

## 3 守卫（必须自己新建，四态起：绿/红/漂移/不可判）

| # | 守卫 | 内容 | 反例（必须红） |
|---|---|---|---|
T3-01 | 相交点名（不阻断） | 两张在飞卡 `writeScopes` 相交 ⇒ **照常派发**，回执点名两卡与具体路径 | 相交却未在回执点名 ⇒ 守卫红；**把相交的卡拦住不派** ⇒ 守卫也红（过度保守同样是错的） |
T3-02 | 目录边界 | `src/a` 与 `src/ab` 判**不相交**；`src/` 与 `src/a.ts` 判**相交** | 用裸前缀匹配 ⇒ `src/a` 与 `src/ab` 被判相交 ⇒ 守卫必须红 |
T3-03 | 两类串行 + fail-closed | 任一方声明独占窗口 ⇒ 串行；`writeScopes: []` ⇒ 与任何在飞卡都算相交（fail-closed） | 独占窗口仍并行 ⇒ 红；写范围缺失当空集放过 ⇒ 红 |
T3-03b | 干净合并不得误判 | 同文件不同区域 ⇒ 合并成功 | 该情形被判冲突 ⇒ 红（说明用文件级锁替代了真实三路合并） |
T3-04 | worktree 生命周期 | 建 → 写 → 合并 → 移除；`drop` 的卡也能移除 | 冲突后 worktree 被删掉 ⇒ 守卫必须红（现场必须留） |
T3-05 | 合并冲突不自动解决 | 两边改同一文件同一处 ⇒ 冲突被如实报出 + 落事件 + 留现场 | 自动 `-X ours` 合过去 ⇒ 守卫必须红 |
T3-06 | owner 形态与 `C-52` | 新派发 owner = `角色-8位uuid`；两个不同 uuid 的同角色会话**不产生**相同 owner；`C-52` 按角色前缀判自评，换角色 ⇒ 判独立 | 同角色不同 uuid 产生相同 owner ⇒ 红；`C-52` 一律判自评 ⇒ 红 |

## 4 禁区

1. **不许**给 `.sdo/` 建 git 仓库（`ADR-024`）。
2. **不许**自动解决合并冲突；冲突必须留痕 + 留现场。
3. **不许**改写历史卡的 owner（历史不重写）；读侧兼容即可。
4. **不许**在 `journal.jsonl` 上做任何重写/压缩。
5. **不许**用裸字符串前缀判路径相交（`src/a` vs `src/ab` 就是反例）。
6. **不许**因为这批改动放宽任何既有判据；`C-52` 的回退口径**只允许**按 §2.5.4 那一处改。
7. 不碰 `src/domain/gates.ts` 的判据逻辑（批 1/2 的活）。
8. **不许**在真实仓库上做破坏性演练（`git worktree` 测试一律在临时目录或临时仓库里做）。
