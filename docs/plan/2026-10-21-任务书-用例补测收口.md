## 0 这份任务书是怎么来的（先看读数，再看活）

### 0.1 起点与做法

`.sdo/tests/TC-*.yml` 登记了 **167** 条用例，其中 **59 条从未跑过**（无任何 `TR-*` 结果）：`TC-092`、`TC-094…TC-150`、`TC-161`。

本轮把 59 条分给 **6 个只读子代理**（工具面被宿主收窄成 `read/grep/glob`，无 `bash`）各核 ~10 条：拆 `expected` 子句 → 找对应守卫 → **逐字引用**断言行。跑测与判定由驾驶舱做：

1. 每个被点名的守卫文件**真跑**（`node --test --test-concurrency=1`），记真实 pass/fail；
2. 逐条读被引用的 `file:line`，核断言是否真的断言了那句话；
3. 只对 **expected 的每一句都能指到断言（或指到一次可复现的运行读数）** 的用例记 `pass`。

### 0.3 为什么 PARTIAL 一律不记 pass（口径变化，明说）

前两轮我把 2 条「部分覆盖」的用例（`TC-084`、`TC-086`）记成了 `pass` 并把偏差写进 `evidence`。**本轮改了口径**：`pass` 的意思是「这条用例的 `expected` 成立」，而 `expected` 里只要有一句没被断言，这句话就只是**主张**，不是结论。33 条 PARTIAL 全部停在不记——它们不是"没查"，是"查了，还差断言"。

这也意味着：**不记不等于没问题**。§2 的 33 行就是欠账清单。

### A1 `TC-092` / `DEF-029` —— 守卫夹具不写项目自己的台账：**零断言**

**现状（我亲自核过）**：`test/m93.test.ts:39` 把夹具根定在 `node_modules/.sdo-test/m93`，这是**夹具定义**，不是断言。全仓（`test/` + `src/`）搜 `DEF-029`、`项目台账`、`三路读数`、`零改动`、`latest-wins`、`夹具落点` 等关键词，**没有任何断言**核「跑守卫前后项目台账不变」。`DEF-029` 说当年有 54 条 `TC-060` 夹具记录写进了项目自己的 `.sdo`（latest-wins 能盖住真实结果）——修是修了，但**没有守卫**，回归随时可能回来。

**要做的（写性质断言，不要写枚举断言）**：

1. **静态不变量**：遍历 `test/**/*.test.ts`，取出所有被**当作 store 根**使用的路径常量（形如 `const BASE = join(ROOT, …)`）以及任何 `new SdoStore(...)` / `new Journal(...)` 实参能追溯到的字面量，断言它们**全部**落在 `node_modules/.sdo-test/` 之下。任何解析到仓库自身 `.sdo/` 的，判红并点名 `文件:行`。
   - 断言的性质写成「**任何**把夹具写进项目台账的守卫都算违规」，不要写成「m93 的 BASE 不在 .sdo 下」——后者只守一处，下一个夹具换个变量名就漏（这是 `REV-069` 教过的：DoD 枚举面本身就是缺陷模式）。
2. **动态不变量**：在 `node_modules/.sdo-test/` 下建一个 store，**真跑一次** `m93` 所测的那条判据（`evaluateGate` 的 `trace.defect-links`，G5 / `C-58`），然后断言**仓库自身**的三路读数逐字不变：
   - `.sdo/tests/results/` 的文件名清单（排序后逐项相等）；
   - 其中 `caseId === 'TC-060'` 的记录条数；
   - `.sdo/` 目录树的指纹（`相对路径 + 内容 sha256` 有序拼接后再 sha256）。

**落点**：新文件 `test/m207.test.ts`（现存最高 `m206`）。

**反例要求（必须做）**：把夹具根临时改回 `join(ROOT, '.sdo')`，新守卫**必须红**；改回来必须全绿且 `harness` 指纹与红跑**相同**。三条读数（红/绿/恢复哈希）写进 done 证据。

**不要这么写**：只核 `listTestResults(store).length` 一档。那正是 §2 里 `TC-099` 的缺口形态——长度相等而内容不同，照样漏。

### A2 `TC-161` / `REQ-062` —— 零实现、零断言，却有 `req-tc` 边（已记 `DEF-149`）

**现状**：`REQ-062`（评审独立性五项）**一行未实现**，`test/` 下 `REQ-062` 零命中、`review.pack` / `sample` / `input-pack` / `soft-delete` 等标识符全仓零命中；但 `TC-161` 在册，且在 `.sdo/trace/links.jsonl:615` 有一条 `REQ-062 → TC-161` 的 `req-tc` 边 ⇒ 覆盖率把它算成"需求有用例覆盖"。

**两条出路（需人类裁定后开工）**：

### A3 `TC-148` / `DEF-148` —— `expected` 与现盘**方向相反**

**现状**：用例要求「/dev 一族**不再靠单列特例过滤**」；现盘 `src/domain/writeScope.ts:203` 仍是 `const candidates = (input.paths ?? []).filter((path) => !isDevicePath(path))`——特例**没删**，只是搬进了 `src/domain/scopePaths.ts:204` 的 `{ kind: 'device' }` 分支。且 `test/m124.test.ts:207` 只断言「/dev/null 放行」这一**行为**，不核"特例是否已移除"。

**两条出路（需人类裁定）**：

驾驶舱不建议替裁定选：(a) 才是用例字面主张的东西；(b) 承认现状行为正确、只是措辞。**谁改，都要留痕。**

### A4 `TC-108` —— `expected` 第 4 句与现盘断言相反（用例漂移，不是缺测）

用例要求「把卡挂到**不相干契约**上 ⇒ 该检查照旧判红」；现盘 `test/m149.test.ts:174` 断言的是「契约与这张卡无关 ⇒ 按『没有对象』走 N/A」。

## 3 纪律（每条都踩过）

1. **不许为了让用例过而改断言**。缺的是断言就补断言；缺的是**行为**才改实现。两者在 done 证据里要分开写。
2. **每条新断言都要变异自证**：把对应实现改坏 ⇒ 新守卫红；改回来 ⇒ 全绿且 `harness` 指纹与红跑**相同**。红/绿/恢复哈希三条读数进 done 证据，`mutationExpected` 给数字。
3. **涉及用例措辞的（A2 / A3 / A4）只走 `sdo_test action=update`**，不许直接改 `.sdo/tests/*.yml`——那是台账，只有驾驶舱写。
4. **散文棘轮**：`node scripts/refresh-prose-gap.mjs --check` 必须**恰好相等**；`--write` 会写坏（`DEF-131`），只能手工改测试里的登记值。
5. **文档索引**：新增 `docs/**/*.md` 必须登记进 `docs/README.md`（`m89` / `M89-02` 会拦）。
6. **全量回归**：`node scripts/run-tests.mjs`；本轮基线 **1475 tests / 1475 pass / 0 fail**。本卡只许加不许减，加了几个要在 done 证据里给**算式**。
7. **`.sdo/` 是台账，只有驾驶舱写**；创造模式只写 `src/` `test/` `docs/` `scripts/`。
8. **别一次全做**：先 A1（真缺口），A2/A3/A4 等裁定；§2 建议一次 8~10 条分批交付，每批一卡。
