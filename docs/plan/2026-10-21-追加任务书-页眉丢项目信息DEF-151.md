## 2 修法（一处实现，两处入口共用）

在 `SoftwareDevOffice` 里加**一个**私有方法，别在两个入口各拼一遍（`DEF-142` 的教训就是同一件事两份实现）：

```ts
/** 渲染页眉的项目元信息（DEF-151）：只有这一处实现，两个渲染入口共用。 */
private testingRenderMeta(call: OfficeCall): { projectName?: string; process?: string; phase?: string } {
  const project = /* 项目台账读取入口：与 office.status(call).project 同源 */
  if (project === undefined) return {}                       // 没有台账 ⇒ 交给渲染层写「（无）」（fail-open，别抛）
  const def = processOfProject(project)                      // src/office.ts:313 已有
  return {
    projectName: project.name,
    process: String(project.process),                        // 盘上现值形态就是 `waterfall`（原始 id，不是标签）
    phase: phaseLabel(def, project.phase),                   // 盘上现值形态是 `开发`（标签，不是 `construction`）
  }
}
```

然后把两处入口改成：

```ts
// renderVerificationDocs
writeTestingDoc(store, 'plan', { store, seq, ...this.testingRenderMeta(call) }, journal)
// 签字投影（office.ts:1790）
renderTestReportSignable({ store, ...this.testingRenderMeta(call) })
```

**目标口径（盘上现值就是验收基准）**：`项目：PRJ-001 SDO 研发办公室插件本体` / `流程：waterfall` / `阶段：开发`。

### 三件不许做的事

1. **不许改 `testingRender` 的缺省文案**。「（无）」是 fail-open 的正确表现 —— 项目台账**真的**缺名字时才该出现；改成永远写某值会把"台账没读出来"藏起来。
2. **不许在渲染层内部偷偷读 `.sdo/project.yml`**。`testingRender` 是纯渲染（入参定文本、幂等），读台账是 `office` 的职责；渲染层自己读会让「同一入参两次渲染逐字节一致」这条不变量失效（`REQ-035`）。
3. **不许只修一处**。`renderVerificationDocs` 与签字投影是同一条病的两个出口，只修前者 ⇒ `C-59` 签字对上的仍是一份页眉被削的投影。
