## 2 修法（一行，`src/domain/writeScope.ts`）

**现有**（约 203–210 行）：

```ts
const deviceTargets = new Set(
  classified.filter((item) => item.kind === 'device').map((item) => (item.kind === 'device' ? item.raw : '')),
)
const candidates = (input.paths ?? []).filter((path) => !deviceTargets.has(path))
```

**改成**（按数组下标对位，不要拿 `raw` 当身份键）：

```ts
const candidates = (input.paths ?? []).filter((_path, index) => classified[index]?.kind !== 'device')
```

`classified` 本来就是 `input.paths.map(…)`（同一长度、同一下标），下标是唯一不会因 trim / 归一而错位的身份。

顺手把上面那段解释 `deviceTargets` 的注释改成说明「按 `classified` 的下标对位，不按字符串相等（`raw` 是 trim 过的）」，别留一段描述已删代码的注释。

## 3 测试：`test/m124.test.ts` 末尾加一格 `M124-13`

一格测试、三段断言。三段都**必须**有，缺一段这一格不算完成：

1. **空白不改变设备节点的结论**（`DEF-150`）：
   `['/dev/null', ' /dev/null', '/dev/null ', '\t/dev/stdout']` **逐个** ⇒ `kind === 'allow'`、`violations` 为空。
   断言消息里点明「空白不许改变设备节点的结论」，不要写成 `assert.equal(d.kind,'allow')` 这种没有理由的形态。
2. **带空白的真越界仍拒，且按原始绝对路径点名**（把 `DEF-074` 的幽灵路径面钉死，也让这条测试有判别力）：
   `' /tmp/probe.txt'` ⇒ `kind === 'deny'`、`code === 'write-scope-outside-workspace'`、`violations` 里是 **`/tmp/probe.txt`**，且 `detail` 里**不许**出现 `tmp/probe.txt` 这种剥掉前导斜杠的幽灵形态。
3. **归属三类在一处可区分**（`TC-148` 的第三句；`m124` 里现在没有这一格）：
   同一个测试里跑三条路径 —— 设备节点（`/dev/null`）⇒ `allow`、工作区外（`/tmp/x`）⇒ `deny` 点名原始绝对路径、工作区内（`src/a.ts`，在卡写范围内）⇒ `allow` —— 并断言三者的 `kind` / `code` 各不相同（`assert.notEqual` 或 `deepEqual` 列表都行，但要让读者一眼看出"三类"）。
   `evaluateWriteScope` 的入参照抄现有 `M124-06` 的形态（`role: 'dispatched'`、`guardedTools: ['edit']`、`cardScopes: ['src/a.ts']`，`workspace`/`workspaceRoot` 用 `BASE` 下的夹具目录而不是 `/ws` —— **别用我复现命令里的 `/ws`**，那是给一次性探针用的）。

**变异自证（写进 done 证据）**：把第 2 节那一行改回 `deviceTargets.has(path)` ⇒ `M124-13` 必须红（第 1 段挂）；改回 ⇒ 全绿且 `harness` 指纹与红跑**相同**。
