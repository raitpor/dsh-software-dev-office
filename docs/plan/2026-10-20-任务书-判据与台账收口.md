## §2 任务一（必须）：`DEF-143` —— `C-50` 不许把「无主结果」当失败用例

### 2.1 现状代码锚点（已核过，照着读）

| 位置 | 内容 |
|---|---|
| `src/domain/records.ts:831` | `verificationStats()`：产出 `cases / results / passed / failed / skipped / skippedCaseIds / failedCaseIds / unjournaled / tampered / unadopted / passedAdopted …` |
| `src/domain/gates.ts:1719` | `'tests.passed'`（即 `C-50`）：`if (stats.failed > 0) return fail(… k104, { p1: stats.failedCaseIds.join(' ') })` |
| `src/domain/gates.ts:1745` | 已登记但**没有结果**的用例 ⇒ `unrun` ⇒ 判红（这一面是对的，别动） |

### 2.2 修法（推荐方案，照做；要换方案必须先在回执里说明理由与代价）

**核心纪律**：本仓不允许改写既有读数的语义（`failed` / `failedCaseIds` 有其它用例与回执按它断言）。
**新语义一律加新字段**。所以：

1. `verificationStats()` **新增两个字段**（既有字段一个都不改）：
   - `orphanResultCaseIds: string[]` —— 有结果、但 `caseId` **不在用例登记表**（`listTestCases`）里的 id，去重、排序稳定；
   - `failedRegisteredCaseIds: string[]` —— **已登记**用例里最新结果是 `fail` 的 id（这是 `C-50` 今后该看的集合）。
2. `C-50`（`tests.passed`）的判红改为读 `failedRegisteredCaseIds`，**不再**用 `stats.failed`：
   - `failedRegisteredCaseIds` 非空 ⇒ 判红并**逐条点名**（话术不变，仍用 `k104`/`k105`）；
   - 无主结果非空 ⇒ **判绿但必须报出**（不改判红面）：用一条**新语言键**在 ok 话术里说
     「另有 N 条无主结果（caseId 不在用例登记表，不计入用例通过率）：<id 列表>」。
     **绝不许静默丢弃这条信息**（本项目最忌讳「查不到就算过」）。
3. `skip` 面、`unrun` 面、`unjournaled`/`tampered`/`unadopted` 面**一律不许动**。

**为什么这是正确的方向**：无主结果既不是「通过」也不是「失败用例」——它是**另一种东西**（变异观测 / 历史残留）。
把它算成失败，判据就永远红且永远无法收口；把它算成通过，就是假绿。**只有"单列并点名"这一条路**是对的。

### 2.3 DoD（逐条可核）

1. `verificationStats()` 新增 `orphanResultCaseIds` 与 `failedRegisteredCaseIds`，类型与注释齐备（写清为什么加新字段）。
2. `C-50` 只按 `failedRegisteredCaseIds` 判红；无主结果走 ok 话术**点名报出**。
3. **对真实台账**：`sdo_gate action=check gate="验证门禁（G6）"` 的 `C-50` 由红转绿，且回执里能看到
   「5 条无主结果：M95-03 TASK-063-RED TC-076-RED TC-076-RED-SUB TC-103-RED」。**这条由驾驶舱核，你交代码即可。**
4. 新增 `test/m205.test.ts`（≥5 条断言），必须覆盖下列**四态**：
   - **无主结果存在 + 已登记用例全绿 ⇒ 判绿**，且 ok 话术里点名了那几条无主结果；
   - **已登记用例有一条 fail ⇒ 判红**，且点名的是那条（**不许**因为存在无主结果就整体放宽）；
   - **同一条无主结果**（同一 caseId 多条）不重复点名（去重）；
   - **无主结果 + 已登记 all pass + 既有其他红面（如 `unrun`）同时成立 ⇒ 仍按 `unrun` 判红**（各面互不遮蔽）。

### 2.4 反空转红线（违反任一条即不通过）

- ❌ **不许**把判红条件改成 `stats.failed > 0 && failedRegisteredCaseIds.length > 0` 这类「两个都要满足才红」的写法 —— 那是把判据放宽。
- ❌ **不许**改 `failed` / `failedCaseIds` 的既有语义（`test/m43`、`test/m56` 等按它断言）。
- ❌ **不许**为了变绿去删/改 `.sdo/tests/results/*.yml` 或那 5 个 id（append-only 真源，改了就是篡改；
  `C-50` 自己的 `tampered` 面会抓到）。
- ❌ **不许**在 `C-50` 里静默 `continue` 掉无主结果而不报出。
