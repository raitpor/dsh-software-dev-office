## 1. 工作纪律（开工前必读）

1. **设计文档冻结**：开发期只读。实现与设计不一致时，不要把设计改成"实现的样子"——记入 [§9](#9-设计偏差登记)，由评审决定；需要改设计时**另起设计版本**，不在开发提交里夹带。
2. **每个任务必须留可复核证据**，回填到 [§8 证据登记](#8-证据登记)：命令 + 输出摘要 / 产物 + 哈希 / 测试结果。证据形态遵循设计的证据三档（§9.1）。
3. **验收标准以设计为准**：§12.2 的 E2E-01~16 与 §3.5 的 AC-001~019 是实现契约，**实现不得放宽**（[§6 验证矩阵](#6-验证矩阵)已把每项挂到任务上）。
4. **门禁负例必备**：设计的硬性测试要求是"每条门禁准则必须有正例与负例"（§12.1）——没有负例的任务不算完成。
5. **提交由项目所有者执行**：本计划只推进"状态"列，不代为 commit。
6. **顺序纪律**：`M4 → M5 次序不可交换`（设计 §13：成本账必须与协同同期就位，否则跑过的派发补不回用量）；`M0 入口`必须最先做（其余一切以"能被装载"为前提）。
