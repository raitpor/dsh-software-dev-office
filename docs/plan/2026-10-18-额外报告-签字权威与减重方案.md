# 额外报告（给 SDO 驾驶舱会话）：签字权威应统一为**问答选项** + 一份**不放松判定**的减重方案

- 写书人：创造模式会话（第十三批执行者）｜ 2026-10-18
- 来由：与用户的对话（"模型经常代签/签名不认"、"点选项的签字理应更有权威"、"要减重但不能放松判定"）
- 性质：**提案 + 待协商**。本文件**不改任何台账**；具体落法与取舍请驾驶舱与用户确认后落 `.sdo/`（`REQ`/`AC`/任务卡/缺陷）。
- **配套**：同一轮对话里的另外三个问题（「为什么越修越肿」「重写还是重构」「为什么模型钻空子」）的诊断与评估，已单独成文：[交接报告-系统诊断与重构评估](2026-10-18-交接报告-系统诊断与重构评估.md)。

## 一、事实基础（现盘可复算）

| 事实 | 读数 |
|---|---|
| 唯一真正"不经过模型"的签字通道 | `channel=question`（工具自己问、宿主回传所选选项）—— 历史上成功过 4 次（`gate/signed` seq 1195/1197/1706/1741） |
| 可被模型自填的"批准"面 | **5 处**：`sdo_gate action=sign` 的 `quote`（`statement` 通道）、`sdo_plan action=profile` 的 `approvedBy`+`impact`、`sdo_defect action=waive` 的 `waiveApprovedBy`、`sdo_task` 的 `mitigatesWaiver.waiveApprovedBy`、`sdo_requirement` 相关 `approvedBy` |
| 已发生的代签 | `gate/signed` seq **3490**：`channel` 记成 `command`、`basis` 是一句**工作指令**（"把 REQ-060 补进需求基线，重签 G2"） |
| 已发生的"签名不认" | ① 失效集合过宽（追溯边/环境登记等**记账写入**也算设计真源变更）；② 推进/派卡**不校验**入口门禁签字有效（真机 4 张卡在失效窗口内照常施工）；③ `DEF-110`：通道没弹时把插件自己的诊断记成"用户拒签" |
| 用户感受 | "经常让我说一句不重复的话作为签字" —— 这句话**要经过模型**，本质是让模型自证用户同意 |

**结论**：**原话是弱形式，选项是强形式**。权威只能来自"值从宿主回来、模型只看到标签"，以及"签的是**一份 sha256 指定的呈现物**"。

## 二、提案 1：统一成一个原语，六处全部换过来

```
present(payload) → 落盘取 sha256 → ask(options) → answer{label, selectedAt}
   ⇒ 台账记 { decision, label, payloadSha256, channel:'question', at, atSeq }
```

规则：

1. **选项固定三档**：`批准` / `拒绝` / `要求修改`；需要内容时由**宿主**收集"说明"（用户输入，模型不代填），说明与同一个 `payloadSha256` 绑定（防"旧说明贴到新内容"）。
2. **`approvedBy` 这类字段改成"问答记录 id"**（指向台账里那条 answer 事件），不再是自由文本 —— 审计能点到"哪一次问答、当时看到的是哪份内容"。
3. **重放判定换锚**：R-27 的"同一句原话只算一次" ⇒ "**同一 `payloadSha256` 只算一次**"（不依赖措辞，比句子哈希更准）。
4. "说一句不重复的话"退化为**可选备注**，**不再具备签字效力**。

### 降级策略（关键：通道一坏不能让人干不了活）

返回三态，**不许再混成"拒签"**（`DEF-110` 的病根）：

| 通道结果 | 破坏性决策（G2/G3 签字 / `drop` / 交付包 / 阻塞级缺陷豁免） | 非破坏性决策（普通豁免、备注批准） |
|---|---|---|
| `answered`（选中"批准"） | 有效 | 有效 |
| `declined` | 无效（记"拒签"，可重提） | 无效 |
| `unavailable`（宿主没注入 answerer） | **拒绝并给可执行出路**（在 GUI 里重试 / 先呈现再签），**绝不退回原话** | 允许 `channel=command` 的**弱批准**，台账标 `weak: true`，**不计入门禁签字有效性** |

### 需要驾驶舱与用户确认的四点

1. 是否接受"**破坏性动作只有问答通道一条路**"（否则原话通道永远是后门）；
2. `unavailable` 时**弱批准**的适用范围（本提案只给非破坏性决策）；
3. 选项文本（建议固定为"批准 / 拒绝 / 要求修改"，理由由宿主收集）；
4. 是否把"5 处自由文本批准"迁到问答记录 id（迁移期：旧字段只读，新字段必填）。

## 三、提案 2：减重方案（**不放松判定**）

**原则**：只减三样 —— **自我证明装置**（登记表 / 逐站点普查 / 报告仪式）、**重复实现**（同一规则两处遍历）、**文本冗余**（死键 / 同义键）。**判据、守卫、用例一条不减。**

**验收不放松的证明方式**（每步都要满足）：
1. 同一套用例前后**全绿**（当前基线 **1418**，随本批增长）；
2. 每个减重项**自己的变异**仍单点红；
3. **豁免登记条数只许降**（新增即红）；
4. 减重读数表（前/后）写进报告。

### 预算表（现算 → 目标）

| 项 | 现在 | 目标 | 判定强度怎么保住 |
|---|---|---|---|
| 源码行数 | 52,191 | −8~10% | 只合并重复实现、抽文件；判据一行不删 |
| 巨型文件 | `office` 4,755 / `index` 4,400 / `gates` 2,783 | 各 ≤2,500 | 拆出回执渲染 / 宿主适配 / 状态装配，判定函数原样搬 |
| 语言键（中/英各） | 2,772 | −10% | 死键现算（≈34，需排除 `kWaiveChecked_*` 这类拼接键）+ 同义合节（`uiIndex 429 / uiDesign 426 / uiDescribe 378 / uiGates 377` 四节占 58%） |
| 身份登记（`m191`） | 13 条 | 0 | 身份键从"`file:line`"改成"`file`+内容指纹"：悬空照样必须可解析，只是不再随行号漂移 |
| 散文普查（`m189`） | 2,215 站点 | 文件级预算 | **唯一需要用户点头的口径变更**：逐站点棘轮 → "每文件 ≤N 站点 + 新增站点必须带用例 id" |
| 报告守卫族（`m190`） | 6 个 case | 2 个 | 6 条规则全部保留在数据里，合并成"一个结构检查 + 一个逐份判" |
| 报告仪式 | 每项一张表 + 自查格（第十二批报告 526 行） | ≤150 行 | 保留：钉红 / 守卫 / 变异 / 复原 / 零改动 五项；自查格合并成一张总表 |

### 五个工作包（按风险从低到高）

1. **身份改内容指纹**（去 13 条登记 + 每次编辑的假红）——零风险。
2. **报告守卫四合一**（6 → 2）——规则不变，只去重复遍历。
3. **死键清理 + 同义合节**（−10% 文本）——中英同步，键面完整性判据照旧。
4. **拆 god files**：`receipts.ts` / `hostAdapter.ts` / `statusAssemble.ts` ——判定代码一行不动。
5. **散文普查降级为文件预算** —— 唯一改变判定口径的一项，**需用户明确点头**；不点头就保持原样。

### 明确"不许动"的清单（防减重变放松）

判据全集、用例全集、G2/G3/G7 的判据集合、四个语言节的完整性检查、变异四件套、`REQ-060` 自查（可合并成表，不可删项）、以及三条"信任根"判据（签字 / 交付绑定 / `req-tc` 覆盖）。

## 四、与第十三批的关系（建议）

- 第十三批 §2.1（`DEF-112`）已排"`command` 形态不得充当签字依据"；§2.2（`DEF-110`）已排"通道三态"。本报告的**提案 1** 是它们的**同族出口**：把另外 **4 处** `approvedBy`/`quote` 一并换成"问答记录 id"，否则只堵一个门、留四个侧门。
- 建议落法：在 `.sdo/design/` 或 `requirements` 里立**一条 REQ（签字的机械定义）** + 一条 AC（"破坏性动作只认 `channel=question` 且绑定 `payloadSha256`"），再由驾驶舱拆卡；本报告不代替它。
- **减重**建议单独立一项（可作第十四批的"结构项"），第 1–4 包先行；第 5 包等用户对口径变更点头。

## 五、需要用户拍板的三件事

1. 破坏性动作是否只认问答通道（放弃"原话签字"）；
2. `unavailable` 时是否允许**弱批准**（只给非破坏性决策）；
3. 散文普查是否可以从"逐站点"改成"文件级预算"。
