## 2. 选择机制（模型自选，不问用户）

1. **谁选**：`office`（流程官）。`sdo_plan` 已在 office 的 allow 里，不新增工具。
2. **何时选**：`sdo_plan action=decompose`（拆分完成，卡集合已知）之后、**推进到构造之前**。入场判据（§4 的 `C-33`/`C-83`）没有 profile 即红，所以"忘了选"会被门禁抓住。
3. **怎么选（模型决策 + 可核对依据）**：模型只许依据**已落盘的项目事实**选包，并把依据写成 `derivedFrom[]`：
   - 允许的依据词表（MVP，机械可核对）：`scale=trivial|normal|critical`、`reqKind=<kind>(<REQ-id>)`、`contractCount=<n>`、`defect:escape=<n>`、`stack=<值>`；
   - `derivedFrom` **至少一条**必须是上表里能机械核对的项（判据检查：能解析 + 指向的事实存在）；
   - 另记 `reason`（自由文本，给人看）。
   > 这是"模型自选"的**可审计化**：不要求选得"对"，要求**选得有据**。
4. **记录**：新增动作 `sdo_plan action=profile`（入参 `packages[]` / `scope` / `derivedFrom[]` / `reason` / `exempt[]`）⇒ ① journal 追加 `plan/profile-decided`（append-only，含复议历史）② 写 **`.sdo/construction/profile.yml`**（真源，可手改，与 `.sdo/design/*.yml` 同规）。
5. **可复议**：随时可再调一次 `action=profile`（覆盖 `profile.yml`、追加历史）。**已完成的卡不追溯判红**（否则一改口径全绿变全红）。
6. **范围**：`scope: all` 或 `[TASK-…]`；`exempt[]` 是**逐检查项**的豁免 `{task, check, why}`，`scale=critical` 时豁免还必须有对应的 `sdo_gate action=waive` 记录（复用既有豁免通道，不新造机制）。

## 8c. 工具层的教训（2026-10-03 复审 B1）

交付物通道**曾整条是死的**：`TestArgs` 加了 `mutation`/`contractTest`，但 **`sdo_test` 的工具声明没同步** ——
工具边界上不存在的参数会被**静默丢掉**，`index.ts` 的分流分支永远进不去（模型照 README 写也写不进去）。
修法：`parameters` + `execute` 逐字段映射都要有。

**同一缺陷类的第三次出现（PLAN-1）**：`sdo_plan action=profile` 的 `parameters`/映射也没有这 5 个参数 ——
修 `sdo_test`（B1）时**只修了眼前那只工具、没有扫同类**，于是决策入口照样是死的（真机 sdo-test 会话发现）。
另外新守卫第一次跑就抓到 `sdo_adr` 的 `id` 也没进声明（同类）。**现在有机械守卫**：`M25` 断言"`*Args` 里有的字段，
工具 schema 与 execute 映射里都要有"（17 个工具、按工具分块、带反例自证），与既有的 `F-7`（反向：映射不许读 schema 没有的参数）互补。

**给后续增量的规则**：
1. 任何新增的工具参数，**三处必须同时改** —— `TestArgs`（内部类型）、`parameters`（模型可见的 schema）、`execute` 映射（把值搬进去）；
2. **用例必须至少有一条经"真实注册的工具"调用**（`apply()` 注册表 → `tool.execute(...)`），不要只调 `office.*`：
   后者绕过工具边界，边界上的静默丢弃照不出来（这正是本轮 462 条全绿却漏掉 blocker 的原因）；
3. schema 与映射之间有一层免费保险：`args` 由 schema 推导 ⇒ 从 schema 删字段会让映射**编译不过**；
   但"加了 `TestArgs` 字段却忘了加 schema"类型系统管不着，只能靠第 2 条。

## 9. 实施步骤（建议顺序，每步都要双向用例 + 变异）

1. **词表与落盘**：`CONSTRUCTION_PACKAGES`、`CONSTRUCTION_CHECKS`、`.sdo/construction/` 读写（schema 校验 + 坏行/坏结构处理）、语言包键。
2. **`sdo_plan action=profile`**：入参校验（`derivedFrom` 至少一条可核对）、写 journal + `profile.yml`、回执（含"选了哪些包、依据、范围、豁免"）。
3. **`claim` 卡点**：`construction-profile-missing`、`contract-not-frozen`（+ `wip-exceeded` 告警）。
4. **`done` 卡点**：`tdd-red-green-missing`、`tdd-mutation-missing`、`contract-test-missing`（`hardened-critical` 四项在阶段 2）。
5. **门禁判据**：四个流程 YAML 加 `C-33`/`C-43`/`C-83`/`C-84` + 检查函数 + `sdo_status`/看板读数。
6. **文档**：README（新增小节 + 边界）、CHANGELOG、`docs/README.md` 索引、角色卡（office 的"决定 profile"步骤、developer/tester 的"补交付物"步骤）。
7. **阶段 2**：`small-batch`（告警）与 `hardened-critical`（四项硬拦）。

**MVP 边界**：步骤 1–6，包只上 `tdd` + `contract-first`（两者都有可现算的硬检查，先证明形状可行）。

## 10. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 过度门禁 ⇒ 假证据 | 硬拦只给"证据存在性 + 时序一致性"；度量类只告警 |
| 模型自选"暗箱" | 强制 `derivedFrom`（至少一条可机械核对）+ `reason` + 复议历史；G4/GI 有人（流程官）复核 |
| 改口径导致历史卡翻红 | 复议**不追溯**已完成卡 |
| 升级影响面 | 只影响**升级后新进入/新退出构造阶段**的项目；已过 G4/G5 的项目不追溯（sdo-test 已在交付阶段，不受影响）——写进 CHANGELOG 的升级须知 |
| 包名进了判据 ⇒ 改名全红 | 判据只引用动作/事实；包名只出现在数据与文案 |
