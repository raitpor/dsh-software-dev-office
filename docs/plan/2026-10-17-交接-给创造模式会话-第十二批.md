# 交接：第十二批（给创造模式会话）—— 需求→判据断链收口 + 随包面无关性 + 弱绑成族

> 起因：用户 2026-10-17 的两个追问 ——「语言无关不是写在需求里的吗？你为什么连需求都不遵守，是插件缺陷还是你忘了」；「在册不等于被遵守，插件侧应如何补强制措施」。
> 结论（驾驶舱已核）：**两边都成立** —— `REQ-060`（must）**零判据/零用例/零追溯边**（54 条 must 里唯一一条），而它本季已**复发 7 条缺陷**；同时驾驶舱连续四批没把它当验收项。本批把这条件**从机制上**接住。

## 0. 本批是什么（先读这段）

一句话：**把"在册"接上"对手方"** —— 13 条 open 缺陷成族收口 + 6 条强制措施（机械化、语言无关）+ 1 格补核 + 1 条流程项。

### 本批清单（可机械核对，防误读）

- **缺陷 13 条 = 6 major + 7 minor**（算式：major = `DEF-102` `104` `105` `106` `107` `108`；minor = `DEF-087` `093` `096` `099` `100` `101` `103`）
- **结构项 2 条**：`S1` 立卡时的**角色能力对账**；`S2` 判据的**真机形态守卫**
- **补核 1 格**：`H` 不变量清单的**守卫覆盖**（现算 **28** 条 / 11 个 category / 引 **14** 条 REQ；**哪些真有守卫尚未核完**）
- **流程项 1 条**：每批 §5 增 **`REQ-060` 自查格**（见 §5）
- **分组**：A 组（判据与机制）/ B 组（随包文本与遗留小项）/ C 组（弱绑成族 + 交付绑定真跑）—— 见 §6

### 🛑 口径（三条，本批独有）

1. **`REQ-060` 是 must，`AC-241` 逐字规定**：凡判定依据是「某种文件格式的**内部结构**」或「某个具体项目的**固定布局**」⇒ **必须改成「项目声明 + 格式无关的通用比较」，否则方案被否决**；且**回执或评审必须点名这处格式依赖**。⇒ 本批**每一条改动的报告都要回答这两个问题**（§5 的自查格）。
2. **「四份文件该节逐字节相同」这条口径作废**（第十一批 §3.4 的副作用）：`docs/`（项目侧）与 `skills/`（**交付侧**）**不该同源** —— `DEF-102` 就是这么被灌出来的。项目特有的清单/命令**只落 `docs/README.md`**。
3. **判据只认可复算的读数**，不认形状、不认面级计数（`DEF-094` 水表 / `DEF-098` 理由与实测不符 / `DEF-100` 占位 proof / `DEF-108` 垫表 —— 同一族）。

### ⚠️ 贯穿全批的机械要求（沿用，**不许退化**）

1. **变异四件套**：① 自证字节变了**且真的写盘了**；② 每次变异前还原**全部面**并**重编译**；③ 用**直接** `node --test --test-reporter=tap <file>` 自证"脚本跑完了"（`--test-reporter` 经 `scripts/run-tests.mjs:37` 的自拼 `spawnSync` **传不进去**）；④ 每格打印该副本树的 **`lib` 整树 sha** + **逐用例取 fail**（不取文件级）。
2. **副本树 15 项清单**（`src`+`test`+`lib`+`skills`+`docs`+`scripts`+`README.md`+`presets/`+`tsconfig.json`+`client.d.ts`+`CHANGELOG.md`+`client.js`+`package.json`+`package-lock.json`+`node_modules` 软链）⇒ **本批起清单只落项目侧**（`docs/README.md`），随包卡里只留原则（`DEF-102`）。
3. **基数类断言给算式**（`R22-③`）；**《豁免面清单》逐份判、不许面级分母**（`DEF-108`）。
4. **交付绑定**：本批交付的**提交信息里要能查到关键产物的 sha256**，或按项目声明走清单落点（`DEF-107`）。
5. **评审卡不许要求"自己跑命令/自己算文件哈希"** —— reviewer 掩码没有 `bash`/`write`/`edit`（见 `skills/role-reviewer.md:47/49/55`）；动态读数引用 tester 复验卡。

## 3. 要修什么

### 3.1 A 族 `DEF-102`（major）—— 随包角色卡去项目化

**问题**：三张随包卡（`skills/role-{developer,tester,reviewer}.md`）里有「第 7–16 条」那一组纪律，整段是**本仓的工具链与目录**：`npm test`、`npm run build`、`node scripts/run-tests.mjs`、`node --test --test-reporter=tap`、`tsc`、`lib/`、`tsconfig.json`、`presets/`、`client.d.ts`、`package-lock.json`、`sha256sum`、`cmp`、`find | xargs`、`diff -rq`，甚至 `domain/writeScope.ts`（本仓文件路径）。**任何项目装上本插件都会读到这些**。

**修法（三件）**：
1. **只留与项目无关的原则**：变异打在守据读的那一层 / 先还原再变异 / 不要凭 mtime 判断改动 / 副本要在自造树里做 / 基数类断言给算式 / "没跑"≠"跑了没红" / 同一条判据的多个出口一起扫 …；
2. **凡涉及具体命令/目录/语言工具的，一律改成占位符 + 「以项目声明为准」**（例：`＜项目的全量测试命令＞`、`＜项目的交付产物目录＞`、`＜项目的副本树清单＞`）；
3. **本仓特有的那份清单与命令移到项目侧** `docs/README.md`（第十一批刚加的第 18 条「基数类断言给算式」等**原则**保留在随包卡）。

**另两处**：`presets/sdo-office.patch.yml:47` 的 `disciplineAllowPaths: ['.sdo/','docs/','test/']` ⇒ 要么改成从项目配置读，要么在文件头**明写「这是本仓示例，不是通用默认」**；`skills/*.md` 里若还有别的本仓路径，一并清。

**验收**：`grep -nE "\bnpm\b|\btsc\b|node_modules|tsconfig|client\.d\.ts|presets/|package-lock|sha256sum|diff -rq|xargs" skills/*.md` ⇒ **0 命中**；三条原则逐条仍在（逐字比对）；项目侧清单位于 `docs/README.md` 且可查；**REQ-060 自查格**填写。

### 3.2 A 族 `DEF-103`（minor）—— 语言包示例去项目化

`src/data/lang/{zh-CN,en}.yml` 里 `evidence` 的帮助文本示例改成**工具无关占位**（如 `＜项目的测试命令＞（＜通过数＞ passed）`），中英同义；顺手扫两包是否还有别的"具体命令/具体数字"例子（`.sdo/…` 这类插件自身约定可保留）。
**验收**：`grep -nE "\bnpm\b|\btsc\b|\b420\b" src/data/lang/*.yml` ⇒ **0**；两包键集与结构同步（既有 `m36`/`m7` 守卫不回归）。

### 3.3 B 族 `DEF-104`（major）—— 阶段纪律空转 + 死配置

**问题**：`discipline.ts:55` 的「实现阶段前不许写代码」用 `path.startsWith('src/') || path.startsWith('test/')` 判，而**宿主传给 `write`/`edit` 的 `file_path` 是绝对路径** ⇒ **真机恒 false**（插件自己的 `writeScope.ts:11-14` 注释已写明）；另 `disciplineAllowPaths`/`disciplineTools` **从来没人读**（死配置）。

**修法（四件）**：
1. **路径归一化**：把宿主传来的绝对路径按工作区根归一后再比对（`writeScope.ts` 的 3b 卡级纪律**已有先例**，照它做）；
2. **项目可声明**：新增 `.sdo/config.yml` 的 `discipline.codePaths`（列表），`src/`+`test/` 降为**默认值**；**用默认值时回执必须明说**（不许静默）—— 这一条同时满足 `AC-241`；
3. **死配置**：`disciplineAllowPaths`/`disciplineTools` **要么复活（真读）要么删除**（二者都要有判据挡回归：声明了却没人读 ⇒ 红）；
4. **真机形态守卫**：喂**绝对路径**（而不是相对路径夹具）验一次；再补一格「非 `src/` 布局（如 `cmd/`/`internal/`）在早期阶段写代码必须被拦」。

**验收**：真机形态用例红→绿可复现；自定义布局被拦；缺声明时回执点名"用了默认实现代码面"；死配置零残留（或真被读）；**REQ-060 自查格**填写。

### 3.4 C 族 `DEF-105`（major，**元缺陷**）—— 需求→判据断链

**问题**：`REQ-060`（must）**零判据/零用例/零追溯边**；负责"未覆盖 must 需求 ⇒ 拦门禁"的检查器 `coverage.uncovered` **根本不存在**（当年负责注册它的 `TASK-003` 被 dropped）⇒ 一条 must 约束**没有任何机制接住**，本季已复发 7 次。

**修法（三件，缺一不可）**：
1. **把 `AC-241` 机械化**：新增一格「**随包面无关性**」判据 —— 扫**发布面**（`package.json#files` 对应的 `skills/`、`src/data/`、`presets/`），命中"语言/工具链特定且**可判定**"的词即红并点名 `file:line`；**token 表每条必须给理由**（避免变成 `DEF-080` 那种名单）；**该判据自身**也必须语言/项目无关；
2. **给 `REQ-060` 补追溯与用例**：至少一条 `req-tc` 边 + 一条覆盖"随包面无关"的用例；
3. **让「未覆盖的 must 需求」进判据**（复活 `TASK-003` 的意图），并把 `REQ-060` 作为它**第一个**应抓到的实例。

**验收**：① 判据在大 `skills/` 里注入一个 `npm test` ⇒ 红并点名；② `REQ-060` 有 `req-tc` 边且用例可跑；③ 造一条假的"未覆盖 must 需求" ⇒ 门禁红并点名；④ `coverage.uncovered` 在流程数据与代码里都真实存在。

### 3.5 D 族 `DEF-106` / `DEF-107`（major）—— 在册无守

**`DEF-106`（契约）**：**31** 份契约只有 **4** 份有契约测试记录。修法：每份契约至少一条 `contractTest` 记录（或由项目**显式豁免并给理由**，结构声明、语言无关）；判据只认 id 与记录，不认实现形态。
**验收**：31 份逐份有记录或逐份有豁免；缺一份即红并点名契约 id。

**`DEF-107`（交付绑定）**：**558** 行提交信息含哈希 = 0、`lib/` 不被跟踪。修法：**项目声明交付绑定形态** —— `git commit`（提交信息须含关键产物哈希）或 `sha256 清单`（给落点）⇒ 插件**按声明核对**，查不到即红。
**验收**：声明为 commit ⇒ 提交信息缺哈希时红；声明为清单 ⇒ 落点缺失时红；两种形态各一格用例。

### 3.6 E 族 弱绑成族（`DEF-108` major + 同族预防）

**`DEF-108`**：`test/m190.test.ts:363` 的界 = `tableCount >= reports.length * 3`（**与面内报告份数耦合**）。修法：**逐份判**（每份自身 ≥3 张，或**显式声明「本报告不含《豁免面清单》」并给理由**）+ **两格守卫**：① 一份 0 表报告 ⇒ **必须单点红**；② 一份 3 表 + 一份 0 表 ⇒ **仍必须红**（**专挡垫绿**）。顺手把 `:363` 断言消息里**硬写的「A 3 + B 3 = 6」**改成算式（`R22-③`）。
**同族成族收口**：`DEF-094`（水表）/ `DEF-098`（理由与实测不符）/ `DEF-100`（占位 proof）/ `DEF-093`（清单自报可骗）/ `DEF-096`（自解析恒可解析）—— 逐条确认它们的守卫是否已覆盖"空表/垫表/水表/占位/自解析"这五种形态；缺的补一格。
**验收**：五种形态各一格"注入即红"的用例；`M190-04` 在"新落一份 0 表报告"时**仍然红**（不再假绿）。

### 3.8 G 结构项（两条）

- **`S1` 立卡时的角色能力对账**：插件已在 `roles.ts` 里知道每个角色的工具面 ⇒ 建卡/改卡时若 DoD **点名了该角色面里没有的工具**（本轮实测两例：reviewer 要 `bash`、tester 要 `sdo_hash`）⇒ **当场告警并给改法**。验收：造两张卡各命中一次，告警文案点名字符串与角色。

### 3.9 H 补核（先核后改，别先改）

`.sdo/design/method-invariants.yml`：**28** 条不变量、引 **14** 条 REQ。**逐条核「有没有守卫」**（用例 id / 判据 id / 现算语句），产出三张表：**有守卫（点名）**、**无守卫（补或按身份登记豁免 + 理由）**、**无法判定（说明为什么）**。**不要**在这一格顺手改实现。
**验收**：28 条逐条有归属；"无守卫"的每条补上或登记豁免；报告里给算式（`28 = 有守卫 + 无守卫 + 无法判定`）。

## 4. 红线（沿用 + 本批）

沿用：① 不许 `git checkout/restore/stash` 覆盖工作区（取基线用 `git show` + 手工补丁）；② 只读会话**不许走 `npm test`**（会重建 `lib/`）；③ 不许改 `docs/plan/` 的历史任务书（冻结件）；④ 变异只在自造副本树。
**本批新增**：⑤ **不许为了过判据而改判据的界**（`DEF-108` 的反面：把"逐份判"改成"看总数"就是作弊）；⑥ **不许把项目侧内容写进随包面**（`DEF-102`）；⑦ **不许用"角色不明"的旁路落账**（`DEF-099`）。

## 5. 验收口径（每组都按这个交）

1. 每条缺陷：**钉红读数（修前）+ 守它的用例 + 变异逐用例红（四件套）+ 复原字节自证 + 写入文件清单（路径 + mtime + sha256）+ 写范围外零改动**。
2. **`REQ-060` 自查格（本批新增，必填）**：本条改动是否依赖 ① 某种文件格式的**内部结构**？② 某个具体项目的**固定布局**？若是 ⇒ 说明**如何改成项目声明 / 通用比较**；若不是 ⇒ 说明依据是什么。**报告与回执都要点名**（`AC-241`）。
3. 判据类改动：**逐份/逐条判**，不许面级分母；必须有一格"空/垫/表/占位/自解析"的注入即红用例。
4. 交付绑定：本批提交信息或声明的清单落点里，**必须能查到本批关键产物的 sha256**。
