## 1. 三个方法包：最小必产项（卡门禁）+ 建议项（不卡）

### 1.1 结构化方法（`structured`）

| | 内容 |
|---|---|
| **最小必产项** | ① **数据字典**：每个数据项有名称/类型/来源/去向/校验规则<br>② **分层数据流图（DFD）**：至少两层，每个加工有输入/输出，且**无凭空出现的流**（父层流必须分解到子层）<br>③ **ERD**：实体 + 关系 + 基数（1:1/1:N/M:N），每个实体有主标识 |
| 建议项 | 功能分解图、状态迁移表、加工小说明（结构化英语） |
| 机械检查 | 数据字典覆盖 DFD 上出现的**每一个**数据流名 ✓；DFD 每层通过"父子平衡"检查（父层输入输出集合 == 子层边界集合）✓；ERD 关系两端基数非空 ✓ |

### 1.2 面向对象方法（`oo`）

| | 内容 |
|---|---|
| **最小必产项** | ① **类/接口清单**：每个类型有**职责**与**协作方**（不许只有名字）<br>② **关键用例的时序**：至少覆盖所有 must 需求的用例，每条消息有发送者/接收者/触发条件<br>③ **分层/包依赖规则**：声明允许的依赖方向，且**违规即失败**（如 domain 不得依赖 infra） |
| 建议项 | 状态机（有状态实体）、设计模式应用说明、接口契约的可见性/异常口径 |
| 机械检查 | 类清单里的"协作方"必须能解析到已登记的类/接口（无幽灵引用）✓；时序里的参与者必须是已登记类型 ✓；依赖规则做**方向性**检查（含既有追溯图）✓ |

### 1.3 敏捷-演进式方法（`evolutionary`）

| | 内容 |
|---|---|
| **最小必产项** | ① **技术债台账**：每条有类型（设计/代码/测试/文档）、影响面、**偿还触发器**与计划<br>② **架构决策的可逆性分级**：每个关键决策标注"可逆 / 有成本 / 不可逆"，不可逆决策必须写明**为何现在必须定**<br>③ **每个迭代的设计增量**：本迭代新增/变更的设计元素清单（无迭代的项目按阶段替代） |
| 建议项 | YAGNI 取舍记录、重构计划、演进路线图 |
| 机械检查 | 债务条目字段齐备且"偿还触发器"非空 ✓；不可逆决策缺理由即失败 ✓；设计增量引用的元素必须真实存在 ✓ |

## 2. 选择与组合机制

1. **复用**已有的 `design:method` 问题（**不另造**）：把它的选项扩展为**可多选**（组合 = 取所选包最小必产项的**并集**）。
2. 选项固定为：`structured` / `oo` / `evolutionary` / `none`，并保留"模型基于需求给出推荐 + 理由"（现状已支持，扩展到多选）。
3. **堵漏洞（重要）**：`none` 只在用户**显式选择**"本项目不做设计方法产物"时合法；此时 G3 判据 `design.method-products` 判 **N/A + 理由**。
   **但**：若问题未回答 / 回答为空 / 答案无法解析成上述任一取值 → **判失败**（不允许"不选就没要求"蒙过去 ✗）。
4. **未选中的方法包**：其判据一律 **N/A + 理由**（"本项目选择了 structured + oo，未选 evolutionary"），既不失败也不通过 —— 与本插件既有的三态口径一致。

## 3. 数据落盘（先把现有形态读明白再决定，别发明）

- 选择结果与选中的包：落在**设计问题账本**里（`design:method` 那条问题的答案），另存一份可查的「本项目启用方法」快照供门禁现算。
- 方法产物：**照 `architecture.ts` 现有元素/视图的存储方式**存（同目录风格、同 YAML 形状、同 journal 事件约定），新增事件如 `design/method-selected`、`design/artifact-updated`。
- 追溯：每个产物条目必须能引用需求（`requires: [REQ-xxx]`），无来源的条目由既有 `trace.orphans` 抓（不新造判据）。

## 4. G3 判据（新增，流程数据里延续 C-2x 编号）

| 检查器键 | 触发条件 |
|---|---|
| `design.method-selected` | 选择问题未回答 / 答案非法 → 失败；已选（含显式 `none`）→ 通过 |
| `design.method-products` | 对**每个选中的包**，逐条检查其最小必产项是否齐备 → 缺任一即失败；显式 `none` → N/A + 理由；未选中的包 → N/A + 理由 |
| `design.method-consistency` | 选中的包产物之间不自相矛盾（例：类清单引用不存在的数据项；DFD 流名不在数据字典）→ 违反即失败 |

**门禁回执**必须逐包显示：已选 / 未选（N/A + 原因）/ 缺哪些必产项。
