## 3. 要修什么（8 项）

### 3.1 `DEF-089`（**major**，**open**，**最高优先**）—— 同族第二出口未同步 glob ⇒ `done` 对账反向误判

**现象（V18 实测，第八批复验）**：`src/domain/scopePaths.ts` 里 **`scopePathsIntersect`**（派发前的脏范围判定）拿到了 glob 支持，而**同文件的 `scopePathWithin`**（注释自称"与 `scopePathsIntersect` 同一套语义"）**没有** ⇒ 含 glob 写范围的卡改**域内**文件时，被 **`done` 对账**（`src/domain/orchestrator.ts:234` 的 `auditWriteScopes`）判成**越界**：写范围 `src/integration/**` 的卡改 `src/integration/a.ts` ⇒ `ok=false, violations=["src/integration/a.ts"]`（**反向假阳性**）；无 glob 对照 ⇒ `ok=true`。同一输入两出口**答案相反**（`scopePathWithin(...)=false` vs `scopePathsIntersect(...)=true`）。**真台账里 `TASK-006.yml` 的写范围就是 `src/integration/**`** ⇒ **现盘就有卡会踩**。
**修法**：把 glob 语义**下沉成两个出口共用的原语**（例如"把 scope 展开成匹配器，两出口都调它"），`scopePathWithin` 改为走该原语；**不许**在任一出口里另写一份匹配。
**DoD**：① 含 glob 写范围的卡改**域内**文件 ⇒ `auditWriteScopes` **通过**（`ok=true`）；② 改**域外**文件 ⇒ **判越界并点名**；③ 无 glob 的既有读数**逐字节不变**（回归）；④ **对偶守卫**：同一组输入喂两个出口，断言**答案一致**（含 glob / 无 glob 各一格），且**只改其中一个出口的变异必须让它红**（这样"只改一个出口"这类补丁以后进不来）；⑤ 用 `TASK-006` 形态在**合成工作区**里跑一次真实 `done` 对账，把回执贴进报告。
**验收**：**行为**（域内通过 / 域外点名 / 对偶一致 三态）+ **结构**（共用原语、无第二份匹配）+ 反例。

### 3.2 `DEF-085`（minor，**open**）—— `codeOnly()` 不剥**行尾注释**

**现象（V20 + 收口会话两路实测）**：`test/m161` 的 `M161-05` 第 3 条站点断言过 `codeOnly()` 后，仍可能被**同一行的行尾注释**喂饱：形如 `'statement', 'decision', // 'coverage', '分支'` 时 ⇒ 守卫**绿**（收口会话 E3 复现，且**全量 `m161` 5/5 绿**，不是筛选造成的假绿）。**现盘风险行 = 0**（四处表达式命中行全为纯代码行），故是**潜在缝隙**、非活体假绿。
**修法**：`codeOnly()` 除剥**整行**注释外，还要剥**行尾注释**（按该文件的语言形态处理，别误伤字符串里的 `//`）。
**DoD**：① 把表达式同形文本写进**行尾注释** ⇒ 守卫**红并点名**；② **只动行尾注释**而代码不变 ⇒ **不该绿**；③ 四处站点仍各自单点红（回归）；④ 别把字符串里的 `//`（例如 URL、路径）当注释剥掉 —— 给一格反例。
**验收**：**行为**（行尾注释喂不饱 / 字符串里的 `//` 不误剥 / 四处单点红）+ 全量绿。

### 3.3 `DEF-090`（minor，**open**）—— 宽窄分级的**理由**与真实分档键不符、比例性相反

**现象（V18 实测）**：第八批写的 §8.3 分级表**逐字符与实现相符**（7 行 0 不符），**但表里的"理由"不是实现的真实分档键**：真实键是**字面前缀段数**（`globLiteralDepth < 2 ⇒ 只提示`）⇒ 同一脏文件由宽到窄扫描：`**` / `*` / `src/**` / `src/*` ⇒ **只提示（照派）**；`src/domain/**` / `src/domain/*.ts` ⇒ **停派**。真注册面同形：**`TASK-006`（`src/integration/**`）被停派**，而**更宽的 `TASK-007`（`src/**`）只提示、照派** ⇒ ① 表行 2 的理由（"点了子树 ⇒ 信息量与单一路径相当"）对**整目录 glob** 不成立；② 表行 4 自称要避免的"宽范围噪声"**恰在最宽那档没防住**，而**收窄后的整目录反而会因一个脏文件停派** ⇒ **比例性是反的**。
**修法（二选一，报告里说明选了哪个与理由）**：① **改理由**：表的说明与代码注释都改成真实分档键（字面前缀段数），并**明说这是保守近似**、把"宽档不拦"的**代价**写清；② **改策略**：按**匹配精度/匹配集大小**分档（例如整目录 glob 与单路径等价处理、`**` 出现在前缀位置才降级为提示）。
**DoD**：① 表里的**每条理由都点名实现真正使用的键**（不许出现"读起来自洽、行为却相反"）；② **一格表驱动的守卫**钉住"同一脏文件在各档下的期望行为"（以后改策略 ⇒ 表与守卫一起改，机械对得上）；③ 若选 ②，给出改前/改后的档位对照与新档位下的反例；④ 真台账 `TASK-006`/`TASK-007` 两形态的读数写进报告。
**验收**：**结构**（理由与键同源）+ **行为**（表驱动守卫各档可红）+ 真台账两形态读数。

### 3.4 `DEF-091`（minor，**open**）—— 候选口径可被"引用行自身"喂饱

**现象（V19 实测 + 驾驶舱独立复算）**：`test/docRefs.ts` 判"`` `file.ts` `` 里的 `` `symbol` `` 是否在该文件里真有"时，把**候选**取成"**引用行里出现的所有反引号词**"（`candidates.push(...)` 那个循环）⇒ 引用行里**多写一个确实存在的词**，行里那个**真悬空**的符号就被放过：**S2（悬空 + 多一个真词）⇒ 绿（漏判）**；**S3（同样是悬空，只差"没有多余真词"）⇒ 红**。**注**：`docRefs.ts` 的注释**自己承认**了这个取舍（"抽取器不猜哪个才是符号"）—— 问题在于**这个取舍的代价（真阴性）没被评估过**。
**修法**：候选取"**结构上被指为符号的那一个**"（例如 `` `file.ts` `` 之后紧跟的那个 `` `sym` ``、或 `sdo:ref` 标记内的标识符），而不是"行里所有反引号词"。
**DoD**：① **S2/S3 那一对必须同判**（都红）；② 真机现场那种"注释里连着举好几个"的行 ⇒ 不许因此放过真悬空（给一格）；③ 既有 `M189-01`–`03` 的中英文四格**仍全对**（回归）；④ 反例：行里多写**不存在**的词 ⇒ 判定不变。
**验收**：**行为**（S2/S3 同判 / 连举多词 / 四格回归）+ 全量绿。

### 3.5 `DEF-092`（minor，**open**）—— 棘轮余量 0 = 永久豁免

**现象（V19 实测）**：`test/m189` 的 `M189-05` 用 `KNOWN_STALE = 2` 允许 2 条符号 issue（只许减少），而**现盘恰好 2 条**，且两条**都是抽取器自己的假阳性**（`records.ts:199` 把反引号里的**第二个**文件名当符号；`reviewDoc.ts:469` 把命令名 `tsc` 当符号）⇒ **余量 0**：任何**新的真**悬空与这两条在**计数上不可区分**，棘轮会替它兜住 ⇒ 它**不是"临时容忍"，而是"永久豁免"**（假阳性不会自然减少，只会随代码变动换位置）。
**修法（二选一，报告里说明）**：① 棘轮条目**带可核身份**（文件 + 行号 + 被误判的 token），并断言"计数不变**且身份集合不变**"（换位置即红）；② **先修抽取器**让那两条假阳性为 0，再把下界回到 **0**（更彻底，推荐）。
**DoD**：① 若走 ①：把某条假阳性**挪到别的行** ⇒ 守卫**红**；② 若走 ②：两条不再出现（并给一格证明它们**真的**不再是 issue）；③ **新造一条真悬空**（合成夹具）⇒ **必须红**（证明棘轮不再能兜住真问题）；④ 既有 5 格回归。
**验收**：**行为**（换位置/真悬空各自可红）+ 全量绿。

### 3.7 `DEF-087`（minor，**open**）—— `reportFaces` 只判顶层面 ⇒ 面内过度物化是盲区

**现象（V20 实测 + 驾驶舱三方核实）**：同步面**确实**从 `package.json#files` 推导（5 组输入 ⇒ 5 种输出、无硬编码清单 ✓），夹具三态也成立 ✓；**但**判据只比**顶层面** ⇒ `docs/` 之所以被抓到，**只因它恰好是一个顶层面**；同类**面内**过度物化 —— 实例 `src/` 里 **71 个未被 `files` 声明的文件**（工作树 `src` 96 vs 实例 81：24 内容不同 + 15 实例没有）—— **在当前判据下是盲区**。
**修法**：判据从"顶层面"**下沉到"按 `files` 声明的路径逐层比"**（`lib/src`⇒`lib`、`src/data`⇒`src` 之后，还要在**该面内部**逐文件对账）；并把"**实例应按包面物化**"写成可核结论（物化脚本/安装路径按 `files`，而不是整块拷仓库 —— `docs/` 42 文件与 `src/**/*.ts` 39 个都是整块拷贝的产物）。
**DoD**：① **夹具**：顶层面齐备但**面内**多一个文件 ⇒ **必须报出**（这是盲区的可观察形式）；② 面内**少**文件也要报；③ 现有三态夹具（齐备/少一面/多一面）回归；④ 真实例的**只读**观测给出"面内差集"清单（预期含 `src/` 那 39 个），写进报告；⑤ 不引入环境依赖（路径参数化）。
**验收**：**结构**（逐层对账）+ **行为**（面内多/少各一格 + 三态回归）。

### 3.8 `R20`（纪律项，minor）—— 把**五条复验方法论**写进随包角色卡与 README

**背景**：第八批 `D1` 把三条纪律写进了四份文件（`skills/role-developer.md`、`role-tester.md`、`role-reviewer.md`、`docs/README.md`，四份**逐字节相同** ✓，且第八批 `R18` 又补到**七条**）。本批要补**五条**（都是这两轮复验**当场流血流出来的**）：
1. **副本树复制清单（完整版）**：`src` + `test` + `lib` + `skills` + **`docs`** + `scripts` + 仓库根被测试读到的文件（`CHANGELOG.md`/`client.js`/`package.json`/`package-lock.json`）+ **指向仓库 `node_modules` 的软链**。**少一样，树内全量就会假红**（实测：缺 `docs` ⇒ **9 fail**；再缺软链 ⇒ **1 fail**）。
2. **变异要打在"守卫真正读的那一层"**：同一条守据可能**同时**读**编译产物**（`import` 的 helper）与**源码文本**（`readFileSync`）⇒ 只变异 `lib/` 对读源码的那半**天然无效**（**层选错，读数就不完整**）。
3. **变异自证要加"脚本跑完了"的证据**：`patch()` 能自证"字节变了"，**证不了"脚本跑完了"**（上一批有一次 `SyntaxError` 让脚本没跑，那一轮读数全是**遗留变异体**的旧读数）。
4. **并发仓里的纯度采样**：`find | xargs sha256sum` 这类**边读边算**的样本会被并发会话带偏 ⇒ 要**同一时刻连采两次互核**；且 **`newermt` 只证"被碰过"，"没变"必须靠整树 sha + `cmp`**。
5. **`diff -rq` 的中文标签会骗出假 0**：按 `differ$`/`Only in` grep 计数会得 0 而总数 39（自相矛盾）⇒ **数行数，不要 grep 标签**。
**DoD**：① 五条**逐字**追加进四份文件（**保持四份"该节"逐字节相同**）；② 删/改任一条 ⇒ 守卫**红并点名是哪一条**；③ 既有七条**不许被改写**（只许追加）；④ `skills/` 同步实例副本、`diff -rq` 零差异（**`lib/` 与 `.sdo/` 不被 git 跟踪 ⇒ 按第 4 条的口径核**）；⑤ 两包语言包与 `m7` 不受影响。
**验收**：**结构**（四份同哈希 + 单条可红 + 既有七条未改）+ 全量绿。

## 4. 红线（沿用 + 本批强化）

1. **绝不用 `git checkout -- <file>` / `git restore` / `git stash` 回滚**；回滚用**工作区内 `cp` 备份**。
2. **绝不允许改仓库的 `lib/`**（交付产物、被同步进实例副本）；一切变异/试验在**副本树**里做（复制清单见 §7.1）。
3. **变异三件套**：先自证字节变了 + 每次变异前先还原上一处 + **自证脚本跑完了**。
4. **不要走 `npm test`**（它是 `npm run build && …`，**会重建 `lib/`**）；要跑全量直接 `node scripts/run-tests.mjs`。
5. **`lib/` 与 `.sdo/` 都不被 git 跟踪** ⇒ 判"有没有改产物/台账"**必须**用 `find <路径> -newermt <开工时刻>`（`lib/` 另加**整树 sha256**），且**读数限定到目标路径**、**同一时刻连采两次互核**。
6. **写形态一律用工作区根的绝对路径**；**`diff` 计数数行数，不 grep 标签**。
7. 不 `push`、不打标签、不改版本号（仍 `0.1.6`）；**不打离线包**（`ADR-018`）；不动 `.sdo/` 真源与需求基线；别自己改缺陷/卡的状态；别动 `.sdo/tests/`。
8. **长 JSON 参数一律 `JSON.stringify` 成字符串再传**（值里不要写 ASCII 引号 —— 用 `「」`）。
9. `sdo_test action=defect` 的 `discoveryLevel` 必须用词表值：`评审`/`单元`/`集成`/`系统`/`验收`/`生产`。
10. **改了工具参数就三面同改**（schema 声明 / `listDecl` / 调用面归一）；**声明是生效点**。
11. **⚠️ 本批新增（贯穿全批）**：**凡改动判据/守卫的项，交付必须附《豁免面清单》**（判据 / **故意不抓什么** / 为什么 / **每条对应的变异**），并对清单里**每一条各做一个变异**证明"不抓"是有意且已知的。**没有这张表 ⇒ 该项不算交付。**
