### 3.1 `DEF-087`（**功能性**）—— 同族"只看副本"的第三、四处静默

**现象（V24 实测）**：
- **G-1** `test/syncFaces.ts:87` 的 `reconcilePath` 在"**源缺、副本有**"时返回 `{path:"stale", missing:[], extra:[], drifted:[], absent:false}` —— **与"齐备"那一格逐字同形**；把它改成"把副本文件列进 `extra`" ⇒ **0 红（存活变异体）**。真实后果：`files` 里某条声明路径在**仓库源**里被改名/删除（声明面陈旧）而实例副本还留着旧路径时，**报告与"完美齐备"不可区分**。
- **G-2** `undeclaredUnder`（`:108-123`）**只遍历副本**：同一份源（含未声明的 `src/domain/adr.ts`，`files=['src/data']`）—— 副本整棵 `src` 缺 ⇒ `undeclared:[]`；副本有 `src/data` 没 `src/domain` ⇒ `[]`；**副本补上才看得见** ⇒ 源面未声明物化**只有在副本里也物化了**才可见。
- **现盘不触发**（9 条声明在源里全存在、`absent` 行 0、`undeclared` **766** 与第十批 §8.13 同值）⇒ 是**未登记的豁免面**，不是现盘假绿。
**修法（二选一；V24 明确"**别只改表**"——现在这两处连"有意的代价"都没声明）**：① **纳入判据**：源缺时把副本文件列进 `extra`（或单列一栏 `sourceMissing`）；`undeclaredUnder` **加源侧**（源面未声明也要报）；② 或**显式写进《豁免面清单》**并**各配一格变异**（必须写明代价：声明面陈旧会与"齐备"同形）。
**DoD**：① G-1 形态（源缺、副本有）⇒ **报出并点名**（或表里声明 + 变异**红**）；② G-2 形态 ⇒ **源侧未声明可见**（或表里声明 + 变异红）；③ 三态夹具 + 面内四格（多/少/内容不同/未声明）**全回归**；④ **不传 `sourceRoot` 时形状与第八批 JSON 逐字相同**（零破坏，自己比一遍）；⑤ 真实例**只读**观测读数写进报告。

### 3.2 `DEF-096`（守卫覆盖）—— 去掉 `\b` 词边界 ⇒ 0 红

**现象（V24 实测）**：把符号存在性判定的 **`\b` 词边界去掉** ⇒ `M189-09` **0 红** —— 判据确实做**子串包含**（`realSymbolX` 会喂饱 `realSymbol`），而**守卫没喂这种输入**。**判据本身没错**（§3.1 的修法已让自解析形态正确），缺的是**"子串喂饱"这一格的守卫**。
**修法**：补一格守卫 —— 在被指文件里放一个**名字是目标符号超串**的标识符（如目标 `realSymbol`、文件里有 `realSymbolX`）⇒ 断言该引用**仍判悬空**（或按设计**判存在**，但必须**写明**：两者选一，报告说明理由）；若决定"子串即算存在"，则**在该判据的《豁免面清单》里登记**并配变异。
**DoD**：① 该格存在且**单点可红**（去掉 `\b` 或改成子串匹配 ⇒ 守卫红）；② 中英四格（`M189-01`–`03`）与 `M189-06`/`M189-09`/`M189-10` **不回归**；③ 反例：**恰好等于**目标符号的标识符 ⇒ **不许判悬空**。

### 3.5 `P-A`（预防项）—— 交付注释里的标识符必须可解析（推广到**全部**交付注释）

**背景**：`DEF-095` 的修法已在 `test/docRefs.ts` 证明"**注释里的标识符必须可解析**"可做且语言中立（`M189-10`）。本条把它**推广到全部交付注释**，让"注释引用不存在的函数名/字段名"这类缺陷在**源头**被挡住（本季已复发多次：`DEF-077`、`R13`、`R13`②、`DEF-086`、`DEF-090`、`DEF-095`）。
**修法**：一格**结构**守卫 —— 扫描**交付面注释**（`src/` 与 `test/` 的注释文本）里出现的**反引号标识符**，断言每个标识符能在**该文件或仓内**找到定义（复用 `docRefs` 的符号可解析机制，不另造匹配器）。
**DoD**：① 在注释里写一个**不存在的**标识符 ⇒ **红并点名到文件 + 注释**；② **误报控制**：合法但来自外部约定/第三方/语言的标识符（如 `node --test`、`JSON.stringify`、`tsc`）**不许**报红 —— 给一格反例清单并说明判定口径；③ **语言无关**（不许出现任何中文/英文措辞白名单）；④ 现盘**全绿**（若现盘有历史违规 ⇒ **按身份登记**，不许放宽守卫）。

### 3.6 `P-B`（预防项）—— 表格/清单的"为什么"必须能指向一条可跑的读数

**背景**：`DEF-090`/`DEF-098` 那一族的成因是"**表读起来自洽、行为却与理由不同**"。表格里的"为什么"如果没有一条可跑读数支撑，就无法被判据抓住。
**修法**：**在《豁免面清单》的结构守卫上再加一列要求** —— 每行的"为什么"必须包含**一条可跑的读数**（变异读数如 `M187-06`，或一条**现算命令**如 `python3 … | wc -l`），且该读数**可复现**（守卫断言：列非空 + 形如用例 id 或含命令标记）。
**DoD**：① 某行"为什么"只写空话（无读数）⇒ **红并点名该行**；② 某行引用的**用例 id 不存在** ⇒ **红并点名**（沿用 `DEF-094` 的加强）；③ 现盘 9 张表**全部补齐**并通过；④ 反例：**合法读数**（存在的用例 id / 可跑命令）**不许**红。

## 4. 红线（沿用 + 本批）

1. **绝不用 `git checkout -- <file>` / `git restore` / `git stash` 回滚**；回滚用**工作区内 `cp` 备份**，且**备份必须在任何变异之前取**（V24 的 `pristine/` 文档备份在第一次变异**之后**才做 ⇒ **备份自身被污染**）。
2. **绝不允许改仓库的 `lib/`**；一切试验在**副本树**里做（清单见 §7.1）。
3. **变异四件套**：① 先自证**字节变了且真的写盘了**；② 每次变异前先还原**全部面**（含 `docs/`）**并重编译**；③ **自证脚本跑完了**（用**直接** `node --test --test-reporter=tap <file>`）；④ **每格打印该树 `lib` 整树 sha**。
4. **"文件被还原了" ≠ "编译产物被还原了"**：还原源码后**必须重编译**，否则 `lib/` 里留着上一格变异产物 ⇒ 读到**假绿/假红**（V24 实测）。
5. **"没跑"与"跑了没红"必须分开记**：变异参数走 JSON 易被转义吃掉（`Bad escaped character in JSON` ⇒ 3 格根本没跑，V25 实测）。
6. **变异要打在能影响目标断言的那一层/那一处**（V25 有 1 格改在**共用原语**上 ⇒ 0 红、无意义）。
7. **不要走 `npm test`**；要跑全量直接 `node scripts/run-tests.mjs`。
8. **`lib/` 与 `.sdo/` 都不被 git 跟踪** ⇒ 判"有没有改产物/台账"必须用 `find <路径> -newermt <开工时刻>`（`lib/` 另加**整树 sha256**），读数**限定目标路径**、**同一时刻连采两次互核**；**`newermt` 只证"被碰过"**。
9. **写形态一律用工作区根的绝对路径**；**`diff` 计数数行数，不 grep 标签**。
10. 不 `push`、不打标签、不改版本号（仍 `0.1.6`）；**不打离线包**（`ADR-018`）；不动 `.sdo/` 真源与需求基线；别自己改缺陷/卡的状态；别动 `.sdo/tests/`。

12. `sdo_test action=defect` 的 `discoveryLevel` 用词表值：`评审`/`单元`/`集成`/`系统`/`验收`/`生产`。
