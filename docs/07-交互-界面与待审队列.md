# 交互：界面与待审队列

> 交互的目标不是"展示更多"，而是让三个问题各自有**一个页面**就能回答：
> **我在审什么**（一行的命题）、**agent 在做什么**（看板）、**还有哪些待办与计划**（计划页）。
> 形态复用 `dsh-context` 已走通的那套：一级页面 + 会话 tab + 侧栏面板 + 斜杠命令 + 设置卡。

---

## 1. 形态

| 位置 | 内容 | 说明 |
|---|---|---|
| **一级页面**「SDO 控制台」 | 总览 / 待审 / 计划 / 证据 / 缺陷 / 团队 / 审计 / 设置 | 与 Plugins、Automation 同级的侧栏入口 |
| **会话 tab**「SDO」 | 当前会话相关：我在做什么卡、待我决策的项 | 切换会话不丢上下文 |
| **侧栏面板** | 与 tab 同一份数据，窄屏形态 | 阅读时不必离开对话 |
| **斜杠命令** `/sdo` | 弹窗：待审队列前 5 项 + 健康度 | 不开页面也能批一件 |
| **设置卡** | 免密窗口时长、通知、默认视图、语言 | 与 `dsh-context` 的偏好卡同形 |

---

## 2. 八个页面

| 页面 | 回答的问题 | 关键交互 |
|---|---|---|
| **总览** | 现在在哪个阶段、健康度、最该看的三件事 | 点任意数字 → 钻到对应清单 |
| **待审** | **我要决定什么**（项级，一项一行） | 批准 / 驳回 / 要改；可批量但每行独立 |
| **计划** | 待办、计划、依赖链、容量 | 拖动排序只改"建议顺序"，需落动作 |
| **证据** | 每条声明的出处、指纹、有效 frontier | 点开看命令与读数；失效的高亮 |
| **缺陷** | 分布、复发族、未修清单 | 按 family 聚合；点开看"哪条判据该抓没抓" |
| **团队** | 谁在做什么、谁能决策哪个域 | 权限矩阵只读 + 申请入口 |
| **审计** | 签字记录、快照导出、豁免清单 | 导出一份 `export --at <frontier>` |
| **设置** | 免密窗口、通知、默认视图 | 免密窗口**默认关** |

**语言**：界面跟随**宿主 locale**，缺省 `zh_CN`，一期 `zh_CN` / `en_US` 两包；规则（归一化、回退链、键奇偶、硬编码 0）见 [12](12-横切-语言无关与安全脱敏.md)「多语言」，此处只管显示。

> 页面数量刻意压在 8 个：**每加一个页面都要回答"现有页面哪个回答不了"**，否则会重演 v1 的"文档/页面只增不减"。

---

## 3. 待审队列：四项契约（核心）

每一行必须同时具备四项，缺一项**不允许出现**：

| 项 | 内容 | 反例（v1 出现过） |
|---|---|---|
| **命题** | 一句可反驳的话，含代价 | 「TASK-261 全绿，请审」 |
| **证据** | 可点开、可复算（命令 + 读数 + 指纹） | 「详见报告」 |
| **差异** | 相对上一版改了什么（`ledger diff`） | 「已按意见修改」 |
| **后果** | 不批会阻塞什么、会不会顺延 | 缺失 |

**批准 = 一次签发动作**（[08](08-签字-身份与免密.md)）：绑 frontier、绑内容哈希、需要签章口令（或未过期的免密窗口）。

**分歧项（`disputed`）也是同一队列里的行**：标题前缀「待裁定」，展示双方主张 + 各自输入版本；动作是**选左 / 选右 / 撤回 / 延后**，选完必须填一句“被否掉的主张为什么错”。语义见 [09](09-协作-权限-并行与子代理.md)「分歧裁定」。

**委托项（`delegated`）是同一队列里的另一种行**：标题前缀「委托审计」，四项契约不变，但动作是三选一——**确认（转正）/ 推翻（触发级联复位）/ 延期（计一次超时）**。语义见 [09](09-协作-权限-并行与子代理.md)「预授权 grant」。

## 4. 人话命名（解决"REQ-123 是什么"）

| 规则 | 例 |
|---|---|
| 主标题永远是**人话**；编号只在次要位置（灰色小字、悬停、复制按钮） | **「发布范围必须能按版本声明」** · REQ-041 |
| 列表默认显示：标题 · 状态 · 负责人 · 影响面 | 不显示编号列 |
| 任何编号都可点开"对象页"，页内才有完整 id 与追溯图 | — |
| 后端不用改：视图里本来就带 `title`；编号只是 `id` 列 | `sdo_query` 返回 `title` 优先 |

---

## 5. 状态与配色

- **颜色不是唯一编码**：每个状态同时有文字或图标（色盲/打印可读）；
- 语义固定：绿=通过、红=失败、灰=不适用、**黄=未验证**（这一态必须有，不能只有两态）；
- **失效**（frontier 过期）用斜纹 + 文字"已失效"，不是只变灰。

---

## 6. 空态与错误态

| 情形 | 界面行为 |
|---|---|
| 没有待审项 | 「没有需要你决定的事」+ 最近一次决策时间 |
| 视图取不到（`query_miss`） | 显示"这个视图还不在" + 一键"报告缺失"（落 `query_miss`） |
| DB 连不上 | 显式红条 + 最近一次成功读数的时间与 frontier（**不许显示旧数据当新的**） |
| 无权限 | 显示"需要 X 权限" + 申请入口；不静默隐藏整行 |

---

## 7. 降级（重要）

**没有界面时不能签字**——这是设计，不是缺陷：

- 卡进入 `blocked(awaiting_signature)`，出现在 `review_queue` 的 P0；
- 唯一例外：UI 生成的一次性凭据（5 分钟、单次、落"非 UI 签署"事件），**默认关闭**；
- 绝不允许 agent 持长期凭据代签（[08](08-签字-身份与免密.md)）。

---

## 8. 实现约束（承接 `dsh-context` 的经验）

1. **界面零本地计算**：所有数字来自 `sdo_query`，前端只做格式化；前端出现计算逻辑即视为缺陷。
2. **视图驱动**：新增页面 = 新增视图 + 一个渲染器，不改 host 业务代码。
3. **开发回环**：client 插件改动需 `pnpm run dev:web` 才能热更；M0 只做一个最小页面，避免长期等构建。
4. **i18n**：中英双语；视图的 `columns` 里带两套显示名，避免"界面文案与数据对不上"。

---

## 9. 验收读数（M1–M2）

- 打开待审页，**3 秒内**能说出"我要决定什么、代价是什么"（可用真人计时）；
- 任一行点开证据，能在 **2 次点击**内看到命令与读数；
- 故意断开 DB：界面显示红条 + 最后成功时间，**不显示旧数字当新的**；
- 全站搜索 `REQ-` 编号作为主标题的情况：**0 处**。
