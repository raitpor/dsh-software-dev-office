# docs 索引（哪些文档是权威、哪些是历史）

本目录有 **设计 / 计划 / 核实** 三类文档。它们写于不同时间、承担不同角色 —— 用之前先看这张表，
别把历史文档当现行规格。**代码与数据文件永远是第一真源**。

## 0.1 写作规约：文档里不许写"绑机器"的东西（两条机械守卫）

| 不许 | 换成 | 守卫 |
|---|---|---|
`/home/<某人>/…`、`/Users/<某人>/…`、`C:\…`、`--home-<某人>-` | `<仓库根>` / `<测试工作区>` / `<临时目录>` | `M89-01`（**判红**） |
会话 uuid 片段、本机回环地址加端口、`$HOME` 下写死实例版本的路径（即"实例目录 + 具体版本号"） | `<会话id>` / `<GUI 地址>` / `<实例目录>` | `M89-04`（**棘轮：只许减不许增**） |

`M89-01` 刻意**不**禁 `~/.local/...` 与 `/tmp/`（对任何机器都可照抄，不绑机器）；`M89-04` 也不判红，
因为它们是"一次运行的标识"而不是"一台机器的绑定"——历史文档不改，新增处必须在登记值里写清理由。

## 0. 权威顺序（冲突时按这个来）

```
① 代码与数据          src/**、src/data/**（动作词表 / roles.yml / processes/*.yml / lang/*.yml）
② README.md           面向使用者的现行说明（工具、动作、配置键、边界）
③ CHANGELOG.md        逐条变更与"为什么这么改"
④ docs/plan/**        增量设计（每条新能力落地时的设计说明，含取舍）
⑤ docs/design/**      历史设计初稿与调研（方向与原则仍有效，**表格式清单已过期**，见下）
⑥ docs/verification/** 核实记录：缺陷、事故、上游问题、设计与实现的偏移
```

- **触发点二：G7 门禁签字前** —— 签字冻结的是"这份清单"，清单不存在就没东西可签。
- **反例（不许发生）**：只读补核卡（`tester` / `reviewer`）**不许** `package`（`sdo_deliver` 不在它们的
  工具面里，见 `DEF-113`）；真机 `DLV-001` 就是只读卡误调造成的。

## 回归类出口的 `known` 口径（第十三批 §3.3 `DEF-115`，**项目侧**）

- **默认传 `known`**（用例登记表里的 id 清单）：不传等于默认放弃"这条边指向的用例是否真实存在"的校验
  （真机事故：`req-tc` 指向未登记的 `TC-076-GREEN-SUB`，出口不传 `known` ⇒ 幽灵用例被静默算进覆盖）。
- 确有"用例还没登记"的正当场景 ⇒ 传 `known` 并在 `narrow` 里说明，**不要**靠不传 `known` 绕过。
- 结果投影里，**指向不存在用例的结果**必须标注（不静默计入覆盖率）。

## 读散文棘轮怎么维护（第十三批 §4.3，**项目侧**）

- `test/m189.test.ts` 的 `KNOWN_PROSE_GAP`（逐文件的"读散文站点"条数）**不再手工数**：
  加了一条带中文报文（读自由文本）的断言后，跑 `node scripts/refresh-prose-gap.mjs --check` ⇒ 它会打印
  `新增 / 变化 / 删除` 明细并以 exit 1 收尾；`--write` 重生成登记表。
- **口径不变**：棘轮仍是"登记与现算**恰好相等**"（`M189-13` 的 `deepEqual`），脚本只把"手工数数"换成
  "现算 + 打印差集"，不放松任何判定。想**减少**条数 ⇒ 把断言改成带 `label`（或成对自证），别改数字蒙混。

## 变异自证的操作规范（第十三批 §4.4，**项目侧**）

- **变异副本树不许放 `node_modules/` 下**：`node_modules` 里的软链会把 `lib/**/*.d.ts` 泄进"见证面"，
  把已经登记过的悬空符号喂饱（实测：副本树放 `node_modules/.sdo-test/` 时 `m191` 的见证面多出 3 个名字、
  树内基线红 1 条；改放 `tmp/` 后全绿）。
- 推荐路径：`tmp/<批次>-<项>/`（仓库根下、被 `.gitignore` 忽略）；副本树里**不要**放 `lib/`、`node_modules/`。
- 变异脚本自证四件套不变：① 字节变了**且真的写盘**；② 先编译再跑；③ **逐用例**取读数（tap 的 `not ok`）；
  ④ 复原后重建再跑一次基线。

## 变异与交付产物的纪律（`D1-P`，**项目侧**）

> **分工（`DEF-102` 起）**：与项目无关的**原则**在随包卡 `skills/role-{developer,tester,reviewer}.md` 的 `D1` 节（三份逐字节相同）；**本仓**的具体清单、命令、路径**只在本节** —— 不许写进随包面（随包卡会被任何项目读到）。

1. **副本树复制清单（15 项）**：`src` + `test` + `lib` + `skills` + `docs` + `scripts` + `README.md` + `presets/` + `tsconfig.json` + `client.d.ts` + `CHANGELOG.md` + `client.js` + `package.json` + `package-lock.json` + **指向仓库 `node_modules` 的软链**。少一样，树内全量就会**假红**（逐版实测：缺 `docs` ⇒ **9 fail**；再缺软链 ⇒ **1 fail**；第 3 版还缺 `README.md`（7 处）/ `presets/`（10 处）/ `tsconfig.json`（1 处）/ `client.d.ts`（1 处）⇒ **1371 / 1351 / 20 fail**）。**并在变异前先跑一次树内全量、断言 `pass`/`fail`/`skip` 三个数与仓库读数一致**（树不完整在**第一步**暴露）。这一份是**唯一来源**：任何地方提到副本树清单都只许**引用**它。
2. **全量测试**：`node scripts/run-tests.mjs`（**不许** `npm test` —— 它会 `npm run build`，**重建** `lib/`）。
3. **构建**：`npm run build`（`tsc`），产物在 `lib/`。`lib/` 与 `.sdo/` 都**不被 git 跟踪**（`git ls-files lib` = 0、`git ls-files .sdo/` = 0）⇒ 判"有没有改交付产物 / 台账"要用 `find <路径> -newermt <开工时刻>` + **整树 `sha256sum`** + `cmp`。
4. **自证「脚本跑完了」**：`--test-reporter=tap` 只在**直接** `node --test --test-reporter=tap <file>` 下有效；经 `scripts/run-tests.mjs` **传不进去**（该脚本第 **37** 行自拼 `spawnSync`）。
5. **写范围闸门只看命令文本**：它拦 `rm -rf` 这类**写形态**，而 `node scripts/run-tests.mjs` 会写 `node_modules/.sdo-test/` 却**不被拦** ⇒ **别把"没被拦"当成"写了也没关系"**（拦截是启发式，纪律是自律）。
6. **`diff -rq` 的中文标签会骗出假 0**：按 `differ$` / `Only in` grep 计数会得 0 而总数 39（自相矛盾）⇒ **数行数，不要 grep 标签**（原则见随包卡第 12 条）。
7. **`docs/plan/` 下的历史任务书是冻结件**：**不许**改历史任务书（当批报告只在**当前批**的任务书里追加一节）；副本树清单以本节为准。
8. **基数类断言的现算命令（例子）**：`awk '/^  writeScopes:/{f=1;next} /^  [a-zA-Z]/{f=0} f&&/^    - /{print FILENAME": "$0}' .sdo/tasks/*.yml`（有 `writeScopes` 的条目数）；含 glob 的再挂 `| grep -E '[*?[]'`。写进报告的每个基数都要附这种可跑算式。
