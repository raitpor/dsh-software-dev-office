# 项目经理环路：PM 是谁、每一步读什么、写什么

> **框架坐标**（对齐 [01 理论与边界](01-理论与边界.md)）
>
> - 守的层：**L2 · L3**（只讲"谁在用这些机制"，不新增机制）
> - 涉及真源：三者（PM 不产生新的真源，只推进它）
> - 对应命题：命题 1–5
> - 本文引入/定义的概念：PM 的授权、PM 环路、最小读集、PM 完成读数

> 前 14 篇回答"机制怎么运作"。这一篇回答另一半：**谁在用它推进项目**。
> 一个重要使用者是 **agent**：它当项目经理（PM），人类只决定"产品对不对"。所以本文不写"人怎么点按钮"，只写 **PM 每一步读哪几个视图、判什么、写哪几个动作**。

## 1. PM 不是角色，是一组权限

沿用 [07](07-协作-权限-并行与子代理.md)「权绑 scope、不绑身份」：**没有"PM 角色"这个字段**，只有三样授权，谁持有谁是 PM：

| 授权 | 允许做什么 | 落到哪 |
|---|---|---|
| `plan@domain:<name>` | 声明目标节点、拆解、建卡（`goal.declared` / `task.created`） | 需求域 |
| `assign@<scope>` | 派发与再平衡（`dispatch`/`lease`；第 3 项语义待定，见文末） | 代码域 / lane |
| `escalate@<scope>` | 把机器判不了的升级给人（`attention.raised`） | 该 scope |

**"谁是 PM"是查出来的，不是存出来的**：`team` 视图按 `grant` 现算。一个项目可以有几个 PM（各管一个 domain/lane），同一 scope **建议只留一个**——并行规划会互相踩 `goal_node` 与卡序。换人 = 转移 grant，落一条事件，不另设"PM 交接"这种东西。

> 为什么不做成角色：v1 用全局角色（developer / reviewer / office）判断，结果"角色对但域不对"照样能操作（[07](07-协作-权限-并行与子代理.md) §1 的教训）。PM 也一样——它应该只在自己那个 domain 里说话。

## 2. 环路：五步，每步只读固定几个视图

**PM 的价值不在"看得多"，在"下一步做对"**。所以每一步都限定最小读集；读超了就是视图缺投影，应该补视图而不是让 PM 多读。

| 步 | 读（≤2） | 判什么 | 写什么（`sdo_act`） | 完成读数（机器判） |
|---|---|---|---|---|
| **① 对齐** | `review_queue`、`alignment` | 复述是否绑当前 intent 与关键条款 hash；每条 requirement 是否有 2 正 1 反；差异是否逐条处置 | `restate`、差处置、或开 `attention`（人才能拍的） | `intent.restated_consistent`、`alignment.examples_present` |
| **② 规划** | `plan`（按分解树折叠） | 叶节点是否有验收判据；父节点是否有集成清单；依赖是否有环；卡是否一卡一判据 | `declare`（goal_node）、`create`（task）、`split` | `node.acceptance_bound`、`node.integration_listed`、`stage.requirement_complete` |
| **③ 派发** | `pm_queue`、`agents` | 谁有 scope×right；水位够不够；哪张卡该复用哪个 agent | `assign`（预占）/ `revoke`（收回）/ `dispatch`（发 lease） | `assign` 与 `lease` 对账（§6） |
| **④ 监控** | `pm_queue`（≤7 行） | **只处理 reason_code 命中的行**；不读全量 board 再自己排 | `unblock`、`attention`、`rework` 请求 | `pm_queue` 里 `blocked`/`gate_red` 清零 |
| **⑤ 收口** | `pm_queue`、`evidence` | gate 是否全绿且 verdict 非手填；证据是否带指纹；release 前置（§6/§7）是否齐 | `request_sign`、`deliver` | `task.complete`、`stage.gate_bound`、`release.*` 判据 |

**第 ④ 步是全篇的重点**：PM 每天做的事不是"通读看板"，而是"按排序处理前 7 条"。为此 `pm_queue` 把排序写死在视图里（[05](05-观测与交互.md) §10.1），不让每个 PM 自己发明优先级。

## 3. 最小读集表（为什么是这几个）

| 决策 | 只读 | 理由 |
|---|---|---|
| 现在有没有卡在人身上 | `pm_queue` | 排队一行带 `reason_code`，比读 5 个视图快 |
| 这张卡能不能开工 | `plan` + `pm_queue` | 依赖与阻塞都在 `plan` 的 `blocked_by[]` |
| 这个人/agent 能不能接 | `agents` + `team` | scope×right 在 `team`，水位在 `agents` |
| 这件事能不能算完 | `evidence` + `baseline` | 判据读数与尺子版本，两者缺一不可比 |

**不做的事**：不读 `board` 全量再自己排序（那是 `pm_queue` 的活）；不读 `evidence` 逐条核（那是 `verify` 与判据的活）；不读聊天记录（[05](05-观测与交互.md) §9：为什么是这样 → 决策/变更链）。

## 4. PM 与实现者的交互：只有账本，没有侧信道

PM 对实现者的**全部**作用面就是四个对象，**没有别的通道**（不直接给子代理发消息、不改别人的工作副本）：

| 对象 | PM 用它做什么 | 实现者看到什么 |
|---|---|---|
| `task` | 建卡、写 `inputs[]`、设 `scope_paths[]`、标 `kind` | 待认领的卡 |
| `lease` | 授权谁在什么窗口里写哪个 scope；**收回** = `revoke`（在飞卡先 `blocked(lease_revoked)`） | 自己持有的租约（过期/被收回即失效） |
| `task.assigned` | **预占**：把可领集合收窄到某个 actor（**不授予写权**） | 只有被预占的 actor 能认领 |
| `attention` | 升级给人（不是催办工具） | 卡被 `blocked` 的原因之一 |
| `review_round` / `dispute` | 发起评审、裁定分歧 | 待我回复的评审/裁定 |

**PM 明确不做**：不替人签（签名只由人）；不 spawn/kill 子代理（宿主的事，插件只记 `dispatch`/`lease`）；不手改别人的工作副本；不 `verify` 自证（那是独立对账）。

> **催办怎么做**：不发明"催办"动作。PM 能做的是**改派**（撤销 lease 再发）或**升级**（开 `attention` 说"这件事需要你决定"）。用 `attention` 当进度条是失败模式（见 §5）。

## 5. PM 的失败模式（每条都有读数）

| 失败模式 | 长什么样 | 读数（谁会发现） |
|---|---|---|
| **只看 ready** | 只派 `unclaimed` 的卡，`gate_red`/`blocked` 堆着 | `pm_queue` 里高优先行停留时长（`since`） |
| **盲批** | 一次批 10 条 `attention`，只看标题 | 签字时长中位数（≤10s 目标被绕过）、`review_queue` 批量操作计数 |
| **用 attention 当进度条** | "你做完了吗" 也开 attention | `attention` 里 `kind ≠ decision` 的比例 |
| **派给了没有权限的 agent** | 卡到 `admission` 才被 `clause_unjudged`/`no_lease` 拒 | `admission.rejected` 的 `reason_code` 分布 |
| **只发卡不对账** | 发了 5 张，实际 3 个在跑，2 张躺在 `ready` | `pm_queue` 的 `unclaimed` 行 + `verify`：预占期内的认领者必须是 `reserved_by` |
| **把规划当私事** | 拆解只在自己上下文里，`goal_node` 没落 | `plan` 视图树为空、`stage.requirement_complete` 红 |

## 6. PM 怎么知道"这轮做完了"

不是"卡都 done"（卡可以一直开着），而是：

1. `pm_queue` **为空**，或只剩 `waiting_human`（机器侧已无可推进）；
2. `gaps` 里没有新增未决项（有就说明有东西被静默降级）；
3. `evidence` 的指纹与 `baseline` 的版本对得上（不是拿旧尺子的读数交付）。

这三条成立，PM 才算把这一轮"管完"——**这是 PM 的完成读数，不是产品的完成读数**。产品是否做对，仍由人类用 [09](09-交付与迁移.md) 的交付判据与 scenario 抽样决定。
