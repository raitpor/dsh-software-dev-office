## 六、本轮学到并已生效的操作口径（血的教训，逐条都可复算）

1. **永远不要从回执或界面报数字** ✗ —— 回执会被截断（本轮 `next` 回执 35k–38k 字符，只显示 8k ✗）。要点数就去 `journal.jsonl` 数 `task/claimed` / `dispatch/started`。
2. **`.sdo/` 是公共写面** ⇒ 纯台账活（补录、写报告、写缺陷）**无需认领**即可做；**改产品代码必须持有活认领**（`src/`、`test/` 会被写范围闸门拦）。
3. **长 JSON 文本参数通道不稳** ✗（`decompose` 的 `suggestions`、`review` 的 `findings`）：同晚同样大小的 payload 有时成功有时被拒 ⇒ 处置=**压短 / 换形状 / 单条重发**，不要原样重试；**标量参数动作（`task` 的 update/drop/release、`next` 的 limit）稳定可用** ⇒ 优先用它们。
4. **立卡只有 `decompose` 一条路**（`sdo_task` 无 create）；`done` 卡**不可改**（历史不重写）⇒ 返工要么新立卡，要么在 `planned/ready/in-progress` 时 `sdo_task action=update`（可改 title/dod，改后需重新认领）。
5. **孤儿写锁**：卡 `in-progress`、其 owner 会话已 `dispatch/finished(completed)` ⇒ 锁仍在 ✗ ⇒ 由流程官显式 `release`。
6. **子会话的"全绿"自述一律自己复跑**：每张卡收工时跑 `npx tsc -p tsconfig.json` + `node scripts/run-tests.mjs`（基线会随卡增长；**截至 02:37Z = 1059/1059**），再采信。
7. **转述 ≠ 核实**：凡行号 / 文件名 / 哈希 / 计数 / 全称否定要写进台账，一律**现读或现算**（本轮因此更正了 DEF-043、DEF-049、DEF-051 三处由转述而来的错）。
8. **`plan.noCardElements` 已首次填充**（12 个 DES id + 依据 + 维护纪律）：**下次 `decompose` 的 `planned` 不该再长 12 张** —— 那是它生效的机械证据，请顺手验一次。

9. **`block` 的理由要写 `note`，不是 `reason`** ✗（DEF-068）：写 `reason` 会被静默丢弃、卡上反记「（未说明）」—— 台账里的一条**假陈述**。只有 `drop`/`unblock`/`reassign` 读 `reason`。
10. **"被拒了几次"在真源里查不到** ✗（DEF-059 更正）：认领被拒**不落任何事件**（全库 `task/claim-blocked` 只有 4 条，全部来自显式 block 调用）⇒ 想知道争用多严重，只能读子会话报告或**被拒者主动 block** 的理由，别指望数事件。
11. **owner 字段不等于活会话** ✗（DEF-053 第二例）：`subagent:developer:3` 这类槽位名会换会话（DEF-066），判占用的唯一依据是**该会话在 journal 里的最新派发终态**（`completed`/`error` 都算终态）—— 本轮 TASK-104 的锁就是这样被识别并释放的。
12. **新建 `docs/*.md` 必须同时进 `docs/README.md` 索引** ✗：守卫 `test/m89` 的 **M89-02** 要求索引收录 `docs/` 下每一篇且无死链 —— 本轮驾驶舱写交接单时漏了索引，全量当场红一条（TASK-103 的实现会话做了对照实验定位到是我的文件，不是它的改动）。**这是驾驶舱自己的错，已修**（索引首行已加）。
13. **卡 done ≠ 全量绿** ✗：`done` 的证据校验只看**你引用的那条命令**的退出码（本轮 TASK-103 引的是 `tsc --noEmit` 0 错，而同时刻全量是 1047/1048 红一条）⇒ 采信交付时**自己再跑一遍全量**，别把"卡 done 了"当成"树是绿的"。
14. **派发没有"指定卡"的入口** ✗：`sdo_plan next` 只能按 `readyTasks()` 的顺序取 —— **规模秩（trivial<small<medium<large）→ id 升序**（`src/domain/plan.ts:774-790`），同档时**小 id 先走**（所以 TASK-024 永远排在 TASK-107 前面）。想按人的裁决顺序派，**唯一诚实的杠杆是 `blockedBy`**：要么把竞争者排到目标之后（`blockedBy: [TASK-xxx]`），要么给"需要冻结树"的后段卡加 `blockedBy: ["*"]`（机制原意就是"排在所有其它卡之后"）。**不要**靠改 `size` 调序（那是改事实）。
