# 数字必须带口径（`TASK-263`，2026-10-25）

> **一句话纪律：数字离了口径就不是读数，只是字符。**
> 写下一个数之前先写清**它是怎么数出来的**；读到一个数时先问**它的口径是什么**。没有口径的数，
> 既不能当证据用，也不能拿来反驳别人。

本文是**项目侧**说明（写法与命令只对本仓库成立）。判据本体在
[`scripts/check-number-provenance.mjs`](../scripts/check-number-provenance.mjs)，守卫格是
[`test/m250.test.ts`](../test/m250.test.ts)。

## 1. 为什么立这条（同一天三次，全部造成误判）

三次都**不是谁数错了**，三次都是**同一句话里的数字没写口径**，于是两个都对的读数看起来互相矛盾：

| # | 现场 | 两个读数 | 真实口径 |
|---|---|---|---|
| ① | 评审记「`任何×没有` **12** 行」，实现 `grep` 得 **1** 行 | 12 / 1 | 12 = **不设上限**档；1 = **`gap≤4`** 档。差的是"窗口"这一面 |
| ② | 卡面「**15** 条无 `reason` 畸形」，现算 **0** 条 | 15 / 0 | 15 很可能把**引用形态** `sameAsSeq`（按设计不带 `reason`）当成畸形数了。差的是"数什么" |
| ③ | `REV-115` 核 `dispatch/aborted`：`grep -c` = **12 行**；按 `event.type` 精确计数 = **0** | 12 / 0 | 12 是**别的**事件**正文**里提到这个词；0 才是该事件的条目数。差的是"按类型还是按正文" |

同一族还有个更早的：`m189` 的 `KNOWN_PROSE_GAP` 某文件 **49 → 61** 那次改错 —— 数的是"读散文**站点**"，
不是"文件数"，也不是"断言数"。

## 2. 口径标记的定义表（写死，机检同源）

口径标记的形态是 **`口径:`**（半角/全角冒号都认；`旧口径：` / `新口径：` / `统一口径：` 这种把词当前缀的
普通散文**不算**标记），后面按**五个面**写清读数：

| 面 | 要写清什么 | 机检认得的写法（举例） |
|---|---|---|
| **正则** | 用什么模式匹配（正则 / 字面串 / 具体命令） | `正则`、`regex`、`pattern`、`grep`、`--include`、`=~` |
| **路径** | 匹配面是哪个目录或文件（"全仓"就等于没说） | `src/`、`test/`、`.sdo/`、`*.ts`、`目录` |
| **窗口** | 全行匹配还是同行匹配、有没有上限 | `全行`、`同行`、`行内`、`窗口`、`不设上限`、`gap≤4` |
| **计数** | 数行还是数次数、数条还是数次数 | `数行`、`行数`、`次数`、`条数`、`wc -l`、`grep -c` |
| **类型轴** | 按 `event.type` 精确计数，还是按正文匹配 | `event.type`、`按类型`、`类型字段`、`正文` |

**缺项可容忍**（写全五面当然最好，守卫不会因为"少写一面"判红）；**一面都没有就不算读数**
——`口径:` 后面跟一句空话（`口径: 很准`）仍然是缺标记，仍然红。这一条就是卡面那句
「缺哪项可容忍，一项都没有就不能算读数」的机械形态。

## 3. 正例与反例

**正例**（正则 + 路径 + 窗口 + 计数四面齐）：

```text
`grep -rn "不存在" src --include=*.ts | wc -l` = 169 行
口径: 正则 `不存在`；文件面 `src/**/*.ts`；全行匹配；数行（`wc -l`）
```

**反例**（无正则、无目录、无窗口 —— 这个 196 换成任何数都"看起来成立"）：

```text
不存在 196 行
```

**第三个例子**（同一段话里两个都对，因为口径不同）：

```text
`grep -c 'dispatch/aborted' .sdo/journal.jsonl` = 12 行
口径: 正则 `dispatch/aborted`；文件 `.sdo/journal.jsonl`；全行匹配；数行（`grep -c`，含正文里提到这个词的其它事件）

按 `event.type` 精确计数 = 0 条
口径: 按类型（`event.type === 'dispatch/aborted'`）；文件 `.sdo/journal.jsonl`；数条（不是数行）
```

## 4. 什么算读数、什么不算

算（四种形态任一命中）：

- **量词**：`12 行` / `15 条` / `3 次` / `7 个` / `50%`；
- **英文计数词**：`15 tests` / `13 pass` / `2 fail` / `3 files`；
- **加粗**：`**0**`（断言里的强调读数）；
- **结果位**：紧跟 `=` / `→` 之后的数（`按 event.type 精确计数 = 0`）。

不算（**名字 / 位置 / 版本**不是计数）：`REV-001`、`TASK-263`、`CT-024`、`m249` 这类标识符与编号；
`721d98…` 这类哈希；`2026-10-13` 这类 ISO 日期；`0.1.6` 这类版本号；`src/index.ts:254`、`:427-434`
这类路径与行号锚点。机械口径 = 数字紧邻字母/数字/`.`/`#`/`/`/`:`/`\`/`-` 时**不是独立数字**。

## 5. 扫哪里：只扫评审核实记录，不扫全文

**只扫** [`.sdo/reviews/verified.yml`](../.sdo/reviews/verified.yml) 里每条 `evidence`（`verify-review` 的
`proof` 落在这里）。**刻意不扫全文**：卡面、注释、变更日志里到处是编号与哈希，全仓 linter 的噪音会把
守卫自己淹死 —— 而"核实结论里的数字"恰好是唯一必须当场可复算的那一面。

载体不存在时（未初始化的仓、插件包被单独 checkout）脚本打印 `carrier: absent` 并 **exit 0**
—— 项目数据不在交付物里，这条检查不该因为"没有台账"而红。

## 6. 存量登记（不让历史当场全红）与它的维护

判据立起来那一刻，盘上已有几百条核实记录**一行口径都没有**。所以存量**按记录身份登记**
（`<reviewId>#<index>`），每条给 `n`（该记录名下未带口径的**处数**）与**非空 `why`**（带入库日期）。
判据不为登记放宽：

- 截止时刻**之内**却不在登记里的读数 ⇒ **红**（不许靠"少登记几条"隐瞒）；
- 登记的 `n` 与现算**不等**（多了、少了、记录没了）⇒ **红**并要求收紧登记（登记表不是永久豁免）；
- **不改写任何历史 proof 文本** —— 历史是事实，要登记不要改写。

**截止时刻**（`REGISTRY_AS_OF`）：台账是只增且**并发在写**的。若"任何未登记读数都判红"直接进全量，
本卡落地后下一分钟就有别人的正常核实把全量顶红 —— 那不是守卫，是噪音源。所以切成两半：

- `at <= 截止时刻` ⇒ 存量：必须逐条登记（守卫格判红）；
- `at > 截止时刻` ⇒ 新记录：脚本照旧 **exit 1 并点名**（"新记录必须写口径"这一半在这里），
  但守卫格只打印读数、不判红。

维护命令：

```text
node scripts/check-number-provenance.mjs                     只检查（不同步 ⇒ exit 1；载体缺失 ⇒ exit 0）
node scripts/check-number-provenance.mjs --json              机读（字段名全 ASCII）
node scripts/check-number-provenance.mjs --emit-registry     打印现算登记表（不写盘）
node scripts/check-number-provenance.mjs --write-registry    重写本脚本里的登记表（截止时刻推到最新一条）
node scripts/check-number-provenance.mjs --help              打印第 2 节那张定义表
```

`--emit-registry` / `--write-registry` **都会打印差集**（`+ 新增` / `~ 变化` / `- 减少`）——
静默重生成就是"把守卫关掉"，明细可见才不是（与读散文棘轮同一条纪律）。

**换了载体就换口径**（`--carrier=<夹具>`）：存量登记**只对"本仓的那份台账"生效**。别的载体一律按
**零登记**判（`scope: probe`，没有截止时刻）—— 否则拿一条夹具跑一次，几百条存量会立刻被判成"过期"，
探针会把守卫自己顶红。相应地，`--write-registry` **只接受本仓载体**（拒绝用夹具覆盖真登记表）。

## 7. 已知缝隙（如实登记，别当它不存在）

- **只认紧邻形态**：`hits: 5` 这种"冒号 + 数"的写法**不算读数**（紧邻字符是 `: `）—— 宁可漏判，
  也不把边角形态塞进判据；
- **面检测是关键词**：`口径:` 后面灌一串关键词能蒙过"至少一面"，面的**内容**由 review 判；
- **标记必须与数字同句**（以 `。` `；` `;` 换行切分）：跨句写口径不算；
- **截止之后的新记录不进守卫格**（见第 6 节）：想让新记录也把关，跑一次脚本看退出码即可；
- 本守卫**只管评审核实记录**：卡面 DoD、评审判词、交付报告里的数字仍靠人（与 review）把关 ——
  这条纪律的价值不在"全都自动抓"，而在"至少在必须复算的那一面不留假读数"。
