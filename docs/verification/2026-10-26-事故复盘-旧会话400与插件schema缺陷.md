## 3 被证据排除的假设

1. **「上下文超窗」**（交接文档 §1 的推断）：**不成立/至少不被支持**。最后一次成功请求 ≈ 502 k tokens（窗口 1 M），而同一会话在 turn 96 曾有 661 k tokens 的请求**成功**；失败期间窗口配置未变。
2. **「工具 schema 变了」**：不成立。失败 4 小时内的 5 份 header 工具集哈希一致。
3. **「插件回执把上下文撑爆」**：方向不对。`tool/result` 只占 8.4 MB（总量 102.6 MB 的 **8%**）；最大头是 assistant 消息（61.5 MB，含 reasoning）。插件的另一份自造内容是**每轮注入的状态块**（15.8 MB / 2 282 次），合计约 **23%** —— 是可优化项，但不是主因。
4. **本地校验器的拒绝**：不成立。适配器里那几条 `INVALID_REQUEST`（tool 结果无对应调用、历史以未结算工具结尾等）都会带自己的句子；实际文案是兜底句 `request failed (400)` ⇒ 是**服务端**拒绝。

## 4 「可归因的插件缺陷」——**09:5x 已更正为误诊**（原判断撤回）

原判断：`items: { type: 'json' }` 不是合法 JSON Schema ⇒ 插件发出的 schema 非法、且没有守卫。**撤回**，三条反证（子会话在 `.worktrees/task-288` 副本里实测 + 我方复核）：

1. **`defineTool` 的入参是作者面 DSL，不是 JSON Schema**（宿主 `@deepseek-ai/dsh-tools`）：`json` 是伪类型，编译成 `{}`；`items: {}` 反而会在编译期报错（`items.type must be string/number/integer/boolean/null/array/object/json, or use oneOf`）⇒ 照原修法字面落地，22 个工具一个都注册不出来。
2. **注册面（真正发给 API 的那一份）今天全合法**：22 个工具 / 273 个参数，非法 schema **0** 条、残留 `type:"json"` **0** 条；`sdo_adr.alternatives` 与 `sdo_release` 五个参数都是 `{"oneOf":[{"type":"string"},{"type":"array","items":{}}]}`。
3. **守卫早就在**：`test/m139.test.ts` 的 `M139-01` 逐参数跑宿主 `assertSupportedJsonSchema`（失败文案原话就是「供应商侧会直接 400」），`M139-02` 钉死注册面不得出现 `type:"json"` 且数组分支 `items` 必须是 `{}`，`M139-03` 钉源码声明形态。

**历史事实不变**：旧会话 10-14 两次 400 的响应体确实由 `"json"` 触发；但那是**当时的宿主/编译链把这个伪类型原样透传**的结果，不是今天代码的缺陷（该会话跨 21 个 schema 版本，插件与宿主都在演进）。

**处置**：`DEF-257` 更正关闭（误诊）；`TASK-288` 作废（`never-done`，子会话零产品改动：两个源文件 sha256 与 HEAD 逐字节一致、`test/m272.test.ts` 未创建、副本 `git status` 空；前后全量同值 1881/1859/0/22 skip）。
**教训（记给下一次做复盘的人）**：判定「发出去的 schema 非法」必须看**注册面**（编译器输出）而不是源码里的 DSL 字面量；下结论前先 `grep` 一遍 `assertSupportedJsonSchema` / `M139`。

## 5 不能归因的部分：致命 400 的真因**未知**

- 宿主 `providerError()` 在响应体没有 `error.message` 时用兜底文案，**原始响应体被丢弃**（`dsh-llm-deepseek` 适配器 `providerError`）。20 次失败没有留下任何可判读的原因。
- 请求体本身不落盘（只落 header），因此无法事后重放。
- 可确认的是：**同一份历史既让普通请求失败，也让压缩请求失败** ⇒ 只要历史里存在一个被服务端拒绝的成分，压缩这条唯一恢复路径也会被同一原因挡住（死锁）。这与「换一个模型/清空历史才能恢复」的表现一致。

### 上游（宿主）两条应上报的问题

1. **400 的响应体必须透传**（截断到合理长度即可）：否则 `(400)` 这类文案会永久掩盖真因——本次复盘绕了 94 份 header 才能排除三个假设。
2. **压缩不能与故障共用同一条被拒路径**：压缩请求应能在「历史被认为非法」时降级（砍最旧工具回执/最旧对话段、分块 map-reduce），先保命再谈质量。

## 6 对插件侧的建议（不新开缺陷，已有跟踪）

- **状态块体积**（15.8 MB / 2 282 次，最大 17.5 KB）：与 `TASK-219`（紧凑只读视图）同向；建议在 `TASK-219` 的 DoD 里补一句「状态块自身有体积预算与折叠」。
