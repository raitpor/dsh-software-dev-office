## 签署者当场确认的四件事

1. **`guarantee`/`applies_to` 不进 `criterion` 表**（台账 D-026）：它们是判据 code 的目录属性（引擎侧常量 + 快照），`docs/03:47` 的 `criterion` 只有 `id/spec_id/kind/status_enum/remedy`。目录与 `docs/04` 的比对由测试守（24 条 + §4.1 的 23 行）。
2. **负例缺失 = 注册被拒，不是警告**：`criterion.registered` 的荷载**必须带 `fixtures[]`（≥1 正 1 反）**，且注册时实跑——正例跑 `pass`、负例跑 `fail`，反了报 `fixture_mismatch`。**唯一例外是 `legacy:true`**（只给 v1 迁移用），且 `verify()` 会把 legacy 注册数报出来（`legacy_criterion_registrations`），读数 ② 只用非 legacy 注册取证。
3. **预算是“每条夹具各自中位数再取 max”**：250ms 的慢夹具不会被 15 条 1ms 快夹具稀释成“1ms 通过”；生产路径不接受调用方传 `budget_ms`（防绕过）。
4. **core 三条无后门**：若 baseline 里没有任何 `requirement` kind 的 stage，三条 core **一律判不生效**（原因 `missing_required_kind`）——不能靠删掉 requirement stage 来绕开防代签。依据是 `docs/04` §4.1 末尾“lite 不能连 requirement 也缺”（台账 D-040）。
