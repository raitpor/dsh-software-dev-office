## 签署者确认的复述（要点）

1. **锁以事件为真源**：`lock.acquired`/`lock.released` 是真 reducer，不是 ACK；认领只经 `append()`，行与事件**同生同死**（第 1 轮 P1“孤儿锁”已消除：`BEGIN IMMEDIATE` 内 INSERT+COMMIT 再补事件的写法已删，相交判定下沉重到 fold）。
2. **相交按路径段**，不是字符串前缀；活锁互斥由 `migrations/016_lock.sql` 的部分唯一索引 `ux_lock_active_prefix` 兜底。
3. **三道闸必须同时在**：①`acquireMainTreeLock` 的 `rootLockPrecheck`（纯函数预检，`card_id` 条件在此，单测可锁）；②`lock.acquired` reducer 的 `heldConflict`（事件流权威，fold 失败即整批回滚）；③唯一索引。**不要只改一处就宣称规则生效**（第 5 轮复认实测：只删预检的 `card_id`，端到端仍被 reducer 挡住，红证只出在单测）。
4. **主树锁先于 merge**：`admitWorkcopy` 在 merge 之前取根锁（`.`）；根锁只能由工作副本工具经**一次性能力**取得（网关 `unauthorized_root_lock` + reducer `initiator='sdo-workcopy'` 自证），业务层 `acquireLock('.')` 一律 `no_permission`。
5. **释放鉴权**：`releaseLock` 校验 `row.actor === session.actor`（否则 `no_permission`），reducer 同守卫；卡锁收尾由工具内部构造 `sdo-workcopy` 身份（不再要求调用方传 session），逐前缀失败以 `lock_release_failed` + `details: failures[]` 上报（不吞成 `append_failed`）。
6. **过期锁不自动回收**：按 `docs/07` §13「默认 2h；到期需续，不自动续」，`verify` 只报 `lock_leaked`（活锁超 `expires_at` + 10min 宽限即报），释放由人/控制台显式操作。
7. **`lock_missing` 只看“历史上申请过锁”的卡**：从未申请过锁的卡不进检查（申请/释放接线在 M4-2 的 `claim`/收尾）。

## 签署者确认的四条已知边界（不阻塞收卡，须在后续卡承接）

1. **Windows junction 未实机验证**（`vcs_link_unsupported` 是 fail-closed 回退，不是实测结论）。
2. **跨卡并发准入靠本卡主树锁串行**（M4-1 C7）：锁表本身不保证两卡不撞同一段主树；`admitWorkcopy` 的根锁是唯一串行点。
3. **部分前缀释放不回滚**：`releaseCardLocksAsTool` 逐前缀独立释放，可能“部分已释放、部分仍 active”，调用方按 `failures[].prefix` 补偿或人工处理（D-152）。
4. **`lease.revoked` 的 reducer 不校验 `event.actor`**（只按 `card_id` 找行、只改 `released_by`，锁仍 active）；M4-1 没有 lease 表/能力可依据，actor 与能力的收紧留到 **M4-2** 建 lease 时做（D-150）。
