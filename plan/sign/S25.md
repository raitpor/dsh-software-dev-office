## 签署者确认的复述

1. **撤权不删行**：撤权是权限事实，队列是视图派生。撤权后该 actor 的待审项**按权限过滤而不可见**，`pm_queue`/`review_queue` 的 SQL 与事件一条不改（`rows + hidden = raw.rows`，hidden 的 id 都能在 `attention` 等源头表里找到）。
2. **撤权后只给申请入口**：页面露出 `apply_entries`（先指 `escalate@scope`，M4 换真 `grant`）；入口本身不需要权限，提交动作才要权限。
3. **宁可不给数字**：撤权（或其影响不可确定）时**不出过滤后的数字**，只出 `filtered_by_permission` miss + 入口——避免“不可复算的数字”与“存在性泄露”。有权限时空队列仍如实出 `to_decide = 0`。
4. **`escalate` 只能升到自己有 `read` 的域**，且任务所属域要被覆盖；越域 ⇒ `no_permission` / `scope_mismatch`。`withdrawAttention` 只能撤自己提的，且 attention 所属任务域要对。
5. **历史不受影响**：撤权前的判定、签字、回执一律仍然有效（`historySnapshot` 与 `verify` 双向对照）。
6. **默认 deny-all**：`seatRightsPort` 静态放行已删，生产路径用 `dbRightsPort`（真库 grant）驱动，缺 grant ⇒ deny-all；`src/` 里出现该默认分支有用例守卫。
