## 签署者确认的复述（要点）

1. **新起理由必须机器复算**：`new_reason` 只认 `docs/12` §3 的三条（`no_idle_capable` / `context_irrelevant` / `watermark_exhausted`），各按卡 C1 的复算表从“快照 + 事件”算出；编造词 ⇒ `invalid_field`。
2. **但快照是调用方给的**：本卡只保证“快照自洽 + 证据入事件可审计”，**不证明实际池状态**（D-200，v0.2.1 再定池真源）。因此 M4 不成立“强制复用”，只成立“复用读数可复算”。
3. **`agent.spawned` 不再是裸 ACK**：写网关消费一次性能力（mint 不导出、绑 `payload_hash`、读后即删）；裸 append ⇒ `unauthorized_agent_event` + 0 事件（D-199）。
4. **一次派发 `pick_declined` 至多 1 条**；连续 3 次新起 ⇒ `agent.spawn_streak` 告警进 `gaps`；`agent.spawned` 与 `agent.spawn_streak` **同一批原子落事件**（失败整体回滚，D-203）。
5. **`gaps` 视图经迁移 020 重建**，接管 `spawn_streak` / `pick_declined_streak`，与 `002_views.sql` 旧定义**逐行等价**（`test/db/gaps-equivalence.test.ts`；删 `waiver` 分支会真红）。
6. **读数现算**：`readings:m4` 不写死数字，树冻结后复跑取证；默认写 `plan/milestone/`，取证一律 `--out` 临时前缀。
7. **边界**：`agent.reused` / `agent.pick_declined` 仍是裸 ACK（读数可被任意写者注入，D-202）；`pickDeclined` 不校验活租约窗口。
