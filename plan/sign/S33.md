## 签署者确认的复述（要点）

1. **租约只有一条生路**：`lease.issued` 只能由 `dispatchLease`（一次性工具能力）产生；`claim` 必须持**活租约**，否则 `no_lease`、0 事件。该闸**恒开**——原设计里“库内出现 `lease` 事件后才生效”的激活边界已删（冷启动空库首条 claim 会永久放行，等于不检查；D-159 作废、D-167 记录）。
2. **预占不是授权**：`task.assigned`（预占）不产生写权；认领者必须等于 `reserved_by`，否则拒。
3. **撤租约的授权与 scope 同源**：动作统一为 `assign`，scope **只**取自租约行的 `scope`；payload 若带 `scope` 必须与行一致（否则 `invalid_field`），租约不存在或非 active ⇒ `lease_not_active`；直 `append('lease.revoked')` 与 API `revokeLease` 走**同一条** `hasRight(assign, lease.scope)`（D-174）。这一条修掉的是“同一条规则被 payload 选择绕过”——原先 scope 由 payload 声明并回退 `domain:core`，任意 domain 的 assign 权都能撤别域租约。
4. **D-150 收口**：`revokeLeaseLocks` 这条“无租约行也能给锁标 `lease_revoked`”的过渡 API 已删（D-175）；锁行标记只由真撤销（lease reducer）触发。
5. **事件与行同生同死**：租约行由 fold 投影产生、物化由 `append()` 单事务完成；`expireLease` 的多条伴随事件（`task.blocked`/`unblocked`）也在同一次 append 内，无中间态。
6. **fold 的防御层被测到**：`lease.revoked` 的三条 reducer 守卫（行存在且 active、`payload.scope === row.scope`、`revoked_by === event.actor`）现在都有 fold 级负例（`test/core/lease/reducer.test.ts`）；删任意一条 ⇒ 该组用例红（E19/E20，Lead 亲做变异）。

## 签署者确认的四条已知边界（不阻塞收卡，须在后续卡承接）

1. **租约 TTL 只有常量**：`DEFAULT_LEASE_TTL_S` = 4h（S30 第 3 条）；`config` 覆盖读取留后续卡。锁 TTL 是另一个旋钮（2h + 10min 宽限，`docs/07` §13），两者不混用。
2. **撤租约不删工作副本**：只写 `task.blocked(lease_revoked)` → `ready`，`.work/<card>/` 保留（回收由 M4-0 的 `removeWorkcopy` 负责）。
3. **无租约行的 M4-1 旧锁**：只能靠 admit/remove 时的 `releaseCardLocksAsTool` 清；若工作副本已不存在且无租约，不会自动清（升级边界，D-175 accepted，正常 M4-2 流程不产生）。
4. **fold 不校验“撤的人是否持 `assign`”**：fold 没有 grant 视图，该条件由网关矩阵（`KIND_ACTIONS['lease.revoked'] = {action:'assign', scope:'lease'}`）与 API `revokeLease` 同源保证（D-174）。
