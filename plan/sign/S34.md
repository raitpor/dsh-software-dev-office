## 签署者确认的复述（要点）

1. **公共面是“迁移拥有的数据”**：`public_face` 六条前缀只由 `migrations/018_public_face.sql` 播种；它**不在 `TABLE_NAMES` 里**，所以 `append`/fold 根本没有第二条物化写路（C1 选①）；另有 `projection_guard` 三道触发器挡窗口外的直接 SQL 写。
2. **卡的写域与公共面双向不相交**：按**路径段**判（`src/core` ↔ `src/core/criteria/` 相交；`a/b` vs `a/bc` 不相交），并归一 `./` 与 `..`（`src/core/../migrations/x` 会先归一成 `src/migrations/x`，不再靠原串包含蒙对）。写域**权威来源是 `task` 行的 `scope_paths`**（`CreateRequest`/`CommitRequest` 的 `scope_paths` 已删）——空写域 ⇒ `scope_undeclared`、缺卡行 ⇒ `task_not_found`、越界 ⇒ `scope_violation`；提交时还会对**真实 diff 路径**再验一次（第二道闸，防止“写域合法但改动里夹带公共面文件”）。
3. **卡只能申请**：`publicface.requested` 由 `requestPublicFace` 产生，`intent_hash = sha256(canonicalJson(intent))`（服务端算，不收调用方 hash），`(card,intent_hash)` 幂等；申请只 +1 事件、不产生 snapshot，因此永不进卡的提交（C5）。
4. **执行只在单写者**：`public_face_writer` 单行（`id=1` 固定主键 + CHECK + 单行触发器），交棒必须留 `publicface.writer_changed` 事件（`from`/`to`/时间单调三条 fold 守卫，各有 fold 级负例与变异红证）；执行走一次性能力绑 `payload_hash`，直 append ⇒ `not_public_face_writer`；同 request 二次执行幂等（`idempotent:true`，`executed` 仍 1 条）；交棒真并发（两进程 barrier）⇒ 恰 1 成功、`writer_changed` 恰 2 条。
5. **verify 会抓脏数据**：卡写域命中公共面 ⇒ `public_face_scope_overlap`；申请超 7 天未执行 ⇒ `public_face_request_stale`；`public_face_writer` 投影对账 ⇒ `missing`/`extra`/`mismatch`（三码都有正式用例，直接构造脏数据可红）。

## 签署者确认的三条已知边界（不阻塞收卡，须在后续卡承接）

1. **`publicface.requested` 是低权动作**：任何持 `claim@module` 的 actor 都能替某张卡发申请（申请不写公共面、可审计、幂等，执行处才是闸）。建议 M4-4 或 M4-5 加“申请者须为该卡 owner/producer 或显式授权”，否则低权可刷他人卡的申请队列。
2. **`projection_guard` 本身可被同库写者打开**（与 M4-3 之前的 `renderer_catalog` 同一模式，D-095）；这是“库内写者不在威胁模型”的口径，M4 不改。
3. **`public_face` 的直接 SQL 写只能靠触发器挡**：没有 verify 级对账（`public_face` 是 DDL 种子表、不在 fold 里，没有期望值可比）；触发器窗口外 ABORT 是唯一防线。
