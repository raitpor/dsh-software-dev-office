# 开发计划（自 design-v2.0 冻结起）

> 冻结：`frozen/design-v2.0` = `f37f4dc`，见 [../FREEZE.md](../FREEZE.md)。
> 里程碑与判死读数以 [`docs/09` §16](../docs/09-交付与迁移.md) 为准；本文只排**怎么做、谁做、什么时候算过**，不改那里的定义。

## 1. 一句话

五个里程碑 9–11 周：M0 真源与视图 → M1 对齐与返工面 → M2 签字与门禁 → M3 权限与独立性 → M4 并行与复用。**M2 结束起 SDO 开始管自己的卡，M3 结束起 SDO 接管自己的开发流程**（见 [02-SDO接管方案](02-SDO接管方案.md)）。

## 2. 节奏与容量

| 项 | 约定 |
|---|---|
| 容量 | 1 个人（签署者/基线所有者）+ 3 个实现 agent + 1 个独立评审 agent |
| 卡粒度 | 一张卡 ≤ 1 天；超过就拆。卡必须有可执行判据，不接受“完成后评审” |
| 提交 | 一卡一提交（或一天一批），提交信息带卡号；**不跨卡混提交** |
| 评审 | 每卡：实现者自证 + 独立 reviewer 只读复核；每 M 收口：整套评审 + 人签 |
| 门 | 判死读数不达标 **不进下一个 M**（docs/09 §16 的硬规则），修到达标为止 |
| 缓冲 | 每个 M 预留 20% 时间给“判死读数不达标”的返工 |

## 3. 工作分解（卡清单）

### M0 · 真源与视图（1.5–2 周）

| 卡 | 内容 | 泳道 | 依赖 |
|---|---|---|---|
| M0-0 | 仓库骨架：`package.json` / TS 配置 / 测试骨架 / `make test` / 目录约定；**DB 驱动选型 spike**（加密、跨平台、无原生编译的取舍，结论写进卡） | core | — |
| M0-1 | schema 与迁移：34 表（`docs/03` 25 + 支撑 9）+ 库层约束 + `user_version` 推进；迁移幂等（回滚不在本卡，重建库即可；`docs/02` §4 其余身份表留后续卡） | core | M0-0 |
| M0-2 | `fold`：事件 → 投影，纯函数；重放两次逐字节相同 | core | M0-1 |
| M0-3 | 13 个视图 + `view_catalog`（`pm_queue`/`alignment`/`pm_gaps` 在内），`min_right` 生效 | surface | M0-1 |
| M0-4 | `sdo_query`：预算、游标、`query_miss` 聚合 | surface | M0-3 |
| M0-5 | 控制台三页（总览 / board / plan）：页面数字全部可 query 复算 | surface | M0-3 |
| M0-6 | 沙箱与可发现性：库在工作区外；读留探针线索、写由 `verify` 发现（**都不承诺归因**） | core | M0-1 |
| M0-7 | 导入器（只读）：v1 导出 → 抽样重建 20 条 claim；存量卡 `seq` 回填并校验 | surface | M0-2 |

判死读数用 docs/09 §16.1 的四条，不另立。

### M1 · 链条、对齐与返工面（2 周）

六表（intent/spec/scenario/criterion/evidence/claim）+ 对齐三件套（复述/例子/回指）+ 判据框架（注册、`applies_to`、有效绑定、负例强制）+ **P15 静态校验器**（只对文件，不冻结、不写 `baseline.rejected`）+ `sdo_check`（离线只读预览，**不落 `gate.judged`**）+ preview 的 `rework_units`。

> 纪律：**M1 只强制 core 三条**（`spec_set.signed` / `assumption_set.signed` / `provenance.present`）；其余 21 条随 M2 签字链落地。假设处置、评审抽样、晚到条款链**不在 M1**。

判死读数：docs/09 §16.2 的七条（含“`gate.judged` 行数为 0”——M1 写了判定行就是给“没有 baseline 的判定”开口子）。

### M2 · 交互与签字（2–3 周）

待审队列四项契约 → 登录/签章口令/`signerd`/免密窗口 → **baseline 冻结**（P15 → 人签 `decision(kind='baseline')` → `prev`/`direction`）→ **门禁判定**（`stage_run.baseline_hash` + `gate.judged`）→ 假设处置链 → 评审抽样 → 晚到条款链 → 撤销级联 → PM 最小环路。

> M2 的目标不是“有签字”，是“**签字便宜**”：单次签字人工时间中位 ≤ 10 秒。超过就改认证设计，不加人。

判死读数：docs/09 §16.3 的四条 + 签字时长。

### M3 · 协作与权限（1–2 周）

actor/scope/right、冲突可见（`conflicts` 不是 `disputed`）、独立性（`dual_human` / `solo_cooldown`）。

### M4 · 并行与复用（2 周）

工作副本、锁表、公共面单写者、复用 reason code、PM 预占与收回。

## 4. 三条并行泳道

| 泳道 | 负责 | 写域 | 不与谁抢 |
|---|---|---|---|
| `core` | schema、事件、fold、verify、P15、门禁判定 | `src/core/**`、`src/db/**` | 不碰 UI、不碰 query |
| `surface` | 视图、`sdo_query`、控制台、导入器 | `src/views/**`、`src/query/**`、`src/ui/**` | 不碰 fold 与 DDL |
| `security`（M2 起） | 登录、`signerd`、免密窗口、签名字段 | `src/sign/**`、`signerd/**` | 不碰门禁判定逻辑 |

**写域是硬边界**：跨域改动走“同一个卡、两个泳道”的显式协作，不靠默契。合并顺序固定 `core → surface → security`，避免 DDL 与视图互相等。

## 5. 风险（按“会杀死里程碑”排序）

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 加密 SQLite 在插件里装不上（原生编译/宿主打包） | M0-0 spike 失败 | 备选：`sql.js` + 应用层加密；再不行降级为“库文件 0600 + 明确不承诺防 root”，写进交接说明——**不许假装有加密** |
| 宿主 UI 插槽不够，控制台三页做不进 | M0-5 第一天就卡 | 先做独立只读页（插件自己 serve），宿主插槽作为增强；**不对宿主提要求**是硬约束 |
| `signerd` 跨平台（Windows 命名管道/权限） | M2 第一周 | 先 Linux（T0 主场景），Windows 走 socket 文件 + 0600 等价物，写清差异 |
| 判死读数不达标却想往下走 | 每 M 收口 | 硬门：读数报告没签字不进下一 M |
| 实现期发现设计缺口就私自绕 | 评审发现“代码与 docs 不一致” | 偏差必须先记 [03-偏差台账](03-偏差台账.md)，绕一次就回滚 |

## 6. 明确不做（scope guard）

- 不接 v1 的写路径（只读导入，一次性）；
- 不做宿主改造、不做多租户、不做云端同步；
- 不做通用工作流引擎——判据只有 24 条 + 内置 `security.*`/`release.*`；
- 不在 M1 之前碰签字与门禁（先有授权再做判定，顺序不能反）。

## 7. 现在就能开的卡

`M0-0` 是唯一无依赖的卡；开它就等于开工。M0-1..7 在 M0-0 落地后并行开三条泳道。
