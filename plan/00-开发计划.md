# 开发计划（自 design-v2.0 冻结起）

> 冻结：`frozen/design-v2.0` = `f37f4dc`，见 [../FREEZE.md](../FREEZE.md)。
> 里程碑与判死读数以 [`docs/09` §16](../docs/09-交付与迁移.md) 为准；本文只排**怎么做、谁做、什么时候算过**，不改那里的定义。

## 1. 一句话

五个里程碑 9–11 周：M0 真源与视图 → M1 对齐与返工面 → M2 签字与门禁 → M3 权限与独立性 → M4 并行与复用。**M2 结束起 SDO 开始管自己的卡，M3 结束起 SDO 接管自己的开发流程**（见 [02-SDO接管方案](02-SDO接管方案.md)）。

## 2. 节奏与容量

| 项 | 约定 |
|---|---|
| 容量 | 1 个人（签署者/基线所有者）+ 3 个实现 agent + 1 个独立评审 agent |
| 卡粒度 | 一张卡 ≤ 1 天；超过就拆。卡必须有可执行判据，不接受“完成后评审” |
| 提交 | 一卡一提交（或一天一批），提交信息带卡号；**不跨卡混提交** |
| 评审 | 每卡：实现者自证 + 独立 reviewer 只读复核；每 M 收口：整套评审 + 人签 |
| 门 | 判死读数不达标 **不进下一个 M**（docs/09 §16 的硬规则），修到达标为止 |
| 缓冲 | 每个 M 预留 20% 时间给“判死读数不达标”的返工 |

### M2 · 交互与签字（2–3 周）

待审队列四项契约 → 登录/签章口令/`signerd`/免密窗口 → **baseline 冻结**（P15 → 人签 `decision(kind='baseline')` → `prev`/`direction`）→ **门禁判定**（`stage_run.baseline_hash` + `gate.judged`）→ 假设处置链 → 评审抽样 → 晚到条款链 → 撤销级联 → PM 最小环路。

> M2 的目标不是“有签字”，是“**签字便宜**”：单次签字人工时间中位 ≤ 10 秒。超过就改认证设计，不加人。

判死读数：docs/09 §16.3 的四条 + 签字时长。

### M5 · 插件化与接管（3–4 周；M4 门已签 S39，M5-0 开卡，先写卡不写码）

> **用户指令（2026-11-16 11:10）**：“做完 M4 …校验目前 SDO 是否能作为插件安装到宿主并且审查功能是否满足需求。若通过则安装到本 dsh 实例然后尝试接管本项目。”
> **用户的纠正（2026-11-16 11:16）**：“你现在都说插件化之前不能安装，那你在 M4 后派评审是否能安装是没有意义的。应该在插件化后（M5）才去做评审这个内容。”
> ⇒ 所以顺序是 **先插件化 → 再评审（可安装性 + 功能满足性）→ 通过才装 → 再接管**。评审门放在插件化之后，不放在 M4 之后；M4 收门后直接进 M5-0。

**做**：

1. **M5-0 插件化 adapter（前置，必须先做）**：把 SDO 从“CLI + 库 + 独立只读页”变成**宿主可安装的插件**——插件清单与入口（包名、`engines`、入口文件）、工具注册（`sdo_*` 走宿主工具面，读写分离，读工具只读）、控制台页挂宿主 UI 插槽（插槽不够 ⇒ 退回独立只读页并在 README 说明，**不对宿主提要求**）、`signerd` 生命周期（由插件起停；socket 与密钥目录 0600/0700；单实例锁）、DB 路径与权限（`~/.local/state/sdo/<project>.db`，0700）、卸载与回滚（停 signerd、关库、不留锁）。
2. **M5-1 评审门（在 adapter 之后）**：`reviewer` + `reviewer-2` 双席位核三件事——①能否在**不改宿主源码、不改宿主私有配置**的前提下装进去（对照宿主插件/包机制）；②**功能是否满足需求**：`docs/01` §1 三条保证逐条给可复跑证据，并按 `docs/09` §16 各里程碑读数给 pass/partial/fail；③装进去后权限与数据边界仍成立（signerd 独立进程、库在状态目录、不碰仓库 `.git`、工具面不暴露写库旁路）。
3. **M5-2 安装到本 dsh 实例**：按评审给出的方式安装、重启、验证（工具可列可调、控制台可达、`verify` 绿），步骤写成可复跑记录（`plan/milestone/M5-安装.md`）。
4. **M5-3 接管本项目**：先用 SDO 自己跑本仓库的卡——**S0 影子**（人工判定、SDO 只记录）≥3 张，再试 S2/S3 的判定与派发；人只签字与裁红卡。

**M5 卡表**（四张工作卡 + 读数门；依赖边必须成立——门卡只能依赖比它早的产卡，这就是 2026-11-16 那次“评审门写在插件化之前”的事故防复发点）

**判死读数（草案，M5-1 卡面定稿时逐条钉死命令）**。每条都必须可复跑、且**变异必红**（能构造出让它变红的输入）；每个读数取证两遍，除时钟/随机 id 外逐字节一致（对齐 M4-G C7/C8 的口径）：

1. **可安装**（执行面：**M5-0 试装→重启→回滚**给评审，M5-2 做常驻安装）：`npm ci && npm run build` 之后能把 SDO 作为插件装进本 dsh 实例，重启后工具可见、控制台可达；**宿主安装树改动 = 0**（profile 的插件登记不算“改宿主源码”，但清单文件须逐项列出）。口径：装前、装后各跑一次 `find <宿主目录> -type f -printf '%p %s\n' | sort | sha256sum`（宿主实例不是 git 仓库，不能用 `git status`），两次摘要一致；并把清单落 `plan/milestone/M5-安装.md`。
2. **功能满足**（工具面口径）：`docs/01` §1 三条保证逐条给出**经宿主工具面**（`sdo_*`）的可复跑证据；`plan/00` 本节的三条 CLI 命令作对照组，两者结论一致；评审给出的 partial 项都有编号与去向。
3. **接管真跑**：本仓库 ≥10 张真卡在 SDO 里走完生命周期（建卡 → 判据 → 证据 → 判定 → 收口），其中 ≥3 张由 agent 执行且 `verify` 全绿。
4. **门禁真挡过**：接管期间有 **≥2 次真实的不合规写入被门禁拒绝**（真实卡上的真红，不是造出来的），且这些卡修复后重新判绿。若接管期没自然出现 2 次 ⇒ 该读数记 **partial** 并写清次数（不许为了达标去造红卡）。
5. **签字不贵**：≥3 次真人签字（含 1 次 `baseline` 冻结），单次中位 ≤10 s。
6. **可回退**（执行面：**M5-3/M5-G**，不在 M5-0 判据内）：一次回退演练——把判定层换回人工、数据无损、`verify` 全绿；M5-0 只负责“卸载/重装后数据还在”（C6）。

**六条读数各自的“变异必红”构造**（M5-G 必须真的造一次）：

| # | 读数 | 变异构造（造完必须变红/变 partial） |
|---|---|---|
| 1 | 可安装且宿主改动=0 | 装完后改宿主目录里任一文件的内容（同大小也可）⇒ `sha256sum` 摘要必须不等 |
| 2 | 三条保证有证据 | 把任一条命令的输出替换成只打印 `ok` ⇒ 判据文件里“断言条数/失败数”校验必须红 |
| 3 | ≥10 张真卡生命周期 | 删掉其中一张卡的 `gate.judged` 事件 ⇒ `verify` 必红、生命周期计数 9 |

**明确不做**：不改宿主源码；不为装进宿主而放松任何判据（例如为跑通把 `gate.judged` 改成非必绑 baseline）；不在接管的同一个里程碑里再改设计（设计改动走 v2.1 人签）。

## 4. 三条并行泳道

| 泳道 | 负责 | 写域 | 不与谁抢 |
|---|---|---|---|
| `core` | schema、事件、fold、verify、P15、门禁判定 | `src/core/**`、`src/db/**` | 不碰 UI、不碰 query |
| `surface` | 视图、`sdo_query`、控制台、导入器 | `src/views/**`、`src/query/**`、`src/ui/**` | 不碰 fold 与 DDL |
| `security`（M2 起） | 登录、`signerd`、免密窗口、签名字段 | `src/sign/**`、`signerd/**` | 不碰门禁判定逻辑 |

**写域是硬边界**：跨域改动走“同一个卡、两个泳道”的显式协作，不靠默契。合并顺序固定 `core → surface → security`，避免 DDL 与视图互相等。

## 5. 风险（按“会杀死里程碑”排序）

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 加密 SQLite 在插件里装不上（原生编译/宿主打包） | M0-0 spike 失败 | 备选：`sql.js` + 应用层加密；再不行降级为“库文件 0600 + 明确不承诺防 root”，写进交接说明——**不许假装有加密** |
| 宿主 UI 插槽不够，控制台三页做不进 | M0-5 第一天就卡 | 先做独立只读页（插件自己 serve），宿主插槽作为增强；**不对宿主提要求**是硬约束 |
| `signerd` 跨平台（Windows 命名管道/权限） | M2 第一周 | 先 Linux（T0 主场景），Windows 走 socket 文件 + 0600 等价物，写清差异 |
| 判死读数不达标却想往下走 | 每 M 收口 | 硬门：读数报告没签字不进下一 M |
| 实现期发现设计缺口就私自绕 | 评审发现“代码与 docs 不一致” | 偏差必须先记 [03-偏差台账](03-偏差台账.md)，绕一次就回滚 |

## 6. 明确不做（scope guard）

- 不接 v1 的写路径（只读导入，一次性）；
- 不做宿主改造、不做多租户、不做云端同步；
- 不做通用工作流引擎——判据只有 24 条 + 内置 `security.*`/`release.*`；
- 不在 M1 之前碰签字与门禁（先有授权再做判定，顺序不能反）。

`M0-0` 是唯一无依赖的卡；开它就等于开工。M0-1..7 在 M0-0 落地后并行开三条泳道。
