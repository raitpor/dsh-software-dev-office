# M5-0 · 插件化 adapter（把 SDO 变成可安装的宿主插件）

## 意图

SDO 现在能证明自己“记的真、判得住”（M0–M4 八门已签），但它仍是**外面的一套东西**：CLI、库、一个只读页。M5 的判死读数第一条是“**能作为插件装进宿主、宿主侧改动 = 0**”——这一条今天必然是 fail，因为还没有插件形态。

这张卡只做**形态**，不改判定语义：插件清单与入口、`sdo_*` 工具注册（读写分离）、控制台页挂插槽或退回独立只读页、`signerd` 生命周期、DB 路径与权限、卸载回滚。**不对宿主提要求**：只用宿主公开的插件机制，插槽不够就退回独立页并写明。

## 对齐

**复述**：SDO 要能被宿主（本 dsh 实例）当作**普通插件**加载：①清单与入口符合宿主的插件约定；②工具以 `sdo_*` 名字出现在宿主的工具面里，**读工具只读、写工具必须走 `append` 网关**（不暴露任何 raw SQL 旁路）；③控制台页优先挂宿主 UI 插槽，挂不上就退回独立只读页（127.0.0.1），README 写清；④`signerd` 由插件起停（socket/密钥 0600/0700、单实例锁、崩溃后可恢复），卸载时停干净；⑤数据库默认在状态目录（`~/.local/state/sdo/<slug>.db`，目录 0700、文件 0600）；显式 `db_path` 在项目下时只许 `<project_dir>/.sdo/**`；任何情况都拒绝仓库根/`.git/`/文档目录/源码目录，仓库里不得多出 `*.db`；⑥**安装前后宿主自身目录清单 sha256 一致**（除插件自己的安装目录），不改宿主源码、不改宿主私有配置；⑦**人类起 dsh 就能用**：不需要先配任何环境变量，页面能登录（**注册要过宿主审批弹窗**，独立页兜底只登录），工具面能读（身份分两条通道，见 C13/C14）。

**正例 2**
1. 在干净环境里按 README 装 SDO ⇒ 宿主重启后 `sdo_*` 工具可列可调，控制台页可达，`verify` 绿，宿主目录清单 sha256 与装前一致。
2. 卸载 SDO ⇒ `signerd` 停止、socket 与锁清除、无残留监听端口，插件自己的目录被移除；数据库文件仍在状态目录（数据不销毁）。

## 泳道

core（`impl-core`）为主；`src/ui/` 属 surface 泳道，本卡只做“独立只读页 + 可选的宿主插槽最小挂载”，**不重写既有三页**（`src/ui/{pages,render,server,serve}.ts` 的语义归 M3-6/S27，本卡只调用）；若需要改既有 UI 代码，先按 D-057 方式报写域扩权。
