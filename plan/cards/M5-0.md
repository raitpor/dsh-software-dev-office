# M5-0 · 插件化 adapter（把 SDO 变成可安装的宿主插件）

## 意图

SDO 现在能证明自己“记的真、判得住”（M0–M4 八门已签），但它仍是**外面的一套东西**：CLI、库、一个只读页。M5 的判死读数第一条是“**能作为插件装进宿主、宿主侧改动 = 0**”——这一条今天必然是 fail，因为还没有插件形态。

这张卡只做**形态**，不改判定语义：插件清单与入口、`sdo_*` 工具注册（读写分离）、控制台页挂插槽或退回独立只读页、`signerd` 生命周期、DB 路径与权限、卸载回滚。**不对宿主提要求**：只用宿主公开的插件机制，插槽不够就退回独立页并写明。

## 对齐

**复述**：SDO 要能被宿主（本 dsh 实例）当作**普通插件**加载：①清单与入口符合宿主的插件约定；②工具以 `sdo_*` 名字出现在宿主的工具面里，**读工具只读、写工具必须走 `append` 网关**（不暴露任何 raw SQL 旁路）；③控制台页优先挂宿主 UI 插槽，挂不上就退回独立只读页（127.0.0.1），README 写清；④`signerd` 由插件起停（socket/密钥 0600/0700、单实例锁、崩溃后可恢复），卸载时停干净；⑤数据库只在状态目录（`~/.local/state/sdo/<project>.db`，目录 0700、文件 0600），不写仓库、不碰 `.git`；⑥**安装前后宿主自身目录清单 sha256 一致**（除插件自己的安装目录），不改宿主源码、不改宿主私有配置。

**人确认**：pending

**正例 2**
1. 在干净环境里按 README 装 SDO ⇒ 宿主重启后 `sdo_*` 工具可列可调，控制台页可达，`verify` 绿，宿主目录清单 sha256 与装前一致。
2. 卸载 SDO ⇒ `signerd` 停止、socket 与锁清除、无残留监听端口，插件自己的目录被移除；数据库文件仍在状态目录（数据不销毁）。

**反例 1**
- 为了让插件能装上而去改宿主源码/私有配置（或要求宿主新增字段）⇒ 视为不满足 C8，评级直接 fail（“能装”必须是“宿主不用让路”）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | **清单与入口**：包 `name`/`version`/`engines`/入口文件/导出符合宿主插件约定（以宿主现有插件为参照，不发明新字段）；宿主 loader 能加载它并得到插件对象 | 用例：在临时 HOME 上按 README 安装加载 ⇒ loader 返回插件；清单字段与宿主已装插件逐项对照 |
| C2 | **工具注册与读写分离**：`sdo_*` 工具经宿主工具面注册；只读工具（如 `sdo_query`、`sdo_verify`）不写库；写工具（如 `sdo_append`、`sdo_pm_*`）内部只经 `append(db, events, {session})`，**不存在 raw SQL / 任意表写入工具** | 用例：调只读工具后 `event` 计数不变；调写工具但不给 session ⇒ `filtered_by_permission`/`no_permission`；静态守卫：工具清单里无 `sql`/`exec`/`raw` 类工具 |
| C3 | **控制台页**：优先挂宿主 UI 插槽；若宿主插槽不提供所需位置 ⇒ 退回独立只读页（只绑 `127.0.0.1`，身份必填），README 写明“为什么退回、宿主插槽缺什么”（只描述，不提要求） | 用例：有插槽时页面出现在槽位；无插槽时独立页起得来且只绑回环；README 有说明段 |
| C4 | **`signerd` 生命周期**：插件启动时按需起（不常驻空转）、卸载时停；socket `0600`、密钥目录 `0700`、单实例锁（第二实例 `already_running`）；崩溃后残留锁能在下次启动被识别并恢复 | 用例：两次启动 ⇒ 第二次 `already_running`；kill -9 后重启 ⇒ 恢复且不误删密钥；卸载后 socket 文件不存在 |
| C5 | **DB 路径与权限**：数据库落到 `~/.local/state/sdo/<project>.db`（目录 0700、文件 0600）；不写仓库、不碰 `.git`；仓库里多出 `*.db`/`access.log` ⇒ 视为不满足 | 用例：安装后跑一次读写 ⇒ 仓库 `git status` 干净、状态目录权限位正确 |
| C6 | **卸载与回滚**：卸载后 `signerd` 停、socket/锁清理、无边车进程与监听；数据库保留；重装后数据还在且 `verify` 绿 | 用例：装→写→卸→装 ⇒ `verify` 绿、计数不变 |
| C7 | **三条保证在宿主内可演示**：`docs/01` §1 的 G1/G2/G3 各有一条**经宿主工具面**（不是 CLI）的可复跑路径，命令写进 `plan/milestone/M5-安装.md` 的对应行 | 用例：三条命令在插件加载后跑绿；与 `plan/00` M5 段的 CLI 版命令结果一致 |
| C8 | **不碰宿主**：安装前后 `find <宿主目录> -type f -printf '%p %s\n' \| sort \| sha256sum` 一致（排除插件自身安装目录）；宿主源码/私有配置零改动 | 用例：装前装后各跑一次，摘要相等；`git -C <宿主> status`（若宿主是 git 仓库）无改动 |
| C9 | **权限边界不因插件化放松**：agent 身份不能代签（`not_a_signer`）；控制台页/工具面都需要身份（无 session ⇒ 拒绝而非默认放行）；插件启动日志打印 actor 解析方式 | 用例：agent 调签名路径 ⇒ 拒；无 session 调读工具 ⇒ `filtered_by_permission` |
| C10 | **迁移可重入**：插件首次启动自动建库/迁移；重复启动不重复迁移；迁移失败 ⇒ 报错退出且不半套 schema（`user_version` 与表数一致） | 用例：连启两次 ⇒ `user_version` 不变；注入坏迁移 ⇒ 启动失败且库版本未提升 |
| C11 | **可观测**：插件加载/卸载/迁移各写一条日志（含 `request_id`、耗时、版本）；工具调用有 `request_id` 贯穿 | 用例：日志行存在且字段齐；同一调用在两个工具里 `request_id` 一致 |
| C12 | **冻结区零改动 + 纪律**：`git diff f37f4dc -- docs design probe` 为空；一卡两笔提交；台账从 D-222 起；不自行 push | 提交前检查 |
