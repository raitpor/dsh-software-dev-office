# M4-5 · 复用 reason code（单一码表）

## 意图

`docs/09` §16.5 把“复用 reason code”列为 M4 的内容。到 M3 收口时，拒绝码已经散在五个地方（`src/db/write-types.ts`、`src/core/verify-types.ts`、`src/sign/errors.ts`、`src/check/`、`src/core/pm/`），同码异义与裸字符串的风险已经出现过（D-025 追加两次、M3-1 的 `no_permission` 分裂出 `cross_prefix_denied`/`no_ownership`）。本卡把码收成**一处定义、处处引用**，并让“每次拒绝都带已登记码”成为可机器检查的事。

## 对齐

**复述**：全部 `reason_code` 在一个文件里定义（`src/core/errors/codes.ts`），带分组、说明、HTTP 语义（若适用）；其它模块只能引用常量，不许写字面量；每个写入/查询/校验拒绝路径都必须返回已登记码；未登记的码在编译期不存在、在运行期非法（`unknown_reason_code` 视为内部错误，不是业务码）。

**人确认**：pending

**正例 2**
1. `grep -r "reason_code: '" src/` 只在码表定义处命中；产品代码里没有裸字符串码。
2. 新增一个码 ⇒ 只需改码表 + 加一条用例；所有既有模块自动可用，README 的码表由脚本生成。

**反例 1**
- 两个模块各自定义同名但语义不同的码（或同一语义两个拼写）⇒ 视为未完成（本卡要消灭的正是这个）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | `src/core/errors/codes.ts` 是唯一来源：`REASON_CODES`（分组：`auth`/`write`/`gate`/`sign`/`release`/`query`/`config`/`internal`）+ 每码 `{code, group, summary, http_status?}`；导出类型为字面量联合 | 用例：遍历码表断言形状；重复码 ⇒ 构造时抛错 |
| C2 | 产品代码零裸码：静态扫描 `src/**`（除码表）无 `reason_code: '<literal>'`、无 `REASON_CODES.<不存在>`（TS 编译期已挡后者） | 扫描用例 + `npm run build` |
| C3 | 既有码全部登记且语义去重：M3 结束时点的 70+ 码逐个登记；同义异名（如 `cross_prefix_denied` 与 `no_permission`）在码表里写清“属于哪个父码、何时用” | 用例：码表内 `code` 唯一；README 的码表由脚本从码表生成（手写版本删掉） |
| C4 | 每个拒绝路径都带码：写网关、查询、校验、签字、CLI 的失败返回都有 `reason_code`（无码 ⇒ `internal_missing_reason_code` 并计入 `gaps`） | 用例：遍历各入口的失败形态（表驱动） |
