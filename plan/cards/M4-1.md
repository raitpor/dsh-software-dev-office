# M4-1 · 锁表（路径前缀互斥）

## 意图

`docs/07` §12 只锁**路径前缀**，不锁整库、也不锁公共面（公共面走 M4-3 的单写者）。这条锁解决的是“两张卡同时改 `src/core/fold/` 下的文件 ⇒ 后提交的覆盖前一个”的具体踩踏。M4 判死读数第 1 条就是它：同文件并发写**一成一败（409）**。

## 对齐

**复述**：`lock` 是事件真源（`lock.acquired`/`lock.released`），带 `path_prefix`、`actor`、`card`、`acquired_at`；认领时若已存在与请求前缀**相交**（互为前缀）的未释放锁 ⇒ 拒绝认领（`lock_conflict`，HTTP 语义 409）；锁随卡收尾释放；`busy` 卡必须同时有未过期 lease 与未释放锁，否则 `verify` 红。

**人确认**：pending

**正例 2**
1. 卡 A 持 `src/core/fold/` 锁时，卡 B 申请 `src/core/` ⇒ 拒（前缀相交）；卡 C 申请 `src/ui/` ⇒ 成（不相交）。
2. 两个进程同时申请同一前缀 ⇒ 恰好一个成功、另一个 `lock_conflict`，且只落一条 `lock.acquired`（不出现两条锁并存）。

**反例 1**
- 用“查一下有没有锁再插”的写法（TOCTOU）⇒ 视为未实现：必须靠唯一约束或事务内冲突检测保证互斥。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | `lock` 表 + `lock.acquired`/`lock.released` 事件；锁的唯一性由 DB 层保证（部分唯一索引或等效 CHECK），并发下不可能出现两条相交的活锁 | 两个**独立进程**同时认领同前缀 ⇒ 1 成 1 败；表里恰 1 行活锁；用例断言事件数 = 1 |
| C2 | 相交判定：`a` 与 `b` 互为前缀（或相等）即冲突；`src/core/` 与 `src/core/fold/` 冲突、`src/co` 与 `src/core/` 不冲突（按路径段比较，不按字符串前缀） | 表驱动用例含边界：相等、子路径、兄弟路径、形近但不相交（`src/core` vs `src/core2`） |
| C3 | 失败码：`lock_conflict` 带 `{prefix, holder, holder_card, since}`；调用方拿到的 HTTP 语义是 409（库函数返回结构化 `status`，CLI/控制台映射） | 用例断言码与字段 |
| C4 | 锁与卡的生命周期绑定：`task.claimed` 时申请、`workcopy.removed` 或卡收尾时释放；卡被 `lease.revoked` 时锁保留（证据还在）但标记 `released_by='lease_revoked'`，不再阻塞同一 actor 的重新认领 | 用例：撤租约后同 actor 重认领不被自己挡；别的卡仍被挡 |
| C5 | `verify` 抓两类不一致：`busy` 卡无活锁（`lock_missing`）、无卡关联的活锁超期（`lock_leaked`，超过 lease TTL + 宽限） | verify 用例 + 探针直插造脏 |
| C6 | 前缀必须落在仓库内且经过规范化（`..`、绝对路径、尾斜杠、大小写）后才比较；非法前缀 ⇒ `invalid_field` | 表驱动用例 |
| C7 | **主树重写走全局锁**（D-135）：准入时的 `rewriteMainTree` 必须持有 scope = 主树的锁（不是每卡锁），跨卡并发准入同批只允许一个；拿不到 ⇒ 结构化 `lock_conflict`（或 M4-1 定的 `main_tree_busy`），**不写主树、不落 snapshot** | 用例：两张卡各自 `admitWorkcopy` 在两独立进程里并发 ⇒ 一条成功一条 `lock_conflict`；主树内容只反映成功那次的 merge；两条 snapshot 不成多 head |
| C8 | 冻结区零改动 | `git diff f37f4dc -- docs design probe` 为空 |

| A1 | 锁只在**认领**时申请，不在写路径上按文件加锁（避免每次写都碰锁表） | confirmed | `docs/07` §12 的认领/完成流程 |
| A2 | 不相交前缀可并行（`src/ui/` 与 `src/core/` 同时写是合法的） | confirmed | 同上；这也是三条泳道的基础 |
