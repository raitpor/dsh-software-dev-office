# M1-4 · `sdo_check` 离线预览

## 意图

`docs/05` §2 把 `sdo_check` 列成“现算判据”的只读查询：给 `{ gate }` 或 `{ criterion }`，现算一遍“如果现在判定，会是什么结果”。M1 没有 frozen baseline，所以**它只能是预览**：`docs/04` §6 第一条写死“每个判定都记 `baseline.hash`，没有 baseline 的判定无效”，因此 M1 的 `sdo_check` **不写 `gate.judged` 行**（`docs/09` §16.2 判死读数 ⑦：M1 跑完 `gate.judged` 行数必须是 0）。

这张卡交付的是**人能在开工前后自己问一句“这条判据现在过不过”的工具**，不是判定引擎。

## 对齐

**复述**：不是“把判据跑一遍打印结果”，而是三件事同时成立才叫预览——① 每条结果都带**为什么**（命中的证据/缺的证据/未绑定的原因），② 明确标注“这是预览，不是判定”（因为不绑 baseline），③ **只读**：不写事件、不写 `gate.judged`、不改任何表。第三件是这张卡最容易出事的边界：一个“顺手把结果记下来”的实现会让 `docs/09` §16.2 的判死读数 ⑦ 直接红，等于给“先判后冻”开了口子。

**人确认**：pending（收卡前必须确认）

**正例 2**
1. `sdo_check --criterion provenance.present`：库里有一条 `evidence.attached` 且其 `spec` 未被作废 ⇒ `{criterion_id:'provenance.present', result:'pass', basis:{evidence_ids:[…]}, preview:true, effective:{...}}`，退出码 0。
2. `sdo_check --gate design`：对 design 阶段适用的判据逐个现算 ⇒ 一张表（每行 `criterion_id/result/reasons[]`），汇总里带 `effective` 与 `stage_gap` 提示，退出码 0（**有 fail 也是 0**——预览不是门禁；只有工具自身错误才非 0）。

**反例 1**
- 判据 `spec_set.signed` 在 M1 无签字链，实际未满足 ⇒ `result:'fail'` 且 `reasons:[{code:'not_signed'}]`，同时输出**必须**写清 `preview:true, judged:false`；若工具写了 `gate.judged` 行，本卡即为不合格。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | 支持 `--criterion <id>` 与 `--gate <stage>` 两种入口；未知 id/stage ⇒ `{ok:false, reason_code:'unknown_criterion'|'unknown_stage'}`、退出码 2（参数错，不是判定失败） | 两用例 |
| C2 | **每条结果带依据**：`pass` 必须给命中的 `evidence_ids`/`spec_ids`；`fail` 必须给 `reasons[{code,detail?}]`（如 `not_signed`/`missing_evidence`/`criterion_not_effective`）；不许只给布尔 | 逐 result 断言字段非空 |
| C3 | **明确标注预览**：每条输出都带 `preview:true` 与 `judged:false`；顶层带 `baseline:null`（M1 无 baseline）；文案里不得自称“判定/门禁” | 字符串断言 + 用例 |
| C4 | **只读**：调用前后 `event`/`gate`/`gate.judged`/`baseline` 行数不变；`src/check/` 内无 `INSERT`/`UPDATE`/`DELETE`（静态扫描，白名单只允许 `SELECT`） | 用例 + 静态守卫 |
| C5 | **`gate.judged` 零产出**：新增专项用例，跑完全部入口后 `SELECT count(*) FROM gate` 类表为 0（`docs/09` §16.2 读数 ⑦ 的取证基础） | 用例 |
| C6 | **消费 M1-1/M1-3，不另造语义**：`effective` 来自 `src/core/criteria/binding.ts`；`gate` 入口的结构来自 `src/core/baseline/validate.ts` 的 preset 常量；`src/check/` 内不得出现第二份 `applies_to`/`guarantee` 表 | 静态扫描 + 代码审查 |
| C7 | **`stage_gap` 可见**：某 stage 的 kinds 与所有已注册判据的 `applies_to` 不相交 ⇒ 输出里显式列出（`gaps:[{stage,code:'stage_gap'}]`），不许静默空表 | 用例（造一个没有判据适用的 stage） |
| C8 | **同一输入两次输出一致**：除 `at`/耗时字段外 `JSON.stringify` 相等（排序稳定） | 两用例对比 |
| C9 | 冻结区零改动 | `git diff f37f4dc --name-only -- docs design probe` 为空 |
