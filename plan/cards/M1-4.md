# M1-4 · `sdo_check` 离线预览

## 意图

`docs/05` §2 把 `sdo_check` 列成“现算判据”的只读查询：给 `{ gate }` 或 `{ criterion }`，现算一遍“如果现在判定，会是什么结果”。M1 没有 frozen baseline，所以**它只能是预览**：`docs/04` §6 第一条写死“每个判定都记 `baseline.hash`，没有 baseline 的判定无效”，因此 M1 的 `sdo_check` **不写 `gate.judged` 行**（`docs/09` §16.2 判死读数 ⑦：M1 跑完 `gate.judged` 行数必须是 0）。

这张卡交付的是**人能在开工前后自己问一句“这条判据现在过不过”的工具**，不是判定引擎。

## 对齐

**复述**：不是“把判据跑一遍打印结果”，而是三件事同时成立才叫预览——① 每条结果都带**为什么**（命中的证据/缺的证据/未绑定的原因），② 明确标注“这是预览，不是判定”（因为不绑 baseline），③ **只读**：不写事件、不写 `gate.judged`、不改任何表。第三件是这张卡最容易出事的边界：一个“顺手把结果记下来”的实现会让 `docs/09` §16.2 的判死读数 ⑦ 直接红，等于给“先判后冻”开了口子。

**人确认**：confirmed（Lead m02380 裁定 M1-4 四口径：preset 取自 `presets.ts` 且默认 waterfall、不消费 P15 形状、`dead_field` 裁 (b) 引擎写入方清单、provenance 只验非空并标 `actor_registry_unavailable`；A2 `unknown` 口径同条确认）

**正例 2**
1. `sdo_check --criterion provenance.present`：库里有 `spec` 且 `created_by` 非空 ⇒ `{criterion_id:'provenance.present', result:'pass', basis:{spec_ids:[…],task_ids:[…]}, preview:true, judged:false}`，并在 reasons 带 `actor_registry_unavailable` 标注（M1 未验 actor 注册，Lead m02380 口径），退出码 0。
2. `sdo_check --gate design`：对 design 阶段适用的判据逐个现算 ⇒ 一张表（每行 `criterion_id/result/reasons[]`），汇总里带 `effective` 与 `stage_gap` 提示，退出码 0（**有 fail 也是 0**——预览不是门禁；只有工具自身错误才非 0）。

**反例 1**
- 判据 `spec_set.signed` 在 M1 无签字链，实际未满足 ⇒ `result:'fail'` 且 `reasons:[{code:'not_signed'}]`，同时输出**必须**写清 `preview:true, judged:false`；若工具写了 `gate.judged` 行，本卡即为不合格。

## 第 1 轮评审修复（2026-11-13，0 P0 / 1 P1 + 5 P2）

- **P1（core 无后门）**：`spec_set.signed` 在“还没有 requirement”时原返 `na`，而 `aggregate` 把 `na` 落到 pass 分支 ⇒ 空库 `runCheck` 给 core 判据 `na`、gate 只剩 core 时把 `na` 洗成 pass。修：无 requirement ⇒ **fail**（`reasons:[{code:'no_requirement_yet'}]`，口径与 M1-1 `missing_required_kind` 同源；写进 A2/已知边界）；`aggregate` 显式把任何 `na` 归 **fail**（纵深防御）；补“空库 spec_set.signed ⇒ fail（不是 na）”用例。
- **P2-1** `isPresetId` 的 `in PRESETS` 改 `Object.hasOwn(PRESETS, value)`；补 CLI `--preset toString` ⇒ `unknown_preset` 退 2 用例（原会 TypeError ⇒ tool_error 退 1）。
- **P2-2** `readonly.test.ts` 的 `gate.judged` 断言改为“表存在则 count=0、不存在也绿”，避免 M2 建表后假红。
- **P2-3** `DeadFieldOptions.writers` 注释标 `@internal test-only`。
- **P2-4** `dead_field` 的 pass 附 `reasons:[{code:'dead_field_checked', level:'info', detail:'N columns checked'}]` 扫描摘要，不让 pass 只给裸布尔。

## 已知边界

- 非 core 的 20 条阶段判据 M1 无求值器 ⇒ `unknown`（`insufficient_data`），不冒充 pass；M2 随签字链补齐。
