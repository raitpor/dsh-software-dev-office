# M4-0 · 工作副本（独立 gitdir + 共享对象库）

## 意图

并行写不能互相踩。`docs/07` §12 定的形态是「**一卡一个 gitdir**、对象库共享（alternates）、检出到 `.work/<card>/`」——不是一个仓库三张卡共用一个 index。本卡把这条落成可执行的东西：建副本、在副本里提交快照、判定 diff 是否 ⊆ 写域、收尾时能删干净。锁（M4-1）与派发（M4-2）都建立在这张卡的目录形态上，所以它先做。

## 对齐

**复述**：每张卡有自己的 gitdir（`<repo>/.sdo/vcs-cards/<card>.git`，含自己的 `index`/`HEAD`），`objects/info/alternates` 指到共享对象库 `<repo>/.sdo/vcs-objects`；卡的工作目录是 `.work/<card>/`；完成时在**卡的 gitdir** 里提交 `snapshot`（`parent` = 卡的基线快照），与基线的 diff 必须 ⊆ 卡声明的 `scope_paths` 才准入；收尾时删副本目录与卡 gitdir，删之前必须可删（无未提交改动），否则 `block(dirty_workcopy)`。

**人确认**：pending

**正例 2**
1. 同时开两张卡，各自 `git add -A && git commit` 互不阻塞、互不污染（两个 index 各自独立；并发跑两次不出现 `index.lock` 冲突）。
2. 卡完成后 `snapshot` 与基线的 diff 只落在声明写域内 ⇒ 准入（`workcopy.removed` 在准入同事务落）；把 diff 扩到写域外 ⇒ 拒绝准入并给出越界文件清单。

**反例 1**
- 三张卡共用一个 gitdir（或共用主工作树）跑并发提交 ⇒ 视为未实现（这是 v1 的踩踏来源，本卡的存在理由）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | 每卡一个 gitdir：`.sdo/vcs-cards/<card>.git` 存在且 `HEAD`/`index` 独立；`objects/info/alternates` 恰好指向一个共享对象库；共享对象库里的对象不被卡 gitdir 复制 | 用例：建两张卡 ⇒ 两个 gitdir；`alternates` 内容断言；`git count-objects` 证明卡 gitdir 自身无松散对象复制 |
| C2 | 工作目录 `.work/<card>/` 的检出内容 = 卡基线快照的文件树（逐文件 sha256 相等），且不在卡写域外的路径上产生文件 | 用例：检出后遍历比对；越界文件 ⇒ 报告 |
| C3 | `workcopy.created` 事件由**工具**在认领时落（含 `card`/`gitdir`/`base_snapshot`/`actor`），带 `decision` 之外的身份来源；`workcopy.removed` 在收尾/准入时落 | 用例读事件行；直插/裸 append 被写网关拒（`docs/02` §11 事件表） |
| C4 | 完成时在**卡的 gitdir** 提交 `snapshot`（`parent=[base]`）；与基线 diff 全是新增/修改/删除的路径清单，且 ⊆ 卡 `scope_paths`；越界 ⇒ `scope_violation`（带文件清单），不落 `task.done` | 用例：写域外改一个文件 ⇒ 拒；写域内 ⇒ 收 |
| C5 | 回收前必须可删：`git status --porcelain` 为空且无 stash/未跟踪文件（除 `.sdoignore` 允许项），否则 `block(dirty_workcopy)` 且副本目录保留（证据不删） | 用例：留一个未跟踪文件 ⇒ 回收被拒、目录还在；清掉后回收成功 |
| C6 | 卡 gitdir 与 `.work/` 都不进仓库工作树（`.gitignore` 覆盖），`git status` 干净 | 用例：`git status --porcelain` 无 `.sdo/`、`.work/` |
| C7 | 准入后**必须重新检出主工作树**到新基线；主树脏（与基线快照不一致）⇒ `block(dirty_main_tree)`，绝不覆盖 | 用例：主树留一个未提交改动 ⇒ 准入被拒、主树未被覆盖 |
| C8 | 合并用内嵌 git 三路合并；有冲突**不自动合** ⇒ `block(merge_conflict)`，交人 | 用例：两卡改同一行 ⇒ 准入落 `merge_conflict` 块，不产出合并结果 |
| C9 | 对象库与 DB 交叉校验：`snapshot` 行的 `git_oid` 必须在 `.sdo/vcs-objects` 里存在且内容哈希对得上；对象库被改 ⇒ verify 红 | 用例：篡改对象库一个对象 ⇒ verify 红 |
| C10 | 性能：单次 VCS 操作 P95 ≤ 2 s；超预算告警（不是静默慢） | 用例：大文件重复操作计时，超预算时有告警输出 |
| C11 | 冻结区零改动 | `git diff f37f4dc -- docs design probe` 为空 |
