# M2-1 · baseline 冻结（P15 接入真实冻结核事务）

## 意图

M1-3 的 P15 是**对文件跑**的纯函数：`validateBaseline(input)` 返回 `ok` + `guarantee_delta` + `reason_codes`，但它**不落任何东西**——不冻结、不写 `baseline.rejected`、不产 decision。这是 M1 刻意收窄（`docs/09` §16.2：M1 不许有 baseline，否则 `sdo_check` 就能“先判后冻”）。

M2-0 把签字链立起来之后，这张卡把 P15 接进**真实的冻结事务**：preview 跑 P15 → 不过就落 `baseline.rejected`，过了就转 `request_sign(decision(kind='baseline'))` → **人签** → 才落 `baseline.frozen`。并且收/放宽都**建新行**，原行 hash 永不变。

依据：`docs/05` 的 `baseline_freeze` 两段式（preview → `will_change` + `guarantee_delta` + `payload_hash` → confirm → sign）、`docs/04` §5.2 六条规则（新行 + `prev`/`direction`、引擎升级同审批、verify 与“引用的那版”比）、`docs/06` §5 baseline decision 载荷。

## 对齐

**复述**：不是“把 P15 的输出存下来”，而是**冻结必须是一次人签的、可追到方向的换尺子**：改的是所有人的尺子，所以先给“这一版会改什么、降了哪条保证”，人签的是这个差，不是一串 hash；签完才落新行，旧行 hash 永远可复算。P15 不过不是“报个错”，是**落 `baseline.rejected` 让队列可见**。

**人确认**：confirmed（签署者 2026-11-15T07:05+08:00，签：复述准确，收卡）

**正例 2**
1. 首版冻结：preview（P15 全过）⇒ `will_change` 列出全部 gate/criteria 为“新增”、`guarantee_delta` 三条全 `kept`、返回 `payload_hash`；confirm 同 hash ⇒ `request_sign` ⇒ 人签 ⇒ `baseline` 表 **1 行**（`prev IS NULL`、`direction IS NULL`、`hash` 可复算）；`baseline.frozen` 事件已落。
2. 收紧：加一条判据到某 gate ⇒ preview 的 `will_change` 列出该 gate 变化、`guarantee_delta` 全 `kept`；人签后 `baseline.amended` ⇒ **新行**（新 id、新 hash、`prev=旧 id`、`direction='tighten'`），旧行与旧 hash 一字不改。

**反例 1**
- 提交一版 `criteria: []` ⇒ preview 返回 `gate_empty` + `core_not_effective`，落 `baseline.rejected` 事件、**`baseline` 表 0 行**、不产生待签请求。

| C1 | **P15 在 preview 阶段跑，且是全量**：preview 调 `validateBaseline` 覆盖 ①–⑪（含 `core_not_effective` 的结构性前置、`engine_missing`、`na_stages` 一致）；P15 不通过 ⇒ 结构化 `reason_code` + `baseline.rejected` | 用例：三份红夹具（`gate_empty`/`core_not_effective`/`engine_missing`）各一条，断言 rejected 事件落、`baseline` 0 行、无待签请求 |

| C7 | **引擎升级同审批**：`criteria_manifest_hash` 变化 ⇒ preview 的 `will_change` 显式标出“引擎变更”、`guarantee_delta` 参与计算；不签字不得生效 | 用例：只改 engine 版本 ⇒ 走同一流程、未签时 hash 不变 |
| C8 | **verify 按“引用的那版”对账**：判定行存的 `baseline_id`+`hash` 必须仍是已冻结且内容可复算的一版；换新 baseline 不让历史判定变红 | 用例：冻结第二版后，引用第一版的判定 verify 仍绿；手改第一版内容 ⇒ 该判定红 |
| C9 | **首版与重复冻结**：首版 `prev IS NULL`、`direction IS NULL`（**没有** `'initial'` 这种枚举值，DDL CHECK 只允许 `tighten`、`loosen` 或 NULL）；用同一内容重复冻结 ⇒ 拒（`baseline_unchanged` 或幂等返回既有行，二选一并在 README 定死） | 用例：同 payload 第二次冻结 ⇒ 行为符合 README 口径，且不产生第二行 |
