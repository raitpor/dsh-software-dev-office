# M2-1 · baseline 冻结（P15 接入真实冻结核事务）

## 意图

M1-3 的 P15 是**对文件跑**的纯函数：`validateBaseline(input)` 返回 `ok` + `guarantee_delta` + `reason_codes`，但它**不落任何东西**——不冻结、不写 `baseline.rejected`、不产 decision。这是 M1 刻意收窄（`docs/09` §16.2：M1 不许有 baseline，否则 `sdo_check` 就能“先判后冻”）。

M2-0 把签字链立起来之后，这张卡把 P15 接进**真实的冻结事务**：preview 跑 P15 → 不过就落 `baseline.rejected`，过了就转 `request_sign(decision(kind='baseline'))` → **人签** → 才落 `baseline.frozen`。并且收/放宽都**建新行**，原行 hash 永不变。

依据：`docs/05` 的 `baseline_freeze` 两段式（preview → `will_change` + `guarantee_delta` + `payload_hash` → confirm → sign）、`docs/04` §5.2 六条规则（新行 + `prev`/`direction`、引擎升级同审批、verify 与“引用的那版”比）、`docs/06` §5 baseline decision 载荷。

## 对齐

**复述**：不是“把 P15 的输出存下来”，而是**冻结必须是一次人签的、可追到方向的换尺子**：改的是所有人的尺子，所以先给“这一版会改什么、降了哪条保证”，人签的是这个差，不是一串 hash；签完才落新行，旧行 hash 永远可复算。P15 不过不是“报个错”，是**落 `baseline.rejected` 让队列可见**。

**人确认**：pending（收卡前必须由签署者确认）

**正例 2**
1. 首版冻结：preview（P15 全过）⇒ `will_change` 列出全部 gate/criteria 为“新增”、`guarantee_delta` 三条全 `kept`、返回 `payload_hash`；confirm 同 hash ⇒ `request_sign` ⇒ 人签 ⇒ `baseline` 表 **1 行**（`prev IS NULL`、`direction='initial'`、`hash` 可复算）；`baseline.frozen` 事件已落。
2. 收紧：加一条判据到某 gate ⇒ preview 的 `will_change` 列出该 gate 变化、`guarantee_delta` 全 `kept`；人签后 `baseline.amended` ⇒ **新行**（新 id、新 hash、`prev=旧 id`、`direction='amend'`），旧行与旧 hash 一字不改。

**反例 1**
- 提交一版 `criteria: []` ⇒ preview 返回 `gate_empty` + `core_not_effective`，落 `baseline.rejected` 事件、**`baseline` 表 0 行**、不产生待签请求。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | **P15 在 preview 阶段跑，且是全量**：preview 调 `validateBaseline` 覆盖 ①–⑪（含 `core_not_effective` 的结构性前置、`engine_missing`、`na_stages` 一致）；P15 不通过 ⇒ 结构化 `reason_code` + `baseline.rejected` | 用例：三份红夹具（`gate_empty`/`core_not_effective`/`engine_missing`）各一条，断言 rejected 事件落、`baseline` 0 行、无待签请求 |
| C2 | **两段式不被跳过**：没有 preview 的 `payload_hash` 就不能 confirm；confirm 的 payload 与 preview 逐字节不一致 ⇒ 拒（`payload_changed`）；preview 过期/前端改了内容 ⇒ 同上 | 用例：改一个阈值后 confirm 旧 hash ⇒ 拒且 0 行；直接 confirm 未 preview 的 ⇒ 拒 |
| C3 | **人签的是差额**：`decision(kind='baseline')` 的 payload 必带 `will_change_hash` 与 `guarantee_delta`（哪条保证从几降到几）；缺任一项 ⇒ `no_blind_sign` 拒（复用 M2-0 的 C5 口径） | 用例：删 `guarantee_delta` ⇒ 拒；`guarantee_delta` 与 preview 现算不一致 ⇒ 拒 |
| C4 | **新行不改旧行**：收紧 ⇒ `baseline.amended`、放宽 ⇒ `baseline.loosened`，都建新行、带 `prev` 与 `direction`；原地 UPDATE 一条已冻结 baseline ⇒ 必须被拒（库层 append-only 已有，补“产品代码无 UPDATE 路径”断言）；旧 hash 复算一致 | 用例：连续两版后 `sha256(旧行内容)` 不变；`direction` 与事件 kind 一一对应（amend↔收紧、loosen↔放宽） |
| C5 | **方向判定由工具算，不由调用方声明**：`direction` 必须由“新旧两版的有效绑定/阈值差异”现算——调用方传 `direction='amend'` 但实际放宽 ⇒ 拒（`direction_mismatch`） | 用例：删一条判据却声明收紧 ⇒ 拒；两个方向各一条正例 |
| C6 | **`hash` 覆盖规则固定**：`hash = sha256(canonical(policy + criteria[] + gates[] + thresholds + assurance + engine + artifact_kinds))`，覆盖项上线后不许减少；README 写清“改哪个字段会改 hash” | 用例：逐字段改动各一条，断言 hash 变；改无关键（如注释）hash 不变 |
| C7 | **引擎升级同审批**：`criteria_manifest_hash` 变化 ⇒ preview 的 `will_change` 显式标出“引擎变更”、`guarantee_delta` 参与计算；不签字不得生效 | 用例：只改 engine 版本 ⇒ 走同一流程、未签时 hash 不变 |
| C8 | **verify 按“引用的那版”对账**：判定行存的 `baseline_id`+`hash` 必须仍是已冻结且内容可复算的一版；换新 baseline 不让历史判定变红 | 用例：冻结第二版后，引用第一版的判定 verify 仍绿；手改第一版内容 ⇒ 该判定红 |
| C9 | **首版与重复冻结**：首版 `prev IS NULL`、`direction='initial'`；用同一内容重复冻结 ⇒ 拒（`baseline_unchanged` 或幂等返回既有行，二选一并在 README 定死） | 用例：同 payload 第二次冻结 ⇒ 行为符合 README 口径，且不产生第二行 |
| C10 | **拒绝码稳定**：`payload_changed`/`direction_mismatch`/`baseline_unchanged`/`gate_empty`/`core_not_effective`/`engine_missing` 进 README；`baseline.rejected` 的载荷含 `reason_codes[]` | 用例：每码一条触发用例 |
| C11 | 冻结区零改动 | `git diff f37f4dc --name-only -- docs design probe` 为空 |

## 假设

| # | 假设 | 状态 | 依据 |
|---|---|---|---|
| A1 | P15 仍是**纯函数**（`validateBaseline` 不变），冻结事务在它外面包一层；“不过就落 rejected”由调用方做，P15 自己仍不写库 | confirmed | M1-3 的 C9“纯函数无副作用”不能破 |
| A2 | `direction` 的“收紧/放宽”判定用**可判定子集**：判据增删、gate 增删、阈值升降、`waivable` false→true、`policy_mode` all_of→any_of；无法判定的改动（如重命名）一律按**放宽**处理并拒签，要人显式确认——宁可严 | pending | 冻结设计没给形式化方向判定；这是实现期偏差，要记 `plan/03` |
| A3 | `baseline` 表已存在（001），本卡一般不需要新迁移；若需（如 `prev` 外键、`direction` CHECK），新增迁移不改表语义 | confirmed | `docs/03`/`docs/04` 冻结文本 |
| A4 | `will_change` 的粒度 = gate/criterion 级增删改 + `na` 转移；不做逐字段 diff | confirmed | `docs/05` 只要求“哪些 gate 增删、哪些判据转 na” |
| A5 | verify 的“已冻结可复算”只查 hash 复算与 `baseline.frozen` 事件一致，不查“当时谁签的”（签名验证在 M2-0 的回执里） | pending | 若 M2-0 提供了 `verifyDecisionSignature`，本卡复用 |
