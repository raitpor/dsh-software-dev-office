# M2-0s · M2-0 的可行性 spike（加密 / unix socket / 权限）

## 意图

M2-0 要建的 `signerd` 有三个**外部依赖**，装不上就整张卡的设计要改：

1. **私钥加密**：`docs/06` §13 要求盘上加密（Argon2id）。Node 的 `crypto` 只有 `scrypt`（够用但不符合文档口径）；Argon2id 需要原生依赖（`argon2` / `@node-rs/argon2`）或纯 JS 实现。
2. **unix socket**：`signerd` 与插件走 `unix socket 0600`。要证明 Node 能起 socket、能验权限、能跨进程可靠通信；Windows 上 unix socket 不可用（本机是 Linux，但要记清楚边界）。
3. **文件权限**：`0600` key 文件与 socket、`0700` 目录，以及“权限错了拒绝启动”。

这张卡**只出结论与证据，不写产品代码**。M0-0 的驱动选型就是同一个套路（先 spike 再定死），那次证明是对的：不先跑通就写，后面要返工。

## 对齐

**复述**：不是“试一下能不能用”，而是**把三个外部依赖的可否、代价、退化方案钉死**，并留下可复跑的证据。凡是装不上/不可靠的，就**如实写装不上**并给退化方案，不许假装有加密（M0-0 的纪律：`--ignore-scripts` 那次就是靠实测才发现 13.x 自带 prebuilds）。

**人确认**：pending（spike 结论要进 M2-0 卡的 A3 假设；签署者确认 M2-0 复述时一并确认下降级方向）

**正例 2**
1. 每个候选（Argon2id 原生 / `scrypt` 兜底 / 纯 JS Argon2）各跑一次“加密 1KB 密钥 → 落盘 → 重开 → 解密”实测，带命令、耗时、装依赖前后的 `npm ls` 差异。
2. unix socket：起一个最小 server（只 echo），另一进程连接、断言 socket 文件权限 0600、目录 0700；错误权限下 server 拒绝启动。

**反例 1**
- 构建时代码里出现“假装加密”的分支（明文落盘却报 ok）⇒ 本卡直接不通过；加密必须能证明**盘上是密文**（读文件字节里搜不到明文）。
