# M2-0s · M2-0 的可行性 spike（加密 / unix socket / 权限）

## 意图

M2-0 要建的 `signerd` 有三个**外部依赖**，装不上就整张卡的设计要改：

1. **私钥加密**：`docs/06` §13 要求盘上加密（Argon2id）。Node 的 `crypto` 只有 `scrypt`（够用但不符合文档口径）；Argon2id 需要原生依赖（`argon2` / `@node-rs/argon2`）或纯 JS 实现。
2. **unix socket**：`signerd` 与插件走 `unix socket 0600`。要证明 Node 能起 socket、能验权限、能跨进程可靠通信；Windows 上 unix socket 不可用（本机是 Linux，但要记清楚边界）。
3. **文件权限**：`0600` key 文件与 socket、`0700` 目录，以及“权限错了拒绝启动”。

这张卡**只出结论与证据，不写产品代码**。M0-0 的驱动选型就是同一个套路（先 spike 再定死），那次证明是对的：不先跑通就写，后面要返工。

## 对齐

**复述**：不是“试一下能不能用”，而是**把三个外部依赖的可否、代价、退化方案钉死**，并留下可复跑的证据。凡是装不上/不可靠的，就**如实写装不上**并给退化方案，不许假装有加密（M0-0 的纪律：`--ignore-scripts` 那次就是靠实测才发现 13.x 自带 prebuilds）。

**人确认**：confirmed（2026-11-14T13:35+08:00；签署者确认 M2-0 复述并当场定下两条：`@node-rs/argon2` 进产品依赖、M2 只支持 Linux/macOS——见 `plan/sign/S11.md` 追加说明、台账 D-049/D-050）

**正例 2**
1. 每个候选（Argon2id 原生 / `scrypt` 兜底 / 纯 JS Argon2）各跑一次“加密 1KB 密钥 → 落盘 → 重开 → 解密”实测，带命令、耗时、装依赖前后的 `npm ls` 差异。
2. unix socket：起一个最小 server（只 echo），另一进程连接、断言 socket 文件权限 0600、目录 0700；错误权限下 server 拒绝启动。

**反例 1**
- 构建时代码里出现“假装加密”的分支（明文落盘却报 ok）⇒ 本卡直接不通过；加密必须能证明**盘上是密文**（读文件字节里搜不到明文）。

## 已知边界（诚实清单）

- **sign 是占位，M2 不许照抄**：spike 的 `sign` 返回 `signature='spike-not-ed25519:<sha256>'` 却标 `method:'ed25519'`——这是为了让协议形状先跑通的**假签名**。M2-0 必须实现真 Ed25519（`node:crypto` sign/verify），`method` 只能标注真实算法，verify 必须校验签名本身，不许拿哈希冒名。
- **常量断言、无真实路径用例**：`socket_path_missing`、`platform_unix_socket_unsupported` 在 Linux 上无自然触发路径，只做常量/分支断言；Windows 行为未在本机执行（本机 Linux），只是代码路径 + 文档口径。
- **目录扫描上限**：单文件 >2MiB 记 `skipped_large_files`（本轮 0 个，最大 728KB）；`artifacts/spike` 之外的路径不在扫描范围。
- **单实例语义边界**：锁判活靠 `kill(pid,0)`（EPERM 视为活）；pid 被系统复用到另一个进程时保守拒启动（需人工清锁），这是 fail-closed 选择。
- **socket 0600 不是认证**：同 OS 用户可连（`docs/06` §12）；客户端认证仍需 capability/HMAC（D-048）。
## 结论（供 M2-0 卡的 A3 与「预览」）

1. **私钥加密：Argon2id 可行，不必退 scrypt。** 推荐 `@node-rs/argon2@2.2.2` 作产品依赖候选（无 install 脚本、2 个包、预编译二进制走 optionalDependencies、`npm ci --ignore-scripts` 可复现、derive 24ms）；`argon2@0.45.2` 次选（12 个包；install 脚本 `node-gyp-build` 实际只挑 prebuild、不编译，且 `--ignore-scripts` 下 require 仍可用，因为 prebuild 解析发生在 require 时）。`scrypt` 兜底实测通过；若待确认①否掉原生依赖，则退 `scrypt`（N=2^15, r=8, p=1）并记台账写明与 `docs/06` §13 的偏差，**不许静默降级/假装加密**。
2. **密钥文件格式**（建议）：单行 JSON 信封 `{format:'sdo-signerd-key-v1',kdf,kdf_params,salt(16B hex),cipher:'aes-256-gcm',nonce(12B hex),tag,ct,key_id}` + AES-256-GCM；1KB 私钥 → ~2.3KB 文件；盐/nonce 每次随机。
3. **unix socket 可用**，但 Node **没有 SO_PEERCRED API**（实测原型上无 `getPeerCredentials`），`docs/06` §12 要求的客户端认证在 Node 下只能走 capability/HMAC 令牌 → **已记台账 D-048**（客户端认证 = socket 0600 + capability 文件 + HMAC）。
4. **socket 路径必须短**（Linux sun_path 107B）：用 `$XDG_RUNTIME_DIR/sdo/signerd.sock`，无则 `/tmp/sdo-<uid>/signerd.sock`；**不能**放 `~/.local/state`（会 ENAMETOOLONG）。库文件不受此限。
5. **权限校验手法**：`st.mode & 0o777` 去掉文件类型位再比；密钥文件先 `O_NOFOLLOW` 打开、再对 fd `fstat` 校验（无 TOCTOU），不用 `fs.stat` 直查；`mkdir`/`writeFile` 的 mode 会被 umask 削，必须显式 chmod 并复验；socket 权限：**实测实现用 `withUmask(0o077)` 包住 `listen`**，socket 出生即 0700、随后 `chmod 0600`，**不存在 0755 窗口**；卡 E5 的 0755 是独立 raw listen 的对照演示，不是产品路径。
6. **跨平台**：Windows 无 unix domain socket，代码抛稳定码 `platform_unix_socket_unsupported`；**已定**：M2 只支持 Linux/macOS，Windows 启动即 `platform_unsupported`，命名管道留 M4（台账 D-050）。
7. **依赖零污染 + 测试隔离**：`package.json` **没有**加任何依赖；spike 依赖只装在 `artifacts/spike/deps/`（gitignored），现有 `npm ci --ignore-scripts` 不受影响。第 1 轮评审指出 `build` 耦合 spike 测试 ⇒ **已拆开**：`build` 只跑 `tsc`，spike 测试由 `npm run spike:test` 复制到 `lib/spike-test/` 单独跑，`npm test` 恒为 621。
