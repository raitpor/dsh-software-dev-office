# M2-6 · 签字页与签字成本

## 意图

`docs/09` §16.3 给 M2 定的目标不是“有签字”，是“**签字便宜**”：单次签字的人工时间中位 **≤10 秒**，签字页 ≤2 次交互。超过就说明认证设计错了，不是人多事。

M2-0 给了 `signerd` 与解锁；这张卡做**人眼前的那一段**：签字页展示什么（命题 + 证据 + 这一签会改什么 + 降了哪条保证）、怎么确认（≤2 次交互、免密窗口内连签）、以及**把人工时长测出来**（M2-G 的读数基础）。同时它是 `no_blind_sign` 的最后一公里：人看到的必须是 renderer 渲染的命题，不是模型生成的摘要。

依据：`docs/06` §1（三层凭据、passkey 优先）、§3（signerd 拓扑）、§5（decision 状态与 `no_blind_sign`）、§7（免密窗口状态机）、`docs/05` 签字交互。

## 对齐

**复述**：不是“做一个确认弹窗”，而是**让人在 10 秒内、看清自己在签什么、并且只点两次**。三件事必须同时成立：①看到的是机器渲染的命题（不是模型写的漂亮话）；②看到“这一签会改什么”（`will_change` + `guarantee_delta`，尤其基线冻结）；③免密窗口内连签不用重复解锁，但 frontier 一变立刻要求重解锁。

**人确认**：pending

**正例 2**
1. 一次解锁 → 签字页展示 3 条待签 → 连签 3 条（每条 1 次确认点击，共 ≤2 次交互/条）⇒ 3 个 decision 行，`unlock_wait_ms` 只第一次非零，`sign_ms` 三次都有；总人工时长中位可算。
2. 签字页对 baseline 冻结显示：`will_change`（哪些 gate 增删、哪些判据转 `na`）+ `guarantee_delta`（1/2/3 各 kept/degraded）+ 命题；任何一项与 preview 的 `payload_hash` 对不上 ⇒ 页面拒绝提交并提示重新预览。

**反例 1**
- 前端把 `proposition` 换成模型给的摘要（不是 renderer 渲染）⇒ `no_blind_sign` 红，签发被拒（服务端校验，不信页面）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | **不盲签**：页面提交的 `proposition` 必须是 renderer 从 claim 渲染的结果（服务端复算比对）；不一致 ⇒ 拒 `no_blind_sign`；页面不得展示模型自由文本作为“命题” | 用例：篡改 `proposition` ⇒ 拒；正常 ⇒ 通过 |
| C2 | **两段式不可绕**：签字页只接受带 `payload_hash` 的 confirm；页面上的任何编辑都会让 hash 失效并要求重新 preview | 用例：改一个字段后提交 ⇒ `payload_changed` |
| C3 | **交互次数**：单次签字 ≤2 次人工交互。D-060 会话式批量：preview N 条 → 1 次解锁（绑 `f0`）→ N 次逐条确认（每次只签名、不 append）→ 1 次整批提交；确认期间链头必须保持 `f0`；第 2 条起 `unlock_wait_ms===0` 且 `since_last_unlock_ms>0`。TTL=0 只允许 N=1：`createRequest` 与 `confirm` 两处守卫，拒 `ttl_requires_window`（带 `staged`/`requested`），会话进 `needs_window`；不自动开窗。**成本归因按实际签名顺序 `sign_seq`，不按 `created_at` 创建顺序**（同毫秒创建/乱序确认也必须归对）；`interactions` = 本次解锁 POST 数 + 本次确认 POST（正常路径仍 `[2,1,1]`，同窗口重复 unlock 后首条 = 3）。 | 用例：TTL=0 单条交互=2；TTL=0 N=2 ⇒ 拒且 0 条 decision；TTL>0 preview 3 → 解锁 1 → 确认 3 → 提交 1 ⇒ 3 条 decision 全 `frontier=f0`、交互 `[2,1,1]`、`verify` 绿；负例：确认期间外部注入事件 ⇒ 整批拒（`frontier_stale`）、0 条 decision、回执 consumed；全确认后 submit 前注入 ⇒ 同拒 |
| C4 | **签字成本真实测量**：signerd 回执两个数都要有、名字要诚实——`unlock_wait_ms`=本次签发**实际等人解锁**的时长（复用窗口/批量后续条目为 0）、`since_last_unlock_ms`=距上次解锁的时长（保留）；`sign_ms`=sign 开始到签名完成。页面透出 signerd 的 `unlock_wait_ms`，不用自己的计时；`page_total_ms` 仅展示。**不得写死常量**；测量点写进 README | 用例：注入 120ms 延迟 ⇒ `sign_ms` 变化；批量 3 条 ⇒ `unlock_wait_ms=[x,0,0]`、`since_last_unlock_ms` 单调不减；`interactions`/`page_unlock_wait_ms` 只归给 `sign_seq` 最小的那条（= 解锁 POST 数 + 1），其余 1 次/0；`signerd_*` **逐条与 `receipts.jsonl` 回执真值相等**（变异 C 恒 12345 / 变异 G 恒 0 必红） |
| C5 | **frontier 一变必须重解锁**：窗口内签完一条 → 有新事件 → 下一条要求解锁；页面要明确提示“尺子变了，请重新解锁” | 用例：注入新事件 ⇒ 页面进入 `awaiting_unlock` 态，签不成 |
| C6 | **失败态可读**：`awaiting_unlock`/`no_blind_sign`/`frontier_stale`/`not_a_signer` 各有明确文案与下一步（不是“出错了”）；错误不泄露密钥材料/不下发公钥 | 用例：四种失败各一条；页面/响应里搜不到私钥或签名原文之外的材料 |
| C7 | **不新增宿主依赖**：签字页在本项目内实现（M0-5 的只读控制台同一套 HTTP 栈），不对宿主提要求 | 用例：`package.json` 零新增运行时依赖；启动只绑 `127.0.0.1` |
| C8 | **权限最小**：签字页只读 + 提交签名请求；不得暴露“批量同意全部”（`docs/06` §14 禁“全部同意”式盲签） | 用例：页面无“全部同意”入口；服务端拒绝批量签同一 payload 的捷径 |
| C9 | 冻结区零改动 | `git diff f37f4dc --name-only -- docs design probe` 为空 |

## 已知边界

- `ttl_requires_window` 是页面/服务层码（不是 signerd 码），已加入 `SIGN_REASON_CODES` 闭集与失败文案表。
- TTL=0 的“单条”指一次解锁授权一次签名；`preview` 可以先列多条，但确认时会被守卫拒。
- `since_last_unlock_ms` 在旧回执/夹具中可缺省（字段可选）；新回执必带，`parseReceipt` 若出现则校验非负数字。
- 页面 `page_total_ms` 含人思考时间，仅展示；M2-G 读数用 signerd 两值 + 服务端交互计数。
- 页面不能开 TTL 窗口：TTL 由 signerd 启动参数/环境变量 `SDO_SIGNERD_WINDOW_TTL_MINUTES` 决定（页面只读取窗口状态）；`needs_window` 时需人工以 TTL>0 重启 signerd 后从页面重新解锁。
- 成本表归因按 `sign_seq`（实际签名顺序），不按 `created_at`；`created_at` 只决定页面展示顺序。
- `interactions` 是服务端可观测的 POST 数（解锁 POST + 本次确认 POST），不是 DOM 点击；同窗口重复 unlock 会真实增加该值。
- 页面计时 `page_total_ms` 与成本 `at` 统一用注入时钟；真实运行时注入时钟即系统时钟，`page_total_ms` 含人思考时间、仅展示。
