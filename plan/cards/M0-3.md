## 意图

把「视图是数据」这句设计变成可以查的东西：13 个视图全部建在库里、目录 `view_catalog` 自描述、**新增视图只加一条 INSERT 不改代码**。这一卡之后，agent 与 PM 的第一动作是 `sdo_query(view:'list')`，而不是猜表名。

## 对齐

- 复述：这一卡不写查询工具、不做预算与游标（那是 M0-4），只保证“问什么、答什么、谁能看”这三件事在库里是说清楚的；视图 SQL 只读，目录里的 `columns`/`doc`/`min_right`/`row_budget` 不是注释而是数据。
- 人确认：pending（收卡前会问；不默认通过）
- 正例 1：`INSERT INTO view_catalog` 一条新视图（迁移里）→ 目录多一行、`viewsForRight('reader')` 能列出它，**代码零改动**。
- 正例 2：`pm_queue` 在夹具上返回 ≤7 行且顺序与 `docs/05` §10.1 写死的排序一致（同一 `as_of` 两次查询逐行相同）。
- 反例：把 `pm_queue` 的 SQL 写成 `SELECT … ORDER BY since`（丢排序）或在视图 SQL 里塞 `DELETE`——前者测试红、后者被静态校验拒。
