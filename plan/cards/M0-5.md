## 意图

给人三个能看的页面（总览 / board / plan），**页面上的每个数字都能用 `sdo_query` 复算**。M0 只做“独立只读页”，不赌宿主插槽——`docs/05` §8 的一级页面是最终形态，本卡先把它跑通。

## 对齐

- 复述：这一卡不做交互式审批、不写事件、不做宿主插件；它只把 13 个视图里的数字渲染成三页，并且保证“页面上没有第二个真源”。
- 人确认：pending（收卡前会问）
- 正例 1：空库启动 `node lib/src/ui/serve.js`（或 `npm run console`）⇒ 三页可开，总览显示 `stage=unset / health=green`，board 显示 0 张卡。
- 正例 2：插一张卡（事件序列）后刷新 ⇒ 总览的“卡数/红过/待确认”三个数字与 `query('overview')` 逐字段相等。
- 反例：页面把数字写死在模板里（空库也显示 3 张卡），或页面自己开 SQL 读表 —— 都算 C2/C3 失败。

## 已知边界

- M0 只做“看图”，不做审批/签字（P10 在 M2）；总览里的“PM 队列”是 `pm_queue`（PM 的下一步，≤7 行，只读），**不是待审队列**；待审是 `attention`/`review_queue`，M2 才做交互。
- 没有登录/身份：页面以固定 `decider` 或可配置 right 读（本机只读）。
- 不承诺实时推送：刷新才更新；M2 再接事件流。
- 控制台固定读取权限（默认 `decider`，`SDO_CONSOLE_RIGHT` 可改）：M0 无登录身份、不区分人/agent，权限裁剪的生产消费者仍是 M0-4 的 `query()`（视图级；列级 human_only 见 `plan/03` D-016）。
- 数据经 `sdo_query`：单次 ≤8KB、`row_budget` 截断；截断时页面明确提示，控制台**不提供**续查按钮（`next_cursor` 留给调用方）。
- 库必须已迁移：控制台自己**不迁移/不建表**；`user_version=0` 或 `view_catalog` 空 ⇒ 启动即失败（fail-closed），无明文/降级路径。
- 数字来源只允许 `view_catalog` 里的视图；页面不直接读表，新增页面=新增视图+渲染器（不要在任何界面文案里写死视图数量，目录会变）。
- 与 `docs/05` §9 八页定位的差异（已按 Lead 要求逐条对齐 README）：本卡 `/board`、`/plan` 合起来是 §9「计划」页的两个面（任务板面 / 依赖链面），不新增第八页序号；§9「总览」的三问 M0 只做第 1 问的数字层（第 2/3 问需 intent/impact 视图，M1+），点数字下钻 M2；§9 待审/证据/缺陷/团队/审计/设置 M0 不做（待审只以 `pm_queue` 前 7 行在总览露出，无批准按钮）。
- 总览第 2–3 问（“改了影响什么 / 为什么”）M0 不做：需要 intent/impact 视图与事件链钻取，M1+；M0 只做第 1 问的数字层。
- plan 页的分解树折叠与拖动排序 M2：M0 只按 `seq` 平铺计划行，不实现树形折叠。
- 语言：`docs/05` §9 要求界面跟随宿主 locale（`zh_CN` 缺省、`en_US` 二包）；M0 独立页无宿主 locale，界面中文硬编码，i18n 留 M2。
- 评审 P3 已知边界（本轮不做）：①C3 静态扫描是 best-effort（可被动态拼接/间接调用绕过，真正的只读保证在 `query()` 的 SELECT-only 校验与 DB 只读面）；②页面多次 `query` 的 `as_of` 取 overview 的 frontier，未做“同一快照”隔离（M0 视图只读表、无并发写者，M1 写网关后再收紧）；③表格列名按硬编码渲染，未与 `view_catalog.columns` 逐列校验；④HTTP 状态码按原值返回，500 与 HEAD 的独立用例未做；⑤`renderPage` 不转义数值以外的结构（当前模型只有字符串/数字，JSON 单元格走 `display`）。
