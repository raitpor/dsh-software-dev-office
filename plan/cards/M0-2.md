## 意图

把“事件是唯一真源”变成代码：一个**纯函数**把事件序列折成当前状态，重放两次逐字节相同，未知事件一律炸而不是悄悄跳过——视图（M0-3）与门禁（M2）都只能从它读数。

## 对齐

- 复述：这一卡不建视图、不落库，只回答“给定这串事件，现在的事实是什么”；它的输出会被 M0-3 的 13 个视图直接消费，所以**可重放**和**不静默吞事件**是硬要求。
- 人确认：pending（收卡前会问；不默认通过）
- 正例 1：同一串事件喂两次，`JSON.stringify(fold(events))` 逐字节相等（键序稳定）。
- 正例 2：一条 `assumption.disposed` 带无效 `decision_id` 时，fold 产出的假设仍为 `open`（不是被“处置”了）。
- 反例：fold 里有 `if (kind === 'x') { ... } else { /* 忽略 */ }`——未知事件被吞，等于真源可丢。

## 判据

| # | 判什么 | 怎么跑 | 正例 | 负例 |
|---|---|---|---|---|
| C1 | 纯函数 | 静态检查 + 一次运行 | 无 `fs`/`Date.now`/`process.env`/随机；输入只有 events 与起始状态 | 函数里读时钟或写库 |
| C2 | 重放确定性 | 同串事件 fold 两次 + 打乱输入以外的东西 | 两次序列化逐字节相同 | 靠对象键序碰巧相同 |
| C3 | 幂等 | 同一条事件投递两次 | 结果不变（幂等键：`(spec_id,input_id,旧 hash)` 或事件 id） | 重复投递导致计数翻倍 |
| C4 | 规则对得上设计 | 把 `docs/02` §6 的折叠规则逐条列成表，一条一测 | 每条规则有正例 + 一条反例 | “大部分对” |
| C5 | fail-closed | 未知 `kind` / 缺字段 / JSON 坏 | 抛错并带事件 id 与 kind | 静默跳过 |
| C6 | 不污染冻结区 | `git status` + `make all` + `make test` | 零改动、全绿 | 顺手改文档 |
