# M2-0 · 认证与签字链地基（signerd + 解锁 + 免密窗口）

## 意图

M1 的 `decision` 行是**手写 `append`** 出来的：`decision.valid` 建行、`decision.signed` 补签名，`signature` 可以是任意字符串。那只是“表形状对了”，**授权链是假的**——谁都能 append 一条 `signed`。M2 的第一件事是把这个洞堵上：签名只能由 `signerd` 在**人类解锁后**产生，事件只能由插件转发。

这张卡只做**地基**：`signerd` 进程 + 解锁 + 免密窗口 + decision 真路径 + 拒绝码。baseline 冻结（M2-1）与门禁（M2-2）都建立在它之上——没有它，冻结就是“再写一条假 decision”。

依据：`docs/06` §1 三层凭据、§3 signerd、§5 decision 状态（`pending`/`awaiting_unlock` 不是 decision 行）、§7 免密窗口状态机、§14 三条可判据（`security.no_proxy_sign` / `security.no_blind_sign` / `security.window_bound`）。

## 对齐

**复述**：不是“加一个签名函数”，而是**把签名的产生权从插件搬到一个只有人能解锁的进程里**，并且让“没解锁/免密窗口过期/内容变了/agent 想签”这四种情况在**产生 decision 行之前**就被拒。签完的行还要能被 verify 认出“这条确实经过 signerd”，而不是插件自己盖章。

**人确认**：confirmed（2026-11-14T13:35+08:00，签署者确认复述「对，这是我要的」，见 `plan/sign/S11.md`）

**正例 2**
1. 解锁（口令或 passkey 模拟器）→ `sdo_act(sign)` 一条 baseline → `decision` 表出现 **1 行** `status='valid'` 且 `signature` 非空、`signer` = 解锁的 actor、`frontier` = 解锁时记录的 frontier；`verify()` 绿。
2. **一次解锁只允许一次签发**（`docs/06` §7 表格：绑定「单次签发」、签完就锁）⇒ 签完立刻回 locked，第二条必须重新解锁（`awaiting_unlock`）；解锁后**未签发前** frontier 变了 ⇒ 直接 `frontier_stale`、窗口失效。

**反例 1**
- 未解锁时 `sdo_act(sign)` ⇒ 返回 `awaiting_unlock`，**`decision` 表 0 行**（不是“先写 pending 行再补签名”）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | **signerd 是独立进程**：私钥只在 signerd 内，插件进程内存里没有解密后的私钥；通信只经 unix socket（0600），协议只有 `unlock`/`lock`/`sign`/`status` 四个动作，signerd 不判断业务、不落库 | 用例：插件侧对象图里搜不到私钥字节；socket 权限断言 0600；`sign` 请求只带 payload hash/frontier，不带业务语义 |
| C2 | **密钥落盘口径**：私钥盘上加密（Argon2id），文件 0600、socket 0600；启动时校验权限，错了拒绝启动并给稳定错误码 | 用例：把 key 文件 chmod 0644 ⇒ 启动失败（码进 README）；密钥文件内容不含明文私钥前缀 |
| C3 | **未解锁不产行**：未解锁 `sign` ⇒ `awaiting_unlock`，`decision` 行数不变（0）；`pending`/`awaiting_unlock` 是**请求态不是 decision 行**（`docs/06` §5） | 用例：断言 `count(*)==0`；再断言没有“半成品行”（无 `signature IS NULL` 且 `status='valid'` 的行） |
| C4 | **不可代签**：agent 凭据调用 `sign` ⇒ 拒（`not_a_signer`）+ 落一条告警事件；`signer ≠ producer`（同一个人不能既产又签，除非显式 waiver——M2 先拒） | 用例：agent token ⇒ 拒且 0 行；producer 与 signer 同一 actor ⇒ 拒 |
| C5 | **不盲签**：payload 缺 `proposition`（或四元组不全）⇒ `no_blind_sign` 拒，0 行；`proposition` 必须由 renderer 从 claim 生成，不由调用方随口给 | 用例：删 `proposition` ⇒ 拒；`proposition` 与 claim 渲染结果不一致 ⇒ 拒 |
| C6 | **免密必绑 frontier**：解锁后**签发前** frontier 变化（新事件）⇒ `frontier_stale`、窗口失效，**不**静默续窗；签发成功即回 locked（`docs/06` §7「单次签发」） | 用例：解锁 → append 一条无关事件 → 签 ⇒ 拒 `frontier_stale`；解锁 → 签成功 → 再签 ⇒ `awaiting_unlock` |
| C7 | **窗口 TTL**：`window_until` 到期即失效；TTL 缺省 **0（关）**，可选 5/15/60 分钟（`docs/06` §7）；免密**默认关闭**，要显式开 | 用例：把 `window_until` 拨到过去 ⇒ 拒；默认配置下解锁后不设窗口 ⇒ 签完即锁 |
| C8 | **decision 真路径**：`decision.valid`/`decision.signed` 只能由 signerd 流程产生；产品代码里不存在“直接把 `signature` 填进 `append`”的路径（静态扫描 + 运行时：裸 append 一条 `decision.signed` ⇒ 被写网关拒，码 `signature_not_from_signerd`） | 用例：直接 `append({kind:'decision.signed', payload:{signature:'x'}})` ⇒ 结构化拒绝、0 行；`src/` 里除 `src/sign/` 外零处构造签名载荷 |
| C9 | **verify 认得出**：`verify()` 能核对“decision 行的 `signature`/`key_id`/`signer`/`frontier` 与 signerd 记录一致”（signerd 留最小可审计回执，不含私钥、不下发签名原文之外的任何密钥材料）；不一致 ⇒ `runtime_inconsistent` | 用例：手改一行 `decision.signature` ⇒ verify 红；删 signerd 回执 ⇒ verify 报 `signature_unverifiable` |
| C10 | **拒绝码稳定**：`awaiting_unlock`/`not_a_signer`/`no_blind_sign`/`frontier_stale`/`signature_not_from_signerd` 进 README 错误码表，形状 `{ok:false, reason_code, message}` | 用例：每个码至少一条触发用例与一条“不该触发”的反向用例 |
| C11 | **签字成本可测**：每次签发给 `unlock_wait_ms`/`sign_ms`（写进 signerd 回执），为 M2-G 的“中位 ≤10s”提供测量点；测量不得含 UI 渲染以外的造假（不许写死常量） | 用例：两次签发的时间字段是真实测量（随注入延迟变化），读数为 0 时不通过 |
| C12 | **`security.alert` 与 `key_id`/`channel` 真的落地**：`security.alert` 进 `ACK_KINDS`（否则 append 拒 `unknown_event_kind`），`event_kind` 登记数 92→93；`decision.signed` 的 fold 把载荷里的 `key_id`/`channel` 投影进行（否则 006 加的列永远 null） | 用例：append 一条 `security.alert` ⇒ ok 且不投影到业务表；签一条 ⇒ `decision` 行的 `key_id`/`channel` 非空且与 receipt 一致 |
| C13 | 冻结区零改动 | `git diff f37f4dc --name-only -- docs design probe` 为空 |
