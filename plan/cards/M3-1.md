# M3-1 · 权限判定接线（查询投影 + 写路径 no_permission）

## 意图

把 M3-0 的矩阵接进两条真实路径：**读**（`sdo_query` 按 actor 的 read 权过滤，miss 记 `filtered_by_permission`）与**写**（每个动作查自己的权，越权 ⇒ `no_permission`、不落事件）。M2 之前权限是静态矩阵 + 代码注释，这张卡把它变成运行时事实。

## 对齐

**复述**：读和写用同一套权——读不到不是「空结果」而是「权限 miss」（可解释、可计数），写不进不是「静默失败」而是结构化 `no_permission`。`docs/07` §2 的每个动作在写路径上有且只有一处检查点，检查点清单要能被机器比对（少一个就红）。

**人确认**：pending

**正例 2**
1. reader 的 actor 查 `pm_queue` ⇒ 行被过滤且 `miss.reason='filtered_by_permission'`（`query_miss` 可聚合），不是返回 0 行假装没数据。
2. 无 `write@module:src/db` 的 actor 写 `task.created` ⇒ `no_permission`、event 0 行、链头不变。

**反例 1**
- 越权后「部分成功」（写了一半事件）⇒ 必须整批回滚，不许留半条。
