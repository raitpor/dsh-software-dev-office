## 意图

让 SDO v2 有一个能跑测试的最小骨架，使 M0-1..7 可以三条泳道并行开工；同时把“加密 SQLite 到底装不装得上”这个会杀死里程碑的问题在第一天定死。

## 对齐

- 复述：你要的是“开始写代码”，但先要有能承载后续七张卡的地基——包括构建、测试、目录约定、以及数据库驱动的选型结论。不是先做功能。
- 人确认：**pending**（这条复述未经你点头；若你否掉，骨架仍可复用，只是选型结论要重做）
- 正例 1：`npm test` 能跑通一个 hello 级测试，且测试文件与源码分目录。
- 正例 2：驱动 spike 的两种方案各自跑过一次“建库 → 加密 → 关闭 → 重开”的实测，结论带命令与耗时。
- 反例：只写了 `package.json` 与目录、没有任何可执行测试——那叫脚手架，不叫骨架。

## 判据

| # | 判什么 | 怎么跑 | 正例 | 负例 |
|---|---|---|---|---|
| C1 | 安装与构建可重复 | `npm ci && npm run build`（或等价的 `make test`） | 干净目录一次通过 | 依赖 lock 缺失或需手动步骤 |
| C2 | 测试骨架可跑 | `npm test` | 至少 1 绿 1 故意红（红证明确实跑了断言） | 全绿但无断言（空跑） |
| C3 | 目录约定落地 | 看 `src/{core,db,views,query,ui,sign}` 与 `test/` 的对应关系 | 每个目录有 `README` 或入口文件说明职责 | 目录空建、无线索 |
| C4 | 驱动选型有结论 | 记录两条候选的命令、结果、耗时、失败原因 | 结论 + 复现命令 | “我觉得 A 更好” |
| C5 | 不污染冻结区 | `git status` 与清单核对 | `docs/`、`design/` 零改动（等于 `frozen/design-v2.0`） | 顺手改了文档 |

C5 是硬判据：**骨架卡不许碰尺子**。
