# M3-4 · 渲染器注册目录（收口 D-034）

## 意图

M1-6 时 `claim.derived_by` 只靠 `view_catalog` + 常量代理（D-034），M3 补真目录：`renderer_catalog` 登记“渲染器 id → 实现模块 → 可渲染哪些视图”，`claim` 行只认已登记渲染器；未注册 ⇒ `renderer_unregistered`。

## 对齐

**复述**：结论行不是谁都能写：只能由**已登记的渲染器**从视图行渲染出来，登记即代码（注册行指向 `src/` 里的实现），没有第二条路。M1-6 的常量代理是临时替身，本卡换成真目录，并让 `verifyClaims` 能核对“这条 claim 的 `derived_by` 真的存在且能渲染它引用的视图”。

**人确认**：pending

**正例 2**
1. 注册 `renderer:claim-v1 → src/claim/render.ts` ⇒ `writeClaimRows` 接受；未注册 id ⇒ `renderer_unregistered`、0 行。
2. `verifyClaims` 检查 `derived_by` 在目录内、登记声明的 `views[]` 覆盖实际来源视图。

**反例 1**
- 手写 claim 行（不经渲染器）⇒ 拒；直插库 ⇒ `verifyClaims` 报 mismatch。
