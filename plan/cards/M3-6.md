# M3-6 · 列级裁剪（收口 D-016）

## 意图

M0-4 曾裁定“列级裁剪 M0–M2 不做”（D-016：`view_catalog.columns` 无 `human_only` 标记、查询层也没有 actor 身份）。M3 有了 actor 身份，把 `human_only` 列标记补上并在查询层裁剪：agent 读不到人工专用列。

## 对齐

**复述**：不是“少显示几列”，而是**agent 拿不到不该拿的列**：`view_catalog.columns` 每列带 `human_only`，查询层按 `actor_kind` 裁剪，并把“被裁掉的列”记成显式事实（可解释）。这需要 v2.1 文档追认（冻结区不能原地改），代码先按此口径实现并记账。

**人确认**：pending

**正例 2**
1. 某列 `human_only:true` ⇒ agent 查询结果不含该列，且返回的 `columns` 元数据与实际列一致（不是悄悄少一列）。
2. human 查同视图 ⇒ 列齐全；reader 权限不足时行级 `filtered_by_permission` 仍生效（行级与列级叠加，不互相绕过）。

**反例 1**
- 列标记只写目录没进视图定义（或反之）⇒ 检查红（两处机器一致）。

## 已知边界（第 2 轮补充）

- **总览页新增 `team` 表**是为让“列级裁剪”走产品渲染真链路（`team` 是 13 视图里现成含
  `human_only` 列的唯一视图）；`/board`、`/plan` 没有 human_only 列，不承担该证据。该表只读、
  数字/行仍来自 `query('team')`，不新增视图、不改排序口径（D-011）。
- 无会话身份时控制台拒绝启动（失败码=进程退出/抛错），**不提供“空白页 + 0 读数”降级**；
  这是有意的 fail-closed，覆盖 M0–M2 的 `SDO_CONSOLE_RIGHT` 兼容路径（该参数保留只为环境
  校验，不再决定可见性）。
- `redacted_columns` 只含列名不含值；HTML 只提示“已隐藏 N 列”，不回显被裁列名/值。
- **`/sign` 不经过 `requireAccess`**：签字页（M2-6）有自己的身份/签名窗口模型，不需要
  `ConsoleAccess`/`SDO_CONSOLE_ACTOR`；“无 session 即拒”只约束三条只读页（`/`、`/board`、
  `/plan`），不覆盖 `/sign`。`SDO_CONSOLE_RIGHT` 自 M3 起仅日志/兼容，不参与判权（M4 删）。
