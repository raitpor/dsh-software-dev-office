# M3-2 · 冲突可见（`conflicts` 不是 `disputed`）

## 意图

两人并发改同一对象的同一字段：**一个成功、一个 409**，失败者的主张不丢——进 `conflicts`（双方主张 + 时间 + 各自基于哪版），等人裁决。与 `disputed`（对同一事实的两种判断，走评审）严格分开：冲突是“写不进去”，不是“说得不一样”。

## 对齐

**复述**：冲突不是错误、也不是分歧，是**同一处被两个人同时写了**这个事实。系统必须让失败者看到“你要写什么、对方写了什么、你基于哪版”，并且**不许自动合并**（M3 不做 CRDT、不做 last-write-wins）。冲突行由事件派生，裁决走人签，不进 `disputed` 通道。

**人确认**：pending

**正例 2**
1. A、B 同时改 `spec` 同一字段 ⇒ 先提交者 `ok`，后者 `conflict`（409 语义、带 `conflict_id` 与 `base_hash`），`conflicts` 视图出现一行含双方摘要。
2. 人签 `decision(kind='sign')`（载荷 `extra.conflict_resolution={conflict_id, adopted_actor, note}`，D-089）采纳一方 ⇒ 冲突行 `resolved`、被采纳方重放回链、另一方 payload 留在冲突行里可追溯。

**反例 1**
- 把冲突写进 `disputed`（或反过来）⇒ 检查红：两个集合不许互相污染。

### 冲突检测的入列/不入列（Lead m08516 裁定）

强制声明的是内容编辑类 kind（当前 `spec.revised[clause]`、`criterion.revised[remedy]`）；豁免的是生命周期迁移与单写者产生的事件（`task.*` 的状态迁移、`config.changed`、`goal.reparented`、`restatement.diff_dispositioned` 等），它们不并发覆盖同一字段。

| kind | 是否要求 CAS 声明 | 理由 |
|---|---|---|
| `spec.revised` | 是（`field='clause'`） | 并发编辑同一需求的条款正文会静默覆盖对方措辞（lost update） |
| `criterion.revised` | 是（`field='remedy'`） | 并发编辑同一验收判据的正文/补救，直接影响门禁语义 |
| `task.*` 生命周期（claimed/done/reopened/blocked/unblocked/assigned/unassigned/dropped/dependencies_changed） | 否 | 由 M3-1 租约 + 权限保证单写者；非法迁移由状态守卫拒，不吞内容 |
| createOnce 类（`*.defined`/`*.registered`/`*.recorded`/`*.proposed`…） | 否 | 只建不覆盖，同 id 不同内容由 reducer 直接拒 |
| `decision.*` / `release.*` / `gate.judged` / `stage.exited` / `assumption.disposed` / `assumption.invalidated` / `restatement.invalidated` | 否 | 由 signerd 一次性能力或签名决策单点产生；payload schema 固定，伪造由能力/签名兜底 |
| `config.changed` / `goal.reparented` / `restatement.diff_dispositioned` | 否 | operator/单写者路径（M1-5 审计 + 权限）；并发可见性留 M3-4 视图评估 |
