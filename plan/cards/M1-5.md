# M1-5 · preview 的 `rework_units`

## 意图

`docs/01` 把「返工面可见率 100%」写成硬指标：变更的回执里**必须有一个数字**说清“这次改动要作废多少已完成的工作”。这一卡只做那个数字：给定一次变更（事件批），算出 `rework_units` = **因本次变更作废的已完成 `work_unit` 数**，并与 `will_change` 同源同算、一起返回（`docs/11` §7.5：只给影响面不给返工量，等于让人自己心算代价）。

`docs/04` 的 `change.rework_counted` 判据是它的验收对手：payload 缺 `rework_units`、或写 0 但实际作废 2 ⇒ 红；**手填不算**，必须工具算。

## 对齐

**复述**：不是“数一数受影响的对象”，而是**在 fold 内存态上试算一次变更**：把变更事件批"假如追加"到当前事件流后面重放一遍，比较前后 `work_unit` 集合——**在变更前存在、变更后不在**的行就是作废单位。因此它必须用与真实落库**同一套 fold**（`src/core/fold`），不能另写一套判定。

## 实现口径（M1-5 落定）

- **有效集合差**：`work_unit` 在 fold 里只增不删（`src/core/fold/reducers/workunit.ts` 只有 `materializeWorkUnit` 的 upsert；`task.reopened` 只改 task 行），字面“集合差”恒空。M1-5 落定口径：变更前存在的单位，变更后满足任一 ⇒ 作废——①该行本身 hash 变或行消失；②它引用的 `task`/`criterion`/`evidence`/`spec` 任一行 hash 变或行消失。Lead 已核并采纳（**D-037 gap** 由 Lead 记：`work_unit` 无删除/失效载体，M1 用有效集合差近似；v2.1 若要字面集合差必须先补事件语义）。
- **计数不重复 + 证据**：一条单位只计 1；证据 `{task_id, criterion_id, spec_id, changed_refs[]}`，`changed_refs` 列出触发行（`work_unit:<id>` / `task:<id>` / `criterion:<id>` / `evidence:<id>` / `spec:<id>`）。
- **“hash 变”口径**：`rowHash(row)=sha256Hex(canonicalJson(row))`（`src/core/fold/canonical.ts`，64 hex 无前缀，与 `computeEventHash` 同一套 canonical JSON）。这是**实现约定**、不是设计条款：`docs/11` 只说节点 hash 变，未规定行粒度摘要；选它是因为 fold 不存 per-row 版本号且键序稳定。对应关系：docs/11 §2“内容变（hash 变）⇒ 失效但不删除” + §3“已完成 task 复开”。
- **不碰 `src/core/`**：没有为凑字面集合差给 fold 加删除语义（`docs/03:35` 没有规定 `work_unit` 删除；跨写域）。

**人确认**：pending（收卡前必须确认）

**正例 2**
1. 现有 3 条已完成 `work_unit`，变更把 `SPEC-1` 的条款内容改掉（`spec.revised`）⇒ 引用 `SPEC-1` 的 3 条全部作废：`reworkUnits=3`、`willChange` 含 3 条 `work_unit` 路径（`invalidated`）、两者同一次调用返回。
   - 原拟用例“把 `criterion` 的 `spec` 绑到另一条 `spec`”**不可达**：`criterion.spec_id` 只在 `criterion.registered` 时定，`criterion.revised` 只改 `remedy/status_enum`（fold 事实）；改用 `spec.revised` 是同语义替换（Lead 已批）。
2. 变更只动一条不相关 `spec` 的条款、没有任何 `work_unit` 依赖它 ⇒ `reworkUnits=0`（数字 0，不是 `null`/`undefined`/`"0"`）。
3. **对照**：只改一条没有 `work_unit` 的 `task` 的无关字段（`task.assigned`）⇒ `reworkUnits=0`，但 `willChange` 仍列出该 task 行——证明不是“见了变化就全算作废”。

**反例 1**
- 调用方在 payload 里自带 `rework_units: 0` ⇒ 被忽略（或直接拒 `invalid_args`），输出仍是工具算出的 2。

## 已知边界

- `work_unit` 未物化（M1-0 只物化 7 张表）⇒ 本卡只读 fold 内存态；若将来物化，口径不能变。
- `work_unit` 无删除/失效载体 ⇒ M1 用“有效集合差”近似（D-037，Lead 记）；字面集合差需 v2.1 先补事件语义。
- 空批的 `payloadHash` 没有库状态可锚（只表示“没有变更”）；非空批靠事件 `prev`/`hash` 锚链。
- `previewChange` 的批接受规则与 `append()` 同源但**不是同一次执行**：preview 只做校验+fold 试算，
  真正的 UNSET/UNIQUE/物化安全网仍只在 `append()` 里发生。
- **行 hash 口径是实现约定**：`rowHash=sha256Hex(canonicalJson(row))`；`docs/11` 只说“节点 hash 变”，未规定行粒度算法。换 canonical 序列化口径会改变作废判定，须同步改测试与文档。
- `preview` 行（`docs/11` 的 `preview_id`/`expires_at`）不在本卡，记 D-033。
- “作废”只覆盖 `work_unit`；其他对象的失效（`spec` 作废等）不折算成 `rework_units`，那是 `will_change` 的事。
- `will_change` 只报 fold 内存态的直接行差 + 被作废的 `work_unit` 路径，不是 `docs/11` §3 的完整复位传播（完整传播归 M2 change 链）。
- ~~**C6 非零样本的 append 路径被 M1-0 挡住**~~ **已关闭（D-038，M1-7 全表物化后）**：`task.*`/`evidence.attached` 现在可经写网关真落库，非零样本改走真 `append` 对账（见 C6/E4）。旧的“折网关直插事件行 + fold 重放”只保留为同用例内的对账段，注明不是替代路径。
- 测试夹具绕网关直插 `event` 行只为造出 `work_unit` 前置状态（生产路径不这么做）。
- `evidence.attached` 的 `command:'node --test'` 是**合法可执行命令**（001 `evidence.command` NOT NULL），不是为过约束塞的假值（评审确认）。
- 同用例里 `deepEqual(replay, actual)` 两侧都经 `collectInvalidatedWorkUnits`，只证明 **fold 确定性**，不是第二份独立证据；独立证据是 preview 的对象（fold 试算）与 append 后落库链重算的对象分别构造。
- `work_unit` 行数不变只说明“作废是有效集合差、不删行”；行内容另用逐行 deepEqual 钉住（见 C6/E4）。
