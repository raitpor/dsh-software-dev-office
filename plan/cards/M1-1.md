# M1-1 · 判据框架（注册门槛 + 适用性 + 有效绑定）

## 意图

`docs/04` 说判据不是检查清单，是**可复算的断言**；而它值不值维护成本，取决于「冤枉过几次人」和「抓到过几条真缺陷」。这套东西要能跑，先得有**注册路径**：一条判据没有 `remedy`、没有正例、**没有负例**、超预算、或者没声明守哪条保证——都不许进。

这张卡不给 24 条判据写实现（那是后续卡的事），只建**框架**：目录（code → 适用性 / 保证 / remedy 形状）、注册（五道门槛）、以及**有效绑定**的机械算法（M1-3 的 P15 要用它判 `core_not_effective`）。

## 对齐

**复述**：这卡交付的不是“判据库”，而是“**判据能不能进门的规矩**”。其中最贵的一条是负例——v1 只管“改坏会红”，从不管“不该红的不红”，于是“逼人灌水才过”的判据只能靠评审肉捕。所以**负例缺失 = 注册被拒**，不是警告。

**人确认**：confirmed（2026-11-14T12:39+08:00，签字见 `plan/sign/S7.md`）

**正例 2**
1. 注册一条判据：`remedy` 非空、1 正例夹具（跑 `pass`）、1 负例夹具（跑 `fail`）、单次 < 200ms、`guarantee='1'` ⇒ 成功，`criterion` + `criterion_fixture` 行落库，`verify` 绿。
2. 对 core 三条（`spec_set.signed` / `assumption_set.signed` / `provenance.present`）跑有效绑定：全部 5 条条件满足 ⇒ `effective=true`；把某道门的 `waivable` 改成 true ⇒ 该判据 `effective=false`、原因 `waivable_gate`。

**反例 1**
- 注册一条**只有正例、没有负例**的判据：`docs/04` §6 明写“没有负例夹具的判据不可 `active`——由注册校验（写入路径）保证”，实现却放行 ⇒ 这条判据将来红的时候没人知道是不是冤枉人。

## 判定

手工（M1 无 baseline）：`effective` 与原因码都必须是**结构化返回**；P15（M1-3）会消费它，形状先按 `{criterion_id, effective, reasons[]}` 定死。

- C1 **pass**：目录是文档的机械快照；变异①证明少一条就红。
- C2 **pass**：五条拒绝码各一负例；`register.ts` 本身零写入，注册只有 `criterion.registered` 一条事件路径（C8）。
- C3 **pass**：三向 `fixture_mismatch`；变异②把语义比较关掉后 C3 用例红。
- C4 **pass**：只算 core 三条，3 / 2 两档读数。
- C5 **pass**：五条件 + 五个具体原因码，另含表约束型判据不参与 gate。
- C6 **pass**：`stage_gap` 是“该 stage 出口没合格 gate”，不是“某处有 gate”。
- C7 **pass**（结构保证 + 用例）：API 无 delta 入参、实现不读 `assurance`；用例运行时塞 delta 不改变结果。**已知边界**：这是“框架不给后门”，不替代 M1-3 对 baseline 声明与目录的交叉校验（A2）。
- C8 **pass**：生产代码零 `INSERT INTO criterion*`；夹具只由 reducer 在同一次 fold/materialize 里写。
- C9 **pass**：冻结区 0 diff。
- C10 **pass**：载荷扩展按 D-032 裁定 ①；reducer 同事务写两表；`verify` 绿；半套夹具不会出现（冲突时整批回滚）。
- C11 **pass**：`MATERIALIZED_TABLES` 8 张；`criterion_fixture` 不加入 `VERIFIED_TABLES`——verify 的对账面仍是 4 张投影（task/spec/release/decision），夹具行由写路径安全网与 DDL 约束保证，不与 M0-6 口径冲突。

### 已知边界

- `criterion_fixture` 不进 `VERIFIED_TABLES`（见 C11）：verify 的判断面保持“4 张投影”，夹具靠 reducer 事务 + DDL 约束；若后续要把夹具纳入 verify 对账，是独立卡的口径变更。
- C7 的“无后门”是**本模块 API 形状**的保证；M1-3（P15）必须只通过 `evaluateBinding` 消费，不得在 CLI 里另写判定。
- M1-2 的 C5 现在可以生产绿：注册带 2 正 1 反的判据走 `criterion.registered`（含 `fixtures[]`）即可，无需直插 `criterion_fixture`。
- 本卡未新增事件 kind、未改 `criterion` 表 DDL；`criterion_fixture` 已存在于 001 迁移。
- `legacy: true` 的三点限制：只许 M1-6 导入路径使用、必须被 `verify` 计数暴露、M1-G 读数不得用它取证；除此之外没有后门。
- `status_enum` 取值校验不在本卡：`registerCriterion` 不校验它（注册方给），reducer 也只做字符串收窄（缺省 `draft`）；M1-2 的判据生命卡若要限定枚举，应加在那张卡的 reducer/校验层。
- `criterion_fixture` 进物化集但**不进** `VERIFIED_TABLES`：verify 不对夹具表做双向对账。
