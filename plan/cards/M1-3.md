# M1-3 · P15 静态校验器（对 baseline 文件）

## 意图

`docs/04` 的 baseline 是“尺子”，但尺子本身要先能验：空 gate、未注册判据、core 三条没真绑上、缺 `engine`——任何一条不过就不该冻。M1 还没有签字链，所以这张卡**只做校验**：吃一个 baseline 文件（JSON），吐出 `{ok, reason_codes[]}`。

关键边界（`docs/09` §16.2 写死）：**不落冻结、不写 `baseline.rejected`、不产生任何事件**。`baseline.rejected` 是“冻结失败”的记录，属于 M2 的冻结事务；这里只是“文件校验不过”。

## 对齐

**复述**：不是“写个 schema 校验”，而是把 `docs/04` §5.2 的 ①–⑪ 十一条**机械判定**做实，尤其第 ⑦ 条——**先按判据的保证元数据算出 `guarantee_delta`，再查 core 三条是否在每个适用的 stage 出口都“有效绑定”**。这条是整套东西最容易被糊过去的地方：core 可构造的漏法有**三种**——塞进 `any_of` 门、放进可豁免的 gate、少绑某个检查点 stage（“core 绑到 `na` 阶段”构造不出来：core 三条的 `applies_to` 都是 `ALL_KINDS`）；另加**结构性前置**（policy 连 requirement kind 都缺，见 C7）。

**人确认**：pending（收卡前必须确认）

**正例 2**
1. 一份合法 baseline（瀑布 preset，五 stage，每 stage 一个 `all_of`/`waivable=false` gate，gate 内含 core 三条）⇒ `{ok:true, guarantee_delta:{1:'kept',2:'kept',3:'kept'}, reason_codes:[]}`。
2. lite policy（缺 `design`/`review` kind）⇒ `{ok:true}`，但 `guarantee_delta` **1/2/3 三条全 `degraded`**（保证 2 因 `design.alternatives_declared` 是 design-only 判据、没有 design kind 阶段可绑）并逐条列出缺的判据（**不是拒**，因为 core 三条在每个存在的 stage 出口仍有效）。

**反例 1**
- `criteria: []` 的空 gate ⇒ `{ok:false, reason_codes:['gate_empty', 'core_not_effective']}`（两条：空 gate 本身 + core 随该 gate 失效；卡面期望码集合见“负例期望码集合”表）。

## 结构错口径（P2-3）

结构错**只出一个码**，且**不产任何业务码/级联码**：`reason_codes` 恰为 `['stage_bad_kind']`、`['duplicate_gate_id']` 或 `['invalid_baseline']`；`guarantee_delta` 三项统一 `degraded`（fail-closed）；**不带 `missing`**。业务码只在结构合法时出现。

| 结构错 | code |
|---|---|
| stage `id` 空/非字符串、`kinds` 非数组/空/含非法 kind | `stage_bad_kind` |
| 非对象输入、`stages` 非数组或为空、stage/gate 不是对象、`after` 不是非空字符串数组 | `invalid_baseline` |
| `gates` 非数组、gate `id`/`stage` 不是非空字符串、`criteria` 不是非空字符串数组 | `invalid_baseline` |
| `policy_mode ∉ {all_of, any_of}`（大小写敏感）、`waivable` 非 boolean、`policy.gates` 不是 stage→string[] 映射 | `invalid_baseline` |
| `assurance.na_stages` 不是字符串数组、或含非法 stage kind（与 `kinds` 同一套判定） | `invalid_baseline` |
| `gates[]` 里出现重复 gate `id` | `duplicate_gate_id` |

短路优先级：其余 generic 结构错（先 `return`）> stage 形状错（`stage_bad_kind`）> 重复 gate id（`duplicate_gate_id`）。stage 形状坏的 stage **不再校验它的 `after`**（形状错优先，注释已按实现改）；别处另有 generic 结构错时以 `invalid_baseline` 为准。
`criteria: []` 不算结构错（走 `gate_empty`）；重复 stage id 走业务路径（`stage_bad_kind`，delta 仍按目录计算）。
`duplicate_gate_id` 选“拒收”而非“不管”：重复 gate 定义会让 `find` 首条生效、第二条只参与绑定扫描，绑定读数含混。`index.ts` 的非对象短路与 `validate.ts` 的 `structuralFailure` 同口径（全 `degraded`），不再出现 EMPTY 返回全 `kept` 的两套语义。
