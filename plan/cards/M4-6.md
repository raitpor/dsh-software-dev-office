# M4-6 · 人类签字样本采集（R4 承接）

## 意图

M2 门（S19）与 M3 门（S29）两次都是 `overall partial`，唯一原因是 R4「人签中位 ≤10s」**没有人类样本**（`human_samples=0`），只有工具侧代理。M4 是影子期：项目所有者真的用签字页签几次，把 `unlock_wait_ms`/`sign_ms` 采到 ≥5 条，再按同一口径重出读数。**这张卡的价值不是“凑够 5 条”，而是第一次让人类进环路、并留下可复算的证据。**

## 对齐

**复述**：样本来自**真流程**（真 `signerd`、真输入口令、真点确认），不是脚本注入；每条样本记 `sample_id`/`at`/`decision_id`/`unlock_wait_ms`/`sign_ms`/`interactions`/`note`；样本落 `plan/milestone/M4-人类样本.json`（人可读 `M4-人类样本.md`），**不进 baseline、不进事件链**（这是测量数据，不是真源）；采到 ≥5 条后重跑 M2/M3 的 R4/R5 类读数，`partial → pass` 只在样本数与口径都成立时发生。

**人确认**：pending

**正例 2**
1. 项目所有者用 `/sign` 页签一条真实决策 ⇒ 回执里 `unlock_wait_ms`/`sign_ms` 是真值（不是 0、不是注入），样本文件多一行。
2. 采到第 5 条后复跑读数 ⇒ R4/R5 变 pass，报告里写明“样本 5 条、中位 X ms、采集时点”。

**反例 1**
- 用脚本伪造 5 条样本（`sign_ms` 由 `--inject` 填）⇒ 视为造假：样本必须能追到真回执与真 decision。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | 样本文件结构：`{samples:[{sample_id, at, decision_id, unlock_wait_ms, sign_ms, interactions, signer_kind:'human', note}]}`；每条 `decision_id` 在库中存在且 `signature` 非空 | 用例：读文件逐条查库 |
| C2 | 样本来自真回执：每条能追到 `receipts.jsonl` 的 `receipt_id`（或 signerd store 对应行），且 `sign_ms` 与回执里的一致（不是采样后手改） | 用例：对账回执 |
| C3 | 采集过程无注入：脚本不接受 `--inject-delay`；若检测到 `injected_delay_ms` 字段 ⇒ 该样本标 `contaminated:true` 且不计入中位 | 用例：注入样本被排除 |
| C4 | 样本量门槛：`humans ≥ 5` 且 `distinct_decision ≥ 5`（同一决策签两次不算两条）；不足 ⇒ 读数照实 `partial`（不许四舍五入） | 用例：4 条 ⇒ partial、5 条 ⇒ pass |
| C5 | 重出读数：M2 R5 / M3 R4 的 `human_samples`、中位数、`partial→pass` 全部由样本文件现算（不许写死） | 变异：改一条样本的 `sign_ms` ⇒ 中位跟着变 |
| C6 | 隐私：样本文件不含口令、不含 socket 路径、不含 key 材料；`note` 只写可公开内容 | 用例：正则扫 `passphrase`/`key`/`token` |
| C7 | 冻结区零改动 | `git diff f37f4dc -- docs design probe` 为空 |
