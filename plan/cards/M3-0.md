# M3-0 · actor/scope/right 身份层与决策权矩阵机器化

## 意图

把「权」从代码里散落的 `if` 变成可查的真源：`actor`（谁）、`scope`（在哪）、`right`（能做什么）三张表 + 迁移 008；`docs/07` §2 的决策权矩阵变成**机器可解析的目录**（动作 → 所需权 → 可否自签 → 可否双人），代码只查目录、不写死判断。`actor` 必须由会话凭据证明，不能由调用方在 payload 里自称（收口 D-056）。

## 对齐

**复述**：不是「加个登录」，而是**一次动作先回答三个问题**：谁在做（actor 来自会话）、在哪个域做（scope 前缀）、有没有这个权（right 查表）。权绑 scope 而不是绑角色——同一个人可以在 A 模块写、在 B 模块只能评审。矩阵是数据不是代码：新增动作要在目录里登记，未登记一律拒（fail-closed）。

**人确认**：pending

**正例 2**
1. `hasRight(human-1, 'write', 'module:src/db')` ⇒ allow；同一 actor 对 `module:src/ui` 无 write ⇒ 拒 `no_permission`（结构化，带 action/scope/actor_kind）。
2. 迁移 008 在空库建三张表并写缺省矩阵行；二次迁移 `applied=[]`；矩阵目录与 `docs/07` §2 表格机器比对（文档新增动作而未登记 ⇒ 红）。

**反例 1**
- payload 自带 `actor: 'someone-else'` ⇒ 拒（`actor_not_from_session`），不许「以 payload 为准」。
