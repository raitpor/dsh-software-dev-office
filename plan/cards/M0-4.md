## 意图

把 `view_catalog` 变成唯一读入口：`query(view, args)` **只执行目录里的 SQL 子查询**，按 `min_right` 裁剪并留痕，超预算就截断给游标、绝不静默，每次都带 `as_of`。这一卡之后，“缺什么视图”有使用记录可查（`query_miss`），而不是靠人猜。

## 对齐

- 复述：这一卡不新增视图、不写业务事件、不做写网关；它只回答“给定一个视图名与参数，我能看到什么、为什么看不到、到哪一组事件为止”。
- 人确认：pending（收卡前会问；不默认通过）
- 正例 1：`query('pm_queue', {})` 返回 ≤7 行 + `as_of`，同一 `(view,args,as_of)` 两次调用逐字节相同（含行序）。
- 正例 2：reader 调 `query('review_queue')` ⇒ 不返回行，且 `miss.reason='filtered_by_permission'`、sink 收到一条 `query_miss`。
- 反例：`query('release_gaps_by_owner')` 返回空数组而不报 miss（等于“没有数据”和“没有这个视图”分不清）。

## 已知边界与消费约定（实现期确认，收卡前写入）

- `where`/`order` 在 M0 显式拒绝为 `invalid_args`：视图 SQL 自己定序，查询层不做下推/改写（D-013）；支持面是 `view/select/limit/cursor/as_of`。
- `list` 行形状 `{name,doc,columns:[{name,label,unit?,type}],min_right,row_budget}`（目录原样，无执行细节 `sql`）：13 行整包 8917B 已超 8KB，decider 首屏 11 行 / 7867B、`truncated=true` 并发游标，续查拼回 13 行——与其他视图同一套整包预算机制（截断行数、不削形状）；探针视图名长短不同时 bytes 有 1–2B 抖动，判据以 11 行/≈7867B 为准。
- **列级裁剪 M0–M2 不做**（D-016，Lead 裁定）：`docs/05` §6 要求 agent 视图不含 `human_only` 列，但 `view_catalog.columns` 没有可见性标记载体，且查询层不知道 actor 是人是 agent（`rights` 只有 reader/reviewer/decider/signer，actor 身份在 M3）。本卡只做视图级 `min_right` 裁剪；列级留 M3 的 actor 模型落地后补。
- 结构化 miss 比 docs/05 §5 多四类：`invalid_args`/`stale_as_of`/`unsafe_view_sql`/`result_too_large`；消费方遇到未知 reason 按通用 miss 处理（不得当“无数据”）。
- 预算按**整包**：`bytes` = `JSON.stringify(QueryResult)` 的 UTF-8 字节数（含游标/as_of/view/bytes 自身）。游标存**行摘要** `last_row_hash`（32 位十六进制，定长），所以「行 + 游标 + envelope」一起量；单行连游标都放不下 ⇒ `result_too_large`（预算硬后果，不是数据缺失）。第 54 轮 P1 起整行不再进游标：4000 字符行、20 行视图可正常分页；8000 字符行是边界——单行视图可读（整包 8093B），多行视图因加游标超 8192B（行 8027B + 游标 154B + envelope ≈ 8262B）而给 `result_too_large`；本版边界约 7.9KB/行（游标 154B 时），设计口径缺口见 D-018。
- `query_miss` 事件写入不在本卡（D-012）：`MissSink` 默认 no-op；M1 写网关接真事件。
- `as_of` 是**输入一致性令牌**（事件头集；M0 没有 snapshot id 概念，不支持按旧 `as_of` 读历史）：同一 `as_of` 结果确定，旧 `as_of`/frontier 变化一律 `stale_as_of`；M1 用写网关/快照保证「表」与「返回的 frontier」同事务。
- 分页边界核对**只查 `offset-1` 一行**：能发现边界行被改写/删除造成的 offset 漂移，发现不了非边界行的增删（那些靠 frontier 变化兜底）。多页读取因此要求 frontier 稳定：M0 无快照隔离，活库长分页可能中途 `stale_as_of`，须从第一页重来。
- 边界核对会**重跑一次视图子查询**（`EXPLAIN` 与 page 查询同计划，只取 1 行）：M0 数据量可接受；大表在 M1 用 keyset/索引优化。
- `last_row_hash` 依赖 `JSON.stringify` 的行表示：同驱动/同 Node 大版本内稳定；换驱动或 BLOB/数值表示变化时表现为 `stale_as_of` 后从第一页重查（fail-closed，不会重/漏）。
- `MAX_INJECTION_CHARS_PER_ROUND`（1500）与 `SDO_QUERY_P95_MS`（50）已在 `budget.ts` 单点定义，但 M0 没有注入层/骨架性能探针消费它们；留给后续卡引用。
