# M4-7 · 新起告警与复用读数

## 意图

`docs/09` §16.5 的两条判死读数落在“复用”上：一次派发的 `agent.pick_declined` **≤ 1 条**、连续 3 次新起 ⇒ 告警进 `gaps`。v1 的对照数字是 83——即一次派发里反复拒绝/重新挑选的噪音。这张卡把“复用优先”变成可读的数，而不是一句主张。

## 对齐

**复述**：复用是默认（池里有可用 agent 就复用），新起必须给**可机器复算**的原因（`agent.spawned{reason}` 且理由在枚举内、且能对上当时的池状态）；一次派发过程中 `agent.pick_declined` 最多 1 条（第 2 条起视为选择逻辑有问题）；同一 actor 连续 3 次新起（中间没有复用）⇒ 告警事件 + `gaps` 一行（`kind='spawn_streak'`）。

**人确认**：pending

**正例 2**
1. 派发一次、池里有空闲 agent ⇒ 落 `agent.reused`，`agent.pick_declined` 0 条，`agent.spawned` 0 条。
2. 池空 ⇒ `agent.spawned{reason:'pool_empty'}`；连续第 3 次新起 ⇒ `agent.spawn_streak` 进 `gaps`（`kind='spawn_streak'`, `count=3`）。

**反例 1**
- 一次派发里 `agent.pick_declined` 落 2 条以上 ⇒ 视为未达标（读数直接红，不许“解释成正常”）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | `agent.spawned` 的 `new_reason` **以 `docs/12` §3 为准**：`no_idle_capable` / `context_irrelevant` / `watermark_exhausted`；三条各按其复算规则核对（见下「C1 复算表」），落事件时必须带池快照证据（`idle[]`、每个候选的 `last_task_files[]`、`watermark` 与限值、以及该 actor 是否存在 `agent.compaction_attempted`）；理由与快照矛盾 ⇒ 拒 `spawn_reason_mismatch` | 用例：候选非空却报 `no_idle_capable` ⇒ 拒；有交集却报 `context_irrelevant` ⇒ 拒；无 `compaction_attempted` 却报 `watermark_exhausted` ⇒ 拒 |
| C2 | 一次派发内的 `agent.pick_declined` 计数：`dispatch_id`（或派发区间）内 ≤ 1；第 2 条起告警进 `gaps`（`kind='pick_declined_streak'`），不阻断写入但必须可见 | 用例：造 2 条 ⇒ gaps 有行；造 1 条 ⇒ 无 |
| C3 | 连续新起：同一 actor 连续 3 次 `agent.spawned`（其间无 `agent.reused`）⇒ 落 `agent.spawn_streak` 事件 + `gaps` 行（`count`、`first_at`、`last_at`）；计数按事件序列折叠（不是查表） | 用例：3 次 ⇒ 有；2 次 ⇒ 无；中间插一次 reused ⇒ 计数归零 |
| C4 | 复用默认：池里有可用 agent 时，走新起必须带 C1 的合法理由，否则拒；「可用」的判定（`idle` + 技能匹配）写成函数并被两侧引用 | 用例：可用却新起且无理由 ⇒ 拒 |
| C5 | `gaps` 可见：`gaps` 视图能查到两类 `kind`（`pick_declined_streak`/`spawn_streak`），字段 `kind`, `subject`, `count`, `last_seen` 与视图契约一致 | 用例：`query({view:'gaps'})` 命中 |
| C6 | 读数口径：`scripts/readings/m4/r-pick.mjs` 现算“一次派发 pick_declined 条数”与“连续新起次数”，不许写死；变异（造 2 条 declined）⇒ 读数红 | 用例 + 变异 |
| C7 | 冻结区零改动 | `git diff f37f4dc -- docs design probe` 为空 |

### C1 复算表（以 `docs/12` §3 为权威）

| `new_reason` | 复算规则（写侧必须核对） | 数据不足时 |
|---|---|---|
| `no_idle_capable` | 候选集为空：按步 1 从池快照算 `idle` 且技能匹配的候选数 = 0 | 快照缺字段 ⇒ 拒（`invalid_field`） |
| `context_irrelevant` | 所有候选的 `last_task.files ∩ card.scope.files = ∅` | 候选**没有** `last_task` 记录 ⇒ 视为无交集（记边界，D-192） |
| `watermark_exhausted` | 候选全部 `watermark ≥ 限值`，且该 actor 存在 `agent.compaction_attempted` 事件 | 缺 `agent.compaction_attempted` ⇒ 拒 `spawn_reason_mismatch` |
