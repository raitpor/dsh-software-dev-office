# M4-4 · `right.revoked` 事件入口（收口 D-113）

## 意图

M3 的 R3 读数证明「撤权后待审项消失并显示申请入口」成立，但撤权本身是**列级表示**（`UPDATE scope SET revoked_at`），没有事件入口——这意味着撤权可以绕过写网关与 `verify`，而“谁能撤谁的权”在矩阵里也没有行。本卡补 `right.granted`/`right.revoked` 两个事件、撤销动作与 fold 投影，把 M3 的 R3 改成经写网关的同一语义复跑。

## 对齐

**复述**：`right.granted` 与 `right.revoked` 是 `right`/`scope` 状态的**唯一生产者**（列只是投影）；撤销动作需 `admin@domain`（与 `config` 同级），不能撤自己的最后一个 admin 权；撤权后该 actor 的 read/decide 立即失效（与 M3 一致：行消失、只给申请入口、不给数字）；R3 读数改用撤销动作，结论必须与 M3 完全一致。

**人确认**：pending

**正例 2**
1. `revokeRight({actor: alice, right:'decide', scope:'domain:release'})` ⇒ `right.revoked` 事件 + 投影更新；alice 随后查 `review_queue` ⇒ 行消失、页面出申请入口、无数字。
2. 撤掉某人全部 admin 权（自己最后一个）⇒ 拒 `last_admin_right`，一事件不落。

**反例 1**
- 直接 `UPDATE right SET valid_to=...`（不走事件）⇒ `verify` 必须红（`runtime_inconsistent`）。

## 既有调用点（收紧类判据，`plan/01` §4.1 第 8 项）

本卡把「`scope` 行只能由事件产生」从口号收紧为可验：`verify` 对无事件的 `scope` 行报 `right_grant_untracked`。收紧前 `src/`、`test/`、`scripts/` 里的直插点（2026-11-17 实测）：

| 位置 | 直插条数 | 迁移方案 |
|---|---|---|
| `src/db/auth.ts`、`src/db/auth-bootstrap.ts` | 2 | 改走 `append(right.granted)`；bootstrap 只保留「首次 admin 引导」一条，且同样走 append |
| `test/db/`（auth / scope-owns / renderer / write.materialize.round61） | 4 | 改 `seedGrants`（走 `append`） |
| `test/query/`（permission / column-trim） | 2 | 同上 |
| `test/ui/`（agent-board） | 1 | 同上 |
| `test/db/append-auth.ts` 的 `grantAll`/`seedRights` 等 70 个调用点 | 70 调用 | `grantAll` 改为「矩阵 `required` 并集的最小闭集」（每 actor ~10–15 条），需要全权时用显式 `grantEverything` |

**覆盖不降说明**：夹具仍覆盖同一批 actor/权组合；事件数断言改**增量**断言（`after - before`），表达的是“这一批写了一/没写”，比绝对值更贴近用例本意。静态守卫：`grep -rn "INSERT INTO scope" src/ test/ scripts/` 只允许出现在 `migrations/`（做成用例）。

**为何不走 `right_legacy` 快照降级**：快照挡不住“迁移后新插的行”，挡不住就只能再给夹具开窗口——那正是 M4-1 B / M4-2 B·C 一路被否掉的测试侧 seam。测试夹具的旧写法本身就是绕写网关的遗留，改掉才是正确方向。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | `right.granted`/`right.revoked` 事件（`docs/02` §11 登记 + `event_kind` 迁移 `INSERT OR IGNORE`）；`right` 表状态是 fallback 折叠结果，事件是唯一生产者 | 用例：裸 append ⇒ `unauthorized_right_change`；直插/直改表 ⇒ verify 红 |
| C2 | 撤销动作 `revokeRight`：需 `admin@domain`；不能撤自己的最后一个 `admin` 权（`last_admin_right`）；幂等（重复撤同一权 ⇒ 幂等或显式 `already_revoked`） | 用例三条 |
| C3 | 撤权即时生效：撤 `read@domain:pm` 后同 actor 的查询立刻 `filtered_by_permission`（不需要重启/重建连接）；撤 `decide@domain:X` 后 PM 队列行消失 | 用例：动作后同进程查询即变 |
| C4 | 撤权不删历史：已有 `decision`/`review` 行保留，`verify` 不因“actor 已无权”判历史行非法（权限是时点语义，不是追溯） | 用例：撤权后 `verify` 仍绿 |
| C5 | `verify` 两侧对账：事件序列折叠出的有效权集合 = `right` 表行（多/少/字段不一致均红），并报 `right_projection_mismatch {actor, right, scope}` | 用例 + 探针直插 |
| C6 | R3 读数改口径：`scripts/readings/m3/r3.mjs` 用撤销动作而不是 `UPDATE`；**三条读数结论不变**（pass/pass/pass、overall partial 仍只因 R4） | `npm run readings:m3` 复跑，结论与 S29 一致 |
