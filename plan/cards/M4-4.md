# M4-4 · `right.revoked` 事件入口（收口 D-113）

## 意图

M3 的 R3 读数证明「撤权后待审项消失并显示申请入口」成立，但撤权本身是**列级表示**（`UPDATE scope SET revoked_at`），没有事件入口——这意味着撤权可以绕过写网关与 `verify`，而“谁能撤谁的权”在矩阵里也没有行。本卡补 `right.granted`/`right.revoked` 两个事件、撤销动作与 fold 投影，把 M3 的 R3 改成经写网关的同一语义复跑。

## 对齐

**复述**：`right.granted` 与 `right.revoked` 是 `right`/`scope` 状态的**唯一生产者**（列只是投影）；撤销动作需 `admin@domain`（与 `config` 同级），不能撤自己的最后一个 admin 权；撤权后该 actor 的 read/decide 立即失效（与 M3 一致：行消失、只给申请入口、不给数字）；R3 读数改用撤销动作，结论必须与 M3 完全一致。

**人确认**：A1–A3 已由 Lead 于 2026-11-17 拍死（见「假设」表与「协作偏差」段）。

**正例 2**
1. `revokeRight({actor: alice, right:'decide', scope:'domain:release'})` ⇒ `right.revoked` 事件 + 投影更新；alice 随后查 `review_queue` ⇒ 行消失、页面出申请入口、无数字。
2. 撤掉某人全部 admin 权（自己最后一个）⇒ 拒 `last_admin_right`，一事件不落。

**反例 1**
- 直接 `UPDATE right SET valid_to=...`（不走事件）⇒ `verify` 必须红（`runtime_inconsistent`）。

## 既有调用点（收紧类判据，`plan/01` §4.1 第 8 项）

本卡把「`scope` 行只能由事件产生」从口号收紧为可验：`verify` 对无事件的 `scope` 行报 `right_grant_untracked`。收紧前 `src/`、`test/`、`scripts/` 里的直插点（2026-11-17 实测）：

| 位置 | 直插条数 | 迁移方案 |
|---|---|---|
| `src/db/auth.ts`、`src/db/auth-bootstrap.ts` | 2 | 改走 `append(right.granted)`；bootstrap 只保留「首次 admin 引导」一条，且同样走 append |
| `test/db/`（auth / scope-owns / renderer / write.materialize.round61） | 4 | 改 `seedGrants`（走 `append`） |
| `test/query/`（permission / column-trim） | 2 | 同上 |
| `test/ui/`（agent-board） | 1 | 同上 |
| `test/db/append-auth.ts` 的 `grantAll`/`seedRights` 等 70 个调用点 | 70 调用 | `grantAll` 改为「矩阵 `required` 并集的最小闭集」（每 actor ~10–15 条），需要全权时用显式 `grantEverything` |

**覆盖不降说明**：夹具仍覆盖同一批 actor/权组合；事件数断言改**增量**断言（`after - before`），表达的是“这一批写了一/没写”，比绝对值更贴近用例本意。静态守卫：`grep -rn "INSERT INTO scope" src/ test/ scripts/` 只允许出现在 `migrations/`（**尚未做成用例**，只有 grep 证据，见「已知边界」4）。当前实测见 E10：产品内仅 `src/db/auth.ts:285` 的事务内投影 + viewer 夹具分支 + 负例；表数 47（`test/db/migrate.test.ts`）。

**为何不走 `right_legacy` 快照降级**：快照挡不住“迁移后新插的行”，挡不住就只能再给夹具开窗口——那正是 M4-1 B / M4-2 B·C 一路被否掉的测试侧 seam。测试夹具的旧写法本身就是绕写网关的遗留，改掉才是正确方向。

## 已知边界

1. `src/db/auth.ts:285` 的 `applyRightEvents` 是**产品内唯一允许直写 `scope` 的地方**——它在 `append` 事务内、由本批 `right.*` 事件驱动；它算“投影”，不是绕过事件。
2. `withWriteDb` 库直插 `scope` 目前**不会在夹具层抛错**，靠 `verify` 的 `right_grant_untracked` 抓（因为 `test/core/verify.test.ts` 等故意造脏数据的用例需要能直插）。`withViewerDb` 侧在 `BEGIN IMMEDIATE` 拦截 `append`（`{ok:false}`、0 事件），负例见 `test/db/fixture-guards.test.ts`（`append(security.alert)` 必须失败）。
3. `scripts/readings/fixtures.mjs:169` 的 M0 旧读数夹具仍是「直插 `scope` 行 + 直插 `right.granted` 事件」成对写入（M0 读数走手算链、不能经 `append`）；事件存在 ⇒ `verify` 对账通过，但严格说不是“事件唯一生产者”路径，M4 后续读数基建卡再收。
4. 静态守卫（`INSERT INTO scope` 只允许白名单）**尚未做成用例**，当前只有 `grep` 证据（E10）。
5. 耗时：`npm test` 50–78s（基线≈37s），随机器负载波动；未超 Lead 给的 2× 上限（≈74s）仅在轻载时成立，重载时会触及。
6. 撤权对历史行是时点语义：撤权后 `verify` 仍绿（E2），历史 `decision`/`review` 行不被追溯判非法。
7. `verify` 目前只对账 `scope` 投影，不含 `actor`/`scope_owns` 表（它们的生产者不在本卡范围）。
8. `revokeRight` 是“读行→append”，没有唯一约束；并发两次撤销可能落两条 `right.revoked`（投影幂等、`verify` 仍绿）。M4 单进程假设，不硬修。
9. legacy 背填事件的 `actor` 取旧行 `granted_by`（可能是任意历史值）；019 迁移不可重跑（靠 `user_version` 跳过）。
10. `withViewerDb` 的 append 拦截发生在 `BEGIN IMMEDIATE`：`append()` 内部捕获后返回 `{ok:false}`（不向调用方抛裸错），证据见 E7；直插 `event` 行的读路径夹具仍允许。
