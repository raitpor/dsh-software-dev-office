# M2-4 · 评审抽样 + 晚到条款链

## 意图

这两件事都属“证据缺口的自动发现”，所以放一张卡：

1. **评审抽样**：`review.required` 里有“被抽样命中”一条——按**单调卡序号**取模 `(seq - sample_seed) mod sample_every == 0`，`sample_every ∈ [2,10]`，评审卡（`kind='review'`）不参与抽样（否则递归）。`sample_every`/`sample_seed` 是 baseline 的 `policy.review`，**改它要签字**（`docs/04` §4、`docs/08` §1/§2、`docs/00` 原则 2）。
2. **晚到条款链**：条款在卡开工之后才被改（“晚到”），准入必须拦：卡关联的 requirement/design 条款**最近一次修订之后没有 pre-work 判据读数** ⇒ `clause_unjudged`；`spec_set` 的载荷带 `clause_readings[]` 与 `readings_hash`，P13 按依赖闭包重判 pre-work（`docs/03` §4、`docs/06` §5、`docs/07` §准入、`design/03` P4/P13）。

## 对齐

**复述**：不是“加个抽样开关”，而是**抽样必须是尺子的一部分、且可复算**：同一份 baseline 下，给定卡序号序列，抽中哪些卡是确定的、可被别人重算出来的；换了 `sample_every` 就是换尺子，要签字。晚到条款同理：不是“检查一下有没有读数”，而是**在准入那一刻**按条款当前版本查“你引用的条款，改过之后有没有人重新判过”。

**人确认**：pending

**正例 2**
1. baseline 的 `review{sample_every:5, sample_seed:7}` → 卡序号 7/12/17… 被抽中；评审卡（`kind='review'`）不参与；给定同一序列重算结果一致（纯函数，可被 reviewer 复算）。
2. 一条 requirement 在 09:00 有 pre-work 读数、10:00 被 `spec.revised` 改了 → 10:30 一张引用它的卡申请准入 ⇒ 拒 `clause_unjudged`（理由是“读数早于修订”）；补读数后可进。

**反例 1**
- `sample_every=1` 或 `=11` ⇒ baseline 冻结必须被 P15 拒（`review_params_invalid`，`docs/04` C 组已有这条）。
