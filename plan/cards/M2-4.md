# M2-4 · 评审抽样 + 晚到条款链

## 意图

这两件事都属“证据缺口的自动发现”，所以放一张卡：

1. **评审抽样**：`review.required` 里有“被抽样命中”一条——按**单调卡序号**取模 `(seq - sample_seed) mod sample_every == 0`，`sample_every ∈ [2,10]`，评审卡（`kind='review'`）不参与抽样（否则递归）。`sample_every`/`sample_seed` 是 baseline 的 `policy.review`，**改它要签字**（`docs/04` §4、`docs/08` §1/§2、`docs/00` 原则 2）。
2. **晚到条款链**：条款在卡开工之后才被改（“晚到”），准入必须拦：卡关联的 requirement/design 条款**最近一次修订之后没有 pre-work 判据读数** ⇒ `clause_unjudged`；`spec_set` 的载荷带 `clause_readings[]` 与 `readings_hash`，P13 按依赖闭包重判 pre-work（`docs/03` §4、`docs/06` §5、`docs/07` §准入、`design/03` P4/P13）。

## 对齐

**复述**：不是“加个抽样开关”，而是**抽样必须是尺子的一部分、且可复算**：同一份 baseline 下，给定卡序号序列，抽中哪些卡是确定的、可被别人重算出来的；换了 `sample_every` 就是换尺子，要签字。晚到条款同理：不是“检查一下有没有读数”，而是**在准入那一刻**按条款当前版本查“你引用的条款，改过之后有没有人重新判过”。

**人确认**：pending

**正例 2**
1. baseline 的 `review{sample_every:5, sample_seed:7}` → 卡序号 7/12/17… 被抽中；评审卡（`kind='review'`）不参与；给定同一序列重算结果一致（纯函数，可被 reviewer 复算）。
2. 一条 requirement 在 09:00 有 pre-work 读数、10:00 被 `spec.revised` 改了 → 10:30 一张引用它的卡申请准入 ⇒ 拒 `clause_unjudged`（理由是“读数早于修订”）；补读数后可进。

**反例 1**
- `sample_every=1` 或 `=11` ⇒ baseline 冻结必须被 P15 拒（`review_params_invalid`，`docs/04` C 组已有这条）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | **抽样是纯函数**：`isSampled(seq, kind, review)` ⇒ `kind==='review'` 恒 false；否则 `(seq - sample_seed) mod sample_every === 0`；同输入同输出、可被独立重算 | 用例：固定序列 golden；评审卡不入样；`mod` 为负时按数学取模（不是 JS `%` 的负数） |
| C2 | **参数来自 baseline、且受冻结核校验**：`sample_every∈[2,10]`、`sample_seed` 整数；越界 ⇒ P15 `review_params_invalid`（`docs/04` 已有） | 用例：0/1/11/非整数各一条；合法值放行 |
| C3 | **抽样命中即要求评审**：命中且无 pass 的 `review_round` ⇒ `review.required` fail；`reviewer ≠ subject_producer`；round 绑**评审时点**的 `baseline_hash`/`frontier`，收口时不与当前 baseline 重比 | 用例：命中无 round ⇒ fail；round 有但 reviewer 是作者 ⇒ fail；换 baseline 后旧 round 仍有效 |
| C4 | **`clause_unjudged` 准入**：卡关联条款的**最近一次修订时刻**若晚于该条款的 pre-work 读数时刻 ⇒ 拒（只查 pre-work 类判据，post-work 的 `task.complete`/`design.code_matches` 不在准入查）；不查“条款是否已在有效 `spec_set` 里”（避免自指） | 用例：无读数、读数早于修订、读数晚于修订、条款未被引用——四种各一条 |
| C5 | **`spec_set` 载荷**：`clause_readings[]`（每条 requirement 的 pre-work 读数）与 `readings_hash` 由**工具渲染**，`content_hash` 覆盖 `readings_hash`；模型不能填 | 用例：手改 `clause_readings` 一项 ⇒ `content_hash` 变、签名失效；模型侧接口拿不到写入口 |
| C6 | **P13 依赖闭包重判**：条款变更后，依赖它的卡/条款的 pre-work 读数被标陈旧，重判前不得准入（复用 M0/M1 的变更链语义，不新造第二套） | 用例：改一条被 3 张卡引用的 requirement ⇒ 3 张都要求重判；改无人引用的 ⇒ 无影响 |
| C7 | **不做“评审卡评审自己”**：抽样排除 `kind='review'`，且 `review.required` 对评审卡不适用（否则递归） | 用例：连续 20 张评审卡 ⇒ 0 张被抽样命中 |
| C8 | 冻结区零改动 | `git diff f37f4dc --name-only -- docs design probe` 为空 |
