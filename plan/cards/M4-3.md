# M4-3 · 公共面单写者

## 意图

`docs/07` §12：公共面（登记表、索引、语言包）**不锁**，走“单写者队列”——`public_face` 只有一个写者，其他卡**申请**而不是直接改。这从结构上消掉 v1 的 `DEF-168`（拆卡时写范围系统性漏掉守卫/棘轮/判据注册面）：卡不需要把写域扩到公共面，它只需要申请。

## 对齐

**复述**：公共面有一份登记（`public_face` 声明：哪些路径/表属于公共面）；卡对公共面的改动只能落成“申请”（`publicface.requested`，带改动意图与 diff），由单写者（`public_face` 持有者，一个 actor/进程）统一执行；卡自己的写域里**不许**出现公共面路径（写域校验阶段就拒），所以“忘了把公共面写进写域”不再是缺陷面，而是根本不需要。

**人确认**：pending

**正例 2**
1. 卡 A 的写域不含公共面，它申请“新增一条判据注册” ⇒ 落 `publicface.requested`；单写者统一执行后公共面变动，卡 A 的 diff 仍 ⊆ 自己写域。
2. 卡 A 试图直接改公共面路径 ⇒ 准入/提交阶段拒 `public_face_readonly`，并提示走申请。

**反例 1**
- 把公共面路径塞进卡写域并允许直接改 ⇒ 视为未实现（这正是 v1 拆卡漏项的结构性来源）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | `public_face` 登记是**数据**（表或迁移内声明 + 机器可读），不是代码里的散落常量；登记项含路径前缀、说明、为何属公共面 | 用例：读取登记；新增项必须走迁移（改代码不算） |
| C2 | 卡的写域与公共面**不相交**：准入时若 `scope_paths` 命中公共面 ⇒ 拒 `public_face_readonly`（带命中项） | 表驱动用例 |
| C3 | 申请动作：`requestPublicFace(actor, card, intent, diff)` ⇒ `publicface.requested`（走 `append`、有权限检查、幂等键 `(card, intent_hash)`）；同卡同意图重复申请 ⇒ 幂等或显式 `already_requested` | 用例：幂等重放、重复拒绝 |
| C4 | 单写者唯一：同一时刻只有一个 actor 能执行公共面写（`public_face` 持有者），他人执行 ⇒ `not_public_face_writer`；持有者切换必须留事件（谁在何时把单写者交给谁） | 用例：两个 actor 同时执行 ⇒ 一成一败 |
| C5 | 卡完成时，公共面相关改动**不在卡的 snapshot diff 里**（即使申请被接受，执行也发生在单写者那边，不混进卡的提交） | 用例：申请被接受后卡 diff 仍 ⊆ 自己写域 |
| C6 | `verify`：`publicface.requested` 未被执行的（超期）进 `gaps`；公共面路径出现在任何卡的 `scope_paths` 里 ⇒ 红 | verify 用例 |
| C7 | 冻结区零改动 | `git diff f37f4dc -- docs design probe` 为空 |

## 假设

| # | 假设 | 状态 | 依据 |
|---|---|---|---|
| A1 | 公共面登记先只覆盖**判据注册面**与**视图目录**（`view_catalog` 的种子、`criterion.registered` 的公共表），不一次性把 `src/views/**` 全划为公共面 | open | 待定：范围小一点更能验证机制 |
| A2 | 单写者不是常驻进程，而是“持有 capability 的 actor 在受控动作里执行” | confirmed | 与项目“不新增常驻服务”的约束一致（M2-0 已有一个 signerd，再加一个常驻写者成本高） |
| A3 | 申请的“执行”本身是普通事件写入，但必须由单写者上下文发起（`public_face_writer` 能力） | confirmed | 与 M3-1 的“按 kind 判权 + 能力”一致 |

## 预览

`src/core/publicface/{catalog,request,writer}.ts`、`src/db/publicface.ts`；迁移：`public_face` 登记表（或复用 `view_catalog` 式自描述表）+ `publicface.requested`/`publicface.executed` 事件 kind + 单写者持有者列；写网关加 `public_face_readonly` 与 `not_public_face_writer` 两码；准入校验加公共面相交检查。
