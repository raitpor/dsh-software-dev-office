# M1-7 · 投影对齐（物化全表）

## 意图

M1-0 把写入口收窄到 **7 张表**，不是设计想要的样子，而是第 62 轮实测炸出来的权宜：给“物化全表”一次做完时，四类硬伤让任何一次 `append` 都能永久失败（台账 **D-031**）：

1. `config`（PK `key`）、`snapshot_parent`（复合 PK）、`release_item`（复合 PK）**没有 `id` 列**，物化按 `row['id']` 建键 ⇒ 重放 `UNIQUE constraint failed`，一次 `config.changed` 之后全库写不进去；
2. `FOLD_ONLY_COLUMNS` 只覆盖少数表，`attention.answered_at`/`defect.closed_at`/`review.verified_at`/`goal_node.reparented_at`/`stage_run.judged_at` 让对应 kind 直接 `materialize_failed`；
3. `release.frozen` 的 `frozen_by` fold 存字符串、001 DDL 要求 `json_valid`；
4. `stage_run.gate_id`/`baseline_hash` 在 `stage.entered` 时无值，DDL 却 NOT NULL。

这张卡把那四个前置条件做掉，然后把物化面放开——**因为下游在等**：M1-6 的 v1→`claim` 重建要 `task` 可写；M1-5 的 C6 端到端对账（预览作废数 == 真落库作废数）要 `task`/`work_unit` 真落库（台账 **D-038**）。

## 对齐

**复述**：不是“把 `MATERIALIZED_TABLES` 加满”，而是**先把四个前置条件逐个钉死、再放开安全网**。顺序反了就是“改一行配置、全库永久写不进去”：现在的 fail-closed 安全网（fold 产出落在物化集外 ⇒ 整批失败）是保护，不是障碍；先补齐，再开闸。

**人确认**：pending（收卡前必须确认）

**正例 2**
1. 全部 supported kind（含 `task.*`/`release.*`/`config.changed`/`attention.*`/`defect.*`/`review.*`/`goal.*`/`stage.*`）各一条最小合法事件 ⇒ `append` 返回 `ok:true`、目标表出现预期行、`verify()` 绿；同一批连写两次幂等。
2. 写一条 `config.changed`（`max_members` 8→10）⇒ `config` 表该键一行、值为 10；再写一条同键不同值 ⇒ 更新而非 `UNIQUE` 冲突；重放同一事件不重复。

**反例 1**
- 物化集里有表但 `FOLD_ONLY_COLUMNS` 缺一列 ⇒ `append` 必须 `materialize_failed` 且**事件 0 行**（不得半截写入）。

## 判据

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | **无 `id` 表的物化键**：`config` 用 `key`、`snapshot_parent` 用 `(snapshot_id,parent_id)`、`release_item` 用 `(release_id,kind,target)`，键必须与 001 DDL 的主键一致；不得靠“给表加 id 列”绕过（那会改 DDL 语义） | 用例：`config.changed` 两次重放；`snapshot_parent`/`release_item` 各行重放后行数与内容不变 |
| C2 | **fold-only 清单完整**：所有“fold 行有、DDL 无”的列都进白名单；测试断言“实际忽略列 == 白名单”（新增列会红），并给每列一条“缺它即失败”的变异红证 | 用例 + 变异（删一列白名单 ⇒ 对应 kind `materialize_failed`） |
| C3 | **`release.frozen.frozen_by` 口径**：以**冻结设计的 DDL 为准**（`json_valid` 的 JSON 数组、≥2 human），fold 侧产出该形状，**不改设计**；若 fold 现在存的是裸字符串，改 fold | 用例：`release.frozen` 写两个 human ⇒ DDL 接受、`verify` 绿；写 1 个人类值 ⇒ 拒 |
| C4 | **`stage_run` 空值口径**：`stage.entered` 时 `gate_id`/`baseline_hash` 允许为空（还没判定），`gate.judged` 后必须非空；口径写进 README 并落到 DDL/物化之一 | 用例：只 `stage.entered` ⇒ 行存在且两列为空；`gate.judged` ⇒ 两列有值 |
| C5 | **开闸**：`MATERIALIZED_TABLES` 扩到 fold 能产出的全部表；安全网保留（fold 产出集外表 ⇒ 整批失败） | 用例：把某表从集合里临时删掉 ⇒ 对应 kind `materialize_failed`（证明安全网还在） |

| C7 | **append-only 语义收口（D-039）**：同一 subject 的重复事件（不同事件 id）不再“后者静默覆盖前者”——`restatement_diff`/`decision` 等派生行必须“同 id 同内容幂等、同 id 不同内容拒”；如果某个 reducer 的“同 subject 覆盖”是设计本意（如 upsert 类投影），必须在 README 逐条列明并给测试 | 用例：同 subject 不同 payload ⇒ 结构化拒绝或显式冲突码；现有 M1-2 的 `diff_conflict` 门读数不变 |
| C8 | **回归**：M1-0 的 17 正例、M1-2 的 align 41、M1-5 的 preview 14 仍绿；**M1-5 的 C6 改回“非零作废走真 `append`”**（D-038 的收口），并更新 M1-5 卡与读数 | 用例：M1-5 的非零样本真 append 后对账 3==3 |
