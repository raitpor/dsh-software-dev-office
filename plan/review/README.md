# 计划评审记录

PM（Lead）的产出也是可审对象。这一目录存**计划本身**的评审记录，与卡的代码评审分开：

| 文件 | 什么时候写 |
|---|---|
| `Mx-计划.md` | 开卡时（新 M 的卡表 + 范围裁定） |
| `Mx-计划-变更加.md` 的追加段 | M 内卡表变更累计 ≥3 张或改了依赖边时（追加到同一文件，不重编号） |

## 模板

```markdown
# <Mx> 计划评审（<日期>）

**被审对象**：`plan/00` 第 <n> 节卡表、<相关卡面>、`plan/sign/S<n>` 裁定
**审的人**：`reviewer` / `reviewer-2`（只读）
**作用域**：增量（这份计划相对上一版）/ 整套（新 M 开卡）

## 1. 这份计划要达成什么
（一句话：谁在什么之后能做什么样的判断）

## 2. 评审结论
| # | 级别 | 问题 | 依据（文件:行号 / 可复现命令） | PM 处置 |
|---|---|---|---|---|
| 1 | P1 |  |  |  |

## 3. 未采纳的建议（附理由）
- 
```

## 规矩

1. **审计划 ≠ 审代码**：这里不评价实现细节，只看顺序、范围、依赖、可达性、读数与卡面是否一致。
2. 评审人**只读**，报告以回复形式给出，由 PM 代落盘（评审人不写工作树）。
3. 每条 P0/P1 必须带可复现依据（引用行号或命令）；没有依据的“感觉”写在“未采纳的建议”里。
4. 计划评审不替代里程碑评审：一个看“计划是否自洽”，一个看“成果是否达标”。
