# 流程执行细则（在 SDO 接管之前，手工按设计跑）

> 目的：现在没有 SDO，但**流程形状要和 SDO 将来产生的一样**。这样接管时不是“换一套流程”，而是“把同一套记录搬进事件表”。

## 1. 过程映射（docs/03 的 P1–P15 → 现在怎么做）

| 过程 | 现在怎么执行 | 留下的证据 | 交给 SDO 的时点 |
|---|---|---|---|
| P1 意图 | 你的消息 → 卡里的「意图」段（写结论，不抄原话） | 卡文件 + 消息时间 | M1 六表 |
| P2 需求/判据 | 卡的「判据」表：每条带正例、负例、怎么跑 | 判据表 + 命令 | M1 判据框架 |
| P3 变更预览 | 动手前写「这一改会碰谁、要作废什么」，粗估返工 | 卡的「预览」段 | M1 preview |
| P4 准入 | 手工清单：写域定了吗、判据能跑吗、依赖卡收了吗 | 卡的「准入」勾选 | M2 门禁 |
| P5 派发 | PM 指定席位 + 写域；一张卡一个席位（跨域另开卡） | 卡的 `owner`/`write_scope` | M3 末 |
| P6 提问 | 卡里的「待确认」；拿不到答案就挂起，不猜 | 卡文件 | M1 attention |
| P7 执行 | agent 在写域内改、提交、自证 | 提交 + 测试输出 | 现在就有 |
| P8 合并 | 主干 = `main`；一卡一提交；reviewer 过后才合 | 提交号 | M2 |
| P9 核实 | reviewer 只读看 diff + 证据，出 P0/P1/P2 | 评审回复 | M2 |
| P10 签字 | **只有你**能签：里程碑收口、基线变更、发布 | `plan/sign/` 下的签字记录 | M2 |
| P11 对齐 | 卡先写「复述 + 2 正 1 反例子」，人点头再动手 | 卡的「对齐」段 | M1 |
| P12 假设处置 | 卡的「假设」表：`open`/`confirmed`/`rejected`/`converted`，**没有 open 才能收卡** | 卡文件 | M2 |
| P13 变更 | 改已收的卡 ⇒ 新开「变更」段，写清作废了什么 | 卡文件 | M1 |
| P14 抽样评审 | 每 3 张卡抽 1 张做整套复核（不是只看 diff） | 评审记录 | M2 |
| P15 校验 | `make all` + 各卡判据；红就不收 | 命令输出 | M1 |

**现在刻意不做**：P4 的机器准入、P10 的密码学签字、P14 的抽样算法。替代物是“人肉执行 + 白纸黑字”，并且**明确标注替代物**——不假装它们已经是 SDO 的能力。

## 2. 卡的记录形状（将来一次性导入）

一张卡 = 一个文件，`plan/cards/M0-0.md`。文件里每一段对应一个将来要写的事件/表行：

| 卡里的段 | 将来落到 |
|---|---|
| front matter（`id`/`seq`/`owner`/`write_scope`/`milestone`） | `task` 行 + `task.created` |
| 意图 | `intent` 行 + `intent.signed`（签字延后到 M2，先记 `proposed`） |
| 复述 / 例子 / 回指 | `restatement` / `alignment.examples_received` / `alignment.referred` |
| 判据表 | `criterion` 行 + `applies_to` |
| 假设表 | `assumption` 行 + `assumption.disposed` |
| 证据表 | `evidence` 行（`uri` + `sha256`） |
| 判定表 | `gate.judged`（M2 前标 `manual`，不绑 baseline） |
| 评审 | `report` / `defect.recorded` |
| 变更 | `task.reopened` / `spec.changed` |

**要求**：写卡时按这个形状填，别写成散文。散文将来要人再翻一遍，等于白记。

## 3. 每周对账（10 分钟，别省）

每周固定回答三个问题，写进 `plan/board/YYYY-Www.md`：

1. 这周开的卡，**有几张是动手前写的**？（补录的卡要单独标出来，它是“流程没接住”的证据）
2. 有没有**绕开卡**的改动？（有就记一条 `bypass`，并在下周修流程，不追责）
3. 门禁/评审**红过几次**？（一次没红要警惕：可能是判据太软）

这三个数就是将来 SDO 的 `gaps` 读数的手工版。接管判据 G1/G2/G5 直接从这里长出来。

## 4. 不许做的事

- 不许把“我们讨论过了”写成 `confirmed`——没有你的明确答复，假设就是 `open`；
- 不许把评审的“看起来没问题”写成 `pass`——`pass` 必须对应一条可复现的证据；
- 不许在卡外改代码（探针除外，且探针结果必须回填到卡）；
- 不许为了让卡收掉而放宽判据：**放宽要另开一张卡，并且你签**。
