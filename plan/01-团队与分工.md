# 团队与分工

> 人只有 1 个（你，签署者），agent 有 3 个固定席位 + 1 个评审席位。**席位是角色，不是模型**：换模型不换职责。

## 1. 角色

| 角色 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **签署者 / 基线所有者** | 你 | 签 `decision`（intent/plan/spec_set/assumption_set/baseline/release/rollback）、否决、改计划、改基线 | 不写代码（除非你选择代劳） |
| **PM / 集成** | Lead（现在）→ SDO 自己（M3 末） | 拆卡、派发、收敛冲突、按门禁收口、维护台账 | 不能代签；不能自己给自己写域的卡开绿灯 |
| **实现者 ×3** | `impl-core` / `impl-surface` / `impl-import`（M0 临时）/ `impl-security`（M2 起） | 在各自写域内改代码、提交、自证 | 不能改别人的写域；不能签任何东西；不能自己判自己过 |
| **独立评审** | `reviewer`（fresh、只读） | 只读复核 diff 与证据，出 P0/P1/P2 | 不写文件（评审报告是回复，不是提交） |

## 2. 三条硬规则

1. **写域即边界**：`core` 管 `src/core/**`、`src/db/**`；`surface` 管 `src/views/**`、`src/query/**`、`src/ui/**`；`security` 管 `src/sign/**`、`signerd/**`。跨域改动必须由 PM 开一张“双泳道卡”，两边都留下改动说明。
2. **不自证清白**：实现者只能提供证据（测试输出、重放结果、复算脚本），“我审过了”不算；过不过由 `reviewer` 说。
3. **不代签**：agent 任何路径都不能产生 `decision` 行。`signerd` 只认人的解锁；实现者连“临时签一下方便测试”都不许——测试用假 signer，且必须标 `fixture`。

## 2.1 提交与推送

- **提交**：节奏按团队自己定。一卡一提交、提交信息带卡号；跨泳道的卡分开提交（各带自己的卡号或同卡两段说明）。文档与代码不混在一笔里——计划/台账与实现各自成笔。
- **推送**：团队**不 push**。远端只由用户推；本地提交攒着没有关系。

这条是用户 2026-11-13 的授权，替代此前“每次提交先问”的约定；其余照旧（不代签、不改冻结区）。

## 3. 每张卡的完成定义（DoD）

一张卡只有在下面五项全齐时才算完：

| 项 | 证据 |
|---|---|
| 代码 | 收卡后提交，带卡号；改动只在本泳道 |
| 测试 | 新增/修改的测试在 `make test` 里跑；失败用例必须先红后绿（贴红→绿两段输出） |
| 判据 | 卡上写的判据逐条可执行；结果贴进卡 |
| 文档偏差 | 与 `design-v2.0` 不一致处已记 [03-偏差台账](03-偏差台账.md)（没有就是“无”） |
| 复核 | `reviewer` 给 `pass`；P0/P1 清零，P2 记录在案 |

## 4. 评审节奏

| 级别 | 谁审 | 什么时候 | 不通过的后果 |
|---|---|---|---|
| 卡 | `reviewer` 只读看工作树 diff + 证据 | 席位交卡时（**先审后提交**） | 不提交、不进主干；改完同一张卡再审（不算“再来一轮”） |
| **计划** | **`reviewer`（或 `reviewer-2`）只读审 PM 的动作**：卡表、依赖边、派工单、里程碑收口、提交纪律 | **开卡时一次**（新 M 的卡表 + 范围裁定）；M 内**卡表变更累计 ≥3 张或动了依赖边**再一次；**每次提交前** PM 自检（见 §4.1） | 不改卡表、不派工；PM 自己修完再审一次（同一份计划，不重编号） |
| 里程碑 | 整套评审（从三条保证重推）+ 人签 | 每个 M 收口 | **不进下一个 M**（docs/09 §16 的硬门） |
| 设计变更 | `reviewer` + 人签 | 只在改基线时 | 不改基线，实现继续按旧版 |

### 4.1 计划评审（2026-11-16 加，用户决定“先保留单 PM，但 PM 的行动也要被评审”）

**为什么有这一级**：单 PM 的错误不是“不知道事实”，而是“把对的事实组装错了”——例如把「可安装性评审」排在「插件化」之前（评审没有可评审对象，只能得出已知结论）。这类错误代码评审抓不到，机器检查只能抓其中一部分（`plan/check.py` 的 R2 抓依赖边），剩下的（范围、可达性、读数与卡面一致）需要一双独立的眼睛看**计划本身**。

**审的到底是什么**（PM 的产出都是可审对象）：

| 对象 | 要核的 | 判红的例子 |
|---|---|---|
| 里程碑范围 | 判死读数在这个 M 内**能不能真跑到**：读数依赖的表/字段/入口是否在这个 M 里产出 | 读数要 `gate.judged`，但建该表的卡排在下一个 M |
| 卡表与依赖边 | 顺序、跨卡依赖、跨泳道写域是否相交 | 门卡依赖后置产卡；两张卡写同一文件却没标顺序 |
| 派工单 | 写域是否显式、是否含“先审后提交”、台账号是否接上 | 派工单只写“改 auth 相关” |
| 里程碑收口 | 收口材料是否只引自己看过的那棵树；partial 的理由是否诚实 | 用旧读数给新树签门 |
| 提交纪律 | 一卡两笔、冻结区零改动、生成物是否被测试弄脏 | 代码与卡混提交；提交里带 `plan/milestone/*` 的脏生成物 |

**审的人**：与实现席位无关的 `reviewer` / `reviewer-2`（谁空谁上；同一份计划只审一次，不叠加）。**只读**——评审报告是回复 + 写进 `plan/review/Mx-计划.md`（PM 代落，评审人不写文件）。

**产出**：`plan/review/<M 或日期>-计划.md`，只写三样：①本计划要达成什么；②评审给 P0/P1/P2 + 每条的可复现依据（引用行号）；③PM 的处置（改了什么、或为什么不改）。

**成本**：一次约 10 分钟、不占实现工时；比“再加一个 PM”便宜一个数量级，而且抓的是相关性错误之外的东西（独立视角看计划，而不是同模型重复推理）。

评审结论必须带作用域（增量/整套），台账里沿用 `design/REVIEW.md` 的写法：P0/P1 逐条给“核实/处置/落点”。**“可以提交”只对它看过的那棵树成立**。

顺序是**先审工作树、再提交**：提交前没有可审的 diff 就给 reviewer 看 `git status` 的新文件与卡；提交后任何改动都要重审（同一张卡，不另编号）。

**PM 提交前自检七项**（机器能查的已进 `plan/check.py`：第 2/5/6/7 项由 R2/R3/R4 直接判红，其余靠自查并在提交说明里写）：

1. `make all` 绿（docs / probe / design / plan 四套检查）；
2. 冻结区 `git diff f37f4dc -- docs design probe` 为 0；
3. 一卡两笔：代码一笔、卡与 `plan/` 一笔，不混；
4. 生成物没被测试弄脏（`git status --porcelain plan/milestone/` 为空，或确实是要提交的新读数）；
5. 提交说明带卡号，且**不含**本机路径 / 会话 id / 账号名（脱敏）；
6. **卡面/判据点名的文件 ⊆ 该卡 `write_scope` ∪ 台账里的显式扩权**（2026-11-16 计划评审 P1-1 抓到的形态：判据要求改 `src/core/verify*.ts`，写域里没有）；
7. **卡表依赖边 ⊇ 卡面准入写的前置卡**（P1-2 的形态：卡表写 `M4-2 ← M4-0`，卡面准入却要求 M4-0 与 M4-1 都收卡）。

## 5. 席位怎么开

| 阶段 | 开场 | 说明 |
|---|---|---|
| M0 | `impl-core` + `impl-surface` + `impl-import`（M0-7）+ `reviewer` | 骨架/视图/导入分开；`security` 不进场（M0 不碰密钥）。`impl-import` 是 M0 的临时席位，测完导入器即回收 |
| M2 | + `impl-security` | 登录、`signerd`、免密窗口、签名字段；这是唯一允许碰密钥的席位 |
| M3 末 | 席位不变，**PM 换成 SDO** | Lead 从“派卡的人”变成“看 `pm_queue` 的人”，见 [02-SDO接管方案](02-SDO接管方案.md) |

## 6. 沟通约定

- 卡是唯一工作单元：没有卡的活不干（临时探针除外，探针结果必须回填到卡）；
- 阻塞先写卡上的 `block_code`，再找人；不在聊天里“口头解阻塞”；
- 每次派发带三样：卡号、验收判据、写域；缺一样实现者可以拒收；
- 任何“顺手改一下”都不许跨出写域——顺手改是漂移的主要来源。

## 7. 接管后的团队

SDO 接管后，这四件事从人/Lead 手里挪走：

| 现在 | 接管后 |
|---|---|
| Lead 拆卡、派发 | SDO 的 `pm_queue` + 预占（M4）；Lead 只看读数 |
| Lead 判断“这张卡能不能收” | 门禁判定（`gate.judged`）绑 `baseline.hash`；Lead 只处理红卡 |
| 台账手写“第 N 轮处置” | 事件链 + `verify`；台账变成投影 |
| 人记得“上次为什么放宽” | `baseline` 的 `prev`/`direction` + `decision` 载荷；忘不掉 |

**不变的是**：签字仍然只能人做，独立评审仍然不能由实现者兼任。
