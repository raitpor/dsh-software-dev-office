## 2. 签字约定

- **一卡两笔提交**：代码/脚本一笔，卡与台账一笔。
- **卡签**：一张卡或一组卡收卡时签，签文件正文必须有 `- 范围：<卡号>`（卡号在行首；门卡用 `- 范围：M<n> 里程碑门`）。
- **门签**：里程碑读数门通过后签，签文件正文必须有 `- 范围：M<n> 里程碑门`；门签同时算该里程碑门卡 `M<n>-G` 的收口签。
- **追加签**：计划冻结段签后发现要改，不覆盖原签，另起 `S<n>-<A..Z>.md`，并在新签里写清“追加了什么、为什么、覆盖哪一段 hash”。
- 历史签字只追加，不改正文（路径迁移等说明以追加行形式写在签文件末尾）。

## 3. 阶段与 preset 选择

- 阶段序列由 `skills/sdo-flow/presets/<preset>.md` 决定；本 skill 自带四份：`waterfall`、`prototype`、`incremental`、`agent-driven`。
- **不设项目级默认 preset**：每个里程碑在自己的 `milestones/M<n>.md` 里写 `preset：<名字>` 与 `preset 选择理由：<≥8 字、不在套话黑名单>`；机检只验“选了 / 在清单里 / 有理由”，**选得对不对由计划评审判**。
- 套话黑名单（共用一份，preset 理由与「语义：不适用」理由都用它）：`无`、`没有`、`不适用`、`不需要`、`无所谓`、`待补充`、`略`、`同上`、`见上`。

## 4. 共享写域总则

- 每张卡在卡面写 `write_scope: [...]`；`check.mjs --plan` 校验卡面点名路径 ⊆ 写域。
- 多个卡都要改的共享文件，在**对应里程碑文件**的「共享写域补充」表里登记，写明“谁先改、其他卡只读”。
- 新增共享文件时必须同时更新登记表与该里程碑的冻结段 hash（签后修改走追加签）。
- **例外：`skills/sdo-flow/scripts/lib/**` 是全局共享写域**（工具脚本的公共 helper），任何卡都可改、无需逐里程碑登记；理由：helper 跨卡复用，逐卡登记会迫使每张卡都去改里程碑冻结段 hash，而 hash 的意义是锁住“计划”不是锁住“实现细节”。

## 5. 文件布局

命名约定：**目录名一律英文**（`cards/`、`milestones/`、`baseline/`、`sign/`、`readings/`、`gates/`、`notes/`、`archive/`、`ledger/`、`.index/`）；顶层文件名可用中文（`意图.md`、`计划.md`、`台账.md`、`看板.md`），模板文件名用英文（`templates/*.md`）。

```
.sdo/
  意图.md         项目意图（含信任前提与追加说明）
  计划.md         本文件：项目级计划
  台账.md         偏差台账（活跃卷；旧卷在 ledger/）
  看板.md         当前看板
  milestones/M<n>.md  每个里程碑：读数、卡表、写域补充、阶段、冻结段
  baseline/       项目基线（需求 R-xx / 架构 ADR / 测试策略 / 质量与风险；目录名英文）
  cards/          卡面
  sign/           签字记录（S<n>.md、追加签 S<n>-X.md）
  review/         分阶段评审记录
  readings/       里程碑读数
  gates/          里程碑出口表（gate.mjs 消费）
  notes/          使用笔记（每里程碑至少 3 条在 M5 起）
  ledger/         台账归档卷
  archive/        已归档里程碑的材料（cards/readings/gates 等）
  .index/         派生索引（ledger.json；不是真源，可 reindex 重建）
```
