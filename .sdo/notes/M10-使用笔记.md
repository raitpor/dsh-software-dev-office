# M10 使用笔记

> 给下一个里程碑的实操摩擦；每条：现象 → 命令 → 结论。

## 1. 模板不是“原样可跑”的成品

- 现象：把 `skills/sdo-flow/templates/gates.md` 原样放进 `.sdo/gates/` 跑 `gate`，报 `G_harden_exit 的表头里没有“判定/结论/状态”列`；模板本身含代码块/占位符，gate 会把它当真实门表找判据。
- 命令：`cp skills/sdo-flow/templates/gates.md .sdo/gates/X.md && node skills/sdo-flow/scripts/gate.mjs --file .sdo/gates/X.md; echo $?`
- 结论：模板必须先替换 `<M>/<preset>/<gate-id>` 并复制真实 criteria 行；R45③ 因此判 partial，不是“模板自带即过”。

## 2. 里程碑缺 hash / done 卡无签仍只报诊断

- 现象：删掉 M10 的 `hash:` 行，`check --plan` 只说「冻结段 hash 缺失」；done 卡无签只说「未签收」，都不给“下一步：”。
- 命令：`sed '/^hash:/d' .sdo/milestones/M10.md > /tmp/x && … check --plan --milestone M10`
- 结论：初始化期（缺意图/基线）已有 `SDO_E_MISSING_*` + 可复制命令，但内容错误仍靠人读文档；R47 判 partial，后续应把这两个错误也挂到 SKILL 的恢复命令。

## 3. 冷启动读数依赖另一个无上下文席位

- 现象：R44 不是本席能自证的；同一个人读自己写的 SKILL 必然“读得懂”，结论会偏。
- 命令：按 `.sdo/notes/M10-冷启动任务书.md` 另派席位，记录写 `.sdo/notes/M10-冷启动记录.md`
- 结论：R44 先占位 partial；没有独立记录前不得写 pass，也不得把“我读得懂”当证据。

## 4. 初始化器建了空计划表，`--plan --milestone M1` 仍会 exit 2

- 现象：`init.mjs` 的下一步第 3 条一度直接给 `check --plan --milestone M1`，但新项目还没有 `M1.md`，命令必然失败。
- 命令：`init.mjs` 后看结尾三步；`node …/check.mjs --plan --milestone M1; echo $?`
- 结论：下一步改为普通 `check`，并注明里程碑文件建好后再用 `--plan`；操作顺序本身也是文档质量的一部分。
