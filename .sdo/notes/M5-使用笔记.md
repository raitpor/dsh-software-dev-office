# M5 使用笔记（agent-driven preset 摩擦）

格式：现象 / 复现 / 建议。

## 1. 计划冻结段每追加一行就要一次追加签

- 现象：M5 期间追加了 S20-A（证据格式基线卡）、S20-B（变异校验基线卡）、S20-C（R21 口径），三次都因为计划里先写死了一个**当时没有在被审树上验算过**的指标或豁免。
- 复现：写“归档第四个里程碑后扫描数不变（±0）”“`check` 耗时下降”，实际实现必然不满足；修一次就要再签一次。
- 建议：写计划时**先在被审树上把指标算一遍**；把“结构性追加（豁免/基线卡）”和“口径变更（指标定义）”分成两种追加签，前者不需要重读全文。

## 2. 卡面判据里的命令会过期，检查器不查

- 现象：M5-2 的 C1 判据行写着 `mutation --criterion …`，而实现已要求 `--card`；照抄判据会 exit 2，读者会以为是自己环境问题。
- 复现：改实现参数后不回头看卡面判据。
- 建议：给 `card.mjs` 或 `check.mjs` 一个 `--lint-commands`：把判据/证据里反引号内的 `node <skill>/scripts/*.mjs …` 抽出来跑 `--help`，跑不通就 WARN（不阻断）。

## 3. 台账“未修”口径反复改，因为一个 status 列承担了两种语义

- 现象：`view next` 的“未修台账”先算 `explain/open`（14 条噪声）、后又漏掉 close 行关闭过的条目；反复三次才定成“只 `defect|gap`，排除 fixed/closed/superseded，close 行关闭的不算，explain 永不算”。
- 复现：看 `defect`/`explain`/`gap` 混在一张表、`status` 同时表示“是否已修”和“是否已解释”。
- 建议：模板里给 `kind=explain` 固定语义“无需处理”，或在台账加一列 `resolved`（派生）；再让 `check` 校验 `kind=explain ⇒ resolved=n/a`。

## 4. 评审席位会中途失败，skill 没有“换席位”的写法

- 现象：M5 期间 `reviewer` 与 `reviewer-2` 各失败一次（无判词），我临时换 `reviewer-3` 才走完。
- 复现：长会话里席位超时/掉线。
- 建议：`references/03` 写一条：席位失败可换**另一个非作者席位**，但必须把上一轮判词原文贴给新席位，并注明“这是第 N 轮的续”，不许把“没判词”当“通过”。

## 5. 台账索引一致性：先做性能优化、后补正确性，会假绿一轮

- 现象：M5-4 第 2 轮为把 10 万行 `check` 拉进预算，把 `checkLedgerVolumes` 改成“只比文件 sha256 + 卷头”，删掉索引里的 open 条目也能全绿；第 3 轮才补回“正文未修行必须出现在 index.open”的线性扫。
- 复现：删 `.sdo/.index/ledger.json` 的某条 `open`（正文不动），旧 check 输出 0 错；新 check 报 `正文未修行 D-x 不在索引 open`。
- 建议：索引校验分两档写死——`quick`（sha/卷头，只防手改）与 `full`（open/行 ID/状态）；默认 `full`，性能吃紧时才由人显式 `--fast`，不要让“快”悄悄替换“对”。

## 6. 索引里存 `line` 会随 reindex/归档漂移

- 现象：M5-4 的 `index.open` 为 `view next` 存了 `file:line`；`rotate`/`restore`/`reindex` 后同一行的行号会变，旧索引指向错误行（甚至另一条 D-编号）。
- 复现：archive M3 后不 reindex，直接 `view ledger D-x`，报“实际是 D-y”。
- 建议：要么索引只存 `id + file`、读取时按内容找行；要么每次读 `line` 时校验该行的 id，不一致就退化为整卷解析并提示 `reindex`（M5-4 当前读路径即后者）。
