# M6 使用笔记（agent-driven preset 摩擦）

格式：现象 / 复现 / 建议。

## 1. “存在即通过”在文本层有无数变体

- 现象：M6-0 四轮评审里，同一个洞换了四种写法：正文注释、伪小节（`### 冻结段说明`）、诱饵行（正文写一行豁免声明）、代码围栏里的示例。每次修完都能再找一个。
- 复现：给任何“查找某行”的检查器加一个 `会误伤的合法写法`，它就可能被同一形状的非法写法绕过。
- 建议：机检的可靠做法不是“更严格的正则”，而是**把位置收紧到唯一小节 + 行首精确格式 + 唯一性检查**；并且承认剩下的是声明式信任，交给评审复跑（写在卡的已知边界里）。

## 2. 早退条件最容易写成“无条件放行”

- 现象：M6-3 的 C4 归档规则最初写成“只要 `.sdo/archive/<M>/` 存在就 return”，结果把“文件仍在、但冻结段被改”的真漂移也吞了；评审用一个临时目录就复现了。
- 复现：保留 `milestones/M6.md`、`mkdir .sdo/archive/M6/`、改坏 `hash:` ⇒ `--plan M6` exit 0。
- 建议：每个 `return`/`continue` 都要能说出**它排除了什么**，并把排除条件写进判据；早退条件里出现“只看一个路径是否存在”时，几乎一定是错的。

## 3. 计划评审该先算指标再写达标线

- 现象：M5 的 R21（扫描数不随里程碑增长）与 M6 的 C2（覆盖六门）都是写的时候没在被审树上算过，落地时才发现不可达，只能追加签改口径。
- 复现：R21 要求“归档第四个里程碑扫描数 ±0”，实测每归档一个就少一批；C2 要求六门，实测本里程碑只经过两门。
- 建议：写读数/判据时**当场在被审树上跑一遍**，把“现在是多少”写进探底行；口径变更与结构追加分开走追加签，前者要重读全文。
