# M9 使用笔记（incremental）

格式：现象 / 命令 / 结论。

## 1. done 卡的证据表是“脚本形态”硬门槛

- 现象：M9-4 收口时把证据表写成 4 列（`判据 | 命令 | 结果 | 判定`），`check` 报一串「证据结果列不是脚本形态」「判定值非法：exit=0」；改成 3 列且「命令与输出」以 `exit=<code>;` 开头才绿。
- 命令：`node skills/sdo-flow/scripts/check.mjs`（报 `证据结果列不是脚本形态：C4`）；`sed -n '26,34p' .sdo/cards/M9-4.md`。
- 结论：done 卡的证据只认两种形态——`exit=<code>` 开头，或「未跑待复跑」；不要把“结果”单列出来。另：表头里的 `命令与输出` 列就是被检查的结果列，不能拆成两列。

## 2. `gate.mjs` 对文件里出现的每个 `G_` 字样都会尝试解析成一张表

- 现象：在 `.sdo/gates/M9.md` 开头的说明文字里写 `` `G_req_design` 16 条 + … ``，`gate.mjs --file` 把说明文字当成第一张表的起点，报「表头里没有判定/结论/状态列」；把说明里的 `G_` 前缀去掉（改写成 req_design/build/verify/integrate）即恢复。
- 命令：`node skills/sdo-flow/scripts/gate.mjs --file .sdo/gates/M9.md`（修前 7 个问题；修后 4 门 34+1 行、exit 0）。
- 结论：勾选表的说明段不要裸写 gate id；要写就写在没有 `## G_` 上下文的地方，否则解析器会把相邻段落吞进去。`trace.exit_zero` 这类“第 35 行”放进任意一门即可，单独开 `## G_trace_exit` 会缺 core 判据而红。

## 3. 归档后改 preset 的“发布快照”必须连常量一起改

- 现象：M4–M8 归档后改 `presets/agent-driven.md` 一处文字，`--presets` 只报「需人签更新发布快照」+ hash 不一致，不再报 `preset_change_requires_archive`；只改文件、不改 `check.mjs` 的 `SNAPSHOT_PRESET_SHA` 常量，永远红。
- 命令：`/tmp` worktree 副本：编辑 `skills/sdo-flow/presets/agent-driven.md` 后跑 `node skills/sdo-flow/scripts/check.mjs --presets`；再替换 `SNAPSHOT_PRESET_SHA["agent-driven"]` 为新 `sha256sum` 并复跑。
- 结论：R38 的“③更新发布快照”= 改常量并重跑，不是“重跑一次就绿”；这一步要人签记录，`--presets` 的 hash 是整文件口径（一个空格也算改）。

## 4. 读数表里的 `<`/`>` 会被当成模板占位

- 现象：R43 写「预算 add<100ms、check<300ms」「>5000 行 WARN」，`check` 报「还有模板占位（<…>）」——检查器用 `<[^>]*>` 扫整份读数，`<100ms` 会跨到后面的 `>` 配成一对。
- 命令：`node skills/sdo-flow/scripts/check.mjs`（报 `.sdo/readings/M9.md:0: 还有模板占位`）。
- 结论：读数里表达比较一律用「小于/超过」，不要用尖括号；否则即使没有真占位也会红。
