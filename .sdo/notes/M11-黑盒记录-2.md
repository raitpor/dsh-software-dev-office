**白盒：文档与脚本行为哪处不一致？**
`templates/card.md` 的卡面有 12 节（临时决策、风险标记、对齐、假设、预览、准入、收口都在），而 SKILL §5.4 称为「卡骨架」的 `card.mjs new` 只生成 6 节 + `- 视角：未声明`，两者对「骨架」的定义不同；照模板补节会被算手写，不补又缺准入/收口。另一处：SKILL §5.1 写里程碑用 `认领需求：` 登记，`milestone.mjs new` 生成的占位行却是 `需求：无（本里程碑尚未认领需求…）`，同一字段两个关键字，生成物本身无法证明哪个会被解析。我改成 `认领需求：` 后 `check --trace` 为 0，但这不能证明是这一行生效。

**黑盒：哪个环节必须靠猜？**
选 preset。SKILL §3 只给四个 preset 的适用场景，没有给「冷启动、无业务需求」项目的选择规则；而 `milestone.mjs new` 又硬编码生成 incremental 的 `阶段序列：req_design→build→verify→integrate`，选其它 preset 就得手改这一行（可能落进「能生成却手抄」）。我只能选 `incremental` 让生成物自洽，SKILL 没有一句话支持这个选择。同理，卡的 `视角` 合法值只写在 `references/03 §3.5`，SKILL 与 `card.mjs new` 都不提示。

**系统：哪个前置条件没写清楚？**
git 的时机。任务书 §2.1 让一开始 `git init && commit -m init`，§2.6 让 `sign.mjs new` 取 HEAD；但此时 `.sdo/` 全是未提交文件，锚点指向不包含计划的空提交，`draft` 必然 `TREE_MISMATCH`（HEAD 缺失三个被签文件）。文档没有一句「git 模式下要在最终提交之后重跑 `sign.mjs new`」，也没说 `draft` 要 `CLEAN` 必须把 `S1.md` 本身也提交、`AHEAD 1` 是允许态；更没写 bb2 位于外层仓库内、`git init` 得到的是嵌套仓库。运行中还出现另一席位创建的 `seat-run/` 与 `黑盒记录.并发席位.md`（后者是本席位的记录被它备份后又覆盖了同名文件），工作树因此带过未跟踪项。

**集成：哪两个命令的产物接口对不上？**
`gate.mjs init` 与 `gate.mjs --file`。前者生成的门表把 34 行的判定列写成 `待判`，后者只接受 `pass/partial/fail`，于是紧接着跑就报 34 个 `没有判定`、exit 1；A 的默认输出恰好不是 B 的合法输入，且中间没有任何命令能批量把 `待判` 变成判定。同一族还有一处文件名接口：`sign.mjs new --force` 重写的是 `S1.md`，却把文件内标题改成下一个编号（我每次都得到 `# S2`），于是 `S1.md` 里装的是 `S2`；`check`/`draft` 都按文件名称 `S1.md`，SKILL §6 却说新签应写 `S<n+1>.md`。

**故障与恢复：踩红字后靠什么恢复？哪条信息该更早出现？**
K1 靠 `milestone.mjs --help` 的用法行恢复，K3 靠任务书 §2.10 的「或如实记录骨架待填判定」，K4 靠 `draft` 自己打印的 `HEAD 缺失` 文件清单定位。最该更早出现的是三句：SKILL §11 补 `milestone.mjs declare --list`；§5.8 的签前预期红码补 `待判`（gate 骨架）和 `TREE_MISMATCH`（git 锚点早于提交）；以及明确「git 模式下 `sign.mjs new` 必须在最终提交后运行；`draft` 的 `AHEAD n` 与 `DIRTY`（签文件未提交）允许，`TREE_MISMATCH` 不允许，`CLEAN` 需连同 `S1.md` 一起提交」。
