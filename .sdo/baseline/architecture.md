# 项目基线：架构决策

> 本文件是项目级架构基线：记录本 skill 自身的架构选择；卡面引用需求 id，不复制需求正文。改动本文件属于项目级基线变更（M8-2 之后走追加签）。

## ADR-001：以 Markdown + 文件系统作为唯一真源，不引入数据库

- 决策：流程状态（意图、计划、卡、台账、签字、读数）全部落在仓库内的 Markdown/JSON 文件；脚本只做解析、校验与追加，不维护第二份状态库。
- 备选：SQLite 单文件库（查询快、事务强）与常驻服务（并发控制强）。未选的原因：二者都让“状态”离开可 diff、可 review、可随身携带的文本；且需要迁移/备份/并发运维，超出本 skill “零依赖、可携带”的目标。
- 后果：得到可直接 diff/评审/归档的账本，以及无需安装的脚本；付出的是全量扫描成本与并发写风险（多会话冲突靠 append-only 与显式冲突行处理，见台账纪律）。大台账用分卷 + 索引缓解（M5-4），但不改变“正文是唯一真源”。

## ADR-002：检查器只验文本结构与引用闭合，不证明语义正确

- 决策：`check.mjs` 只判“字段齐全、引用存在、闭合、版本绑定、hash 一致”；判据是否选对、需求是否写对由评审与人签负责。
- 备选：在检查器里内置业务规则/自然语言判断。未选的原因：会把“判读”伪装成机检，产生新的假绿；且文本层无法证明意图。
- 后果：机检结果可复跑、可解释；代价是必须保留评审与门签，且检查器本身也要靠变异与读数门自证。
