## 意图

让“计划本身”也能被机检：签过的意图与计划不能悄悄换 preset；每条判死读数必须写清“怎么探底”；冻结段被改动必须留下追加签。顺带把“口头授权≠流程放行”写成硬约束文本（不做动工闸，按用户 2026-11-20 裁定）。

## 风险标记

release_touching：改的是所有里程碑共用的 `--plan` 解析，回归面覆盖 M1–M5。

## 对齐（复述）

- 一句话：本卡不改流程规则，只把已有规则变成可复跑的检查，并补一条“计划改动要留痕”的机制。
- 做：①`check --plan` 增 preset 一致性；②增“每条读数有探底行”；③增冻结段 hash 校验与追加签识别；④SKILL §5 与 `references/07` 写入“口头授权≠流程放行”。
- 不做：不新增 `preflight.mjs`；不检查 git 状态；不判断“先动工后立项”。
- 正例：在 M6 计划段上 `--plan --milestone M6` exit 0。
- 反例：把 M6 段 `preset：` 改成 `waterfall` ⇒ exit 1 并点名意图与计划两处。
