# M12-2 · 台账列数口径统一：view 与 check 对同一行给同一结论，历史含未转义竖线的行由工具修正或台账说明，check --deep 也覆盖

status: open

write_scope: [skills/sdo-flow/scripts/view.mjs, skills/sdo-flow/scripts/check.mjs, skills/sdo-flow/scripts/lib/ledger-rows.mjs, .sdo/台账.md, .sdo/cards/M12-2.md]
- 视角：评审应重点确认历史行字节不动、共享解析函数单源、view 与 check --deep 结论一致。

## 临时决策

- 无

## 意图
台账列数口径统一：view 与 check 对同一行给同一结论，历史含未转义竖线的行由工具修正或台账说明，check --deep 也覆盖

## 风险标记

- 无

## 对齐

- 对齐 R52③：工具对历史台账行的列数结论必须一致；对齐 `references/01` 的 append-only（旧行一个字节不改）。

## 判据

| 编号 | 判据 | 类型 | 反例 |
|---|---|---|---|
| C1 | `view state` 对历史行不再报 **`表列数不齐`**（原文案，不是“列数告警”），且经 `skills/sdo-flow/scripts/lib/ledger-rows.mjs` 归一。正例：`node skills/sdo-flow/scripts/view.mjs state 2>&1 \| grep -c "表列数不齐"` ⇒ 0 | 结构 | 恢复 view 本地 `split("|")` 解析 ⇒ 该计数回 1，断言红（当前未修树上实测 1，改后必须 0） |
| C2 | `check --deep` 的列数结论由同一 `skills/sdo-flow/scripts/lib/ledger-rows.mjs` 归一函数产生，与 view 对同一夹具行**列数相等**。正例：在 `/tmp` 副本的 `.sdo/台账.md` 插一行含 2 个裸 `\|` 的 D 行，`node .../view.mjs state` 与该副本 `node .../check.mjs --deep` 对该行给出相同列数（把两边输出落到文件后逐行 `diff`） | 结构 | 删掉共享函数调用、退回各自解析 ⇒ 两个输出对该行列数不同（`diff` 非空）即红 |
| C3 | 历史坏行不静默忽略：只允许追加 explain 行说明“历史行含未转义竖线，按末列并入处理”，不删改历史。正例：`grep -q "未转义竖线" .sdo/台账.md` | 语义 | 把历史坏行整行丢弃 ⇒ D 行消失、`view ledger D-n` 找不到；或改历史行 ⇒ `git diff` 有删除行即红 |

## 假设

- A1：历史行含未转义 `|` 是既有事实，且不能重写；若必须改历史行才能统一，则停并报冲突。
- A2：`view.mjs` 与 `check.mjs --deep` 可共用 `skills/sdo-flow/scripts/lib/ledger-rows.mjs` 的归一结果；若某一方语义必须不同，先在卡上写明差异。
- A3：追加一条 explain 行足以留痕；若需新增历史行改写，停。

## 预览

- 预计改：`skills/sdo-flow/scripts/lib/ledger-rows.mjs`（新，归一多竖线并入末列）、`view.mjs`、`check.mjs`、`.sdo/台账.md`（只追加 explain）。
- 最可能不成立处：同一行在 view 与 deep 的“列数”含义不同（展示列 vs 单元格）；若不同，先对齐定义再改代码。
- 验证：同一夹具行在 `view state` 与 `check --deep` 结论相同；历史行 `git diff` 无删除/修改。

## 视角

- 审“历史行零改动”：`git diff .sdo/台账.md` 是否只有追加。
- 审“单源”：view 与 deep 是否真的调用同一个函数，而不是复制逻辑。
- 审“留痕”：坏行处理是否有可查的 explain 行。
