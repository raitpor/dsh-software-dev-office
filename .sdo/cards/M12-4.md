## 临时决策

- 无

## 意图

第六轮冷启动（手改 0 / 卡点 0 / 越界 0）暴露两处文档与实现自相矛盾：①`SKILL.md:52`/`:90` 仍要求里程碑写 `preset：` 与 `preset 选择理由：`，与 `references/02:79` 的「`preset` 已从真源退场，出现即 `preset_field_removed`」冲突；②未人签的签草案（`判定：待填`）在树变化后报 `signed_anchor_mismatch` ERROR（没人签过却说“签名记录不符”）。

## 风险标记

- 风险：修 ② 时把“未签”判定放宽到“任何没解析出判定的签”，可能让人签过的签（判定行有笔误）逃过锚点校验 ⇒ 必须用“判定行的三种未签形态白名单 + 已签反例必红”夹住。

## 对齐

- 对齐 R56/R52③：黑盒席位的报告必须能推动文档自洽，而不是让它猜哪句算数。
- 对齐 M11-11：tree 锚点的语义是“人签过的那棵树”，未签的草案不构成承诺。

## 判据

| 编号 | 判据 | 类型 | 反例 |
|---|---|---|---|
| C1 | `skills/sdo-flow/SKILL.md` 不再要求写 `preset：`/`preset 选择理由：`：两处（`:52` 的「并写 `preset：` 与 `preset 选择理由：`」、`:90` 的「每个里程碑在阶段段自选 `preset：<名>` 并写理由」）改成「`preset` 只是抄写参考，不写进真源」口径。正例：`grep -cE 'preset 选择理由：' skills/sdo-flow/SKILL.md` = 0 且 `grep -c 'preset_field_removed' skills/sdo-flow/SKILL.md` ≥ 1 | 结构 | 把任一处改回去 ⇒ `grep -c 'preset 选择理由：'` ≥ 1 即红 |
| C2 | 未人签的签草案不做锚点比对：签文件判定为 `待填`/`待签`/`未判`（或判定行缺失）时，`check` 对 tree 锚点**不报 ERROR**。正例：夹具 `init` → `sign.mjs new --kind 计划 --milestone M1` → 改一个纳入文件 → `check` 的 `signed_anchor_mismatch` 计数 = 0（且该签仍被 `plan_sign_unsigned` 点名） | 结构 | 把判定行改成 `- 判定：接受` 再改文件 ⇒ 必须报 `signed_anchor_mismatch`（C3 夹住） |
| C3 | 已人签的签仍比对（不许借 C2 放宽）：夹具同一文件、判定 `接受`、改一个纳入文件 ⇒ `ERROR …: signed_anchor_mismatch：tree 指纹与签名记录不符（签 tree:…，现 tree:…）`，exit 1 | 结构 | 让已签文件也静默跳过 ⇒ 本判据命令红 |
| C4 | 未签判定白名单是**枚举**而非“非接受即未签”：`判定：待填`、`判定：待签`、`判定：未判`、判定行缺失 四种算未签；`判定：拒绝`、`判定：partial`、任意其它非空串一律按已签处理（保守）。正例：夹具体 6 组判定值跑 `check`，未签 4 组 0 ERROR、非白名单 2 组各 1 ERROR | 结构 | 改成 `!/接受/.test(判定)` ⇒ 拒绝/partial 逃检，本判据红 |
| C5 | `references/02-判据与门禁.md` 与 SKILL 口径一致：`preset` 退场那句仍在，且新增一句“SKILL 不得要求写 preset 字段”。正例：`grep -q 'preset.*退场' skills/sdo-flow/references/02-判据与门禁.md && grep -q 'SKILL 不得要求写' skills/sdo-flow/references/02-判据与门禁.md` | 语义 | 删任一句 ⇒ 红；门禁/判据表不动 |

## 假设

- A1：`check.mjs` 里 tree 锚点比对只有一个入口（`signed_anchor_mismatch`），本卡只在它前面加“是否已人签”的闸。
- A2：判定行解析已有单点（`skills/sdo-flow/scripts/lib/verdict.mjs` 的 `parseVerdict`/`isUnsignedVerdict`）；未签白名单复用 `isUnsignedVerdict`，不另写正则。若 `isUnsignedVerdict` 的现有口径与本卡 C4 不同，停下来报 Lead 而不是就地改宽。
