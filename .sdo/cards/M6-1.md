## 意图

真实项目暴露出“结构全绿、业务全错”：八条判据都是格式检查，没人被迫写一条业务语义判据。本卡让卡模板自带「类型」列，并要求每张 done 卡至少有一条语义类判据（或明确写“不适用 + 理由”），评审段留一行语义自检。

## 风险标记

release_touching：改卡模板与 `done` 卡校验，会影响所有后续卡的收口路径。

## 对齐（复述）

- 一句话：把“业务语义”从评审的口头习惯，变成卡面上必须有的一格。
- 做：①判据表加「类型」（结构/语义/边界）；②done 卡 ≥1 条语义，或 `语义：不适用（理由 ≥8 字）`；③done 卡评审段有 `- 语义自检：…`。
- 不做：不判断语义判据写得对不对（评审判）；不回溯 M6 之前的卡。
- 正例：新卡有两条语义判据、评审段有一行语义自检 ⇒ exit 0。
- 反例：done 卡全结构、无“不适用”理由 ⇒ 红。

## 预览

## 评审

- 评审者：`reviewer`（独立、只读、非作者，两轮）
- 判定：**可提交**（第 1 轮改完再审：2 P1 + 2 P2 + 1 P3；第 2 轮 delta 可提交 + 3 P3）
- 第 1 轮挑出的真问题：①`语义：不适用` 扫描整张卡（写进意图/证据注即可绕过）；`- 语义自检：` 只查“存在”，写 `无` 或放 HTML 注释也能过；②`semanticBaselineCards()` 取第一个含“冻结段”的标题、无唯一性检查（插 `### 冻结段说明` 即可把 M6-0 加进豁免或遮蔽真声明）；③`criterionTable()` 取段内第一个表头，示例表可骗过。
- 语义自检：C2（语义判据本身：done 卡必须有语义或写不适用）；评审复跑“全结构 + 意图段写不适用” ⇒ 仍红，恢复绿。
- 修法：限定段（判据/判定）、全卡唯一、理由 ≥8 字与套话黑名单、自检必须点名 `C<n>` 且跳过 HTML 注释；冻结段标题唯一（0 或 >1 都红）；判据表锚定逐格表头 `编号|判据|类型|反例` + 分隔行 + 列数，段内第二个「编号」表头即红。
- 教训：判据的“位置”本身也是判据——只校验存在，就等于允许把答案写在任何地方。

## 判定

- C1 pass：类型列/枚举校验；坏值定位行，缺列由 C4 负例覆盖。
- C2 pass：全结构红；`语义：不适用` 理由 ≥8 字且非套话放行，`无所谓` 红。
- C3 pass：有语义判据且 done，删 `- 语义自检：` ⇒ 红并点名卡号。
- C4 pass：名单只在 M6.5 冻结段解析；删 M5-0 ⇒ M5-0 立即按严格口径报缺类型列。
- baseline 未回溯：M1–M5 名单内卡不触发新规则；M6-0 补 `- 语义自检：C5…` 后全绿。
- 总体：pass（评审复核）。
