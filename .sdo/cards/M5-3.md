# M5-3 · 里程碑归档（文件数与耗时减重）

status: open
owner: lead
write_scope: [`skills/sdo-flow/scripts/archive.mjs`, `skills/sdo-flow/scripts/check.mjs`, `skills/sdo-flow/scripts/view.mjs`, `skills/sdo-flow/SKILL.md`（§11）, `README.md`, `.sdo/archive/`]

## 意图
把已收口里程碑的卡/评审/读数/出口表搬进 `.sdo/archive/<M>/`，用 manifest 锁住字节；检查器只读 manifest，不解析归档内容，从而让活跃区文件数与 `check` 耗时随里程碑数不增长。

## 风险标记

risk_flags：release_touching

## 对齐
- 该做：`archive`/`restore`/`list` 三个子命令；`archive/INDEX.md` 每行一个里程碑（门签号、被签树、文件数、逐文件 sha256）；`git mv` 搬运、内容不改。
- 不该做：不搬 `sign/` 与 `台账.md`（全局审计脊柱）；不改历史签字；不删任何内容。

## 判据
| 判据 | 内容 | 证据怎么给 |
|---|---|---|
| C1 | `archive.mjs archive M3` 把 M3 的卡、评审记录、读数文件、出口表搬进归档目录，并在归档索引里写 manifest（含 sha256） | 夹具副本实测；`git status` 显示 rename 而非内容改动 |
| C2 | `check.mjs` 扫描范围改为「活跃目录 + 归档索引」，不解析归档正文；manifest 哈希不符即红 | 副本改归档里一个字节 ⇒ exit 1 并点名文件 |
| C3 | `view.mjs archive` 列出归档里程碑与文件；`view.mjs archive M3` 列出该里程碑文件清单 | 两条命令输出非空、退出码 0 |
| C4 | `archive.mjs restore M3` 搬回原位、INDEX 标「已恢复」、`check` 仍 0 错 | 实测 restore 后 `diff -r` 与原归档内容一致（除 INDEX 行） |
| C5 | 归档后活跃文件数与 `check` 耗时下降 | 归档 M1/M2/M3 前后各测一次，记录数字 |
| C6 | 不回归 | `check` 0 错 0 警；`view next` 五节；`--plan` 0 漂移 |

A2：合成数据只用于计时，不含真实项目内容。
