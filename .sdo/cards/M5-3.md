# M5-3 · 里程碑归档（文件数与耗时减重）

status: open
owner: lead
write_scope: [`skills/sdo-flow/scripts/archive.mjs`, `skills/sdo-flow/scripts/check.mjs`, `skills/sdo-flow/scripts/view.mjs`, `skills/sdo-flow/SKILL.md`（§11）, `README.md`, `.sdo/archive/`]

## 意图
把已收口里程碑的卡/评审/读数/出口表搬进归档目录，用 manifest 锁住字节；检查器只读 manifest、不解析归档正文，使活跃区文件数不随里程碑增长。

## 风险标记

risk_flags：release_touching

## 对齐
- 该做：`archive`/`restore`/`list`；归档索引每行一个里程碑（门签号、被签树、文件数、逐文件 sha256）；`git mv` 搬运、内容不改。
- 不该做：不搬 `sign/` 与 `台账.md`（全局审计脊柱）；不改历史签字；不删任何内容。

## 判据
| 判据 | 内容 | 证据怎么给（含反例） |
|---|---|---|
| C1 | `archive.mjs archive M3` 把 M3 的卡、评审记录、读数、出口表搬进归档目录，并在归档索引写 manifest（含 sha256） | 副本实测 `git status` 显示 rename；反例：搬完 `git status` 显示 delete+add ⇒ 说明没走 `git mv`，打回 |
| C2 | `check.mjs` 扫描范围改为「活跃目录 + 归档索引」，不解析归档正文；manifest 哈希不符即红 | 副本改归档里一个字节 ⇒ exit 1 并点名文件；反例：不改字节、改 mtime ⇒ 不报（正确） |
| C3 | `view archive` 列出归档里程碑；`view archive M3` 列出该里程碑文件清单 | 两条命令非空、exit 0；反例：`view archive M9` ⇒ exit 2（不存在） |
| C4 | `archive.mjs restore M3` 搬回原位、索引标「已恢复」、`check` 仍 0 错 | 恢复后 `sha256sum` 与 manifest 逐文件相等、`git status` 空；反例：少搬一个文件 ⇒ exit 1 |
| C5 | 归档后活跃扫描文件数下降 ≥10%（且从此不随里程碑数增长） | 归档 M1–M3 前后各记录一次扫描数与耗时；反例：文件数不变 ⇒ 归档没生效 |
| C6 | 不回归 | `check` 0 错 0 警、`--plan --milestone M5` 0 漂移、`view next` 五节；反例：任一非零 ⇒ 视为破坏 |
