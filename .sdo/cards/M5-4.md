# M5-4 · 台账分卷与索引（V1 教训：禁止每次全量读）

status: done
owner: impl-core
write_scope: [`skills/sdo-flow/scripts/ledger.mjs`, `skills/sdo-flow/scripts/check.mjs`, `skills/sdo-flow/SKILL.md`（§11）, `skills/sdo-flow/templates/台账.md`, `.sdo/.index/`, `.sdo/archive/`]

## 意图
台账到 1 万/10 万行仍不慢：卷头元数据 + 未决索引，写 O(1)、读 O(活跃卷 + 未决项)；正文是真源，索引是可丢弃重建的派生。

## 风险标记

risk_flags：release_touching

## 对齐
- 该做：索引记 volumes + open；`rotate`/`reindex`；`index_stale` 检测；正文与索引不一致时以正文为准。
- 不该做：不自动全量重建；不把归档卷读进每次检查；不改已归档卷。

## 判据
| 判据 | 内容 | 证据怎么给（含反例） |
|---|---|---|
| C1 | 活跃卷与归档卷头部都有卷元数据注释（first/last/rows/sha256） | `head -3 .sdo/台账.md` 含该行；反例：删卷头 ⇒ `check` 报缺卷元数据 |
| C2 | 索引记录 volumes 与 open，只随追加/关闭/轮转增量更新；正文是真源、索引可由 `reindex` 完全重建 | `add`/`close` 后 open 正确；反例：手改正文不动索引 ⇒ `index_stale` exit 1 |
| C3 | `ledger.mjs rotate --to <file>` 把已关闭行搬到归档卷并更新卷头与索引；`reindex` 后再跑一次 `diff` 为空 | rotate 后 `check` 0 错、`reindex` 幂等；反例：连续两次 `reindex` 输出不同 ⇒ fail |
| C4 | `check.mjs` 检测索引漂移：手改/删行/行数与索引不符 ⇒ `index_stale` exit 1 | 三例各 exit 1；反例：所有漂移都不报 ⇒ 等于没有索引 |
| C5 | 跨卷 close 可用：原行在归档卷、close 行写活跃卷，`view ledger D-<n>` 能定位到归档卷 | 实测记录定位输出；反例：定位到错误卷 ⇒ fail |
| C6 | 10 万行合成数据：`ledger add` < 100ms、`view next` < 200ms、`check` < 300ms | 生成脚本内联、`time -p` 三次取中位、记录机器与 Node 版本；反例：任一超预算 ⇒ 判 fail 并记缺口 |

## 判定
- C1 pass：活跃卷与归档卷均有卷元数据注释；删首行 check 报缺并 exit1。
- C2 pass：add/close 增量更新索引；手改正文不 reindex ⇒ `index_stale` exit1，reindex 后恢复；正文为真源。sha256 只证各卷文本未变；open/rows/first/last 以 `reindex` 为准，`check` 单次线性扫各卷复核，不写“哈希相等 ⇒ 索引与正文一致”。
- C3 pass：`rotate --to` 整卷改名（内容仅更新卷头行）+ 新空活跃卷；`check` 0 错；连续两次 `reindex` 输出逐字节相同。
- C4 pass：删归档 open/改卷头/改索引三例均 `index_stale` exit1；reindex 修复。检查器单次线性扫：id/kind/status/file/line、rows/first/last 全复核，sha256 只证文本未变。
- C5 pass：跨卷 close 后 `view ledger D-<n>` 同时给原行（归档卷:行）与关闭行（活跃卷:行）。
- C6 partial：②③ 均低于预算；①（R23 要求的 100k 全 open 活跃卷）add 609.9ms、check 520.2ms 仍超预算，view 194.4ms 已达标；如实记 fail，缺口 D-95/D-98。

## 已知边界
- add 仍重写整个活跃卷；①100k 全 open 活跃卷实测 add 609.9ms、check 520.2ms 仍超预算，view 194.4ms 已过（D-95/D-98）；性能预算依赖“轮转后活跃卷小”。
- rotate 是整卷改名（未决行也进归档卷），索引 open 的 `file` 改为归档卷路径；不是“只搬已关闭行”的拆卷。
- `view ledger D-n` 依赖活跃卷里的 close 行或索引 open；若 close 行本身也随卷归档，则只靠索引无法再定位关闭行（需扫描归档卷）。
- 全 open 活跃卷的 check 曾因 O(n²) 达 683.4ms；现改单次线性扫（open/rows/first/last）+ sha 文本校验，100k 全 open 520.2ms 仍超 300（D-95/D-98）；100k 归档 293.7ms、10k 65.5ms 达标。
- 索引缺失曾直接 `return` 静默放行，已修为 ERROR；注销索引即红。
- 归档卷/索引 open 指向的卷缺失时，`list --open`/`view next` 曾静默少行，已改为 stderr + exit2。
