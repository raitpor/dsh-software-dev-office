## 判据

| 编号 | 判据 | 类型 | 反例 |
|---|---|---|---|
| C1 | 有命令能列出**合法门名与判据池**（建议 `milestone.mjs declare --list`，来源 `skills/sdo-flow/references/02-判据与门禁.md` 的白名单 + preset 门集合），只读、exit 0，输出可直接抄进 `declare` | 结构 | 新项目里 agent 只能靠撞错才知道合法名单 |
| C2 | `sign.mjs new --force` 可覆盖**未人签**的草案（`- 判定：` 为空或 `待填`/`待签`，或文件带生成标记）；人签过的（接受/拒绝）⇒ exit 2 + `sign_already_signed`，不覆盖；不带 `--force` 时行为与现在一致（跳过并提示） | 结构 | `--force` 覆盖了已接受签；或已签文件被静默改写 |
| C3 | `gate.mjs init <M> --force` 覆盖重生成门表，覆盖前打印「将覆盖：<路径>」；不带 `--force` 保持「已存在，跳过」 | 结构 | declare 改了映射后只能 `rm` 再 init |
| C4 | `SKILL.md` 补「未签阶段 `gate` 的预期红码」清单：`core 判据 <id> 不是 pass（partial）`、`<门> 有 partial 项（…）但本表第 3 节没有「选项：签：…」`，并说明“这是签前预期，签后由 `sign batch`/人签补齐第 3 节”；同时修冷启动任务书两处错误（`templates/意图.md` 实际名、`card.mjs new` 参数签名） | 语义 | agent 在签前被 gate exit 1 卡住，以为流程坏了 |
| C5 | 三条命令缺参 exit 2、二次执行幂等（`--force` 除外）；证据只写 `exit=<n>`；`check`/`--presets`/`--trace`/`--plan M11`/`--deep` 全绿；冻结区零改动 | 边界 | 为验证在仓库里跑破坏性命令 |
