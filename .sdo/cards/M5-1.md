# M5-1 · 证据只由脚本写

status: done
owner: lead
write_scope: [`skills/sdo-flow/scripts/card.mjs`, `skills/sdo-flow/scripts/check.mjs`, `skills/sdo-flow/templates/card.md`, `skills/sdo-flow/SKILL.md`（§5）]

## 意图
让“跑过”只能由脚本记录：`card.mjs evidence` 必带命令与真跑结果；检查器拒“手写 pass”形态的证据。

## 风险标记

risk_flags：无

## 对齐
- 该做：`evidence` 必带 `--cmd`，结果来自 `--run`；无 `--run` 写「未跑待复跑」。
- 不该做：不禁止人改证据文字（信任前提），只禁止“看起来像结果但不是脚本写的”形态。

## 判据
| 判据 | 内容 | 证据怎么给（含反例） |
|---|---|---|
| C1 | `card.mjs evidence` 无 `--cmd` ⇒ exit 2；`--result` 参数移除或 exit 2 | 夹具两种调用各非零；反例：无 `--cmd` 仍写入 ⇒ 本判据 fail |
| C2 | `check.mjs`：`done` 卡证据行的结果列必须是脚本形态（`exit=<code>` 或「未跑待复跑」） | 夹具：手写 `pass` ⇒ exit 1 并点名判据；反例：`exit=0` 与「未跑待复跑」都放行 ⇒ 正确，不报 |
| C3 | 模板与 `SKILL.md` §5 同步说明“证据列只接受脚本生成” | 两处说明各 ≥1 行；反例：只改脚本不改文档 ⇒ 评审打回（口径不一致） |
| C4 | 变异红证：让 `evidence` 忽略 `--run`（强制写未跑）⇒ C2 用例真红，恢复后绿 | 记录两次 exit；反例：变异后 C2 仍绿 ⇒ 说明 C2 没测到该路径 |

## 假设
A1：`/tmp` 跨界会被清空 ⇒ 所有夹具在单次调用内完成。
A2：合成数据只用于计时，不含真实项目内容。

## 判定
- C1 **pass**：无 `--cmd`、仅 `--run`、`--result` 三态均 exit 2 且零写入。
- C2 **pass**：新卡（M5-1 起）done 后结果列必须 `exit=<code>` 或「未跑待复跑」；手写 `pass` 点名判据 exit 1。豁免集合只由 `.sdo/01-计划.md` 卡表推导：M1–M3 legacy、M4 baseline（结果格式豁免，判据/评审者/判定列照旧）、M5+ 严格；**不在任何卡表 ⇒ 严格 fail-closed**（`M1-new.md`/`M4-x.md` 夹具均 exit1）；M5-0 作为已收口 baseline，由计划 M5 段的「证据格式基线卡」声明豁免（检查器解析该行，不硬编码卡名）。M4 及以前 done 卡证据是 M5-0 人工回填的 baseline，不回填成脚本形态（见「已知边界」与 D-75）。
- C3 **pass**：模板与 SKILL §5 口径一致。
- C4 **pass**：忽略 `--run` 的变异使 C2 的 `exit=0` 断言真红，恢复后绿；两次 exit 见证据行。

## 已知边界
- M4 及以前 done 卡（含 M4-0…M4-G）的证据列是 M5-0 人工回填的历史 baseline，不按 M5-1 的“结果列必须脚本形态”校验；判据/评审者/判定列检查照旧。M4 不回填成脚本形态（当年不是 `card.mjs` 写的，回填等于造假）。
- M5 起的新 done 卡强制脚本结果列；豁免集合只认 `.sdo/01-计划.md` 卡表归属，不按文件名推断，表外卡一律严格。
- M5-0 为已收口 baseline，豁免由计划 M5 段「证据格式基线卡」声明；检查器不硬编码卡名，声明缺失/解析失败即空集、所有卡严格。
