## 意图

让“这批活是按哪一版需求做的”**可判**：里程碑冻结段记项目基线 hash；基线改了而里程碑没声明，`--plan` 必须红。变更协议是“里程碑内记临时决策、收口前结清变更请求”，不是静默跟新版本。

写 `.sdo/milestones/M8.md` 的「M8.5 基线段」会让整文件 hash 变 ⇒ 按流程走**追加签 S34-A**（本卡写域含该文件的基线段，允许改；hash 重算与追加签在 M8-G 前完成）。

## 判据

| 编号 | 判据 | 类型 | 反例 |
|---|---|---|---|
| C1 | `.sdo/baseline/` 含 `requirement.md`、`architecture.md`、`test-strategy.md`、`quality-risk.md` 四份；`templates/baseline.md` 给出四份的格式 | 结构 | 只有 `requirement.md` ⇒ `ls .sdo/baseline/*.md \| wc -l` 得 1（应 4），架构/测试策略无基线可引用 |
| C2 | 里程碑冻结段有 `基线 hash：<sha256>` 行；`--plan --milestone M<n>` 重算当前基线 hash 并比对 | 结构 | 删掉该行 ⇒ 所有里程碑都不绑版本，`--plan` 仍绿 |
| C3 | 基线改动后未声明 ⇒ exit 1，首条报 `baseline_drift` 并给出“旧 hash→新 hash”与声明写法 | 结构 | 比对时忽略 hash 只比文件存在性 ⇒ 改需求正文后仍 exit 0 |
| C4 | 里程碑冻结段有 `基于旧基线：<旧 hash 前 8 位>（理由）` 时 exit 0，且输出提到该声明；理由 ≥8 字且不在 `.sdo/计划.md` §3 黑名单 | 边界 | 写成 `基于旧基线：abcdef12（无）` ⇒ 命中黑名单，应 exit 1（否则等于白名单化） |
| C5 | 基线 hash 口径写死并单点实现：`.sdo/baseline/` 四份按文件名排序，`sha256(路径 + "\n" + 内容)` 拼接后再取总 hash；`check` 与将来的视图不得各算一份 | 语义 | `check.mjs` 自己拼、另一处再拼一次 ⇒ 两处 hash 不同（M5-4 的索引/正文分叉同型） |
| C6 | 变更协议可判：卡模板有「临时决策」段，写明“引用需求 id + 临时决定 + 收口前必须结清”；done 卡若该段有未结清行 ⇒ `check --trace` 报 `pending_change_request` | 语义 | 模板没有该段 ⇒ `grep -c '^## 临时决策' skills/sdo-flow/templates/card.md` 得 0，变更无处记录、静默带入 |
| C7 | `templates/baseline.md` 定义三类基线文档的最小可机检结构：需求条目含 `验收：`；架构决策为 `## ADR-<n>：<标题>` 且含 `决策`/`备选`/`后果` 三字段；测试策略为 `| 变更类型 | 测试技术 |` 表且 ≥3 行 | 结构 | 模板只写 `## ADR` 标题无三字段 ⇒ M8-4 C6 的 ADR 校验必须红（说明模板没钉死格式） |

## 已知边界

1. 基线 hash 只覆盖 `.sdo/baseline/` 四份文件，不覆盖意图（意图有自己的签）。
2. 历史里程碑（M1–M7）无基线，按 M8.5 基线段豁免。
3. hash 保护的是“忘更新”与“静默跟版”，防不了“基线+声明一起伪造”——后者属信任前提（§11）。
4. 修改基线段必须走追加签；本卡不含“重算 hash 后请人签”这一步，那一步在 M8-G 收口前完成（追加签 S34-A）。
