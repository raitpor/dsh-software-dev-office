## 意图
收 M12 三个 gap：git:<sha> 锚点、豁免随归档失效、trace 不认归档卡

## 风险标记

- 无

## 对齐

- D-270：`commitClaims` 只认裸 sha 与 `commit <sha>` ⇒ C1 让它认 `git:<sha>`（并校验 commit 已知性）
- D-272：豁免行随声明方里程碑归档后语义未定 ⇒ C2 定死"归档即失去声明资格"（不放行，或降 WARN 并写明来源已归档）
- D-273：`checkTrace()` 只扫活跃卡 ⇒ C3 把 `.sdo/archive/*/cards/` 也算引用来源
- 三处都是机检层漏检，不是文案；每条都要有"改前红、改后绿"的真跑证据（C4）
- 计划探底补记的第 4 条：`gate.mjs` 的 `PLACEHOLDERS` 不含 `待填`/`待判`，导致"判定 pass + 证据还是生成器占位"能过门 ⇒ C6 修它（否则 R59 的反例③不可达）

## 假设

- A1：归档卡的引用计数只影响"孤儿检测"，不影响签字链与门禁——若发现归档卡被当成"活跃引用"会让其他判据变绿（假绿），停，改为"只用于孤儿检测"的白名单入口。
- A2：`git:<sha>` 校验只在**仓库是 git 仓**时比对；无 git 项目里 `git:` 形态本就不该出现（M11-11 之后写 `tree:`），出现即报错而非静默放行。
- A3：把 `待填`/`待判` 加进 `PLACEHOLDERS` 会不会误伤合法证据（例如证据写成 `grep 待填`）——若会，改为“整格等于占位词才拒”，不改变 C6 的判定语义。
