# M4-2 · 签字材料脚本 `sign.mjs draft`

status: done
owner: impl-core
write_scope: [skills/sdo-flow/scripts/sign.mjs, skills/sdo-flow/templates/sign.md, skills/sdo-flow/SKILL.md（§11）, README.md]

## 意图
签字前把“该核对的事实”一次性摊出来：改了哪些文件、有没有未提交、HEAD 是什么、判据文件在哪一行。**只出事实，不出判定句，也不写签字文件。**

## 风险标记

risk_flags：release_touching（本卡决定人签材料的事实源：输出错一项就可能让人签错树）

## 对齐
- 该做：`draft --milestone M<n>` 输出事实材料（`文件:行`、可复跑命令、HEAD、`git status` 是否为空、读数 overall）；脏树顶部标 `DIRTY` 且 exit 1。
- 不该做：输出“我认为可以签”“判定 pass”这类句子；替人写复述；写 `sign/` 下任何文件；自动 commit。

## 判据
C1 **只出事实**：stdout 断言（不是只 grep 模板）——干净模板下 `node <skill>/scripts/sign.mjs draft --milestone M4` 的 stdout 不出现判定词与签字字段组合。
  反例：数据里埋一条台账「建议签」或读数里写「符合」⇒ 脚本必须原样引用为事实（带 `文件:行`），且**不得**出现 `建议签|可以签|可签|我认为|判定：|选项：签：|签署者：` 任一；出现即 C1 红。
  （评审后定死：正则扩到 `建议签|可以签|可签|推荐签|我认为|判定[:：]|选项[:：]签|签署者[:：]|✅|⚠️`。）
C2 工作树脏（`git status --porcelain` 非空）⇒ 首行 `DIRTY`、exit 1；干净 ⇒ exit 0。
C3 **读数缺失不算错**：`.sdo/readings/M4.md` **从未入库/不存在** ⇒ 输出「读数：缺（M4 未跑）」、exit 0；而**里程碑段找不到** ⇒ exit 2。
  优先级定死：**C2 优先**——若读数文件被 git 跟踪后删除（`git status` 出现 ` D`），属脏树，先报 `DIRTY` exit 1，不再走“缺失=正常”。
C4 输出契约：**只写 stdout，不提供 `--out`，不写任何文件**；退出码表 0 正常 / 1 脏树或树不一致 / 2 用法或环境错；stderr 只放错误。全盘检测夹具：跑前跑后 `git status --porcelain`、`.sdo/sign/` 列表、`/tmp` 下新建文件数均不变。
C5 每个“改了哪个文件”带基线：输出 `git diff --stat <锚点>..HEAD`（有锚点）或 `git diff --stat HEAD`（无锚点），并列 `git status --porcelain`；每条改动给 `文件:行` 或 commit 范围。
C6 **被签对象 vs 当前树**（`AHEAD <n>` 的 n 由 `git rev-list --count` 现算；夹具用“改文件但不提交”，已提交的锚点后改动只能靠 `AHEAD n` + `diff --stat` 发现——这条写进已知边界）：输出必含当前 `HEAD sha`、每个被签文件（由里程碑段/卡面点名的）`sha256`，并与冻结锚点对照，给出 `SAME / AHEAD <n> / BEHIND <n> / NO_ANCHOR`；夹具「改一个被签文件后再跑 draft」⇒ 打出 `TREE_MISMATCH` 与不一致文件清单、exit 1。
C7 **无 git 不装死**：`rm -rf .git` 的副本跑 draft ⇒ 输出 `NO_GIT` 且事实块写明「无法核对版本」，exit **0**（环境缺能力不是人签错误）；用法/环境错仍 exit 2。

## 假设
A1：签字文件仍由人写（或代笔后由人核对），脚本只准备材料。
A2：以 `git` 命令取事实；仓库无 git 时退化为“无法核对版本”，由 C7 触发 `NO_GIT`。
A3：冻结锚点取里程碑段「被签对象：`<commit>`」那行；未签/无该行 ⇒ `NO_ANCHOR`。

## 判定

- 变异红证（已恢复）：①把最终退出码里的 `dirty` 去掉 ⇒ 脏夹具首行仍 `DIRTY` 但 exit 0（应 1）；②关掉输出禁止词自检并在 stdout 加「建议签」⇒ C1 红。
