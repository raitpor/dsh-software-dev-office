# M4-2 · 签字材料脚本 `sign.mjs draft`

status: open
owner: impl-core
write_scope: [skills/sdo-flow/scripts/sign.mjs, skills/sdo-flow/templates/sign.md, skills/sdo-flow/SKILL.md（§11）, README.md]

## 意图
签字前把“该核对的事实”一次性摊出来：改了哪些文件、有没有未提交、HEAD 是什么、判据文件在哪一行。**只出事实，不出判定句，也不写签字文件。**

## 风险标记

risk_flags：无

## 对齐
- 该做：`draft --milestone M<n>` 输出事实材料（`文件:行`、可复跑命令、HEAD、`git status` 是否为空、读数 overall）；脏树顶部标 `DIRTY` 且 exit 1。
- 不该做：输出“我认为可以签”“判定 pass”这类句子；替人写复述；写 `sign/` 下任何文件；自动 commit。

## 判据
C1 输出只含事实块（改了什么/验证命令/HEAD/工作树状态/读数），**不含**“建议签/可以签/我认为/判定 pass”等判定句。
  反例：模板里加一句“建议签” ⇒ C1 红（可用 `grep -E "建议签|可以签|我认为"` 验证为空）。
C2 工作树脏（有 `git status --porcelain` 输出）⇒ 首行 `DIRTY`、exit 1；干净 ⇒ exit 0。
  反例：脏树仍 exit 0 ⇒ 红。
C3 `--milestone M4` 能定位到该 M 的读数文件与卡表（找不到 ⇒ exit 2 并说明缺什么）。
C4 不写任何文件：跑前跑后 `git status --porcelain` 与 `.sdo/sign/` 列表不变。
C5 输出里每个“改了哪个文件”都带 `文件:行` 或 commit 范围，能被第三人复查。

## 假设
A1：签字文件仍由人写（或代笔后由人核对），脚本只准备材料。
A2：以 `git` 命令取事实；仓库无 git 时退化为“无法核对版本”，且必须在输出里写明。
