## 评审

- 评审者：`reviewer`
- 第 1 轮：改完再审（P1×2 + P2）——① 段名清单不能直接抄（机检要反引号）② `--criteria` 样例用半角逗号而实现禁用 ③ `draft` 无 HEAD 口径写反（实测 exit 0）
- 第 2 轮：可收卡（三处闭合）
- 第 3 轮（返工后）：可收卡 + P3（`SKILL.md:108` 正例与“判据：”粘同一行）；P3 已修
- 第 4 轮：**可收卡**，并确认 C8 判 partial 属诚实处置
- 语义自检：C6 的“同形规则”是给人和机器共用的口径：文档写了计划表/卡面同一 token 的正例与裸文件名/引号反例，但机检只比“归一后集合相等”，不判“写法是否可读”——所以语义上够用、不足以保证新人一次写对，这条残余风险已写进边界
- 不可变异确认 C2：SKILL 文本没有执行体，机检不读 SKILL 行，只能人工对照 `presets/*.md`（评审第 3 轮确认）
- 不可变异确认 C3：探底行样例是文档约定，机检读的是里程碑文件而非 SKILL（评审第 3 轮确认）
- 不可变异确认 C4：认领行样例同为文档约定（评审第 3 轮确认）
- 不可变异确认 C5：`--help` 文案与 `die()` 消息同源，删一处另一处仍打印（实测「分号」计数 1→1），属文案而非判定逻辑（评审第 3 轮确认）
- 不可变异确认 C6：`write_scope` 同形规则是文档约定，机检只比归一后集合相等（评审第 3 轮确认）
- 不可变异确认 C7：`draft` 前置与 `--print-frozen-hash` 口径均为文档约定（评审第 3 轮确认）
- 不可变异确认 C8：依赖外部无上下文席位，本轮 3 席 + 多子代理均未产出（评审第 4 轮确认）
- 教训：①“清单”与“样例”要分开写；②同一事实出现两次就会打架（逗号禁用写在正文、样例却用逗号）；③文档比实现更严也是错（`draft` 无 git 明明 exit 0）
