# M4-3 · `view next`（现在能开工什么）

status: open
owner: impl-core
write_scope: [skills/sdo-flow/scripts/view.mjs, skills/sdo-flow/SKILL.md（§11）, README.md]

## 意图
把“下一步做什么”从人翻文件变成一条命令：哪些卡能开工、哪些被依赖卡住、哪些卡/门待签收、哪些台账没关。

## 风险标记

risk_flags：无

## 对齐
- 该做：`view next` 输出五小节（可开工 / 被依赖卡住 / 待签收 / 待签文件 / 未修台账），每节空写「无」。
- 不该做：替人决定优先序、修改任何文件、把“缺读数”说成“已通过”。

## 判据
C1 `next` 输出**固定五节**（顺序固定）：`可开工` / `被依赖卡住` / `待签收` / `待签文件` / `未修台账`；每节为空必须写「无」，不得省略整节。
  正例：空项目 + 一张 `status: open` 无依赖的卡 ⇒ 该卡在「可开工」，其余四节「无」。
  反例：在 `/tmp` 副本把「未修台账」那节的渲染行删掉 ⇒ exit 1（不是“少打印一行”算过）。
  附加节：`未知状态`（见 A2）与 `进行中`（`in_progress` 卡）允许追加在五节之后，不影响 C1。
C2 **依赖来源定死为计划卡表**：`.sdo/01-计划.md` 里该里程碑卡表的「依赖」列（`.sdo/01-计划.md:140-145` 形态），解析顿号/逗号分隔、`M4-0…M4-4` 这类区间、剥掉括号与提交号；卡面 `## 准入 - 依赖：` **只作对照**，不一致时以计划卡表为准并在 stderr 提示。
  反例：把计划表里某卡的依赖删掉但卡面准入仍写着 ⇒ `next` 按计划表判“可开工”，stderr 出现对照提示。
C3 **待签文件**（计划/门）：扫描 `.sdo/sign/*.md`，匹配规则定死——`# S<n> · <里程碑> 计划` 或 `范围：` 行含 `M<d>` 且同处含「计划」/「门」，判该里程碑计划/门**已签**；里程碑段若**没有**「状态：」行 ⇒ 单列到「未知状态」，不静默当“待签”。
  反例（在 `/tmp` 副本）：把某卡的 `status` 改成 `done` 且该卡无签收 ⇒ 必须出现在「待签收」（漏报即红）。
C4 **待签收**：卡 `status: done` 但**无任何收卡记录** ⇒ 列出。已知边界：`M1-G`/`M2-0` 是历史卡（由门签 S4/S8 关，不是「收卡」签），会被如实列出，不追改历史签字。签收匹配定死：签文件标题或 `范围：` 行按 `M<d>-<n>(?!\d)` 边界匹配，且同处含「收卡」。
  反例（在 `/tmp` 副本）：删掉 S14 的「范围」行与标题里的卡号 ⇒ M4-0 必须回到「待签收」（误判已签即红）。
C5 **未修台账**：口径与 `view.mjs queue` 共用同一函数 `isOpenLedgerRow(row)`，定死为——`status === "open"` 一律算；`kind === "defect"` 且 `status ∉ {fixed, closed, superseded}` 算；`kind === "gap"` 且 `status ∉ {fixed, closed, superseded}` 算；**`explain` 与 `accepted` 的说明性记录不算**（否则 20 条 explain 会把队列淹没，实测 `next` 曾列出 7 条 explain）。排序按 D 编号**数值序**。
  反例（在 `/tmp` 副本）：把一条 `superseded` 行算进未修 ⇒ 该用例红；把排序改字典序 ⇒ D-10 排到 D-2 前即红。
C6 **只读 + 退出码 + `--json`**：跑前跑后 `git status --porcelain` 与本文件清单不变；只写 stdout；`--json` 输出可 `JSON.parse` 且含五节的数组；无 `.sdo/` ⇒ exit 2；`check.mjs` 报错不影响本命令（它不跑检查）。
  反例（在 `/tmp` 副本）：让 `next` 顺手写 `.sdo/.cache/next.json` ⇒ C6 红。

## 预览
预计改：`scripts/view.mjs` 加 `next` 子命令；`SKILL.md` §11、`README.md` 各一行。
验：C1–C5 夹具（一张卡依赖未 done、一份读数缺 overall、一条 open 台账、一张 done 无签收）。

## 判定
- C1 pass：五节固定、空节写「无」；删渲染行 exit 1（副本实测）。
- C2 pass：依赖只读计划卡表；卡面仅对照，stderr 实测出现不一致提示。
- C3 pass：签收按标题/范围行；无「状态：」行入「未知状态」且 exit 1。
- C4 pass：done 无「收卡」签收 ⇒ 待签收；补签消失；变异漏报红。
- C5 pass：与 `queue` 共用 `isOpenLedgerRow()`；superseded 不算；D 编号数值序。
- C6 pass：只读（status hash 不变）、stdout、`--json` 可解析含五节数组；无 `.sdo` exit 2。
