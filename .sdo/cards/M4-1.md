# M4-1 · 卡脚本 `card.mjs`

status: done
owner: impl-core
write_scope: [skills/sdo-flow/scripts/card.mjs, skills/sdo-flow/templates/card.md, skills/sdo-flow/SKILL.md（§11）, README.md, .sdo/cards/（仅目标卡，运行时写入；不写别的卡）]

## 意图
让新卡骨架一次生成就合规（`status/owner/write_scope` + 四段），证据行能按判据落进「## 证据」表——但**结果只能来自真跑**，不许手填 `pass`。

## 风险标记

risk_flags：无

## 对齐
- 该做：`new <M>-<n> --owner --intent --criteria "C1:…,C2:…"` 生成卡；`evidence <卡> --criterion C1 --cmd "…" [--run]` 追加证据行。
- 不该做：接受 `--result pass`；自动写判定段；自动改别人卡；替人编判据。

## 判据
C1 `new` 生成的卡含 `status: open`、`owner`、`write_scope`、且四段（判据/证据/判定/评审）齐全；`check.mjs` 0 错。
  正例：`new M9-0 --owner lead --intent "x" --criteria "C1:y"` ⇒ `check.mjs` 0 错。
  反例：生成后删除「## 评审」⇒ `check.mjs` 报缺段落（视为 C1 失败）。
C2 证据行落在「## 证据」表，首格为指定判据 id；**卡里没有证据表** ⇒ 自动补四列表头；**已有表但表头映射不到四列** ⇒ `exit 2` 不改文件（不猜列，与 A2 一致）。
  口径（评审后定死）：**同一判据只允许一行**。重复 `evidence` 就**原地更新**该行（命令/摘要/结果三格），不新增重复行；若表内已存在同判据多行 ⇒ `exit 2` 且不改文件，让人先手工合并。
  反例：表里手工造两条 `C1` 行后再跑 `evidence --criterion C1` ⇒ exit 2、文件字节不变。
C3 **不许手填结果**：不传 `--run` 时“输出摘要”只能写「未跑待复跑」；传 `--result pass` ⇒ exit 2。
  反例：实现里加 `--result` 直写 ⇒ C3 红。
C4 `--run` 透传命令（`--run` 之后的参数**原样**交给子进程，含以 `--` 开头的参数；支持 `--` 终止符；用例 `--run node --version` 必须成功）：**cwd = 仓库根**、**30s 超时**（超时 ⇒ 摘要写 `timeout`、结果 `fail`、脚本 exit 1，不写 124 当退出码）；记 `exit=<code>; <stdout 最后一条非空行>`（stdout 空则取 stderr 最后一条非空行、都空写 `<no output>`）；整段压成一行、转义 `|` 与 `\`、截断 200 字符；非零 ⇒ 结果 `fail` 且脚本 exit 1；零 ⇒ `pass`。
  反例：`--run` 但结果恒写 `pass` ⇒ 用 `node -e "process.exit(1)"` 验证必红；`--run node -e "setTimeout(()=>{},60000)"` ⇒ 30s 后 `timeout` + fail。
C5 用法/环境错：卡不存在、未知判据 id、不在 `.sdo/` 项目内、目标卡 `status: done` ⇒ exit 2 且不改文件。
C6 四态回归（评审补）：`--run true` ⇒ 摘要含 `exit=0` 且结果 `pass`；`--result pass` ⇒ exit 2 且不改文件；不传 `--run` ⇒ 摘要固定「未跑待复跑」；`--run false` ⇒ 结果 `fail` 且脚本 exit 1。

## 假设
A1：卡文件路径 = `.sdo/cards/<卡号>.md`；卡号 `<M>-<n>`；目录不存在时 `new` 创建；脚本**不校验**该卡是否已在 `.sdo/01-计划.md` 登记（那是评审的事）。
A3：`evidence` 只写已存在且未 `done` 的卡；目标路径解析后**必须落在 `<root>/.sdo/cards/` 内**（拒绝对路径、`..`、`.md` 形式的外部路径）；不做 owner 校验（单人/单 agent 场景的显式例外）。
A2：证据表四列固定；旧卡若表头不同，按表头名映射，映射不到就报错（不猜）。

## 判定
- C1 **pass**：`new` 生成 `status: open`/`owner`/`write_scope` + 判据/证据/判定/评审，check 0 错；缺评审段被 check 抓住。
- C2 **pass**：同判据唯一一行、重复原地更新；手工多行 exit 2 且不动文件；表头缺失自动补、列序不同按名映射。
- C3 **pass**：不传 `--run` 固定「未跑待复跑」；任何 `--result` exit 2 不写。
- C4 **pass**：cwd=仓库根、30s 超时写 `timeout` 并 exit 1；摘要取 stdout 最后非空行（空则 stderr、再空 `<no output>`）、单行、竖线与反斜杠转义、截 200。
- C5 **pass**：卡不存在、未知判据、done 卡、仓库外均 exit 2 且零写入。
- C6 **pass**：四态（run true / --result / 不 run / run false）均符合。
- 变异红证（已恢复）：① `runCommand` 返回码恒 0 ⇒ `node -e "process.exit(1)"` 的 `--run` 变成 exit 0（应 1）；② 删除“匹配即更新”分支 ⇒ 重复 `evidence` 变成两行 C1（C2 数行数即红）。
