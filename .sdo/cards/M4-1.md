# M4-1 · 卡脚本 `card.mjs`

status: open
owner: impl-core
write_scope: [skills/sdo-flow/scripts/card.mjs, skills/sdo-flow/templates/card.md, skills/sdo-flow/SKILL.md（§11）, README.md]

## 意图
让新卡骨架一次生成就合规（`status/owner/write_scope` + 四段），证据行能按判据落进「## 证据」表——但**结果只能来自真跑**，不许手填 `pass`。

## 风险标记

risk_flags：无

## 对齐
- 该做：`new <M>-<n> --owner --intent --criteria "C1:…,C2:…"` 生成卡；`evidence <卡> --criterion C1 --cmd "…" [--run]` 追加证据行。
- 不该做：接受 `--result pass`；自动写判定段；自动改别人卡；替人编判据。

## 判据
C1 `new` 生成的卡含 `status: open`、`owner`、`write_scope`、且四段（判据/证据/判定/评审）齐全；`check.mjs` 0 错。
  正例：`new M9-0 --owner lead --intent "x" --criteria "C1:y"` ⇒ `check.mjs` 0 错。
  反例：生成后删除「## 评审」⇒ `check.mjs` 报缺段落（视为 C1 失败）。
C2 证据行落在「## 证据」表，首格为指定判据 id；表头不是 `| 判据 | 命令 | 输出摘要 | 改回去会怎样 |` ⇒ 自动补表头而不是写错列。
  反例：卡里已有同判据行时重复追加 ⇒ 应在已有行后更新，不新增重复行（或明确报错）。
C3 **不许手填结果**：不传 `--run` 时“输出摘要”只能写「未跑待复跑」；传 `--result pass` ⇒ exit 2。
  反例：实现里加 `--result` 直写 ⇒ C3 红。
C4 `--run` 透传命令：真跑、记 exit code 与 stdout 末行；非零 ⇒ 结果写 `fail` 且脚本 exit 1；零 ⇒ 写 `pass`（附命令与末行）。
  反例：`--run` 但结果恒写 `pass` ⇒ 用一条必失败命令（`node -e "process.exit(1)"`）验证红。
C5 用法/环境错：卡不存在、未知判据 id、不在 `.sdo/` 项目内 ⇒ exit 2 且不改文件。

## 假设
A1：卡文件路径 = `.sdo/cards/<卡号>.md`；卡号 `<M>-<n>`。
A2：证据表四列固定；旧卡若表头不同，按表头名映射，映射不到就报错（不猜）。
