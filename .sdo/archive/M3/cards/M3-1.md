## 判据

C1 判五件事：preset 要求的判据是否齐全（缺 ⇒ 红）、每行是否有判定（缺 ⇒ 红）、pass/partial 证据是否为空或占位（`—`/无/看过了/空/`<...>` ⇒ 红）、core 三条是否 pass（否则红）、有 fail 或 partial 时本表第 3 节是否有「签：」接受（无 ⇒ 红）。
  正例：四类负例各 exit 1，首条报错与 `.sdo/01-计划.md` R12 一致（依次：“证据为空/占位”“缺判据 spec_set.signed”“core 判据 spec_set.signed 不是 pass（partial）”“core 判据 spec_set.signed 不是 pass（fail）”；“没有「选项：签：…」接受它”可能排在其后，不要求首条）。
  反例：任一类未红 ⇒ fail。
C2 退出码语义：通过 0；未通过（有错误）1；用法/环境错 2（在项目外运行、`--file` 指向不存在的文件）。
  正例：`cd /tmp && node <skill>/scripts/gate.mjs; echo $?` ⇒ 2；项目内无 `.sdo/gates/` 且不带参数（默认判模式）⇒ 2（环境错：没有可判的表）；项目内有表且全 pass、不带参数 ⇒ 0。
  反例：缺勾选表时返回 0 ⇒ fail。
C3 四种入口可用：`--list`（只列 preset/计划 gate/现有表）、`G_xxx`（查单门）、`--file <路径>`、`--json`（机器可读）；不传参数时默认判所有表。
  正例：四种调用都退出 0/1 且有输出；`--json` 输出可被 `JSON.parse`。
  反例：`--json` 输出非 JSON，或 `--list` 在缺表时崩（非受控退出）⇒ fail。
C4 正例不误红：waterfall 的 `G_req_exit` 9 条全 pass + 有签 ⇒ `pass 9 / partial 0 / fail 0`、exit 0。
  反例：正例被误判红 ⇒ fail。
C5 变异红证：把**某一条**证据改 `—` ⇒ 恰好 1 条报“证据为空/占位”、exit 1；把全表 16 条都改 `—` ⇒ 16 条都报；把某条非 core 行改 `fail` ⇒ 报“…判 fail”、exit 1；恢复后 exit 0。
  反例：改了仍 exit 0 ⇒ 假绿。
C6 文档同步（四处点名）：`SKILL.md` §11 含 `gate.mjs` 三种用法；`README.md` 含 `gate.mjs`；`references/02` 含指向 §11 的一句；`templates/gates.md` 含 `> gate：`。
  正例：`grep -c "gate.mjs" skills/sdo-flow/SKILL.md README.md` 各 ≥1；`grep -c "> gate：" skills/sdo-flow/templates/gates.md` = 1。
  反例：任一处缺失 ⇒ partial 并写缺口。

## 假设
