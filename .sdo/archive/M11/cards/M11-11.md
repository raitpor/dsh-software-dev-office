## 意图

M11-10 把“项目根须是 git 仓库”写成了冷启动第 1 步，用来修第四轮冷启动的 K1。**用户 2026-11-24 否决了这个前提**：“我们没法保证用户机器上有 git，skill 也没法要求必须有 git。” 这条要求是对的：技能以“只要有 Node 就能用”为前提，签字却要一个 commit 号，等于把可移植性偷偷换成 git 依赖。

本卡把被签对象从“git commit id”改成**两种形态任选其一**：有 git 时仍是 `git:<sha>`（不变），无 git 时用 `tree:<指纹>`——对项目文件内容算 sha256。签字、`draft` 锚点、`check` 的漂移判定都按形态分派，语义一致：**签的是那一刻的树，树变了就该看得出来**。

## 假设

- A1：内容指纹的**可比性**只在同一台机器/同一规则下成立；跨机器比较不是本卡目标（签字锚点本来就用来和“当前树”比，不是和别的机器比）。
- A2：`.sdo/.index/` 是派生物（可从正文重建），排除它以免“重建索引就把树算脏”；`.sdo/readings/`、`.sdo/cards/` 等**纳入**（它们是真源）。
- A3：git 形态与 tree 形态**不互相转换**：同一份签里只记一种。若项目后来 `git init`，旧签按 `NO_ANCHOR` 处理（要求重新签或人工确认），不猜。
- A4：用户机器可能既无 git 也无 shell 工具（`sha256sum` 之类）⇒ 指纹必须纯 Node 实现，零新依赖。

## 预览

改完后：`mktemp -d` 里（故意不 `git init`）`sign.mjs new --kind 计划 --milestone M1 --scope …` 直接成功，签里写 `- 被签对象：tree:ab12…`；改动任一文件后 `draft` 报 `DIFF`；在该目录 `git init && git commit` 后新建的签写 `git:<sha>`，`draft` 回到 git 形态的「一致 / 领先 / 落后」三态。

## 已知边界

- 内容指纹**不证明来源**（谁签的由签字链负责），也**不防篡改**（无签名时任何人都能改文件；锚点只解决“树变没变”）。
- 跨机器/跨文件系统（大小写敏感、换行归一）不保证同值；本卡只保证“同机同规则”。
- tree 指纹管**文件树内容**，冻结段内容由冻结段 hash 管，两者不重叠：改冻结段不一定 `DIFF`（里程碑文件被排除），但 `check` 会因冻结 hash 不符报 `signed_anchor_mismatch`。
- 卡签的 tree 指纹排除当前里程碑文件，因此改冻结段时卡签仍 `SAME`；冻结段由计划签的「冻结段 hash」对账，卡签不重复对账（有意的不重叠，不是缝）。
- 指纹覆盖 `.sdo/notes`、`.sdo/archive` 等全部非排除文件（O(文件数)），改无关笔记也会 `DIFF`；本技能量级可接受，大仓需自行评估。
- 指纹计算成本随文件数增长；大盘点项目（数万文件）可能慢，本卡只要求在技能自身量级（数百文件）可用，性能数字写进读数。
