## 这次签的是什么

背景是你今天那句：**“我们没法保证用户机器上有 git，skill 也没法要求必须有 git。”** M11-10 曾把 `git init` 写成冷启动第 1 步，本卡撤掉那条前置，同时不让签字失去锚定能力：

1. **被签对象两形态**：有 git ⇒ `git:<sha>`（不变）；无 git ⇒ `tree:<内容指纹>`。无 git 时 `sign new`/`draft` 正常可用，`NO_GIT` 阻塞路径删除。
2. **指纹单源** `skills/sdo-flow/scripts/lib/fingerprint.mjs`：纯 Node、零依赖、只收普通文件、按路径字节序、`sha256(路径+"\0"+内容sha)` 再整体；默认排除 `.git/`、`node_modules/`、`.tmp/`、`.work/`、`.sdo/.index/`，签字时**额外**排除 `.sdo/sign/` 与当前里程碑文件（`signatureExcludes()` 由 `sign.mjs` 与 `check.mjs` 共用）。
3. **锚点两态分派**：tree 同形态比 `SAME`/`DIFF`；git 保持 `AHEAD`/`BEHIND`；形态不匹配一律 `NO_ANCHOR`；反查所属里程碑按“显式 `- 里程碑：` > 标题 > 范围最后一个 `M<n>` > 报错”，查不到是 ERROR 不是跳过。
4. **`check` 真比对**：改任一被纳入文件 ⇒ `signed_anchor_mismatch`（签 tree:… 现 tree:…），与 `draft` 的 `DIFF` 一致；改 `.sdo/sign/` 或当前里程碑文件 ⇒ 不红（有意排除）。
5. **边界（已写进卡与 `references/03`）**：tree 指纹管文件树内容，冻结段内容由计划签的 `冻结段 hash` 对账，两者不重叠；卡签排除当前里程碑文件，所以改冻结段时卡签仍 `SAME`，由计划签红；指纹覆盖 `.sdo/notes`、`.sdo/archive` 等，改无关笔记也会 `DIFF`，成本 O(文件数)。
6. **文档**：SKILL 步 7、冷启动任务书第 1 步把 git 改为可选；`references/03` 增两形态/指纹规则/排除项/锚点分派；任务书 `判定：待签`→`待填`。
