# 移植到新仓库

## 1. 三步初始化

```bash
# ① 拷 skill（项目根）
mkdir -p .dsh/skills && cp -r <本仓库>/.dsh/skills/sdo-flow .dsh/skills/
# ② 建流程目录与模板
mkdir -p sdo/{cards,sign,readings,review}
cp .dsh/skills/sdo-flow/templates/*.md sdo/
# ③ 首次立项
$EDITOR sdo/00-意图.md      # 按模板写：目标/非目标/降级/判据/假设
```

然后按 `SKILL.md` §3 走第一步：**把复述给人、问签**。没签不写别的。

## 2. 最小集（只想先试）

只留三个文件也能跑：

```
sdo/00-意图.md     立项 + 人签
sdo/cards/C-01.md  第一张卡（判据 + 证据）
sdo/台账.md        偏差（可以空表）
```

适合“一个下午能做完、但需要留痕”的活。里程碑/读数门等第二次再用。

## 3. 和别人协作

- 每个人的卡单独文件，避免同文件冲突；台账是**唯一**共享追加文件，冲突时保留双方行、按 id 排序。
- 签字文件只由**签字人**写（或模型代笔、人确认后提交，并在文件里写明“代笔”）。
- 评审者与作者不同分支/不同会话，评审结论写进卡面，不改别人的产物。

## 4. 迁回插件版（能装插件之后）

1. 先装 SDO 插件，跑 `sdo_status` 确认空库可用。
2. **不要**试图把 Markdown 自动转成事件——文本没有签名，转过去等于伪造授权。
3. 正确做法：以文本账本为**输入**，人签一条 `intent`/`plan` 事件（复用现有签字），把卡重建为 `task.created`；旧卡文件保留为附件（`legacy` 标记）。
4. 迁移完成前两套并行：插件负责新卡，文本负责历史；不要双写同一张卡。
