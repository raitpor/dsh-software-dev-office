## 评审门槛（进实现前必须满足）

1. 每个模块能对应到 `docs/` 的至少一个概念或判据——**没有来源的模块不许存在**；
2. 每条不变量都有**唯一守卫点**（表约束 / 判据 / 领域服务），不允许两处各拦一次；
3. `docs/14` 的 5 个 GAP 全部 `已定`，且结论已回流文档；
4. 依赖规则可机械检查（分层单向、内核无外部依赖）；
5. 协作序列覆盖：认领 → 完成 → 准入 → 评审 → 交付 → 变更重开 → 配置冻结 → 对齐与假设处置。

## 图怎么维护

图**不手画在文档里**：

- UML（类/状态/顺序）与活动流程图用 **PlantUML**（`.puml`）；
- N-S 图、PAD 图、判定树用 **Graphviz**（`.dot`）——PlantUML 没有对应的原生图形；
- **唯一源是 `build.py` 里的模板**；`.puml` / `.dot` 是它的产物（每次重建会覆盖）——改图要改模板，不要直接改产物。

**机器校验**（`make design-check`，即 `design/check.py`）：

| 规则 | 查什么 |
|---|---|
| R0a–R0d | 图片存在、产物存在、事件 kind（文档 + 图，只读 `docs/02` 登记表）、模块 ↔ 组件 |
| R19 | 产物与源文件都等于 `build.py` 重建结果（在临时目录重建后逐字节比对）——**手改产物会被抓** |
| R20 | 标题编号（`## N.` 递增、`### N.M.` 归章且递增） |
| R21 | 状态图的状态集合与 `docs/` 的状态枚举**双向**一致（多一个少一个都红） |
| R22 | 组件图分层依赖：L3→L2→L1→L0/端口；L1 不得直连实现 |
| R23 | 计数一致：`N 张表` / `N 张图` / `N 条阶段判据` 与真实数量相等（跨 `docs/`、`design/`、`probe/`） |
| R24 | P3 无旁路边（四道校验必须串联） |
| R25 | 矩阵结构：**一行一条不变量、一个守卫点**（一行出现 `+`/`/` 或把 `verify` 当守卫都红）；守卫点可落地（类/模块/`03` P 号），`Class.method` 必须真有该方法 |
| R26 | 依赖列 ↔ 组件图**双向**：表里写的依赖图里必须有边（`store`→`DBPort`、`vcs`→`VcsPort`，`core` 不画全）；图里画了模块→端口，依赖列也必须写出对应能力 |
| R27 | 每个登记事件都要有生产者：出处在 `03` 过程逻辑或图里（散文提一句不算），否则必须在 `EXTERNAL_EVENTS` 里逐条点名。**已知边界**：只查"出现过"，**不查是否有动作/权限/拒绝码**——接线完整性仍靠评审 |
| R28 | **§17.1 的执行点必须与正文对得上**：解析落点表，按 `P2` / `02 矩阵` 分别核对正文，且 24 条一个不少；删一行或改错执行点都会红 |
| R29 | **preset 冻结结论可由机器复算**：严格解析 `docs/04` 的 `保证` 与 `applies_to`（非 kind 取值即红）+ `docs/08` §1.1 的三份 gate 目录（未知键即红），复算有效绑定（`all_of` + 不可豁免 + stage 适用），core 三条必须有效绑定；**末尾三组自检**保证"该拦的真被拦住" |
| R30 | **每个过程都有模块归属**：`design/03` §17 表的模块列必须覆盖 P1–P15，且每个名字都在 `design/01` 模块表里（改名、删行都会红） |
| R31 | **顺序图里的 L1→L1 调用必须登记**：实线 `->` 两端都属于 L1 时，目标模块必须出现在源模块的依赖列里（虚线 `-->` 是返回，不算）；抓"图里出现、架构里没登记"的漂移。**已知边界**：`handlers` 的依赖写作「L1 服务」（刻意抽象），L2→L1 不做逐边校验，见 `design/01` §3 |
| R32 | **已废弃的判据句式不许留在实现面**：`docs/` 与 `design/01–03` 里出现"仍为 open 的假设都必须已被…覆盖"之类旧谓词即红（freshness 会漏） |
| R33 | **P4 判定表与流程图一致**：表里「拒绝/阻塞」的每个 code 必须出现在 `p4-admission` 流程图里（同一过程两张表达，漏一边即红） |
| R34 | **状态图的迁移边与 docs 迁移串一致**：串里写的每条 `A → B`（含 `B | C` 的多目标）必须在图里有边——状态集合一致 ≠ 边一致 |

绿色只说明"这二十类漂移没有"，**不说明语义对**——语义仍靠评审。

> `make all` **不重建图**：重建会把过期产物"改对"再让检查比对，等于自己骗自己。要重建跑 `make fresh`（= `design` + `all`），或单独 `make design`。
