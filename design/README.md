# 设计阶段（结构化设计 + 面向对象模型）

> **状态：Draft**——阻塞于 [`docs/14`](../docs/14-待决缺口.md) 的 G1–G5（全部待定）。
> 在 5 个缺口有决定之前，本目录**不构成已批准的详细设计**，不得据此进入实现。

> 这个目录接在 `docs/`（需求/设计基线）之后、实现之前。它回答两件事：
> **系统怎么分层、模块怎么切**（结构化设计），以及 **对象怎么建模、职责怎么分**（OOM）。
>
> 它不是实现：没有代码，只有结构、接口、职责、不变量与协作。

## 评审门槛（进实现前必须满足）

1. 每个模块能对应到 `docs/` 的至少一个概念或判据——**没有来源的模块不许存在**；
2. 每条不变量都有**唯一守卫点**（表约束 / 判据 / 领域服务），不允许两处各拦一次；
3. `docs/14` 的 5 个 GAP 全部 `已定`，且结论已回流文档；
4. 依赖规则可机械检查（分层单向、内核无外部依赖）；
5. 协作序列覆盖：认领 → 完成 → 准入 → 评审 → 交付 → 变更重开。

## 图怎么维护

图**不手画在文档里**：

- UML（类/状态/顺序）与活动流程图用 **PlantUML**（`.puml`）；
- N-S 图、PAD 图、判定树用 **Graphviz**（`.dot`）——PlantUML 没有对应的原生图形；
- **唯一源是 `build.py` 里的模板**；`.puml` / `.dot` 是它的产物（每次重建会覆盖）——改图要改模板，不要直接改产物。
