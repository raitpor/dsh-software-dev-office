# 边界与自证（这份实现能证明什么、不能证明什么）

本实现把三条保证落在**文件、命令、人**上。它成立，但每条都有明确边界；边界不是“缺陷清单”，是**使用前提**。

| 边界 | 具体是什么 | 怎么演示 |
|---|---|---|
| 人签不是密码学签名 | 人签 = 真人选的问答选项；`sign/S*.md` 是可改的文本 | 改 `.sdo/sign/S1.md` 里的选项文字，无人拦截 |
| 账本可改 | 追加式 Markdown 靠人守；`git` 只在你提交后留痕 | 改 `.sdo/台账.md` 一行但不提交 ⇒ `git status` 有改动、无告警 |
| 门禁靠判读 | 没有运行时判定；出口勾选表由人按证据填，跳过一项没人拦 | 在 `.sdo/readings/M1.md` 里把 fail 写成 pass，没有任何东西会拦住 |
| 权限在仓库外 | 谁能看什么由仓库权限决定，不由流程决定 | 把仓库设为私有/公开，流程文件不做任何拦截 |
| 问人是硬依赖 | 没有“提问并给选项”的能力（或没人应答）⇒ 签字无法完成，流程停在原地 | 不实际提问，直接写 `.sdo/sign/S9.md` ⇒ 文件存在但没人签过 |
| 检查器只查格式 | `check.mjs` 核对列数、字段、签字三选一与 preset 结构，不判断证据真假；`view.mjs` 只拼文件 | 把 `.sdo/readings/M1.md` 的 fail 改成 pass ⇒ 脚本仍绿 |
| 判定权分离 | 证据表只放命令与输出，判定列由评审填；`check.mjs` 只查判定列存在、值合法、评审者行存在，不判断判定是否正确 | 把 done 卡某条判定从 fail 改成 pass ⇒ `check.mjs` 仍绿 |
| 信任前提（同 `.sdo/意图.md` §11） | 假设模型可信但会犯错、按 skill 执行且不代签；问答签字=人签；不做密码学保证 | 模型自签 ⇒ 无人拦截；改签字文本/台账 ⇒ 无人拦截（靠 git 与人事后审） |
| 口头授权≠流程放行 | 口头答应不产生签字；没有签或明确裁定的等价记录，流程停在原地 | 口头说“先做吧”然后开工 ⇒ 没有文件拦截，只能靠人与评审追溯 |
| 加载靠读文件 | 没有自动注入；要自己打开 `SKILL.md` 再按需读 references | 只读 `SKILL.md` 不读 `references/03` ⇒ 可能漏掉多轮评审的判词三选一 |

## 四条最要紧的「挡不住」

1. **挡不住代签**：同一会话里模型可以替你点“签”。只有你亲自读复述、亲自选，才算签。
2. **挡不住改账本**：文本可改；`git` 只在你提交后留痕。没提交的改动等于没发生。
3. **挡不住跳过门禁**：判据靠人按清单判读，跳过一项没人拦。
4. **挡不住越权**：没有权限表；可见性由仓库权限决定，不是由流程决定。

## 两条硬阻塞（碰到就停）+ 一条降级

1. 没有问人工具，或没有真人应答 ⇒ **不许签字**，写“阻塞：无人签”，停。
2. 没有文件系统写权限 ⇒ 只能做评审、不能做产物，明确告知调用方。

**降级（不是阻塞）**：没有 `git` ⇒ 审计退化为“文件 mtime + 人认”，提交一笔改为“在本轮说明里列改动文件”，并写进签字文件的「已知边界」（无法用 commit 锚定被签对象）。

## 使用规则

1. 每条边界都要写进当次签字文件的「已知边界」——**不许省略**。
2. 不得为了“看起来更强”而夸大：不写“已验证签名”，写“人签（问答选项）”。
3. 边界可以被缩小（例如加 `git` 钩子、加外部审计），但**只能在签字文件里写清楚**，不许在正文里暗示已经做到。
