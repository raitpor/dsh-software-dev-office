# 归档与版本

- 归档 = 搬五类：`cards/M<M>-*.md`、`review/<M>-*.md`、`readings/<M>.md`、`gates/<M>.md`、`milestones/<M>.md`（搬为 `archive/<M>/milestone.md`）。
- `.sdo/archive/INDEX.md` 是归档事实的唯一登记处：文件数 + 逐文件 sha256 + 状态；`check`/`view` 只读它。
- `check --plan --milestone <已归档>` 先查 INDEX，打印「M<n> 已归档（.sdo/archive/<M>/）」并 exit 0，不再读旧路径。
- `view next` 的默认里程碑只在未归档里选；`view archive` 与显式 `--milestone` 可读归档正文。
- 完整性（四类反例）：
  - 多文件/缺文件/条数不符 ⇒ `archive_integrity_mismatch`，首条点名多出或缺失的文件。
  - `archive/<M>/milestone.md` 存在时原 `.sdo/milestones/<M>.md` 又出现 ⇒ `archive_milestone_not_moved`（沿用旧码；消息明确“优先读原文件会让归档正文被旧副本遮住”）。
  - 归档目录有文件但 INDEX 无对应行 ⇒ `archive_orphan_directory`。
  - INDEX 有行但正文两边都找不到、或 milestone.md sha 不符 ⇒ `archive_milestone_not_moved`；整目录删除时首条必须是它（先判存在性，再判条数/哈希）。
- `archive.mjs archive <M>` 无 `.sdo/milestones/<M>.md` ⇒ `archive_milestone_missing` exit 1（不归档无正文里程碑）。
- INDEX 行状态只认 `已归档`/`已恢复`；其他值 ⇒ `archive_index_invalid` exit 1。

## 改 preset 前先归档

- `presets/*.md` 是发布快照的一部分；任何文字改动都会让 `check --presets` 报快照不一致。
- 改之前，先把仍使用该 preset 的活跃里程碑（未归档）全部归档；当前里程碑若是变更发起者，在它的冻结段写 `- preset 变更发起里程碑：M<n>`（恰好一行、未归档、且是当前里程碑）。
- 未归档使用者仍存在 ⇒ `preset_change_requires_archive` 点名；声明缺失/多行/指向非当前或已归档里程碑 ⇒ `preset_initiator_invalid`；全部归档 ⇒ 只报「需人签更新发布快照」。
- 新增判据必须带 `依据：§12.<n>` 且该小节真实存在：缺 ⇒ `criterion_without_basis`，编造 ⇒ `basis_section_missing`。
