# 真源与账本

## 1. 什么算真源

**文件就是真源**：四类对象各有唯一载体，口径只在一处。

| 对象 | 载体 | 谁写 | 追加还是覆盖 |
|---|---|---|---|
| 意图 / 计划 / 签字 | `.sdo/意图.md`、`.sdo/计划.md`（项目级）、`.sdo/milestones/<M>.md`（里程碑级）、`.sdo/sign/S*.md` | 人签过才生效 | 签字文件只追加新文件，不改旧文件 |
| 卡（工作单元） | `.sdo/cards/<卡号>.md` | 开卡人 | 卡内分节追加（评审、证据），不改历史判定 |
| 偏差 | `.sdo/台账.md` | 任何人发现即记 | **只追加行**；更正用新行 + `superseded` |
| 读数 | `.sdo/readings/<M>.md` | 里程碑收口人 | 每次取证追加一节，标时间与被签树（commit 或文件哈希） |

## 2. append-only 怎么写

- 任何“已经签过/已经判过”的内容**不改**：新事实写成新行/新节，注明取代关系。
- 需要更正时：旧行状态改 `superseded by D-xxx`？**不行**——状态列也只能追加新行，旧行保持原样。
- 每行带 `at`（ISO8601 含时区），禁止只写日期。

## 3. id 规则

| 前缀 | 用途 | 例 |
|---|---|---|
| `S<n>` | 人签记录 | `S3` |
| `D-<n>` | 偏差台账 | `D-12` |
| `C<n>` | 卡内判据 | `C4` |
| `M<n>` | 里程碑 | `M1` |
| 卡号 | 里程碑-序号 | `M2-3` |

id 单调递增，**不复用**、不回收；作废的 id 留空并写原因。

## 4. 对账（代替 verify）

收卡/收门前跑三条：

```bash
# ① 每次判定引用的 id 都存在
grep -o 'C[0-9]\+' .sdo/cards/M2-3.md | sort -u
# ② 签字指向的对象还在
git cat-file -e <commit> && echo ok
sha256sum <被签文件>
# ③ 台账表内不能有空行：空行之后又出现 `|` 行 ⇒ 那一行是游离行，先修表格再继续
#    每批追加完跑一次 `check.mjs`（见 SKILL.md §11）
```

第三条最省事的做法：**表内不留空行**；每批追加完跑一次“`|` 开头的行是否都在表头下”的检查。

## 5. 脱敏

不写：会话 id、用户名、`/home/...`、主机名/IP/端口、工具调用次数。写“某会话”“本机”即可。

## 6. 追溯链（`check --trace`）

需求真源是 `.sdo/baseline/requirement.md` 的 `### R-xx` 条目；卡面 `references:` 行声明本卡覆盖的需求 id。解析只在 `skills/sdo-flow/scripts/lib/trace.mjs`，`check` 与 `view` 共用。

`check --trace` 检查四类断点并一次报全（首条按固定顺序）：`trace_orphan_requirement`（需求无卡引用）、`trace_dangling_ref`（卡引用了不存在的 R）、`trace_duplicate_claim`（同一 R 被两个里程碑的「认领需求：」行认领；同里程碑多卡引用正常）、`trace_orphan_test`（done 卡判据没有可复跑命令或脚本 `文件:行`）；散文证据另报 `trace_test_unverifiable`。`M8-0` 的「探索结论」表由 C8 机检（去向必须真实存在、`不采纳` 理由过 §3 黑名单）。

历史豁免：`.sdo/milestones/M8.md` 的「测试引用基线段」列出 M1–M7；这些 done 卡的测试引用不回溯判红，避免改历史卡。open 卡只列不判。

## 7. `check` 与 `--trace` 的关系

- `check` 默认只跑格式/台账/签字/卡/读数等结构检查，**不跑** `--trace`；追溯链是门签前置条件。
- 门签前必须单独跑 `node skills/sdo-flow/scripts/check.mjs --trace`，要求 exit 0 且 0 问题；`--trace` 与 `--plan` 互斥。
- `trace_orphan_card`：活跃 done 卡（M8 起）`references:` 为空即报，带卡号；M1–M7 历史卡按 M9-0 豁免。

## 8. 基线四份（计划前建）

`.sdo/baseline/` 是设计真源，必须在计划前建好，不能事后补：
- `requirement.md`：每条 `### R-<号> <标题>`，下一行 `- 验收：<可判语句>`；
- `architecture.md`：每个决策 `## ADR-<号>：<标题>`，含决策/备选/后果；
- `test-strategy.md`：`| 变更类型 | 测试技术 |` 表；
- `quality-risk.md`：`## 质量属性` 与 `## 风险登记` 两节。

四份的合并哈希由 `scripts/lib/hash.mjs` 的 `baselineHash()` 计算，写进当前里程碑冻结段的 `- 基线 hash：<64 位>`。任何一份变化都要重算并追加签；旧 hash 只能通过 `基于旧基线：<旧前8>（变更请求：D-<n>；理由：…）` 例外保留。
