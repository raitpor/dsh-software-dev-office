# 计划与卡

## 1. 计划评审八项自检

开卡前、以及计划变更 ≥3 张卡或动了依赖边时，逐项过：

| # | 自检 | 不过的典型 |
|---|---|---|
| 1 | 里程碑范围里每条判死读数，在本里程碑内**真能跑到**？ | 读数的前置卡排在读数门之后 |
| 2 | 卡表依赖边是否都指向**更早**的卡？ | 门卡依赖后置产卡 |
| 3 | 卡面「准入」里的前置卡，是否都在卡表依赖里？ | 卡面写了 M0，卡表只写 M1 |
| 4 | 判据点名的文件，是否都在该卡写域（或共享登记）里？ | 判据要改 `verify.ts`，写域没它 |
| 5 | 跨泳道写域是否相交？相交谁先谁后？ | 两张卡同改 `src/db/write.ts` |
| 6 | 迁移号是否预分配、连续、无冲突？ | 三张卡都写 017 |
| 7 | 收紧类判据是否列了**既有调用点**与夹具迁移方案？ | 闸一开，旧夹具全红 |
| 8 | 收口是否要求“证据绑当前树”，而不是拿旧门的签字？ | 用上一里程碑的签字给新树签门 |

评审结论写 `.sdo/review/<M>-计划.md`：本轮问题、处置、未采纳建议。

## 2. 卡面字段

```markdown
# M2-3 · 假设处置链
status: open            # open → in_progress → done
owner: <泳道/席位>
write_scope: [src/core/assumption/, test/core/assumption-chain.test.ts]

## 意图     一句话说清这张卡让什么成立（建议段）
## 对齐     复述（2 正 1 反：什么时候该做 / 不该做）
## 判据     C1…Cn（每条可判死，带正反例）〔必需〕
## 假设     A1…An（含“若假设不成立怎么办”）
## 预览     动手前预计改哪些文件、怎么验
## 准入     依赖哪些卡的产出；前置条件
## 证据     命令与输出（逐条对判据；done 卡每条判据都要有非空命令/文件:行，且「判定」列有合法值）〔必需〕
## 判定     pass/partial/fail/未判 与理由（由评审据证据填；partial 写缺口、谁认、何时补）〔必需〕
## 评审     第 1 轮 / 第 2 轮判词与处置〔必需〕
## 收口     提交号、签字号、遗留项
```

## 3. 依赖与写域

- 一张卡一个写域；写域外改动**先问**，问完记台账。
- 共享文件（写网关、注册表、码表、`test/fixtures/`）在计划里登记“允许改的卡”，否则视为冲突。
- 门卡（`*-G`）必须有非空依赖，且只能依赖比它早的卡。

## 4. 提交

- **一卡两笔**：产物一笔；卡、台账、看板一笔。
- 提交前 `git status --porcelain` 看 untracked 目录（`migrations/` 最容易漏）。
- 团队/协作者**不 push**，除非被明确授权。

## 协作约定（多人/多会话）

- 每张卡一个文件，避免同文件冲突；台账是**唯一**共享追加文件，冲突时保留双方行、按 id 排序。
- 签字文件只由签字人写（模型代笔须人确认，并在文件里写明“代笔”）。
- 评审者与作者不同分支/不同会话；评审结论写进卡面，不改别人的产物。
