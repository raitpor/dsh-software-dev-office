# 02 脚本使用

> 权威：所有参数、选项、退出码以各脚本 `--help` 与 `check --help` 为准。本册只写「什么时候用哪个命令、输出怎么读、失败怎么办」，**不复制参数表**。

## 1. 命令地图
| 场景 | 命令 | 成功时先读什么 |
|---|---|---|
| 首次建 `.sdo/` | `init.mjs` | 新建/跳过清单与下一步 |
| 基线四份 | `baseline.mjs init` | 「已存在，跳过」即等价 |
| 新建/冻结里程碑 | `milestone.mjs new/freeze` | 写入的里程碑文件 |
| 门禁/判据声明 | `milestone.mjs declare` | 冻结段两行 |
| 建卡 | `card.mjs new` | 判据表/写域/视角 |
| 记证据 | `card.mjs evidence --run` | `exit=<code>` 与输出摘要 |
| 变异验证 | `card.mjs mutation` | red/green 摘要 |
| 计划签/门签 | `sign.mjs new` / `draft` | 草案与锚点 SAME/DIFF |
| 计划/树检查 | `check.mjs`（`--plan/--trace/--deep/--presets`） | 末行「检查完成：N 篇…」 |
| 门表 | `gate.mjs init` / `--file` | 四门 pass/partial 与缺判据 |
| 读数 | `readings.mjs init` | R* 骨架 |
| 视图 | `view.mjs next/state/signs/queue` | 人读摘要 |
| 台账 | `ledger.mjs add/close/list/reindex` | 索引与新增行 |
| 归档 | `archive.mjs` | archive/ 目录与 INDEX |

## 2. 初始化与基线
- `init.mjs` 在空仓库建 18 项；已存在则跳过（`--force` 才覆盖）。跑完看「下一步」行。
- `baseline.mjs init` 建四份基线；与 init 重叠时返回「已存在，跳过」，两者产物等价。
- 基线只引用不复制：文档/签里引 R/ADR 编号，不抄条文。

## 3. 计划与里程碑
- `milestone new` 后填六段：认领/读数+探底/卡表/共享写域/阶段序列（preset 仅作抄写参考、真源不写 `preset：`）/冻结段（格式见 03 §6）。顺序：填六段 → `freeze` → `check --plan`（0 漂移）→ 计划签；改基线或改六段后必须重冻。`freeze` 同时更新 `- 基线 hash：` 与 `hash:`。
- `declare` 写 `- 门禁：` 与 `- 判据：`（唯一真源；无按门映射时按并集闭合）。要 `--map`：`node <skill>/scripts/milestone.mjs declare --list --preset <name>` 直接打印每门映射，按它抄，不用外读 preset 文件。
- `freeze` 直接重算并写回（只动 `hash:` 与 `- 基线 hash：` 两行；不要删 `hash:`/`状态：`/`- 追加签：`，`frozenHashRaw` 已过滤它们，删了会丢追加签记录）。核对或抄签文件时才用 `check.mjs --plan --milestone <M>`（它带 `--print-frozen-hash`）；单跑 `milestone.mjs` 加这个旗标会报未知参数。
- 计划签前 `--plan` 预期红（「尚无计划签」），顺序见 01 §5；`--trace` 单独跑，0 问题再门签。

## 4. 卡与证据
- `card.mjs new` 要求 owner/intent/criteria；产物含判据表 4 列与视角行。
- `evidence --run` 逐判据写 `exit=<code>`；done 卡「判定」列必须 pass/partial/fail。
- 变异用 `mutation` 或卡面变异表，记 `expected=red actual=red`。
- `sign.mjs draft` 的 `CLEAN`/`NO_GIT` 与锚点 `SAME`/`DIFF` 只说明草案可签性，不等于已签。

## 5. 签字与评审
- `sign.mjs new` 出草案；人签后把 `判定：` 改为接受（或按选项）。
- 追加签：`- 追加签：S<n>-X`，写旧/新 hash 双锚点；错一处 `check` 红。
- 评审记录写 `.sdo/review/`（轮次/判词/问题/处置），席位失败字段要填。

## 6. 门与读数
- `gate init` 生成四门表（31/34 行随 preset）；`--check` 只读不写。
- 门表判定只 pass/partial/fail；partial 须在表第 3 节写「选项：签：接受」。
- `readings init` 生成 R* 骨架；逐条填命令、首条输出、verdict、反例。

## 7. 检查、视图与台账
- `check` 全查；`--deep` 加严；`--plan <M>` 单里程碑；`--presets` 快照；`--trace` 需求/测试链。
- 退出码：0 绿、1 红、2 参数错；错误码见 04 §3。
- `view` 只读；`ledger add --kind explain` 默认 closed（确需 open 显式 `--status open`）；`reindex` 重建派生索引。
- `archive` 要求门签且计划状态含「已收口/已归档」；已归档需先 restore。

### 7.1 对账三条（与 `check --trace` 无关）

收卡/收门前跑：

1. **引用 id 都存在**：`grep -o 'C[0-9]\+' <卡文件> | sort -u`，逐条对证据/判据。
2. **签字对象还在**：`git cat-file -e <sha>^{commit}` + `sha256sum <被签文件>` 复算。
3. **台账无游离行**：表内不留空行；每批追加后跑 `check`（每行列数=表头）。空行后又出现 `|` 行 ⇒ 先修表格再继续。

## 8. 失败排查
- 第一步永远是 `check`：看 ERROR 首行与文件:行，WARN 可挂台账豁免，ERROR 不放过。
- 高频：`gate_criteria_undeclared`→补两行声明；`missing_declared_criterion`→门表缺行；`preset_field_removed`→新签删 preset 字段；`signed_anchor_mismatch`→查双锚点/签序；`requirement_missing`→补认领；`frozen_hash_missing`→补 `hash:`。
- 脚本崩栈：保留命令+stderr 尾部，报维护者；不要靠重跑碰运气。
- 拿不准选项时只看 `--help` 原文，不猜、不从旧文档抄参数。
