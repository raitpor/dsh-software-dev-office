# 03 编写规范

> 本册写「文件里该长什么样、什么算合格」；流程顺序见 01，命令用法见 02。

## 1. 真源与 append-only
- 真源 = 事件日志 + `.sdo/` 文本；视图、索引、台账索引都是派生数据（可 `reindex` 重建）。
- 只追加：不 UPDATE/DELETE 真源；更正用新事件或新签。历史行不改，用台账 explain 留痕。
- id 规则：`<kind>:<局部唯一>` 或项目约定；全局唯一；引用写 id，不复制内容。
- 对账（代替 verify）：查 id 存在/签字对象/台账游离行（02 §7.1）；`check --trace` 查引用链是另一件事，别混。
- 脱敏：文档/读数不出现 passphrase、私钥、token、socket 路径。

## 2. 计划与卡写法
- 计划评审八项自检见 `01-流程说明.md` §3 的表（本册不再另列一份，两份清单必漂移）。
- 卡面必需段：意图 / 对齐 / 判据（带「类型」列）/ 假设 / 预览 / 准入 / 证据 / 判定 / 评审 / 收口；其余按模板。
- 字段值：类型只 `结构`/`语义`/`边界`；判定只 `pass`/`partial`/`fail`/`未判`；partial 写缺口、谁认、何时补。
- 判据必须可复跑：正例命令 + 反例（或「不可变异」理由）。done 卡至少 1 条语义判据，或写「语义：不适用（理由）」。
- 写域 = 文件或目录前缀；依赖与共享写域写进计划卡表；卡表「依赖」列决定开工顺序。
- 提交：一卡一提交，信息带卡号；不混提他人改动；提交号填收口。
- 协作：多会话写域不重叠；共享文件先报后改；派生索引冲突用 reindex 收敛。

## 3. 判据与门禁
- 好判据：可执行、可复跑、有反例；三态 pass/partial/fail，`na` 只用于确实不适用且写理由。
- 门禁勾选表：按 preset 的四门；核心三条不可 `na`（`spec_set.signed`/`assumption_set.signed`/`provenance.present`）。
- 常见假绿（逐条排除）：只查存在、数输出文字、空集放行、手填 pass、删判据行、改判据名绕开。
- 判据写在哪：卡判据表 + 里程碑冻结段 `- 判据：`（唯一真源；代码/文档不另设名单）。
- 类型列：结构/语义/边界；表头无「类型」列即红。
- 按门映射：`- 门禁判据：G_x = c1, c2`（一行一门）；无映射按全局并集闭合；`force` 覆盖只能由评审接受并记理由。
- 历史签豁免：只认计划声明 `- 声明豁免：M1、…`；声明方归档后豁免失效（D-272），需在新计划重声明。
- 证据命令块：机检只认 `exit=<code>; 命令; 首条输出` 形态与「判定」列合法值，不解析业务内容。

## 4. 证据与变异
- 每条判据一行证据：`exit=<code>; <可复跑命令>; <首条输出>`；空行/占位（待填/待判/略）不算。
- 变异红证：改一行让命令变红；记 `expected=red actual=red restored=green`；不可变异须写具体理由并获评审确认。
- 卡级变异：删证据、改判定、删判据行、改 case 大小写等；评审确认后才算有效。
- 证据要能复跑：写绝对/相对路径均可，但不得依赖未入库的 `/tmp` 状态。

## 5. 签字与评审记录
- 人签四要素：谁、签什么（被签对象）、何时、选项（签/改）。问答即签字：问题 + 选项 + 本人回答。
- 追加签编号 `S<n>-<X>`（按字母序）；双锚点：旧 hash / 新 hash，链错即红。
- 被签对象两形态：已知 commit（`git:<sha>`）或内容 hash（`tree:<sha256>`）；无 git 时用 tree。
- 签字编号全局递增，不复用、不跳号；卡面骨架记录签字号。
- 评审记录：每轮判词（可收卡/改完再审/退回）、问题清单、处置；评审席位失败记降级与负责人。

## 6. 里程碑三处必填格式
- 探底：独立一行 `- 探底 R<n>：…`，覆盖读数表每个 R。
- 阶段序列：一行、反引号 stage id、`→` 连接；与 preset 的 `### \`stage\`` 同名同序；`preset：` 与理由只写计划，**新签里程碑真源禁写 preset 字段**（出现即 `preset_field_removed`）。
- 冻结段 `hash:`：独立一行、ASCII 冒号、`hash:<64hex>`；重算用 `freeze`（不删任何行，`frozenHashRaw` 已过滤 `hash:`/`状态：`/`- 追加签：`）；追加签写旧/新 hash。

### 6.4 基线四份（计划前建）
- `.sdo/baseline/requirement.md`：每条 `### R-<号> <标题>` + 下一行 `- 验收：<可判语句>`。
- `architecture.md`：每条 `## ADR-<号>：<标题>`，含决策/备选/后果三字段。
- `test-strategy.md`：`| 变更类型 | 测试技术 |` 表，至少 3 行真实策略。
- `quality-risk.md`：`## 质量属性` + `## 风险登记`（风险写处置或边界）。
- 合并哈希由 `scripts/lib/hash.mjs` 的 `baselineHash()` 单点计算，写进冻结段 `- 基线 hash：<64hex>`；任一变化重算+追加签；旧 hash 例外写 `基于旧基线：<旧前8>（变更请求：D-<n>；理由：…）`。

## 7. 台账
- 七列：编号 / 类型 / 位置 / 现象 / 影响 / 处置 / 状态；append-only，不删不改历史行。
- 何时记：偏离设计或工具、已知边界、遗留缺口、人工豁免；同一事实只在一处定义，别处引用。
- 编号 `D-<n>` 递增；`reindex` 生成索引；状态 `open` 须有处置计划，修完改 `fixed` 并给修法。
- 口径统一：同一规则只在一个真源定义（如判据说明只在 criteria-doc）。

## 8. 归档与版本
- 改 preset 前先归档使用旧快照的里程碑；`SNAPSHOT_PRESET_SHA` 与门/判据快照只由人签更新。
- 归档后从 `.sdo/archive/<M>/` 取历史；活跃索引不再引用归档对象（`--trace` 只报孤儿）。
