# 01 流程说明

> 命令参数以 `--help` / `check --help` 为准；本册讲顺序、完成标准与卡住时看哪里。四册索引见 SKILL §4。

## 1. 一条主线
意图 → 计划（计划签）→ 卡（认领）→ 实现与证据 → 评审（≥1 轮）→ 人签 → 读数门（门签）。每一步都是文件+事件；没有签字不算通过。

- 计划 = `.sdo/计划.md` + `.sdo/milestones/M<n>.md`（读数/卡表/写域/阶段/冻结段）。
- 卡 = `.sdo/cards/`；读数 = `.sdo/readings/`；门 = `.sdo/gates/`；签 = `.sdo/sign/`；评审 = `.sdo/review/`；台账 = `.sdo/台账.md`。

## 2. 里程碑生命周期
- 建：定读数 R*、卡表、共享写域、阶段序列、冻结段 → 计划评审 → 计划签。
- 冻结：`milestone freeze` 重算 `hash:` 并同步 `- 基线 hash：`；顺序：`milestone new` → 填六段 → `freeze` → `check --plan`（0 漂移）→ 计划签。改基线或改六段后必须重冻，签前再跑 `check --plan`；此后冻结段只增不改，要改走追加签。
- 收口：卡全 done、读数齐、门表全 pass（或 partial 已被门签接受）→ 门签 → 计划状态「已收口」。
- 归档：`archive` 后移入 `.sdo/archive/<M>/`；归档后 `--plan` 跳过、不回溯。

## 3. 卡生命周期与计划评审
- 建：`card.mjs new`（写域/判据/视角）→ 认领 → 实现 → `evidence --run` → 评审多轮 → done → 收口记提交/签字。
- 写域=边界；跨泳道先报；共享写域在计划卡表列出；依赖未满足不得开工；一卡一提交。
- 开卡前/计划变更 ≥3 卡或动依赖边时，逐项过八项自检：

| # | 自检 | 不过的典型 |
|---|---|---|
| 1 | 读数在里程碑内真能跑到 | 读数卡排在读数门之后 |
| 2 | 依赖边都指向更早的卡 | 门卡依赖后置产卡 |
| 3 | 卡面「准入」前置卡都在卡表依赖里 | 卡面写 M0、卡表只写 M1 |
| 4 | 判据点名的文件都在写域或共享登记 | 判据要改 `verify.ts`，写域没它 |
| 5 | 跨泳道写域是否相交、谁先谁后 | 两卡同改 `src/db/write.ts` |
| 6 | 迁移号预分配、连续、无冲突 | 三张卡都写 017 |
| 7 | 收紧类判据列了既有调用点与夹具迁移 | 闸一开旧夹具全红 |
| 8 | 收口要求证据绑当前树，不用旧门签字 | 用上一里程碑签字给新树签门 |

- 评审结论写 `.sdo/review/<M>-计划.md`：问题、处置、未采纳建议。

## 4. 评审与签字
- 评审者必须非作者；每轮三档判词；问题进 `.sdo/review/<卡>.md`；**轮次不设上限**，改完再审。
- 视角至少两问：白盒/黑盒/系统/集成/故障恢复（04 §4）。
- 变异红证：判据须有「改一行就红」的证据；不可变异要写理由+评审确认。
- 人签四要素：谁、签什么（对象 hash/commit）、何时、选项（签/改）。问答即签字；草案态 ≠ 已签。
- 追加签：改已签对象必须新签，双锚点（旧 hash/新 hash）。
### 4.3 评审席位失败
- 降级给该席位负责人并记入评审，不静默换人、不改判据。

## 5. 读数与门
- 读数 R* 字段固定五项：`id / question / command / raw / verdict`，可加 `caveat`；partial 写缺口、谁认、何时补。
- 量真路径三条：① 硬编码常量不是测量（改输入数字必须变）；② 改坏被测逻辑，读数必须变红；③ 同一命令跑两次，除时间戳/随机 id 外逐键相同。
- 树冻结四步：① `git status --porcelain` 干净，**未提交的卡/台账先提交**；② 记录 `HEAD` + 生成物 sha256；③ 跑全量检查（测试/自检/台账列数）并记命令与汇总；④ 冻结范围写进读数文件头部。取证后再改 ⇒ 读数作废重跑。
- 门签：门表四门（按 preset）+ 声明判据；partial 只能由门签「选项：签：接受」放行。
- 顺序：`--print-frozen-hash` → 计划签 → `--plan` 0 → `--trace` 0 → 门签；缺认领报 `requirement.claimed_or_na`；基线变报 `baseline_drift`。

## 6. 冻结与追加签
- `hash:` 精确形态见 03 §6；重算前删 `hash:`/`状态：`/`- 追加签：` 行。
- 追加签链校验旧/新 hash；错一个即红。

## 7. 并行与协作
- 多会话/席位：写域不重叠；共享写域先到先得；冲突写不进。
- 索引/台账是派生数据，可 `reindex` 重建，不手改。

## 8. 边界与不可机检
- **四条挡不住**：① 代签（模型可替你点签）；② 改账本（git 只在你提交后留痕）；③ 跳过门禁（判据靠人判读）；④ 越权（可见性由仓库权限决定）。
- **两条硬阻塞**：没有问人工具/真人应答 ⇒ 不许签字，写「阻塞：无人签」停；没有文件写权限 ⇒ 只做评审、不做产物。
- **一条降级**：没有 git ⇒ 审计退化为 mtime+人认，提交改列改动文件，并写进签字「已知边界」。
- **使用规则**：每条边界写进当次签字「已知边界」；不许夸大成「已验证签名」；边界只能缩小且须在签字文件写清。
- 三条最贵的教训：① 豁免/白名单只能来自计划声明；② 读数必须量真路径，防「数子串」假绿；③ 两份恰好一样的判定就是分叉，必须抽单点。
- 挡不住：口头授权≠流程放行；签只证明「人确认过某 hash」，不证意图正确。
- 判据不可判死或证据不可复跑时：停下补文档，不降标准；「不适用」须写理由并经人签。
