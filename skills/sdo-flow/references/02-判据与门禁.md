# 判据与门禁

## 1. 一条好判据的形状

```
C<n> 当 <输入/条件> 时，<可观察的结果> 必须 <成立/发生>。
     正例：<怎么做出来> ⇒ <期望>
     反例：<怎么故意破坏> ⇒ <必须红>
```

反例必须**真的能红**：写下命令与输出摘要，否则这条判据只有一半。

## 2. 三态

| 态 | 含义 | 必须附带 |
|---|---|---|
| pass | 正反例都跑过，反例真红 | 命令 + 输出摘要 + 树（commit） |
| partial | 主体成立，有明确缺口 | 缺口一句话、补的时机、谁认 |
| fail | 不成立 | 失败命令与输出 |

`partial` 不许写成 pass；门只在“全部 pass 或 partial 已被人签接受”时通过。

## 3. 门禁勾选表（代替 judgeStage）

```markdown
| 判据 | 判定 | 证据（命令或 文件:行） | 备注 |
|---|---|---|---|
| C1 | pass | `node --test lib/test/x.test.js` 3/3 | 反例改回 ⇒ 1 红 |
```

规则：
- **没有证据的 pass 不算 pass**；证据要能被人复跑。
- 每条 pass 旁边写“改回去会怎样”，空着视为未验。
- 勾选表可用 `gate.mjs` 对账（用法见 `SKILL.md` §11）：它只判“判据齐不齐、判定有没有、证据是不是空的、fail/partial 有没有人签接受”，不判证据真假。

- 门禁结果只能由**人签**确认；模型只能准备表格与命令。

## 4. 常见假绿（逐条排除）

| 假绿 | 症状 | 破法 |
|---|---|---|
| 只断 `ok===true` | 删掉核心分支也绿 | 断副作用（行数、文件内容、事件数） |
| 只断“非空” | 表被别的数据填满 | 断具体行/列的值 |
| 夹具自证 | 期望值由被测代码生成 | 期望值手抄自文档，或独立重算 |
| 字符串比时间 | 时区偏移错序 | 一律 `Date.parse` / ISO 带时区 |
| 变异只改一处 | 另一处兜底让用例仍绿 | 列出所有守卫点，逐点变异 |
| 生成物覆盖 | 跑测试就改写已签文件 | 生成到临时目录 + 前后哈希对比 |

## 5. 判据写在哪

- 卡内：`## 判据`，编号 C1…Cn。
- 里程碑：`.sdo/readings/<M>.md`，逐条对应计划里的判死读数。
- 跨卡共享的判据（如“写路径唯一”）写进计划，卡里引用编号。

## 6. 判据表必须有「类型」列

卡面 `## 判据` 表头固定四列：`编号 | 判据 | 类型 | 反例`。类型只许三值：

- `结构`：表格/字段/文件存在性等格式问题，可机检；
- `语义`：含义正确、口径一致、人签能看懂之类，机器证明不了；
- `边界`：失败路径、越权、空输入、并发等边界行为。

done 卡至少要有 **1 条 `语义`** 判据；确实没有时写 `语义：不适用（理由）`（理由去标点 ≥8 字、非套话）。有语义判据的 done 卡，评审段必须写 `- 语义自检：…`（由评审填，作者不能代填）。缺类型列或类型值非法，`check` 报判据表结构错误。

写判据时正反例一起写：`正例：… ⇒ … / 反例：… ⇒ 必须红`；反例要能真的跑红（见 §1、§4），只有正例的判据只有一半。

## 7. 冻结段声明（M11 起的唯一真源）

新签里程碑只在冻结段写两行：

```markdown
- 门禁：G_req_design → G_build_exit → G_verify_exit → G_integrate
- 判据：spec_set.signed、assumption_set.signed、provenance.present、review.independent、readings.recorded、gate.signed
```

- **不声明 = 报错**：缺任一行，`check --plan --milestone <M>` 报 `gate_criteria_undeclared` 并 exit 1；没有默认集合，也不从 preset 兜底。
- 门禁 id 必须取自 `presets/*.md` 的已知门集合（`G_req_design`、`G_build_exit`、`G_verify_exit`、`G_integrate`、`G_harden_exit`、`G_deliver_exit` 等；不要自编 `G_xxx_exit`）。
- 判据名必须取自**启发式判据池**：`presets/*.md` 正文正则扫描出现的判据 + 少量白名单（`gate.signed`、`readings.recorded`、`review.independent`）。池会随文档措辞变化，**不是权威白名单**；`criterion_not_whitelisted` 只是提示补 presets/白名单。
- `preset` 字段已从真源退场：新签里程碑不得再写 `preset：`/`preset 选择理由：`（出现即 `preset_field_removed`）；preset 只是抄写用的参考模板，不参与门禁判定。M1–M11 已签文件保留为历史记录。
- **并集闭合**：门表 `.sdo/gates/<M>.md` 中出现的判据名（各 `## G_*` 节下行的第 2 列）必须全部出现在冻结段 `- 判据：` 里，多出即 `criteria_table_mismatch`（列出名字与行号）。声明是**全局集合**：一个 34 行的门表通常要列二十几个判据名，这是“显式声明”的代价，不是笔误。
- **边界**：并集对得上 ≠ 每条判据落在正确的门；声明不写按门映射（`G_x = a.b`），因此“判据挪到别的门”机检不了，由评审与人签负责。
- 改这两行会让冻结段 hash 变化，必须走「追加签」；否则 `check` 报 `signed_anchor_mismatch`。


### 7.1 按门映射（应写；无映射则并集闭合）

门多且每门判据不同时，在冻结段追加映射行（可多行），把判据按门分配：

```markdown
- 门禁判据：G_req_design = spec_set.signed, assumption_set.signed, provenance.present
- 门禁判据：G_build_exit = task.complete, trace.test_linked
```

- 语法：`G_id = c1, c2`；`G_id` 必须 `^G_[a-z0-9_]+$`（否则 `gate_id_invalid`）；映射门必须在 `- 门禁：` 序列内（否则 `gate_not_declared`）；判据列表不得为空（否则 `gate_id_invalid`）；判据必须 ⊆ 全局 `- 判据：`（否则 `declared_criterion_unknown`）；同一门只许出现一次（否则 `gate_criteria_duplicate`）。
- 有映射时，`gate init <M>` 只生成映射里的门与行；`gate --file` 对每个映射门做**本门精确**校验：缺 ⇒ `missing_declared_criterion`、多 ⇒ `criteria_table_mismatch`，消息带门 id 与本门集合。
- 无映射时保持全局并集闭合（`want=null` 降级）；但每个门会列出全部判据，极长且容易误填，**应写映射**。映射只补充“按门分配”，不改变“不声明=报错”。
- 成本：映射行与门表都必须随判据增删同步改，且映射参与冻结段 hash、改动需追加签。

### 7.1.1 覆盖开关（force）

- `sign.mjs new --force`：只覆盖**未人签**草案（判定行 trim 后为空、或 `待填*`/`待签*`）；已有人签判词（任何其它非空值）不覆盖，exit 2 `sign_already_signed`。`sign.mjs` 与 `check.mjs` 共用 `lib/verdict.mjs` 的 `parseVerdict()`/`isUnsignedVerdict()`，同一行文本在两侧结论相同。
- `gate.mjs init <M> --force`：覆盖前打印 `将覆盖：.sdo/gates/<M>.md`，按冻结段声明重建门表骨架；不会保留旧判定/证据列（它们属待人手填，重生成即丢弃）。
- `readings.mjs init`：没有 `--force`；已存在时跳过。

## 7.2 `check --plan` 与「判定：待填」

`check --plan` 与普通 `check` 在计划签仍是草案时输出 `WARN plan_sign_unsigned`（exit 不变）；0 漂移只表示与草案记录一致，不能当成人签通过。签前出现 `- 判定：待填` 是正常的；签后应改为真实判词再送门，签后由门签（`gate.mjs` 的判定列）把关。

## 8. 门禁与判据规范池

| 类别 | 规范 | 例子 |
|---|---|---|
| gate id | `G_<stage>_exit` / 已有 preset 里的 id | `G_build_exit`、`G_verify_exit`、`G_integrate` |
| 判据名 | `<域>.<对象>`，小写点分 | `spec_set.signed`、`provenance.present`、`trace.test_linked` |

`gate.mjs` 消费冻结段声明：门表缺声明中的判据 ⇒ `missing_declared_criterion`；门表多出声明外判据 ⇒ `criteria_table_mismatch`（名字+行号）。这两条只证并集闭合，不证判据落在正确的门。`--presets` 只做参考模板快照比对，不一致仅 WARN，不阻断、不作为门禁依据。

### 7.3 历史签声明豁免

- M11-3 之前签的里程碑冻结段没有 `门禁：`/`判据：` 声明。M11 冻结段用一行 `- 声明豁免：M1、M2、…` 显式声明历史边界。
- 列表内的里程碑缺声明时，`check --plan` 降为 `WARN gate_criteria_undeclared_legacy`（历史签，不追溯）；列表外仍 `ERROR gate_criteria_undeclared`。
- 豁免行只允许 `M<数字>` 列表（顿号/逗号分隔）、去重，不得写 `*`；非法 ⇒ `gate_criteria_undeclared_legacy_malformed`。
- 豁免必须来自计划声明，不能在代码里写死编号或按签号/文件名推导。
- 只有**计划签已被接受**的里程碑才能声明豁免；声明方不能豁免自己或比自己新的里程碑（只接受更早的 `M<数字>`）；未签里程碑里的豁免行忽略。
- WARN 会注明 `（声明豁免来自 .sdo/milestones/M<n>.md）`；格式错误的定位到实际声明文件与行号。

## 7.4 证据命令块的机检边界

- 命令含 `|` 时，`card.mjs evidence` 把命令放独立代码块，围栏声明 `命令块 Cx exit=<n>`；证据表写「见命令块 Cx」。
- `check`（普通与 `--plan`）校验：引用与块 id 闭合、块声明 `exit` 与表格结果相等、块体非空、块 id 不重复、无未引用块；分别报 `evidence_block_missing`/`evidence_block_mismatch`/`evidence_block_empty`/`evidence_block_duplicate`/`evidence_block_unreferenced`。
- 机检只保证引用闭合与 `exit` 声明一致，**不执行块内命令**，所以不证明“命令真的跑过”或输出真实；真跑过由取证过程、评审复跑和人签负责。把块内命令改成 `false` 但声明 `exit=0` 不会红——这是已知边界，不是校验缺口。
- C1 的“判据池同源”只覆盖 `declare --list` 与 `check` 的 `criterion_not_whitelisted`；`gate.mjs` 不读该池，其口径是冻结段 `判据：`/门表。


## 池与声明

`milestone.mjs declare --list` 输出的是**可选池**（门 id、判据名），不是门→判据的映射。门表每门应有哪些判据，由该里程碑冻结段的 `- 门禁：`/`- 判据：`/`- 门禁判据：` 声明决定；`gate --file` 发现门表与声明不一致会点名缺少的判据或多余判据。补声明用 `milestone.mjs declare`，补 hash 用 `milestone.mjs freeze`。
