# 04 参考资源

> 查表用；规则正文在 01–03。表若与工具输出冲突，以工具输出为准（`criteria-doc --emit` / `declare --list` / `--help`）。

## 1. 判据池与说明表
- 权威来源：`node skills/sdo-flow/scripts/lib/criteria-doc.mjs --emit`（说明表由它生成，禁止手抄第二份）。
- 新增/改判据：同步 `lib/criteria-pool.mjs` 与 `lib/criteria-doc.mjs`，再跑 `check --presets`。
- 高频判据速查（完整表用上面的命令）：

| 判据 | 一句话 |
|---|---|
| `spec_set.signed` | 规格集合已签，且每条 requirement 有 pre-work 读数 |
| `assumption_set.signed` | 假设集合已签且无 open |
| `provenance.present` | 结论可追溯到生产者与证据 |
| `task.complete` | 卡/任务完成且证据齐 |
| `review.required` | 命中抽样或风险时必须有 pass 评审 |
| `review.independent` | 评审者非作者 |
| `trace.test_linked` | 判据有测试/证据链接 |
| `agent.mutation_red` | 关键规则有变异红证 |
| `readings.recorded` | 里程碑读数已记录且有 overall |
| `gate.signed` | 门表已由门签接受 |

## 2. 门 id 与 preset 清单（参考，不是真源）
- **真源是里程碑冻结段「- 门禁：」「- 判据：」声明；preset 只是可抄写的参考。新签里程碑真源出现 `preset：` 字段即 `preset_field_removed`（不写进真源）。**
- 参考文件（路径 + 它代表的阶段组合）：
  - `presets/incremental.md`：新建项目的增量组合（req_design→build→verify→integrate）。
  - `presets/prototype.md`：原型/探索组合。
  - `presets/waterfall.md`：顺序交付组合。
  - `presets/repair.md`：维修组合（G_repair_*，见文件与 `declare --list`）。
- 门 id 名单：`declare --list` 为当前来源；incremental 四门 `G_req_design`/`G_build_exit`/`G_verify_exit`/`G_integrate`；维修四门以 repair preset 为准。
- 要 `--map`：`milestone.mjs declare --list --preset <name>` 直接打印组合与逐门映射，按它抄；不需要外读 preset 文件也能抄全。
- 本节不写「选哪个 preset」的指引——选择由计划评审按新建/维修判定。

## 3. 错误码与退出码
| 码/值 | 含义与修法 |
|---|---|
| exit 0/1/2 | 绿 / 检查红 / 参数错 |
| `gate_criteria_undeclared` | 冻结段缺 `- 门禁：`/`- 判据：`；补两行并重算 hash |
| `gate_criteria_undeclared_legacy` | 历史签缺声明且已过门；WARN，不回溯 |
| `missing_declared_criterion` | 门表缺声明里的判据行 |
| `criterion_not_whitelisted` | 判据不在规范池；同步 pool/doc |
| `gate_unknown` | 门 id 不在 preset 名单 |
| `preset_field_removed` | 新签里程碑真源写了 preset 字段；删 |
| `signed_anchor_mismatch` | 追加签双锚点/签序不符 |
| `signed_tree_unknown` | 被签对象声明的 commit 不存在 |
| `baseline_drift` | 基线变了；更新冻结段+追加签或写 `基于旧基线：` |
| `requirement_missing` | 缺「认领需求：」或「需求：无（理由）」 |
| `frozen_hash_missing` | 冻结段缺 `hash:` 行 |
| `column_redacted` | agent 查询显式选中 human_only 列 |

## 4. 评审视角矩阵
| 视角 | 固定问题（至少答 2 个） |
|---|---|
| 白盒 | 实现与判据一致？边界/空值/并发想到？ |
| 黑盒 | 只凭文档能复跑？错误信息给下一步？ |
| 系统 | 与上下游接口/状态机一致？失败会怎样？ |
| 集成 | 写域冲突？跨泳道契约变了吗？ |
| 故障与恢复 | 中断/回滚/重放会丢数据吗？如何恢复？ |

## 6. 生成命令索引
- 判据说明表：`criteria-doc.mjs --emit`
- 门 id 名单：`declare --list`
- 门表骨架：`gate.mjs init <M> --check`（只读）
- 读数骨架：`readings.mjs init <M>`
- 帮助：`node scripts/<tool>.mjs --help`、`check.mjs --help`

## 7. 边界与不可机检
- 口头授权≠流程放行；`check` 绿不证明意图正确，签不证明内容正确。
- 挡不住：评审走过场、读数假路径、两份相同判定各自实现；不可机检项归评审与人签，partial 不改 pass。
