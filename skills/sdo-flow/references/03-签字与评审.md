# 签字与评审

## 1. 人签四要素

复述四件：**范围**（意图/计划/单卡/里程碑门）、**被签对象**（commit 或文件+sha256）、**判定**（pass/partial/fail，partial 写缺口）、**已知边界**（仍挡不住什么）。

## 2. 问答即签字

用 agent 的“提问并给选项”能力（名字随 agent 不同；纯文本会话就写编号选项），选项固定：

选项固定：`签：复述准确` / `改：复述不准（请指出）` / `不签：先不做`。

要点：
- 一个问题只签一件事；不许把“我问过”写成“签过了”；真人不在 ⇒ **阻塞**，不许模型代答。
- 一次问答最多合并 3 项（`sign.mjs batch <M>` 出 ≤3 份 ≤8 行草案，含范围/被签对象/判定/已知边界）；每项独立落 `S<n>.md`，草案只走 stdout。

示例：`# S3 单卡签字（M2-3）` + 时间 + 被签对象（commit/文件 sha256）+ 判定（C1/C2 pass；C5 partial 缺真实样本）+ 边界（账本可改、无密码学签名）+ 未决 + 选项三选一。

## 2.5 追加签与编号

同一被签对象（同一里程碑段、同一张卡、同一份读数）需要**再签一次**时（补口径、补一条读数、补一次评审结论），用 **追加签**：

- 文件名 `S<编号>-<A…Z>.md`（如 `S20-A.md`），同编号 A→Z 递增；必须写清被签对象（不能“同上”），保留选项/时间。
- 旧的签字文件**一个字节都不改**；换树/换范围用新编号，不拿追加签当新版本。

检查器只接受 `S<编号>.md` 与 `S<编号>-<字母>.md` 两种文件名，其余报错。

## 3. 多轮评审（不设上限）

| 轮 | 目的 | 判词 |
|---|---|---|
| 1 | 找问题 | 可收卡 / 改完再审 / 拒绝 |
| 2 | 只判上轮问题是否真闭合 + 顺带查新引入 | 同上 |

**判词的三种含义（不许混用）**：

| 判词 | 含义 | 接下来能做什么 |
|---|---|---|
| 可收卡 / 可签 | **它看的那棵树**上没有必须修的问题 | 只能在**这棵树没变**的前提下签字 |
| 改完再审 | 有必须修的问题 | 修完**必须再送一轮**，不能以“评审说过改完可签”为由直接签 |
| 拒绝 | 方向不成立 | 重写，不修 |

**“改完即可签”不是判词**：评审只能判它看到的树；它无法判断你后来改的是否改对、有没有改坏。因此：
- 评审后**只要动了文件**（哪怕只改一行），就必须再送一轮；
- 签字前的最后一轮评审必须是**“可签”且此后零改动**；
- 若确实不想再送审，正确做法是**不改**——把问题记为 P3/已知边界，而不是“改完就签”。

规则：
- 评审者必须**没写这段**；没有独立席位就写“自审（非独立）”。
- 问题分 P0（阻断）/P1（必须修）/P2（应修）/P3（可记）。
- 每条给 `文件:行号` 或可复现命令；“感觉不对”不算问题。
- 判“可收卡”时要写**它看的是哪棵树**；树一变就要复认。

## 3.5 评审视角矩阵（看什么）

| 视角 | 固定问题（每条评审至少答 2 个） |
|---|---|
| 白盒 | ①实现按判据走了吗？②边界/异常有证据吗？③与设计漂移在哪？ |
| 黑盒 | ①只给任务书能走通吗？②哪里靠猜或读源码才懂？③是否缺“下一步：”？ |
| 系统 | ①上下游影响清了吗？②状态机/权限有绕过吗？③回滚路径明确吗？ |
| 集成 | ①交付物清单与安装副本一致吗？②命令在新树可复跑吗？③旧里程碑退化了吗？ |
| 故障与恢复 | ①中断/半写会留下什么？②幂等重跑安全吗？③错误能自恢复吗？ |

**硬规则**：黑盒必须**真无上下文**（禁读 `.sdo/`、禁读源码，只读 `skills/sdo-flow/` 与任务书/目标产物）；**黑盒不替代白盒**——两者盲区互补，不能互相折算、省略或合成一票。卡面 `- 视角：` 写作者声明（值 `未声明` 不算覆盖）。
## 4. 变异红证（证明证据有效）

做法：
1. 先记录绿。
2. 把被测逻辑改坏（一处一改）。
3. 跑同一命令 ⇒ **必须红**；红了记下失败信息。
4. 用 `git checkout -- <file>` 恢复（**不要**用 `/tmp` 备份，容易覆盖残留）。
5. 再跑 ⇒ 必须回到绿。

把命令与两次输出摘要写进卡或读数；写不出来 ⇒ 这条证据是假的。

## 变异结果的边界（M5-2 起）

卡面「变异」表里的 `expected=red actual=red` 是**声明**：`check.mjs` 只验字段与格式，不能证明命令真跑过。评审必须复跑核对；`card.mjs mutation` 在临时副本执行、只输出结果、不写卡，证据仍由 `card.mjs evidence --cmd ... --run` 写入。


## 5. 评审席位失败

症状：子代理 `failed`、没有 closing message、或显示 `inactive` 但从未起回合；`send_message` 返回 `sent:true` 只代表消息已投递，不代表对方已评审。

处置：换一个独立席位重派；在评审记录的「席位」「失败处置」两行写清原席位、失败表现与换派结果。**不许**把 `sent:true` 当已评审，也不许用失败席位的票数凑齐独立评审。

## 签字编号

新增签字文件前**先取号**：`ls .sdo/sign | sort -V | tail -1` 取最大编号 +1；追加签用 `S<n>-<A…Z>`（第一份 `-A`）。
签文件是**只追加**的记录，已存在的编号不得覆盖——覆盖会被 `check` 以“门卡未签收”的形式暴露，但发现时已经损失了记录。


## 被签对象的两形态与锚点

- `git:<sha>`：有 git 时默认；需要项目根自己的 HEAD（不借用外层仓库）。
- `tree:<指纹>`：无 git 时的内容指纹；纯 Node 实现于 `skills/sdo-flow/scripts/lib/fingerprint.mjs`，只收普通文件、按相对路径字节序，每条 `sha256(路径 + "\0" + 文件 sha256)` 再整体 sha256 取 32 位；默认排除 `.git/`、`node_modules/`、`.tmp/`、`.work/`、`.sdo/.index/`；`sign.mjs` 与 `check.mjs` 共用 `signatureExcludes(milestone)`，额外排除 `.sdo/sign/`（签字产物）与**当前里程碑文件**（其完整性由冻结段 hash 单独锚定），避免签字动作自指。tree 指纹管文件树内容，冻结段内容由冻结段 hash 管，两者不重叠；改冻结段不会 tree DIFF，但会由 hash 比对报 `signed_anchor_mismatch`。`sign.mjs` 与 `check.mjs` 共用这一份。
- 锚点分派：同形态可比 ⇒ `SAME`（tree 同 / git 同 commit）、`DIFF`（tree 异）、`AHEAD`/`BEHIND`（git 领先/落后）；无锚点或形态不匹配（签 `git:` 而现无 git，或反之）⇒ `NO_ANCHOR`。形态不同绝不静默 `SAME`。
- 注意事项：内容指纹不证明来源/不防篡改，跨机器不保证同值；`.sdo/readings/`、`.sdo/cards/` 等真源纳入，派生的 `.sdo/.index/` 排除。


## 卡面骨架

卡面骨架由 `card.mjs new` 生成；`templates/card.md` 是供人阅读的参考模板，二者节标题集合一致。字段以卡面为准，模板不参与机检。
