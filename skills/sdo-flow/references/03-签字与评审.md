# 签字与评审

## 1. 人签四要素

复述里必须出现：

1. **范围**：签的是什么（意图 / 计划 / 单卡 / 里程碑门）。
2. **被签对象**：commit 短哈希，或文件 + sha256。
3. **判定**：pass / partial / fail，partial 要写清缺口。
4. **已知边界**：这次签仍然挡不住什么。

## 2. 问答即签字

用 agent 的“提问并给选项”能力（名字随 agent 不同；纯文本会话就写编号选项），选项固定：

- `签：复述准确`
- `改：复述不准（请指出）`
- `不签：先不做`

要点：
- 一个问题只签一件事；多件事分多题。
- 不许把“我问过”写成“签过了”；没选“签”就是没签。
- 真人不在场 ⇒ **阻塞**，不许模型自答或让别的 agent 代答。
- 签完落 `.sdo/sign/S<n>.md`：

```markdown
# S3 单卡签字（M2-3）
- 时间：2026-11-18T17:40+08:00
- 被签对象：commit `abc1234`；`.sdo/cards/M2-3.md` sha256 `…`
- 判定：C1/C2 pass；C5 partial（缺真实样本）
- 边界：文本账本可改；无密码学签名
- 未决：C5 的真实样本在 M3 补
- 选项：签：复述准确 / 改：复述不准（请指出） / 不签：先不做
```

## 2.5 追加签与编号

同一被签对象（同一里程碑段、同一张卡、同一份读数）需要**再签一次**时（补口径、补一条读数、补一次评审结论），用 **追加签**：

- 文件名 `S<编号>-<A…Z>.md`，如 `S20-A.md`、`S20-B.md`；同一编号按 A→Z 顺序递增。
- 追加签必须写清「被签对象」（可以是 commit，也可以是“S20 追加：只新增 R25 行”），不能只写“同上”。
- 正文里保留「选项」「时间」；旧的签字文件**一个字节都不改**（只追加签，不改旧档）。
- 新对象（换了树、换了范围）用**新编号**，不要拿追加签当新版本。

检查器只接受 `S<编号>.md` 与 `S<编号>-<字母>.md` 两种文件名，其余报错。

## 3. 多轮评审（不设上限）

| 轮 | 目的 | 判词 |
|---|---|---|
| 1 | 找问题 | 可收卡 / 改完再审 / 拒绝 |
| 2 | 只判上轮问题是否真闭合 + 顺带查新引入 | 同上 |

规则：
- 评审者必须**没写这段**；没有独立席位就写“自审（非独立）”。
- 问题分 P0（阻断）/P1（必须修）/P2（应修）/P3（可记）。
- 每条给 `文件:行号` 或可复现命令；“感觉不对”不算问题。
- 判“可收卡”时要写**它看的是哪棵树**；树一变就要复认。

## 4. 变异红证（证明证据有效）

做法：
1. 先记录绿。
2. 把被测逻辑改坏（一处一改）。
3. 跑同一命令 ⇒ **必须红**；红了记下失败信息。
4. 用 `git checkout -- <file>` 恢复（**不要**用 `/tmp` 备份，容易覆盖残留）。
5. 再跑 ⇒ 必须回到绿。

把命令与两次输出摘要写进卡或读数；写不出来 ⇒ 这条证据是假的。

## 变异结果的边界（M5-2 起）

卡面「变异」表里的 `expected=red actual=red` 是**声明**：`check.mjs` 只验字段与格式，不能证明命令真跑过。评审必须复跑核对；`card.mjs mutation` 在临时副本执行、只输出结果、不写卡，证据仍由 `card.mjs evidence --cmd ... --run` 写入。
