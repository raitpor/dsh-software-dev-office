# 项目基线（四份）

> 项目级基线只放在 `.sdo/baseline/`，四份文件名固定；卡面用 `references:` 引用需求 id，不复制正文。
> 基线内容 hash 由 `scripts/lib/hash.mjs` 单点计算；里程碑冻结段用 `基线 hash：<64 hex>` 绑定版本。

## 1. requirement.md · 需求

```markdown
### R-01 <可判的需求标题>
- 验收：<一句可判的验收语句；写清命令/可观察结果>
```

每条需求有稳定 id（`R-<n>`）与验收；至少 3 条真实需求，不写占位。

## 2. architecture.md · 架构决策

```markdown
## ADR-<n>：<标题>
- 决策：<选了什么>
- 备选：<还考虑过什么，为什么没选>
- 后果：<得到什么、付出什么>
```

至少 1 条 ADR；三字段齐全，才可被 M8-4 的 ADR 校验识别。

## 3. test-strategy.md · 测试策略

```markdown
| 变更类型 | 测试技术 |
|---|---|
| <脚本/规则> | <单测/副本夹具/变异> |
| <模板/文档> | <结构检查/反例> |
| <基线/计划> | <hash 重算/漂移反例> |
```

表头固定为 `| 变更类型 | 测试技术 |`，至少 3 行真实策略。

## 4. quality-risk.md · 质量与风险

```markdown
## 质量属性
- <属性>：<可观察的取舍>

## 风险登记
| 风险 | 影响 | 处置 |
|---|---|---|
| <风险> | <影响> | <处置/边界> |
```

质量属性与风险登记各至少 1 条；风险必须写处置或明确边界。
